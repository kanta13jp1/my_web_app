# 高リスク producer と入力ハッシュの未完成設計

実装・本番接続・レビュー結果ではなく、次工程の検討材料。本人データ、会社メール、給与明細PDFは取得・送信しない。

## 入力の独立再構成

現行の通常レビューは、保護された base と PR head の Git オブジェクトから `git diff --no-ext-diff --no-textconv --no-renames --unified=40 base...head` を生成し、既存の制限と秘密・金額のマスキング後にSHA-256を計算する。本文やログを検証用artifactに追加しない。検証側も同じ base の信頼済みロジックでローカル再構成し、成果物に記録されたハッシュと照合する。対象ファイル名の欠損・不一致、Gitオブジェクト欠損、サイズ超過、非UTF-8、未対応画像や検査失敗は拒否する。

`input_integrity.py` は架空Gitデータと模擬redactorを使った局所試作。正規のscope・redactorが保護済み base から読み込まれること、入力の上限や全パス、binary・symlink・rename・画像バインディング、Git設定・版差、完成したproducerと独立した実装の比較は未検証。実ユーザーのdiffを外部送信しない。

**停止時間の保証は未完成。** 出力上限は適用するが、Gitの子孫がstdoutを保持すると、親プロセス終了後もreaderのロックにより `close()` が待ち続け得る。合成プロセスで再現済み。現状は制御された合成データに限定し、実データ・本番CIには接続しない。Windowsのshimを含む所有プロセスツリーの安全な隔離・終了と、タイムアウト・残存プロセス・他プロセス非干渉の検証が必要。

## 5観点の生成と段階を区別

既存の承認済み通常AI reviewerは correctness/security/tests の3観点。安全な拡張には、security、rollback、data migration、production smoke、observability それぞれの対象と具体的な根拠、実施/計画/未確認を構造化し、欠落や未確認を勝手に「完了」にしない producer が必要。ユーザーが承認した既存経路を利用し、追加の有料Claude設定を変更しない。秘匿パス・添付・個人の金融観測は除外し、redaction失敗や過大入力時は外部送信を中止する。

特に未配信変更はマージ前に実本番 smoke の成功を示せない。レビュー時には実施可能な smoke **計画**と限定配信・rollback条件を検査し、実 smoke の成否は限定配信後に別途確認する。どちらも証跡がなければ未確認として残し、計画だけで実行済みとは表示しない。審査時の許容条件と実行後ゲートの仕様は要レビュー。

## 本番接続までの残件

- 検査スクリプト自体を trusted base から取得し、PR側コードを特権実行せず、依存するbase上の redactor とscope checkerの真正性・再現性を検証。
- 観点別の機械証跡、head/base拘束、利用可能な検査資料の範囲、実観測と計画の区別、未解決findingの扱いについて独立レビュー。
- 全PRを高リスク扱いする試作の運用負荷と、未実証パスを許す例外の危険性を評価。
- 二重チェック、mutable本文/ラベル、旧成功チェック、readyイベントとbootstrap、取消・レート制限・再送・base変更の実イベント検証。
- 必須化や本番配信はこれらの検証後に別工程で実施。現行試作はブランチ保護を変更しない。
