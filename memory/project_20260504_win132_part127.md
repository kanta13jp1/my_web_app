## 制約 / 学び

1. **「画面 1 枚 → 2 ファイル数十文字列」localization の規模感** — UI 表面 (= page) より service の hard-coded 内容が多い (= 17 ページ × 5 field = 85 文字列). User screenshot で 1 画面異常を見ただけで 2 ファイル深い localization が必要だった.
2. **threat ranking 「Ignore for now」→「当面無視」の翻訳判断** — literal 翻訳 (= "今のところ無視") より UX 自然 (= 「当面」) を選択. 4 段階 ranking の他 3 段階 (= 緊急/高/監視) と同じ語感を保つ判断.
3. **service 内 hard-coded i18n は将来 .arb 化候補** — 17 ページ × 5 field の hard-coded 日本語は再 localization (= 英語/中国語拡張時) で再作業発生. **AppLocalizations + .arb migration** は別 Issue 候補.
4. **brand keywords (= Tome / Airtable / KGI / CSF / KPI / WBS / RLHF) は英語維持** — 日本人開発者が読む業界用語のため translate せず. UX 観点で正しい判断.
