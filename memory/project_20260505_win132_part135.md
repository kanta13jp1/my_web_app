### Component 2: `scripts/sync_inject_rules.py` (~210 行 / dependency-free)

- **dry-run** (default): canonical と home の diff 表示 + drift 行数

- **--reverse**: home を canonical に push (= 開発者編集の repo 反映用)
- **--verify**: integrity check (= 行数 ≤ 80 / rule 数 = 37 / 全 critical rule 残存)
- **--json**: JSON output
- 全 37 critical rules を script 内 list で固定 → drift 検出基準明確化

## 学び

1. **「local-only file の repo 化 trade-off」**:
   - メリット = 履歴保存 / drift 検出 / fleet 横断同期可能
   - デメリット = 同期コマンド忘れ → home が古いまま (= session-start-check で補完)
   - 解決: weekly cron + skill ステップ + dependency-free script のシンプル組み合わせ

2. **「全 37 critical rules を script 内固定」設計**:
   - メリット = drift 検出基準明確 / GHA runner で実行可能
   - デメリット = rule 追加時に script update 必要 (= git 履歴で追跡)
   - 解決: docs/RULES_INDEX.md と script 同期は手動 PR で確認

3. **「.gitignore exception 不要」発見**:
   - `.gitignore` は `.claude/worktrees/` のみ除外
   - `.claude/inject-rules.txt` は default で tracked
   - worktree 内では add 不可 (= main repo に直接 copy + commit)
