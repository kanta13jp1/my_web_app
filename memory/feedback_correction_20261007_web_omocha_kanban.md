## 訂正 1 (重大): 「誠実化」の名で元ネタの価値を壊しかけた

**何をしたか**: 機能の出発点はツイート (@henteko07 / OMOCHA WORKS) で、その価値は
「何をしてるかわからないけど AI が自動でガシガシタスクをこなしてくれる」「**みてるだけで楽しい**」だった。
にもかかわらず `/grill-me` の 2 周目で、「売上インパクトの ¥ 表示は実測でないので廃止」「CPU/メモリゲージを実測 3 種へ差し替え」と
**遊び要素の削除**を提案し、ユーザーに `この機能と全く違わないですか？` + 元 URL を再提示されて止められた。

**何が間違いだったか**: 「数字が実測でない」ことを欠陥と判定したが、この機能の仕様は**アンビエントな鑑賞体験**で、
演出値はバグではなく仕様。誠実さは「演出であると明示する」で満たせるのに、価値そのものを削る方向へ進んだ。

**Why:** 自分の「正しさ」(= 実データ主義) を、ユーザーが示した機能の目的より上に置いた判断ミス。
これは技術的誤りではなく**要求の読み替え**で、CI では絶対に検出できない。
**How to apply:**
- 元ネタ (ツイート / スクショ / 競合画面) が与えられた機能は、**その元ネタを毎ターン判断基準に戻す**。
  「元ネタのどの魅力を保つ変更か」を言えない提案はしない。
- 演出値を扱う時の正解は「削除」ではなく「シミュレーション / 演出とラベルする」。
  実際に採用した `シミュレーション · トークン未設定` / `実データ · GitHub Actions` のバッジ分岐がその形。
- 2 周目の `/grill-me` が 1 周目と**別方向へドリフト**し始めたら、それは追加改善ではなくスコープ逸脱の兆候。

## 訂正 2: 失敗テストを、実装を読む前の仮説で直した

`test/widgets/asset_management_page_smoke_test.dart` が (今回の変更とは無関係に) 日付依存で落ちていた。
最初の修正は「資産の dateKey を固定日 `DateTime(2026,7,10)` にする」で、**これは外れ**。まだ落ちた。
実装 (`lib/pages/asset_management_page.dart`) を読んで初めて真因が判明:

- `_todayDateKey() => _dateOnly(DateTime.now())`
- `_currentSalaryCycleKey()` は `_now` (= 実 `DateTime.now()`) を使い、`debugCalendarNow` では**上書きされない**

テストは固定日の給与サイクルに支払いを入れていたため、salaryDay (既定 25) を跨いだ日に実行すると境界で外れる。
正解は「資産 dateKey と支払い monthKey の**両方**を実 `DateTime.now()` 基準にする」だった。

**Why:** 「日付依存だろう」という当たりは合っていたが、どの時刻源が上書き可能かを**読まずに**修正した。
1 回の CI (数分〜) を仮説検証に使うのは、ローカル SDK が無い環境では特に高コスト。
**How to apply:** テスト失敗は、修正前に必ず (1) 失敗アサーションの実値、(2) 対象ページの時刻源
(`DateTime.now()` / `debugCalendarNow` / 注入 now) を読む。CI を仮説のガチャに使わない。
