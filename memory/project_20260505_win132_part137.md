## 完了

### Phase A: 初回実行 + bug 発覚

```
Register-ScheduledTask : The parameter is incorrect.
  (20,8):UserId:
```

原因: `New-ScheduledTaskPrincipal -UserId $env:USERNAME` で `$env:USERNAME = "kanta"` 単独はダメ. `Register-ScheduledTask` は **DOMAIN\USER** 形式 (= `KANTA\kanta`) を要求.

二重問題:
- script が `Register-ScheduledTask` 失敗後も `Write-Host "INSTALLED"` を表示 → false-positive
- Get-ScheduledTask で確認すると task 不在 = 実は registration 失敗

### Phase B: 修正

`scripts/setup_inject_rules_auto_sync.ps1`:
1. `$userId = "$env:USERDOMAIN\$env:USERNAME"` (= 「KANTA\\kanta」)
2. `Register-ScheduledTask` を `try/catch` + `-ErrorAction Stop` で wrap
3. 失敗時は `Write-Error` + admin elevation hint
4. **registration 後 verify**: `Get-ScheduledTask -TaskName $TaskName` 確認 / 不在なら `exit 5`

## 学び

1. **「Register-ScheduledTask UserId 形式」**:
   - `$env:USERNAME` 単独 = NG
   - `$env:USERDOMAIN\$env:USERNAME` = OK
   - PowerShell 5.1 / Windows 11 で確認
   - **記録 → docs/RULES_INDEX.md に PowerShell-tip section 追加候補** (or `docs/instance-constraints.md`)

2. **「false-positive INSTALLED」防止**:
   - 全 register 系 cmdlet は **registration 後 Get-* で再確認** (= verify-after-write pattern)
   - `Write-Host "INSTALLED"` を Register より前に出してはダメ
   - try/catch + -ErrorAction Stop で確実に exception 拾う

3. **「PowerShell tool 経由の自走」**:
   - Win Claude が Windows native 操作 (= Task Scheduler / Service Control Manager / Registry) を直接実行可能
   - bash + cygwin では同じ tool に到達できない (= part 134 .gitignore 落とし穴と同種の制約)
   - PowerShell tool は Win territory の固有強み

4. **「Plan mode skip 判断」**:
   - 既存 script の挙動修正 = 単純 (= 1 file / 設計判断なし)
