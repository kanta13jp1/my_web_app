## 0. このドキュメントについて

- **目的**: 自分株式会社の「**誰のために / 何を / どこまで / 何をしないか / 成功をどう測るか**」を 1 枚に固定し、後続の機能 Issue・設計 (ADR)・WBS が迷わない上位基準にする。
- **位置づけ**: [`PHILOSOPHY.md`](PHILOSOPHY.md) (恒久理念) と WBS (実行計画) の間を埋める **製品定義**。理念を「測れる要件」に翻訳する層。
- **運用 (living doc)**: 週次レビューで更新 / スコープ拡大時は feature Issue に分割し本 PRD は薄く保つ / 重要な設計判断は [`adr/`](adr/README.md) に ADR 化。
- **v1 注記**: 本版は既存 canon (理念 / 本番機能 / 競合 / WBS マイルストーン) から codify した **baseline**。L1 (Antigravity+Gemini) 探索結果が出たら persona / scope を継続精緻化する (= 原則どおり「固定 → 検証 → 改訂」)。

## 1. ビジョン / コンセプト

- 一文: **「あなたの人生を、あなただけの会社として経営する」**
- ユーザーは人生という会社の **唯一の株主・社長 (CEO)**。本プロダクトはその経営を支える framework / 道具 (= ソフトウェア)。
- 北極星 (ゴール): **IPO = ウェルビーイング** — 自分の価値を最大まで高め、自己コントロールが効き、それを周囲・社会に還元できている状態が持続すること。

## 2. ターゲットペルソナ

| 区分 | 像 | 中心ニーズ |
|------|----|-----------|
| **Primary** | 人生を意図的に経営したい個人 (20–40 代 / 自己投資志向) | 学習・お金・健康・発信・ミッションを 1 か所で俯瞰し、昨日の自分より良くしたい |
| **Secondary** | 副業・独立志向 | 自分の価値 (スキル・経験) をポートフォリオ化し発信したい |
| **Anti-persona** | 他人比較ランキングで競いたい / 最適化を丸ごと AI に丸投げしたい人 | 本プロダクトは最終決定権をユーザーに残す設計のため不一致 (原則 1・8) |

## 3. 提供価値 (6 部署モデル)

理念の「人生 = 6 部署を持つ会社」を製品の価値構造として採用する。**人事 (健康) を最優先** (ここが止まると全部署が機能停止)。

| 部署 | 人生での活動 | 提供価値 |
|------|------------|---------|
| 本社 (経営企画) | ミッション・KPI・取締役会 | 全体俯瞰・自己進捗の可視化 |
| 研究開発 (R&D) | 学習・自己投資 | スキル・知識の増大と発信 |
| 財務 | 収支・貯蓄・投資 | お金=時間資本の最適配分 |
| 人事 (**最優先**) | 心身の健康・休養 | 土台となる健康の維持 |
| マーケ営業 | アピール・人脈 | 自分の価値の発信・接続 |

## 4. スコープ (In-Scope)

GA に含む領域 (6 部署 × 既存本番機能 + 基盤):

- **本社**: ホーム/ダッシュボード, 基本理念ページ, KPI 可視化 (昨日の自分比較)
- **R&D**: AI大学 (多社学習), タグ付きノート, ブログ作成・自動発信, AI ランキング
- **財務**: 家計簿・収支ダッシュボード (MoneyForward 代替方向)
- **人事**: 健康・睡眠・ジャーナル (最優先領域)
- **マーケ営業**: プロフィール公開, SNS 統合
- **横断 AI**: 優しい mentor 型の提案。実行可否は常にユーザーが決定 (原則 1・3)
- **基盤**: Flutter Web + Supabase + Firebase Hosting ([`adr/`](adr/README.md) 参照), モバイル展開 (Issue #1495)

## 5. 非目標 (Non-Goals) — 明示的にやらないこと

理念の NG 例から導出。スコープ膨張を防ぐ防波堤。

- ❌ 滞在時間最大化 / 中毒性設計 (無限スクロール等) — 原則 9 違反
- ❌ 監視・命令型 AI / 罪悪感を与える通知 — 原則 3 違反
- ❌ 他人比較を主軸にしたランキング (副次・希望者のみ表示は可) — 原則 8
- ❌ ユーザーの最終決定権を奪う全自動最適化 (事後通知のみ) — 原則 1
- ❌ ミッションと無関係な単なる ToDo / ポイント稼ぎ — 原則 2・7
- ⏸ (現時点) 法人向け SaaS・チーム機能 — 個人の経営に集中。事業拡大期に再評価

## 6. KPI / 成功指標

2 層に分け、North-Star を事業 KPI より優先する (原則 8・9)。

- **North-Star (ウェルビーイング)**: ユーザーの「昨日の自分」比較での自己進捗・自己効力感・社会還元感。短期 DAU / 滞在時間は北極星にしない。
- **事業 KPI (ガードレール = 生存指標 / WBS マイルストーン)**:
  - MVP 一般公開 **1,000 users** (2026-09-30)
  - **有料 100 顧客** (2027-03-31) → Seed → Series A → **IPO** (2029-12-31)
  - これらは生存のための指標であり、North-Star を犠牲にして追わない。
- **反指標 (監視して避ける)**: 中毒的滞在時間, 他人比較依存度。
