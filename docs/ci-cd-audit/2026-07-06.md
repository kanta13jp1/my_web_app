## 検出した冗長フロー

### A) 重複トリガー

- **なし**: ci.yml は push: staging/develop + PR のみ対象。main は deploy-prod.yml が workflow_call で呼ぶ設計で二重起動なし。✅

### B) cancel-in-progress 未設定で並行実行が積み上がる可能性 (med)

- **mcp-audit-anomaly-cron**: 2h 間隔・`cancel-in-progress: false`。ジョブが 2h を超えるとキュー積みリスク。実態は 0.3 min/run なので確率は低いが防御的に true 推奨。
- **blog-publish-orphan-cleanup**: 6h 間隔・`cancel-in-progress` 未設定。orphan 削除処理が重複実行するリスク。
- **issue-to-wbs**: 6h 間隔・`cancel-in-progress` 未設定。WBS 書き込みが並行すると競合する可能性。
- **tools-hub-mcp-smoke**: 6h 間隔・`cancel-in-progress` 未設定。smoke test は並行不要。

### C) paths フィルタ無し (low)

- schedule トリガーのみのワークフローは push イベントがないため該当なし。
- ci.yml / deploy-*.yml は既に `paths-ignore` 設定済み。✅

### D) 過剰な cron 頻度 (high)

- **claude-session-hygiene-cron**: 180 min 間隔 = 8x/日 on `windows-latest`。前回監査 (06-21) から変化なし。windows 2× billing で月 480×。→ **本実行で 360 min 間隔 (4x/日) へ削減適用**。
- **x-post-metrics-optimizer**: 3h 間隔 = 8x/日。X metrics は 6h 以上の間隔でも十分。→ **本実行で 6h 間隔 (4x/日) へ削減適用**。

### E) cache 未使用 (low-med)

- **e2e-smoke**: `npm ci` 実行だが `actions/setup-node@v6` の cache オプション確認が必要。ただし週次なので優先度低。
- その他主要ワークフローは pip cache / npm cache 設定済み。

### F) 失敗率が高いワークフロー

- サンプル 30 runs すべて成功 (0% failure)。ただしサンプルサイズ小のため統計的有意性低。
- **cron-batch**: コメントで `DISABLED` 明記。schedule を workflow_dispatch のみに変更済み。再有効化未定。

### G) 廃止候補 (med)

- **cron-batch.yml**: `SUPABASE_SERVICE_ROLE_KEY / GEMINI_API_KEY 未設定` でエラーとなるため、コメントで schedule 無効化済み。長期的に削除または secrets 設定して復活させるか判断推奨。
