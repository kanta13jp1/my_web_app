## 検出した冗長フロー

### A) 目的重複 [med]
- `WBS User Task Notify` (wbs-user-notify.yml) と `WBS User Tasks Notify` (wbs-user-tasks-notify.yml) が同一 cron `0 0 * * *` で類似目的 (WBS タスク通知)。統合候補。

### B) concurrency 未設定で並行実行積み上がる [HIGH]
以下 15 本が concurrency 未設定。毎時/毎日 schedule では並行実行が積み重なるリスクがある:
- `Memory Search Sync` (毎時) — **最高リスク** → 本実行で修正済み
- `Daily Report Freshness Monitor` (毎日)
- `Knowledge Graph Indexer Nightly` (毎日)
- `WBS Staleness Audit` (毎日)
- `Blog Publish Orphan Branch Cleanup` (6時間毎)
- `AI Bench Source Recheck` (週次)
- `AI Model Telemetry Monthly Review` (月次)
- `Stale EF Migration Completeness Check` (push + 週次)
- `Release Notes Data` (push + PR)
- その他 6 本 (workflow_dispatch / PR)

### C) paths フィルタなし [low]
- `windows-companion-build.yml` — タグトリガー (`windows-companion-v*`) なので実害なし。

### D) 過剰な cron 頻度 [med]
| ワークフロー | 現在 | 推奨 | 理由 |
|---|---|---|---|
| Feature Review | 毎時 | 毎4時間 or 毎日 | 機能レビューは頻度高すぎ |
| Schedule Resilience Watch | 毎時 | 毎4時間 | 監視系、毎時は冗長 |
| WBS AI Review | 毎時 | 毎2-4時間 | AI レビューは即時性不要 |
| Edge Function UI Audit | 毎時 | 毎4時間 | UI 変化は頻繁でない |
| Infra Health Check | 毎時 | 毎2時間 | Health Monitor (30分毎) と重複気味 |

### E) cache 未使用でビルドが毎回フル [HIGH]
- **CI (ci.yml)**: `~/.pub-cache` キャッシュ未設定。`flutter pub get` が毎回 30-60 秒かかる。→ **本実行で修正済み**
- `setup-flutter-sdk` action: 毎回 `git clone --depth 1` で Flutter SDK (~数百 MB) を取得。actions/cache 未設定。
- push (staging/develop) + PR + deploy-prod/dev/staging (workflow_call) すべてで発動するため、最も削減インパクトが大きい。

### F) 失敗率が高く再実行コストを積むワークフロー [HIGH]
- `tools-hub MCP Smoke` — 6時間毎 schedule で **100% failure** (直近サンプル)。失敗し続けている間も billable 時間を消費。原因調査 + disable が必要。
- `Minimal E2E Gate` — PR トリガーで 100% failure (1サンプル)。Chrome テストの環境問題の可能性。

### G) 廃止候補 [med]
- `cron-batch.yml` (Scheduled Analysis Batch) — ファイル冒頭に `# DISABLED: batch_analysis.py が毎回エラー` とコメント。schedule は既に無効化 (workflow_dispatch のみ)。ファイル自体は削除候補。

## 自動適用した変更 (本実行)

### 変更 1: `ci.yml` — Flutter pub cache 追加
- `Setup Flutter` → `Install dependencies` の間に `actions/cache@v4` を追加
- キャッシュパス: `~/.pub-cache`
- キャッシュキー: `${{ runner.os }}-pub-${{ hashFiles('**/pubspec.lock') }}`
- **推定削減**: flutter pub get 30-60秒 → キャッシュヒット時 5-10秒。CI 実行ごと約 30-50秒短縮。
  push + PR + workflow_call の全トリガーで効く。

### 変更 2: `memory-search-sync.yml` — concurrency 追加
- `concurrency: { group: memory-search-sync, cancel-in-progress: true }` を追加
- 毎時実行が前回実行と重なった場合に古い実行をキャンセル。積み上がり防止。
- **推定削減**: 過去に並行実行が発生していた場合、最大 10分/回の重複コストを排除。
