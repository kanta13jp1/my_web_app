## 検出した冗長フロー (A–G)

### A) 重複ビルドトリガー — 該当なし
`ci.yml` は `staging/develop push` のみ (main は deploy-prod.yml が呼ぶ)。パス重複なし。

### B) cancel-in-progress 未設定による並行積み上がり — 優先度 **high (Issue 提案)**

**`mcp-audit-anomaly-cron.yml` の `script-test` ジョブがスケジュール実行で不要に動作**

- `script-test` ジョブ (deno check / lint / test) は PR 変更検証が目的
- しかし `if:` 条件が未設定のため、2h cron のたびに全 360 runs/月で実行される
- `detect` ジョブのみが実際のセキュリティ監査であり、スケジュール時に必要
- スクリプト変更がない限り `script-test` の schedule 実行は無価値
- **推定削減効果**: `script-test` ジョブ平均 ~3 分 × 360 runs = **約 18 時間/月**
- 対処: `script-test` ジョブに `if: github.event_name != 'schedule'` 追加 → Issue 提案

### C) paths フィルタ未設定 — 該当なし
push トリガーを持つ全 15 ワークフローを確認。全て `paths-ignore:` または `paths:` が設定済み。

### D) 過剰 cron 頻度 — 優先度 **med (新規)**

| ワークフロー | 現在 | 提案 | 削減効果 |
|---|---|---|---|
| mcp-audit-anomaly-cron | */2h (360/月) | */4h (180/月) | 180 runs/月削減 |
| Notion Mirror Sync | */2h (360/月) | */3h (240/月) | 120 runs/月削減 (rate limit考慮) |

上記 2 件は人手レビュー推奨 (security / API rate limit の判断が必要)。

### E) cache 未使用 — 優先度 **med**

Deno を install するが `actions/cache` が未設定のワークフロー:
- `.github/workflows/dependency-audit.yml` (週次, 低影響)
- `.github/workflows/mcp-audit-anomaly-cron.yml` (2h, **高影響** — 360/月)
- `.github/workflows/release-readiness.yml` (週次, 低影響)

`mcp-audit-anomaly-cron.yml` は `denoland/setup-deno@v2` を使用。Deno バイナリ自体はアクションがキャッシュするが、DENO_DIR (モジュールキャッシュ) は未キャッシュ。外部 import があれば毎回ダウンロードが発生する可能性。

### F) 失敗率高ワークフロー — 計測不可
`gh run list` が認証なしのため統計取得不可。過去監査ログから CI は安定稼働中と判断。

### G) 廃止候補 — 優先度 **low**
