## 検出した冗長フロー (A–G)

### 🔴 HIGH

#### F-1: CI・E2E・AI-PR-Review 失敗率 50% (pull_request)
- `CI`, `Minimal E2E Gate`, `AI Agent PR Review` がサンプル 2 runs 中 1 失敗 (50%)。
- 本日の PR マージ起点の過渡的失敗の可能性があるが、継続監視推奨。
- 推定コスト: 再実行分 ~72 ubuntu-min/月。

#### F-2: workflow-failure-handler 内の stale 名称参照
- `workflow-failure-handler.yml` line 32: `"AI大学コンテンツ更新 (2時間毎)"` を監視リストに含む。
- 実際のワークフロー名は **`AI大学コンテンツ更新 (4時間毎)`** (2026-06-22 の名称変更)。
- このまま放置すると、AI大学 workflow の失敗が handler に到達せず Issue 未生成。

### 🟡 MED

#### A: `hotfix-stripe-url.yml` — 目的達成済み・削除候補
- `supabase/functions/schedule-hub/index.ts` に修正対象 URL `my-web-app-b6f7f4` の旧タイポが 0 件。
- この hotfix ワークフローは目的を達成し、以後 `NO FIX NEEDED` と出力するだけ。
- トリガー条件: `push` to `main` + `paths: ['.github/workflows/hotfix-stripe-url.yml']` のみ → 実害は小さいが、混乱の元。

#### B: `cron-batch.yml` — 長期 DISABLED (secrets 未設定)
- コメント `# DISABLED` のまま `workflow_dispatch` のみ。
- `SUPABASE_SERVICE_ROLE_KEY / GEMINI_API_KEY` 未設定のため schedule 復活不可。
- 削除 or secrets 設定の判断が必要。

#### C: `issue-wbs-maintenance.yml` — legacy wrapper 整理
- `Legacy entry point` コメントあり。実体は `issue-to-wbs.yml` に統合済み。
- `workflow_dispatch` のみで schedule なし → 即時削除しても実害なし。

#### D: cancel-in-progress: false のまま残る非 deploy schedule ワークフロー群
- `ai-university-reminder`, `blog-draft`, `blog-engagement`, `competitor-monitoring` など多数が `false` のまま。
- 通知・投稿系は中断リスクあり → 個別判断が必要。

### 🟢 LOW

#### E: `workflow-failure-handler` 監視対象に gaps
- `Blog Engagement (毎日・コメント返信/フォロー/重複削除)` など現行名称変更済みのワークフローが旧名で登録されている可能性あり。
- 実害は小さいが、名称が合わないと failure cluster が作成されない。

#### G: `blog-news-signal-lint.yml` — 単体 lint のみで build なし
- `blog-news-signal-draft.yml` と `blog-news-signal-lint.yml` が 5 分差の daily cron。
- 同一 push/PR で両方が走らないか確認推奨 (lint が draft の結果に依存しているなら順序保証が必要)。
