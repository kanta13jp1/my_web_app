## 検出した冗長フロー (A–G)

### A) 重複トリガー [priority: low]
- 同一 push で重いビルドが重複する件は確認されず。
- `deploy-prod.yml` / `deploy-dev.yml` / `deploy-staging.yml` はそれぞれ別ブランチ (main/develop/staging) で分離されており問題なし。

### B) cancel-in-progress 未設定で並行実行が積み上がる [priority: low]
- 全 112 ワークフローが `concurrency:` を持ち、設定漏れはゼロ。
- `notion-sync.yml` (2h, false): **Notion rate limit (3 req/sec) のため逐次実行が必須** → 変更不要。
- `mcp-audit-anomaly-cron.yml` (2h, 動的): PR は true / schedule は false (セキュリティ監査ギャップ防止) → 最適設計。
- 2h サイクル 5 本のうち `cs-check` / `health-monitor` / `memory-search-sync` はすでに `cancel-in-progress: true`。

### C) paths フィルタ不足 [priority: none]
- push トリガー (非 deploy) を持つ唯一のワークフロー `windows-companion-build.yml` は `push: tags: 'windows-companion-v*'` のみで起動 → docs 変更で不要実行が走るパターンは存在しない。
- 3 つの deploy ワークフローは全て広範な `paths-ignore` 設定済み (docs / memory / .claude / .codex / **/*.md 等)。

### D) 過剰な cron 頻度 [priority: low]
- 過去の ci-audit (2026-06-10 / 2026-06-22 / 2026-07-17) で毎時 → 2h / 2h → 4h への削減、0:00 UTC 集中の分散が実施済み。
- 現状は妥当な水準に達しており、今回新たに削減すべき明確なターゲットは見当たらない。
- 観察: `notion-sync` (2h) は将来 4h へ候補だが Notion mirror の鮮度要件で判断が必要 → Issue 提案のみ。

### E) cache 未使用でビルドが毎回フル [priority: high]
以下 16 本が `flutter pub get` / `npm install` / `pip install` を持ちながら cache を使用していない:

| ファイル | 頻度/月 | インストール | 優先度 |
|---------|---------|------------|-------|
| `notebooklm-issue-crosscheck.yml` | 30 | `pip install notebooklm-py` | **HIGH** |
| `notebooklm-requirements-to-issues.yml` | 30 | `pip install notebooklm-py` | **HIGH** |
| `blog-draft.yml` | 30 | `pip install requests` | med |
| `blog-engagement.yml` | 30 | `pip install requests` | med |
| `blog-verify.yml` | 4 | `pip install requests` | low |
| `weekly-sns-draft.yml` | 4 | pip | low |
| `ai-tool-changelog-watch.yml` | 1 | pip/npm | low |
| `blog-backfill.yml` | 1 | pip | low |
| `blog-batch-publish.yml` | 不定 | npm | low |
| その他 7 本 | 低頻度 | pip | low |

`notebooklm-py` は複数の依存パッケージを持つため `requests` (軽量) より高い節約効果が見込まれる。

**→ 本実行で `notebooklm-issue-crosscheck.yml` と `notebooklm-requirements-to-issues.yml` に pip cache を追加 (後述)**

### F) 高失敗率ワークフロー [priority: low]
