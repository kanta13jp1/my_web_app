## 検出した冗長フロー (A-G)

### 🔴 HIGH

#### [F] minimal-e2e-gate.yml — 100% 失敗継続
- PR トリガー、最新 run で 100% failure (playwright / npm ci 問題)
- `public-e2e-stability` job が毎 PR で `npx playwright install --with-deps chromium` を実行するが失敗
- 推定コスト: PR ごとに ~110s 無駄実行 + CI red 通知コスト
- **対応**: npm依存・playwright バージョン整合性を確認。`--with-deps` が ubuntu-latest で失敗する場合は `npx playwright install chromium` に変更

#### [A] ai-tool-watch.yml / ai-tool-changelog-watch.yml — 同名 "AI Tool Changelog Watch"
- 2 つのワークフローが同じ `name:` を持つ
- `ai-tool-watch.yml`: 日次、Claude/Codex 変更ウォッチ
- `ai-tool-changelog-watch.yml`: 月次、詳細 changelog 取得
- GitHub Actions UI / バッジ / 失敗通知で混乱のリスク
- **対応**: `ai-tool-changelog-watch.yml` の name を `AI Tool Changelog Monthly` に変更

### 🟡 MED

#### [D] claude-session-hygiene-cron.yml — windows-latest で 21 runs/日 (→ **本回 11/日 に削減 ✅**)
- `0 21-23,0-17 * * *` (21 runs/日) → `0 21,23,1,3,5,7,9,11,13,15,17 * * *` (11 runs/日)
- windows-latest は ubuntu 比 2x billable 時間
- 推定削減: ~10 runs/日 × 40s × 30日 = **~200 分/月 (windows時間 ≒ 400 ubuntu-min/月)**
- 2026-06-12 に 30min→60min (前回削減)。本回は 60min→120min へ

#### [E] notebooklm-requirements-to-issues.yml — timeout 180 分 (毎日)
- `timeout-minutes: 180` で daily 実行
- 通常は playwright auth 失敗で早期終了するが、成功時は長時間化
- 推定削減: timeout を 60 分に絞るか、成功時以外は 5 分以内で終了する fast-fail を強化
- **対応 (Issue提案のみ)**: timeout を `60` に短縮 / auth失敗時の早期 exit 強化

#### [E] horse-racing-update.yml — timeout 45 分、12 runs/日
- avg 4 分で成功しているが timeout は 45 分設定
- timeout 短縮で billable 上限を下げられる (失敗時の無駄コスト削減)
- **対応 (Issue提案のみ)**: `timeout-minutes: 15` に短縮

### 🟢 LOW

- ✅ 対応完了 (前回バッチで修正)
