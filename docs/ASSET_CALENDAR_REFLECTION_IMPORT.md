# カレンダーの振り返りデータ

このデータは出来事の記録です。残高や支出明細は作成しません。金額が既存の支出に対応する場合は、その所有者の `linked_flow_id` を指定すると参考金額の集計で重複を避けられます。日記とレシートが同じ出来事なら同じ `source_key` を使用してください。同じキーの再取り込みは既存データを変更しません。

実際に読んだ日を `reading` として指定してください。購入日や蔵書リストの登録日は読書の証拠としません。外食で飲酒した場合は `dining` と `drinkingOut` を両方指定し、持ち帰りのお酒の購入は `alcoholPurchase` として区別します。日付を推測せず、原記録から確定できたものだけを取り込んでください。

## 形式

```json
[
  {
    "source_key": "sample:diary:2026-01-02:one",
    "occurred_on": "2026-01-02",
    "kinds": ["reading"],
    "title": "サンプルの本",
    "source_label": "日記 1月2日",
    "memo": "確認済みの読書メモ",
    "verified_amount": null,
    "alcohol_amount": null,
    "pages": null,
    "minutes": null,
    "linked_flow_id": null
  }
]
```

金額、ページ数、読書時間が不明な場合は `null` または項目を省略します。0 を不明の代わりに入力しないでください。酒代は合計の内訳であり別の支出として足しません。読書のタイトルとメモは `title` と `memo` に記載します。ローカルのファイルパス、口座番号、個人名、原画像など、不要な個人情報は含めないでください。

カレンダーの「日記・読書データを取り込む」で JSON を貼り付け、「内容を確認」で日付・種類・タイトル・出典を見てから保存します。1回200件までです。表示期間の件数は記録日数であり、記録がない日を未実施日とは扱いません。表示期間はカレンダーの給料日サイクルであり、暦月の回数とは異なります。

## リリース順序

1. マイグレーションと RLS の人によるレビュー。
2. 一時 Postgres の所有者・重複・会計不変テストと Flutter CI。
3. 承認された環境へのマイグレーション、本体のリリース。
4. 所有者別取得・取込プレビュー・選択日・再読込のブラウザ確認。

マイグレーションを適用していない環境では取得エラーが表示されます。日記を自動検索したり、私的な記録を公開リポジトリへ送る機能は含みません。
