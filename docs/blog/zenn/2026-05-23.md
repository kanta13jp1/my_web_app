インディー開発者にとって「競合調査」は永遠の課題だ。毎日チェックしていると時間が溶けるし、サボると見落としが出る。そこで私は「自分株式会社」の開発リポジトリに、Claude Code + GitHub Actions + Supabaseを使った**競合自動監視システム**を組み込んだ。

今週、監視対象がついに21社に達した。最新の追加はBolt.new。これでCursor / Replit / Lovable / Bolt.newという**vibe coding 4強**が全て揃った。

## 競合監視パイプラインの仕組み

毎日1回、GitHub Actionsが競合21社の最新シグナルを収集し、`docs/competitor-reports/` に日次レポートを自動生成する。

```
GHA cron → Claude Opus 4.7 (1M context)
         → docs/competitor-reports/YYYY-MM-DD.md
         → docs/competitor-reports/_competitors.json (21社マスター)
         → git commit & push
```

レポートには以下が含まれる：
- 各社の直近シグナル (リリース / 戦略変更 / 価格改定)
- 自社への影響度評価 (🔴🟡🟢)
- 戦略レビュー候補議題

## Karpathy 4サイクルによる知識管理

Andrej Karpathyが提唱する「第二の脳」の4サイクル (Ingest → Compile → Query → Lint) を、自社開発フローに完全統合している。

```
Ingest:  scripts/memory_ingest.py → raw/ → memory/vault/
Compile: scripts/wiki_compile.py  → docs/concepts/ + docs/INDEX.md
Query:   notebooklm CLI           → ゼロトークンリサーチ
Lint:    scripts/knowledge_vault_lint.py → Health Score
```

毎週1回のwiki compileと毎日のlintが自動実行され、「過去の判断に一貫性があるか」を常時チェックできる。

## Flutter Web + Supabase スタック

- フロントエンド: **Flutter Web**
- バックエンド: **Supabase** (PostgreSQL + Edge Functions / Deno)
- ホスティング: **Firebase Hosting**
- CI/CD: **GitHub Actions**

Supabase Edge FunctionsでClaude APIを呼び出し、競合分析やコンテンツ生成を実装している。

// Edge Function例

## 詰まったポイント

### GHA quota管理

Claude APIのquotaをGHAのcronで消費しすぎる問題。対策：

1. **quota fallback**: Claude超過時 → Gemini 1.5 Flash / Codex CLIへ自動切替
2. **Claude非依存cron**: ヘルスチェック系はClaude APIを使わない設計
3. **Prompt Caching**: Opus 4.7 + Prompt Cachingで約88%コスト削減

### 競合「発見」の自動化

新しい競合の自動発見は難しい。現在のアプローチ：
- Webリサーチで関連カテゴリを定期スキャン
- 競合採択基準の明文化
- **7サイクル連続でPlan A第1候補 → 採択** (Bolt.newはこのパターン)
