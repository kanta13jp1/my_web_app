## はじめに

X（旧Twitter）に動画を投稿したことがある方なら、あの「自動ミュート再生」の壁を知っているはずだ。タイムラインに流れてくる動画は無音でスタートする。ユーザーが自分でミュートを解除しない限り、声は届かない。

自分株式会社では、Flutter Web + Supabase を使って「自社プロダクトのアップデートを動画で自動投稿するシステム」を運用しているが、この1週間でその動画投稿パイプラインを大きく強化した。

具体的には次の3点だ：

- **Cloud Run 上にキャプション焼き込みマイクロサービスを構築**（#3813）
- **動画の最初3秒をフックで始まるよう生成プロンプトを改善**（#3819）
- **Growth Hub に投稿パフォーマンスデータをLLMへ渡す仕組みを追加**（#3821）

## キャプション焼き込み Cloud Run サービス (#3813)

Deno の Edge Function ではffmpegをin-processで実行できない。そこで、**超軽量なNode.jsマイクロサービスをCloud Runにデプロイ**した。

```
POST /burn
{
  "videoUrl": "...",
  "srt": "1\n00:00:00,000 --> 00:00:02,500\n自分株式会社のアップデート",
  "forceStyle": "FontSize=24,PrimaryColour=&H00FFFFFF",
  "resolution": "1080x1920",
  "style": "subtitle"
}
→ { "url": "焼き込み済みmp4のURL" }
```

ffmpegの `subtitles` + `force_style` フィルタを使ってSRTをMP4に焼き込み、Supabase Storageに再アップロードする。日本語対応のため `fonts-noto-cjk` をDockerイメージに含めた。

**重要な設計原則**: トランスコーダーがエラーを返した場合は、キャプションなしの元のmp4をそのまま投稿する。キャプションのために投稿が止まるのは本末転倒だ。

## 動画最初3秒のフック最適化 (#3819)

muted autoplayの環境では、最初の3秒でユーザーが「見続けるかどうか」を決める。

従来の「おはようございます。今日の話題は…」というジェネリックな前置きを廃止し、**トピックが存在する場合はローテーション式フックで始まる**ようにした：

```dart
// トピックフック例（ローテーション）
'<topic>、30秒で要点だけ。'
'<topic>について、今すぐ知るべきこと。'
```

## Growth Hub への LLM 文脈強化 (#3821)

`buildXPerformanceContextFromLogs` 関数を拡張し、以下の集計情報をLLMプロンプトに渡すようにした：

- バリアントランキング (上位5件、サンプルサイズ保証付き)
- メディアあり vs なし の平均スコア差
- リンク配置による平均スコア差
- 最適スレッド長バケット
- 「真似すべきフックの構造」

サンプル数が少ないバケットは出力しない (`rows >= 2` or `>= 3` のガード)。

## 詰まったポイント

**キャプションの改行問題**（#3818）: ffmpegの `wrap_unicode=1` オプションで縦型動画フレーム内に収まるよう強制した。

**ポールJSONの漏れ**（#3816）: パースロジックのフォールバックを整備してリプライへの生JSON貼り付けを修正。

**ツイートメトリクスの100ID上限**（#3822）: X APIの制約をバッチ処理で突破。
