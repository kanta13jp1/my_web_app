自社サービス「自分株式会社」のバイラル動画広告生成機能で、AI音声生成の信頼性を大幅に改善しました。

## 背景: ElevenLabs 障害時に品質が落ちる問題

Supabase Edge Function (Deno) 上で動くバイラル動画生成では、以下の流れで AI 音声を生成しています：

1. ElevenLabs API で高品質音声を生成
2. 生成した音声を Hedra に渡してプレゼンター動画を生成

問題は、ElevenLabs が失敗したときのフォールバック設計が不完全だったことです。

## 従来の問題: 条件付きフォールバック

```
ElevenLabs 失敗
  └─ requiresUploadedAudio かつ 音声系エラーの場合のみ → OpenAI TTS を試す
  └─ それ以外 → 品質の低い Hedra 内蔵 TTS へ直行
```

つまり、クォータ超過やネットワーク系のエラーではフォールバックが発動せず、動画品質が落ちていました。

## 修正: OpenAI TTS を無条件フォールバックに

修正後は、ElevenLabs が失敗した場合（理由を問わず）、OpenAI TTS を必ず試みます。

```typescript
const speechChain: string[] = [];

try {
  // ElevenLabs で音声生成
} catch (error) {
  speechChain.push(`elevenlabs=${providerErrorMessage(error)}`);
  
  // フォールバック音声 (requiresUploadedAudio の場合)
  if (params.requiresUploadedAudio && shouldRetryElevenLabsWithFallbackVoice(error)) {
    // ...
    speechChain.push(`fallback_voices=${fallbackResult.reason}`);
  }
  
  // OpenAI TTS は無条件フォールバック ← ここが今回の変更点
  if (OPENAI_API_KEY) {
    try {
      const openAiAudio = await createOpenAiSpeechAsset(params.admin, {
        text: spokenScript.slice(0, 1800),
        templateTitle: `${params.title ?? "share-update"}-openai-tts`,
        lang: params.lang,
      });
      audioProvider = "openai_tts_fallback";
      return await createHedraVideoFromUploadedAudio(params, { /* ... */ });
    } catch (openAiError) {
      speechChain.push(`openai_tts=${providerErrorMessage(openAiError)}`);
    }
  }
  
  // 最終手段: Hedra 内蔵 TTS
  console.warn(
    "Premium speech generation failed; falling back to Hedra TTS",
    speechChain.join(" | ")
  );
}
```

### フォールバック優先順位

| 順位 | プロバイダー | 条件 |
|---|---|---|
| 1 | ElevenLabs | メイン |
| 2 | ElevenLabs フォールバック音声 | `requiresUploadedAudio && 音声系エラー` |
| 3 | **OpenAI TTS** | **ElevenLabs 失敗時・無条件** |
| 4 | Hedra 内蔵 TTS | 最終手段 |

## speech_chain 診断ログ

もう一つの改善が診断性の向上です。`speechChain` 配列に各失敗を追記し、最終ログに全経緯を1行で出力します。

```
Premium speech generation failed; falling back to Hedra TTS
elevenlabs=quota_exceeded | fallback_voices=voice_not_found | openai_tts=OPENAI_API_KEY not configured
```

このログ一行で、なぜ Hedra TTS になったかの全経緯が把握できます。ダッシュボードを開かなくても、レスポンスを見るだけで診断可能です。

## 詰まったポイント

**条件分岐のネスト構造**: 元は `requiresUploadedAudio && ...` の内側に OpenAI TTS が入っていました。これを外に出す際、フォールバック音声の試行順序を崩さないよう注意が必要でした。

**Deno の async エラーハンドリング**: ネストが深い async 処理で、外側スコープの `speechChain` 配列に追記する設計にすることで、どの深さでも診断情報を蓄積できます。

## まとめ

- ElevenLabs 障害時に OpenAI TTS へ自動フォールバックし、動画品質を維持
- `speech_chain` ログで音声生成の経緯を1行で把握可能
- マルチ AI プロバイダー構成での「診断可能なフォールバック」の実装パターンとして応用できる
