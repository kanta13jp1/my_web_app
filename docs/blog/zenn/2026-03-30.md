# Supabase Edge Functions を54本まで育てた話

Flutter Web + Supabase で構築している「自分株式会社」というAI統合ライフマネジメントアプリを毎日ひとりでビルドしています。2026年3月30日に Edge Functions が**54本**に到達したので、今回追加した機能を紹介します。

## 実装した内容

- **notification-center**：アプリ内通知管理（7カテゴリ、RLS対応）
- **onboarding-flow**：6ステップの自動オンボーディング
- **ai-secretary 強化**：12部門の業務知識 + 統計ベース回答
- **agent-personality / agent-department-manager**：AIエージェント個性管理
- **バグ修正4件**

## 通知センターの実装

```typescript
// 7カテゴリ対応の汎用通知API
const VALID_CATEGORIES = ['info', 'warning', 'error', 'success', 'feature', 'system', 'reminder'];
```

DB は `app_notifications` テーブル + RLS で、各ユーザーが自分の通知のみ操作可能。

```sql
CREATE TABLE app_notifications (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES auth.users(id),
  title TEXT NOT NULL,
  body TEXT,
  category TEXT DEFAULT 'info',
  is_read BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
ALTER TABLE app_notifications ENABLE ROW LEVEL SECURITY;
```

新規ユーザー定着率を高めるため、6ステップの完了判定を DB 参照で自動化しました。

const ONBOARDING_STEPS = [

## 詰まったポイント：UPDATE + ORDER + LIMIT の罠

```typescript
// NG: PostgreSQL では ORDER + LIMIT を伴う UPDATE は非対応
await supabase.from('ai_conversations')
  .update({ reply: aiReply })
  .order('created_at', { ascending: false })
  .limit(1); // ← ランタイムエラー

// OK: INSERT で別レコード保存
await supabase.from('ai_conversations').insert({
  user_id: userId,
  message: userMessage,
  reply: aiReply,
});
```

Supabase JS クライアントの `.update()` に `.order()` と `.limit()` の組み合わせは要注意です。
