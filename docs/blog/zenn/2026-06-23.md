## 1. 収入¥0 時に手入力収入導線（CTA）を追加

### 課題

収支サマリーカードで当月収入が¥0の場合、常に赤字に見えてしまう問題がありました。④収支の記録カードには「収入」種別があるのですが、デフォルトが「支出」のため、手入力できることにユーザーが気づきにくかったのです。

### 解決策

当月サイクルの収入が¥0の場合のみ「収入を記録する」CTAを表示し、タップで④収支カードへスクロール・種別を「収入」にプリセット。

```dart
// 収入¥0のときのみCTAを表示
if (totalIncome == 0) {
  return AssetIncomeCtaWidget(
    onTap: () => _scrollToIncomeEntry(presetType: '収入'),
  );
}
```

Widgetスモークテスト2件（表示確認 / 収入有で非表示確認）も追加。

## 2. カード請求負債の確認手順をカード利用明細ベースへ変更

`includedInCard`（カード請求統合）の負債は銀行口座明細では確認できません。`buildBaseGuide` に `billingCardName` パラメータを追加し、カード明細手順へ分岐するロジックを実装しました。

```dart
String buildBaseGuide({String? billingCardName}) {
  if (billingCardName != null && billingCardName.isNotEmpty) {
    return _buildCardStatementGuide(billingCardName);
  }
  return _buildBankGuide();
}
```

## 3. アコムショッピング枠のAnthropic分を現金支出から除外

Anthropicサブスク費用¥40,000をアコムショッピング枠経由の購入として正しく分類。`includedInBillingAccount: true` に変更し、現金の二重計上と期限超過誤アラートを解消しました。

## 4. CI/CD: cancel-in-progress 最適化

```yaml
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true
```

連続プッシュ時の不要なCIランをキャンセルし、待ち時間とコストを削減。

## AI駆動開発の知見

すべての実装でClaude Opus 4.8がCo-authorとして参加。設計議論からコード生成・テスト追加まで一気通貫でAIと協働するスタイルです。

**重要な学び**: AIに実装させる際は「なぜそうなっているか」のドメインコンテキストを先に共有することが成功の鍵。コンテキストなしで依頼すると엉뚱한修正提案になることがあります。
