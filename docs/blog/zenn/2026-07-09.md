Flutter Webで作ったWebアプリ「自分株式会社」(https://my-web-app-b67f4.web.app/) が、長らくGoogleにまともにインデックスされていなかった。

SPAの宿命とも言えるSEO問題だ。Javascriptが実行されないと正確なコンテンツが取れない→Googlebotがクロールしてもblankに近いHTMLしか拾えない→インデックス品質が低い→検索流入ゼロ、という負のループ。

2026年7月の1週間で、この問題を正面突破した。

## 実装した3本柱

1. **/vs-\* 比較ページの静的HTML事前生成 (30社)**
2. **主要8公開ルートのprerender拡張**
3. **Organization/WebSite/Article JSON-LD構造化データの全ページ適用**

## /vs-\* 比較ページ — Flutter WebのSEO最重要レバー

競合他社との比較ページ (/vs-notion、/vs-slack など30社分) を、ビルド時に静的HTMLとして事前生成するスクリプトを作成した。

```python
# scripts/prerender_seo_routes.py
# comparison-routes.json に定義した30社分を静的HTML生成
for slug, meta in comparison_routes.items():
    html = build_comparison_html(slug, meta)
    Path(f"build/web/vs-{slug}.html").write_text(html)
```

**Firebase Hostingの重要な挙動**: 静的ファイルが存在する場合、`firebase.json`のrewrite設定よりも**静的ファイルが優先配信**される。つまり`/vs-notion.html`を置くだけでOK。Flutter Webのroutingには一切変更不要。

生成される静的HTMLの構成:
- `<title>` と `<meta description>` を競合名ごとに固有化
- `<link rel="canonical">` を自己参照で設定
- Article型JSON-LDを埋め込み
- クロール可能な本文を配置

**sitemapの大手術**: 実装前は1990 URLが登録されていたが、47 URLに刈り込んだ。「少ないが高品質なURL」の方がクロールバジェットを有効活用できる。

## prerender拡張 — 主要8ルート対応

```json
// web/seo/public-routes.json
{
  "/": { "title": "自分株式会社 — AI搭載の次世代ナレッジ管理", ... },
  "/features": { "title": "機能一覧 | 自分株式会社", ... },
  "/pricing": { "title": "料金プラン | 自分株式会社", ... }
  // ...8ルート
}
```

GHA deploy時に `prerender_seo_routes.py` が自動実行され、固有title/meta/JSON-LDを持つ静的HTMLを生成する。

英語H2見出しを日本語キーワードへ変換: "Features" → "自分株式会社の特徴・機能一覧"

## 詰まったポイント

### trailingSlash問題

`/vs-notion` と `/vs-notion/` が重複インデックスされる問題が発生。`trailingSlash: false` 設定と自己参照canonicalの組み合わせで解決。

### sitemap削減の判断基準

Google Search Consoleで「クロール済みだがインデックス未登録」が多数あった。動的URLによる低品質ページがクロールバジェットを消費していたため、思い切って1943 URL削除。

### canonical URL管理

Flutter WebはSPA、`index.html`が単一。prerender時に別ファイルとして生成することで、各ページに**静的canonical**を持たせるアプローチが正解。
