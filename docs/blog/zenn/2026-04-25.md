Flutter Web と Supabase を組み合わせてアプリを作っていると、ある時点で必ずぶつかる問題がある。

**「ログインしていないユーザーがページを開いたとき、コンソールに大量の 401 Unauthorized が流れる」**

これは UX 上は一見問題なく見えても、以下の悪影響がある：

- ネットワークタブが汚染され、本物のエラーが埋もれる
- Supabase のログに不要なリクエストが蓄積される
- 場合によってはレート制限に引っかかるリスク
- ローカル開発時のデバッグが著しく困難になる

「自分株式会社」（Flutter Web + Supabase で作った AI統合ライフマネジメントアプリ）では、機能追加を繰り返すうちにこの問題が 16 ページ以上に広がっていた。今回、システム的に一括修正した方法を紹介する。

## 問題の根本原因

Flutter Web の StatefulWidget では、`initState()` でデータフェッチを行うのが一般的なパターンだ：

```dart
@override
void initState() {
  super.initState();
  _loadData(); // ここで Supabase API を呼ぶ
}
```

しかし、匿名ユーザー（未ログイン状態）でこのページに訪れると、RLS（Row Level Security）がブロックするため 401 が返る。

## 解決パターン：Anonymous Auth Guard

解決策はシンプルだ。`initState()` 内でデータフェッチを呼ぶ前に、認証状態を確認する：

```dart
Future<void> _loadData() async {
  // 匿名ユーザーはスキップ
  final user = Supabase.instance.client.auth.currentUser;
  if (user == null) return;

  // 以下、認証済みユーザー向けの処理
  final response = await Supabase.instance.client
      .from('my_table')
      .select()
      .execute();
}
```

ユーザーアクション（ボタン押下）には SnackBar でフレンドリーなメッセージを表示するパターンも有効：

```dart
Future<void> _submitRequest() async {
  final user = Supabase.instance.client.auth.currentUser;
  if (user == null) {
    if (mounted) {
      ScaffoldMessenger.of(context).showSnackBar(
        const SnackBar(content: Text('この機能にはログインが必要です')),
      );
    }
    return;
  }
  // 実際の処理
}
```

## 16 ページを一括修正した手順

| ページカテゴリ | 対象ページ数 | 修正内容 |
|---|---|---|
| AI大学 | 3ページ | badges / content / streaks の `initState` にガード追加 |
| ホーム系 | 2ページ | notification / feature_request にガード追加 |
| ツール系 | 4ページ | time_tracker / reading_list / calendar_events |
| 知識管理 | 3ページ | knowledge_base / goal_tracker / habit_tracker |
| その他 | 4ページ | notifications / daily_judgment 等 |

修正方針は3パターンに統一：

1. **データフェッチのみ** → `if (user == null) return;` で即リターン
2. **ユーザーアクション** → SnackBar で「ログインが必要です」
3. **ページ全体が認証必須** → `initState` の先頭でガードし、ログイン誘導UIを表示

## 詰まったポイント

### `mounted` チェックを忘れない

非同期処理中にウィジェットが破棄されるケースがある：

```dart
if (mounted) {
  ScaffoldMessenger.of(context).showSnackBar(...);
}
```

### RLS ポリシーと整合させる

Supabase 側の RLS でも「anon ロールはアクセス不可」と設定しているはず。フロント側のガードはネットワークリクエスト削減が目的で、RLS は二重のセキュリティとして必ず維持する。

## まとめ

- `initState()` の先頭に `if (user == null) return;` を追加するだけで根本解決できる
- ユーザーアクションには SnackBar でフレンドリーなフィードバックを
- RLS は二重安全網として維持する
- 16 ページ一括修正でコンソールノイズが劇的に減少
