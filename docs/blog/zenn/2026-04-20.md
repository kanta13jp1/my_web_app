# Flutter WebでWBSガントチャートを作り直した [Zenn]

## はじめに

「この商品、もう少し安くなったら買おう」——そう思ってブラウザのブックマークに溜め込んでいる商品リストが、あなたのPCにもあるはずだ。

ところがブックマークには価格情報がない。結局「なんとなく」タイミングを見計らって購入し、翌日にセールになっていたという苦い経験を何度も繰り返してきた。

私が開発している**自分株式会社**（Flutter Web + Supabase の AI 統合ライフマネジメントアプリ）には、すでに「日用品リマインダー（shopping_items）」と「購入後ログ（purchase_sessions）」が存在していた。しかし "購入前の価格追跡" という空白地帯があった。

そこで今回、**NotebookLM の Deep Research** で調査した "Building a Zero-Cost Amazon Price Tracker" の知見を取り込み、**価格トラッカー機能**を実装した。

https://my-web-app-b67f4.web.app/

---

## どんな機能か

- 商品URLを貼るだけで wishlist に登録
- 現在価格を手動ログ（Phase 2 で自動スクレイピング予定）
- 史上最安値・最高値を自動計算（DB トリガー）
- 目標価格を設定→達成時に通知（notification-center 連携）
- 価格推移グラフ（fl_chart、Phase 2 実装予定）

## 実装方法

### DBスキーマ設計 (Supabase PostgreSQL)

2つのテーブルを新規作成した。

```sql
-- 商品 wishlist
CREATE TABLE tracked_products (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  product_url text NOT NULL,
  product_name text NOT NULL DEFAULT '',
  store_domain text NOT NULL DEFAULT '',   -- amazon.co.jp など自動抽出
  current_price int,
  target_price int,                        -- この価格以下で通知
  highest_price int,
  lowest_price int,
  notify_on_drop boolean NOT NULL DEFAULT true,
  is_active boolean NOT NULL DEFAULT true,
  is_purchased boolean NOT NULL DEFAULT false,
  UNIQUE (user_id, product_url)            -- 同一URLの重複登録防止
);

-- 価格推移ログ (時系列チャート用)
CREATE TABLE price_logs (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  product_id uuid NOT NULL REFERENCES tracked_products(id) ON DELETE CASCADE,
  price int NOT NULL,
  source text NOT NULL DEFAULT 'manual',  -- 'manual' | 'scraper' | 'api'
  logged_at timestamptz NOT NULL DEFAULT now()
);
```

**Row Level Security (RLS)** を完備し、`auth.uid() = user_id` で自分の商品だけ参照・更新できる。

### トリガーで最安値・最高値を自動更新

```sql
CREATE OR REPLACE FUNCTION update_tracked_product_prices()
RETURNS TRIGGER AS $$
BEGIN
  UPDATE tracked_products SET
    current_price = NEW.price,
    highest_price = GREATEST(COALESCE(highest_price, NEW.price), NEW.price),
    lowest_price  = LEAST(COALESCE(lowest_price, NEW.price), NEW.price),
    updated_at    = now()
  WHERE id = NEW.product_id;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER trg_price_logs_after_insert
AFTER INSERT ON price_logs
FOR EACH ROW EXECUTE FUNCTION update_tracked_product_prices();
```

`price_logs` に INSERT するだけで `tracked_products` の current/highest/lowest が自動更新される。フロント側で計算ロジックを持つ必要がなく、シンプルに保てる。

### Edge Function は増やさない — ハブパターン

このプロジェクトでは **Edge Function 50本以下** というハードキャップを設けている。今回は既存の `lifestyle-hub` に `price.*` アクションを追加する方針を採った。

```typescript
case 'price.add':
  return await handlePriceAdd(req, supabase);
case 'price.list':
  return await handlePriceList(req, supabase);
case 'price.log':
  return await handlePriceLog(req, supabase);
case 'price.update':
  return await handlePriceUpdate(req, supabase);
case 'price.delete':
  return await handlePriceDelete(req, supabase);
```

**EF 総数を増やさずに機能を拡張** できる。コールドスタートのコストも分散できる。

### Flutter の UI 実装

`PriceTrackerPage` では `_AddProductSheet`（モーダルボトムシート）で商品を追加し、カードリスト形式で一覧表示する。

```dart
Future<void> _load() async {
  final resp = await _supabase.functions.invoke(
    'lifestyle-hub',
    body: {'action': 'price.list', 'only_active': true},
  );
  final items =
      (resp.data?['products'] as List?)?.cast<Map<String, dynamic>>() ?? [];
  if (mounted) setState(() => _products = items);
}
```

## 詰まったポイント

### (1) 既存テーブルとの棲み分け

`shopping_items` と `purchase_sessions` がすでに存在しており、新テーブルとの役割が混乱しそうだった。

| テーブル | 役割 |
|---|---|
| `shopping_items` | 日用品リマインダー（価格なし） |
| `purchase_sessions` | 購入後ログ（事前wishlistなし） |
| `tracked_products` | 目標価格 + URL + 価格推移（本機能） |

コメントで三者の違いを明示することで、将来の混乱を防いだ。

### (2) EF 50本制限との戦い

新規 EF を作成したくなる誘惑があったが、`lifestyle-hub` の action 分岐で吸収した。概念的に近い機能をまとめてデプロイできる利点もある。

### (3) Philosophy Alignment チェック

プロジェクトでは実装前に「9原則チェック」を行っている。価格トラッカーは全9原則をパスした。

- **CEO感**: ユーザーが目標価格を自分で決める
- **資本=時間**: セール到来を自動検知して "価格チェック時間" を0に
- **KPI=昨日の自分**: 「史上最安値」との比較で買い時を判断
