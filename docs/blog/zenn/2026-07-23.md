## はじめに

「AIが仮説を立て、AIがコードを書き、AIが結果を測定する」——この一文が、直近1週間の自分株式会社の開発ログを一言で表しています。

Flutter Web + Supabase で構築したSaaS「自分株式会社」(https://my-web-app-b67f4.web.app/) では、ランディングページ(LP)のグロース施策をほぼ全自動化しました。Claude Code と Codex を組み合わせた AI Fleet が、毎日仮説を生成し、コードを実装し、A/Bテスト結果をレポートする——そんな開発サイクルが実際に回っています。

## 10仮説を一次指標で同時測定

LPには現在10本の仮説が同時走行しています。各仮説にはユニークなファネルIDが割り当てられ、Supabase の Edge Function がイベントを受け取るたびに該当仮説のコンバージョン率を更新します。

```dart
// LP仮説ファネルのイベント記録
await supabase.from('lp_funnel_events').insert({
  'hypothesis_id': hypothesisId,
  'event_type': 'primary_conversion',
  'user_id': userId,
  'created_at': DateTime.now().toIso8601String(),
});
```

毎日Claudeがどの仮説を続けるか・打ち切るかを自動判断します。これにより、ソロ開発者でもエンタープライズ規模のA/Bテストを回せるようになりました。

## ワンタップトライアルの実装

今週最もインパクトの大きかった変更は「ワンタップトライアル」です。初回訪問ユーザーに対して、メールアドレス入力なしでアプリを体験できるゲストトライアルフローを追加しました。

設計の3つのポイント：

1. **セッション保持**: OAuthリダイレクト後もオンボーディング状態を維持
2. **ソーシャルプルーフの先行ロード**: 分析スクリプトの遅延に関係なく信頼獲得要素を即座に表示
3. **文脈の保持**: LP→アプリ遷移時の文脈断絶を防止

## 自律オペレーションコンソール「OMOCHA WORKS」

AI Fleetの稼働状況をリアルタイムで俯瞰できるダッシュボードを追加しました。Claude Code / Codex / Geminiのどのエージェントがどのタスクを担当しているかを一画面で確認できます。

## CIの自動修復ワークフロー

AIが生成するコードには`require_trailing_commas`などのlint違反が混入することがあります。解決策として、`dart fix + dart format + deno fmt`を自動実行するGitHub Actionsワークフローを追加。AIが書いたコードの問題をAIが自動修正する仕組みを整えました。

## まとめ

今週の開発で改めて実感したのは、**AI駆動開発における「測定の自動化」の重要性**です。仮説を立てることも実装することも、今やAIが担えます。しかし「どの仮説が効いたか」を正確に測定し、次の行動につなげるループを設計するのは、まだ人間の仕事として残っています。

自分株式会社では引き続き「AI Fleet × Flutter Web × Supabase」の組み合わせで、ソロ開発者が大企業と競えるSaaS開発を追求していきます。
