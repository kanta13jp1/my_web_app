「自分株式会社」という個人開発アプリを Flutter Web + Supabase で育てています。コンセプトは「自分自身を株式会社のように経営する」——ノート・タスク・投資・家計・競馬予想まで、人生のあらゆる情報を一元管理するオールインワンツールです。

今週は**資産異常検知システム**を中心に、設計から実装・テストまで全スタックを繋ぎました。

## 全体設計

```
anomaly_detections テーブル（PostgreSQL）
  ↓
asset.anomaly.detect Edge Function（Deno）
  ↓
daily-anomaly-scan cron（GitHub Actions / 毎日 09:00 JST）
  ↓
Flutter UI（残高不足・異常の導線表示）
```

## DB テーブル — 冪等 upsert が要

```sql
CREATE TABLE anomaly_detections (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id      UUID NOT NULL REFERENCES auth.users(id),
  category     TEXT NOT NULL,
  target_month DATE NOT NULL,
  amount       NUMERIC(15,2) NOT NULL,
  avg_3month   NUMERIC(15,2) NOT NULL,
  deviation    NUMERIC(6,4) NOT NULL,
  severity     TEXT NOT NULL,  -- 'low' | 'medium' | 'high'
  ai_explanation TEXT,
  created_at   TIMESTAMPTZ DEFAULT now(),
  UNIQUE(user_id, category, target_month)
);
```

`UNIQUE(user_id, category, target_month)` の複合制約が鍵。cron の二重実行や手動再実行でも同じ月のデータは upsert で上書きされるため、重複レコードが生まれません。

## Edge Function — ±20% 閾値

```typescript
const THRESHOLD = 0.20;

const deviation = (amount - avg) / avg;
if (Math.abs(deviation) < THRESHOLD) continue;
```

`ANOMALY_AI_EXPLANATION_ENABLED=true` のときだけ Claude を呼んで自然言語説明を生成。デフォルト OFF なのでトークンコストはゼロです。

テストは Deno で13本：境界値（ちょうど±20%）・3ヶ月データなし・平均ゼロカテゴリ・upsert 冪等性など。

## 日次 cron（GitHub Actions）

```yaml
on:
  schedule:
    - cron: '0 0 * * *'  # JST 09:00
  workflow_dispatch:
    inputs:
      scan_all:
        type: boolean
        default: false
```

`scan_all: true` で全ユーザー一括スキャン。通常は直近アクティブユーザーのみ処理するためコスト最小化。

## 詰まったポイント

### 1. upsert の onConflict

Supabase JS の `.upsert()` は複合キーを **カンマ区切りの文字列** で渡す：

```typescript
.upsert(rows, { onConflict: 'user_id,category,target_month' })
```

スペースを入れるとエラーになるので注意。

### 2. migration のリプレイ安全性

時間依存の `UPDATE` は migration に書かない。将来データがある状態でリプレイすると意図しない上書きが発生するリスクがある。

### 3. GitHub Actions の UTC

JST 09:00 = UTC 00:00 → `cron: '0 0 * * *'`
