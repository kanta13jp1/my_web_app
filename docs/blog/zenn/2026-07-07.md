## 実装1: AIが読めるパブリックメモAPI

### 背景

パブリックメモはブラウザ向けのHTMLページしか提供していませんでした。AIやボットがメモの内容を取得しようとすると、HTMLをスクレイピングするしかなかった。

### 解決策

`format=json` または `format=txt` クエリパラメータを渡すことで、AI・ボット向けの構造化データを返します。

```
GET /public-memo/{id}?format=json
→ { "title": "...", "body": "...", "tags": [...], "related": [...] }

GET /public-memo/{id}?format=txt  
→ プレーンテキスト (LLMプロンプトに直接貼り付け可能)
```

`search` と `related` アクションも追加。メモ同士の関連を自動探索できるようになりました。

### Supabase Edge Function (Deno) の実装

```typescript
// core-hub/memo.public.view
const format = req.url.searchParams.get('format') ?? 'html'
const action = req.url.searchParams.get('action') ?? 'view'

if (format === 'json') {
  return new Response(JSON.stringify(payload), {
    headers: { 'Content-Type': 'application/json' }
  })
}
if (format === 'txt') {
  return new Response(toPlainText(payload), {
    headers: { 'Content-Type': 'text/plain' }
  })
}
```

HEAD リクエストと空ボディ POST にも対応しました。

## 実装2: X投稿のアンチスロップ制約

### 問題: AIが生成する文章はスロップになりやすい

「〜ですね！」「素晴らしい〜」「ぜひチェックしてみてください！」といった空虚な言葉が混入する問題。

### 対策: 制約セットを明示的に定義

- **Feature facts**: 具体的な機能名・数値を必ず含める
- **First-person**: 一人称で書く
- **Banned phrases**: 禁止フレーズリストを明示除外
- **Poll subject-lock**: Xポールの選択肢は投稿テーマと一致させる
- **Relevance gate**: スレッドの各ツイートがメイントピックと関連しているかチェック
- **Feature budget**: 1スレッドで扱うトピックを最大3つに制限

## 実装3: グロースハブの計測強化

X投稿のパフォーマンスをアプリ内で可視化するため、以下のメトリクスを追加:

- **ブックマーク数** (save-worthy コンテンツの指標)
- **プロフィールクリック数** (フォロワー転換の前段指標)
- **URL クリック数** (アプリへの流入計測)

毎朝自動でXの成長レポートをまとめる **daily X briefing cron** も追加しました。

---

## 詰まったポイント

**`&amp;` URL問題**: Edge FunctionでHTMLを組み立てる際、URLをHTMLエスケープすると `&` が `&amp;` になってしまいリダイレクト先URLが壊れていた。format別にレスポンス生成パスを分けることで解決。

**HEAD リクエスト対応**: メモページの存在確認に HEAD リクエストを使うクローラーが 405 を受け取っていた。Edge Function に明示的な HEAD ハンドラーを追加して対応。
