2026年5月25日、Anthropicが「**Dreaming**」という研究プレビューを発表した。AIエージェントの記憶をセッション間で自動整理（重複削除・古いエントリーの剪定）する機能だ。

これを見て私は思った。**「これ、6ヶ月前から自分で作って使ってる。」**

インディー開発者として「自分株式会社」（Flutter Web + Supabase + Firebase Hosting）を一人で運営しながら、私はKarpathy式「第二の脳」を自分のSaaSに完全統合してきた。その中心にあるのがmemory hygieneパイプラインだ。

## Karpathy 4サイクル — 100% dogfood達成

[Andrej Karpathy](https://karpathy.ai/) が提唱する「第二の脳」は4フェーズからなる：

```
Ingest → Compile → Query → Lint
```

私はこれを自分のリポジトリに100%実装し、2026年5月時点で「part 132」までのdogfoodを完了している。

## 核心：`[MEMORY-DECAY]` ルール

Claude Code設定（`~/.claude/hooks/inject-rules.txt`）に毎ターン注入されるルール：

```
[MEMORY-DECAY]
- 30+ day reference 0 のエントリー → consolidate対象
- 200+ entries → MEMORY_<period>.md に分割
- 月1回 consolidate-memory skill でcleanup
```

これは**Anthropic DreamingのDuplicate merge + Stale entry pruneと完全に同じ概念**だ。

## Lint自動化（`scripts/knowledge_vault_lint.py`）

毎週cronで自動実行：

- Orphan note検出
- Broken wikilink検出  
- Duplicate H1タイトル検出
- Missing index entries検出
- **Health Score算出（/100）**

今週: **Health Score 87/100**（major issues: 0）

## Compile（`scripts/wiki_compile.py`）

- `memory/vault/` の全Atomic Noteを走査
- `docs/concepts/` の概念ページを自動再生成
- `docs/INDEX.md` のマスターインデックスを自動更新

CLAUDE.mdはかつて463行あったが、**今は80行**。残りはすべて `docs/` 以下に分散。Karpathy KPI達成。

## Anthropic Dreaming との比較

| 軸 | Anthropic Dreaming | 自社実装 |
|---|---|---|
| 重複検出 | API経由（research preview） | `knowledge_vault_lint.py` + skill |
| 古いエントリー剪定 | stale entry prune | `[MEMORY-DECAY]` 30日ルール |
| 監査ログ | audit logs | git commit history |
| **実装時期** | **2026年5月 research preview** | **2025年11月〜（6ヶ月以上先行）** |
| スコープ | enterprise / API | 個人CEO + 2-instance fleet |

## 詰まったポイント

**1. memoryの「腐敗」問題**: MEMORY.mdが肥大化すると参照精度が落ちた。解決策は「本棚の定期整理」と同じ発想。

**2. Lint → Compile の順序**: 最初CompileをLintより先にやってHealth Scoreが悪化した。正しい順序は **Lint → Fix → Compile**。

**3. CLAUDE.md 463行問題**: すべての指示をCLAUDE.mdに書いていた。Karpathyが言う「必要な時に必要な情報を取り出せること」の意味を体感した。
