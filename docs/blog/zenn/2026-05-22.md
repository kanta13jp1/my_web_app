## はじめに

個人開発プロジェクト「自分株式会社」を Flutter Web + Supabase で構築しています。家計管理・資産管理・AI アシスタントを統合したパーソナル SaaS です。

今週の主な実装は **「給料サイクル別支出チャート」** (PR #1368) です。給料日を基準にした期間で支出を集計し、カテゴリ別に円グラフ表示します。

## 純粋 Dart サービス層の設計

核心は `SalarySpendingBreakdownService` という純粋 Dart クラスです。Flutter Widget にも Supabase クライアントにも依存せず、ロジックだけを持ちます。

```dart
class SalarySpendingBreakdownService {
  const SalarySpendingBreakdownService();

  static const int defaultSalaryDay = 25;

  SalarySpendingBreakdown build({
    required DateTime referenceDate,
    Iterable<SalarySpendingEntry> expenses = const [],
    Iterable<SalaryIncomeEntry> incomes = const [],
    int salaryDay = defaultSalaryDay,
  }) { ... }
}
```

`const` コンストラクターにすることで、`State` クラスの `final` フィールドに直接保持でき、副作用がないのでユニットテストも容易です。

## 給料サイクルの期間計算

給料日が25日の場合、「4/25〜5/24」が1サイクルです。月末をまたぐ処理はずれが生じやすいため、翌月の salaryDay を明示的に構築し、28日以上は丸めて2月末問題を回避しています。

## CI 自動修復

PR マージ後に `dart format` と `deno fmt` チェックが落ちましたが、`ci-auto-fix.yml` による自動修復コミットで人手なし解消。GHA 側で `dart fix --apply && dart format .` を自動コミットする仕組みは投資対効果が高いです。

## まとめ

- サービス層を `const` 純粋クラスにすると DI・モックが最小限
- 月末境界値は事前に明示的に制約する
- CI 自動修復でフォーマットエラーによるブロックがゼロに
