# Flutter × Supabase で実現する AI 資産管理アシスタント

個人開発の SaaS「自分株式会社」では、資産・負債管理機能に AI アシスタントを組み込んでいます。今週は AI へのプロンプトを大幅に強化し、「不明支出の自動トラッキング」と「AI Hub の maxTokens マルチプロバイダー対応」を実装しました。

https://my-web-app-b67f4.web.app/

## 技術スタック

- **フロントエンド**: Flutter Web
- **バックエンド**: Supabase (PostgreSQL + Edge Functions / Deno)
- **AI**: Claude API (Anthropic) + Google Gemini + OpenAI 互換プロバイダー
- **ホスティング**: Firebase Hosting + GitHub Actions

## 実装内容

### 1. 構造化された実装コンテキストをプロンプトに埋め込む

今回の最大の変更は `asset_management_insight_service.dart` への `AssetManagementImplementationContext` 追加です。

```dart
class AssetManagementImplementationContext {
  final String kind;
  final String title;
  final String path;
  final String summary;
  final String excerpt;
  final String improvementUse;

  const AssetManagementImplementationContext({
    required this.kind,
    required this.title,
    required this.path,
    required this.summary,
    required this.excerpt,
    required this.improvementUse,
  });
}
```

単なる数値データを AI に渡すだけでなく、**コードの文脈（どのファイルが何をしているか）** をプロンプトに含めることで、AI がより具体的な改善提案や GitHub Issue 作成のサジェストを生成できます。

`improvementUse` フィールドで「UI 改善案では画面上の表示粒度、Issue 本文、重複判定キー、ユーザー操作の導線まで踏み込む」という指示を与えると、AI は「残高が少ない」という一般論ではなく、「`_buildAssetManagementDeveloperRequestList` の表示項目に優先度バッジを追加すべき」といった具体的な開発タスクを提案します。

### 2. 不明支出の自動トラッキング

`salary_spending_breakdown_service.dart` に不明支出の自動検出・記録ロジックを追加しました。

給与明細から計算した「使途明確な支出」と「口座残高の実際の減少」の差分を不明支出として自動分類します。これにより月次収支の全体像を自動で把握できます。

### 3. AI Hub Edge Function の maxTokens マルチプロバイダー対応

Supabase Edge Function (Deno) として動作する `ai-hub/index.ts` に、プロバイダーごとの `maxTokens` 正規化処理を追加しました。

```typescript
function applyProviderGenerationOptions(
  providerId: string,
  requestBody: Record<string, unknown>,
  options?: ProviderCallOptions,
): Record<string, unknown> {
  const maxTokens = options?.maxTokens;
  if (!maxTokens) return requestBody;

  // Google は generationConfig.maxOutputTokens
  if (providerId === "google" || providerId === "google_flash_lite") {
    const generationConfig =
      (requestBody.generationConfig as Record<string, unknown>) ?? {};
    return {
      ...requestBody,
      generationConfig: { ...generationConfig, maxOutputTokens: maxTokens },
    };
  }

  // OpenAI 互換は max_tokens
  return { ...requestBody, max_tokens: maxTokens };
}
```

Google と OpenAI でパラメーター名が異なる差異を Edge Function 側で吸収することで、Flutter 側は統一インターフェースで複数プロバイダーを制御できます。

`finish_reason` の正規化も追加：

```typescript
function isProviderOutputLengthLimited(reason: string | null): boolean {
  const normalized = reason?.toLowerCase().replace(/[_\s-]+/g, "") ?? "";
  return normalized === "length" || normalized === "maxtokens" ||
    normalized === "maxoutputtokens";
}
```

## 詰まったポイント

**プロバイダー固有の finish_reason の扱い**

Google Gemini は `finishReason: "MAX_TOKENS"`、OpenAI は `finish_reason: "length"` と、同じ「出力長制限」を表すのにフォーマットが異なります。Edge Function 側に正規化ロジックを集約することでテストが書きやすくなりました。

**プロンプトサイズとコスト**

実装コンテキストを埋め込むことでプロンプトが長くなります。`normalizeMaxTokens` で 64〜8192 の範囲にクランプし、不必要な長文生成を防ぎながらコストを抑えています。

```typescript
function normalizeMaxTokens(value: unknown): number | undefined {
  const raw = typeof value === "number" ? value : Number(value);
  if (!Number.isFinite(raw) || raw <= 0) return undefined;
  return Math.max(64, Math.min(8192, Math.round(raw)));
}
```

## まとめ

今週の実装で AI 資産管理アシスタントが大きく改善しました：

- **プロンプトへの実装コンテキスト埋め込み**: AI が「このコードの文脈」を理解した具体的な提案を生成
- **不明支出の自動トラッキング**: 手動入力不要で月次収支の全体像を把握
- **マルチプロバイダー対応 maxTokens**: Google / OpenAI 互換プロバイダーを統一インターフェースで制御

Supabase Edge Functions (Deno) は AI プロバイダーのファサードとして機能させやすく、プロバイダー切り替えをアプリ側に影響させない設計として非常に有効なパターンです。
