## はじめに

「自分株式会社」は Notion・Evernote・Slack など 21 競合の機能を 1 つに統合したAIライフマネジメントアプリです。Flutter Web + Supabase で開発しており、今回は **友達招待システム（ReferralShareCard）** と **Edge Function UI 自動連携** という 2 つの機能を同日に実装しました。

グロース施策として「友達を招待したら特典がもらえる」仕組みは定番です。しかし Flutter Web でそれをきれいに実装しようとすると、紹介コード生成・共有 UI・Supabase との連携など意外と考えることが多い。今回の実装ログをまとめます。

---

## ReferralShareCard の設計

`ReferralShareCard` はホーム画面に配置するウィジェットで、以下の役割を持ちます:

- ログイン中ユーザーの **紹介コード** を表示（Supabase の `profiles` テーブルから取得）
- **コピーボタン** でクリップボードにコピー
- **シェアボタン** で `https://my-web-app-b67f4.web.app/?ref=<code>` の招待 URL を SNS へ共有
- 招待経由の新規登録数を表示（`referral_count` カラム）

```dart
// lib/pages/home_page.dart (抜粋)
ReferralShareCard(
  userId: currentUser.id,
  referralCode: profile.referralCode,
  referralCount: profile.referralCount,
),
```

Supabase 側では `profiles` テーブルに `referral_code text UNIQUE` と `referred_by uuid` カラムを追加し、新規サインアップ時に `?ref=` パラメータを読み取って `referred_by` をセットする Edge Function (`growth-acquisition-signal`) を用意しました。

## Edge Function UI 自動連携パターン

今回もう一つ面白かったのが、**Edge Function ごとに専用の UI ページを自動的に連携する仕組み** です。

`lib/data/home_tool_catalog.dart` にツールカタログを定義し、各エントリに `functionName`・`route`・`icon` を持たせます。新しい Edge Function を追加したら、このカタログにエントリを 1 行追加するだけで、ホーム画面のカードと `/functions/<name>` ルートが自動で生成されます。

今回追加した 3 つの Edge Function UI:

| Edge Function | ページ | 用途 |
|---|---|---|
| `memo-reactions` | `/memo-reactions` | 公開メモの絵文字リアクション一覧 |
| `note-comments` | `/note-comments` | ノートのコメント CRUD |
| `growth-acquisition-signal` | `/growth-acquisition-signal` | 招待経由の獲得シグナル |

`main.dart` にルートを追加し、`home_tool_catalog.dart` にエントリを追記するだけ。673 行追加しましたが、パターンが統一されているため迷いなく書けました。

## 詰まったポイント

### ① Flutter Web で `?ref=` パラメータを読む

Flutter Web では `Uri.base.queryParameters['ref']` で URL パラメータを取得できます。Firebase Hosting の SPA rewrite ルールを使っている場合もクエリパラメータはそのまま Flutter に渡されます。`main.dart` の初期化時に一度だけ読み取って状態管理に乗せる実装がシンプルです。

### ② UUID の型ミスマッチ

`note_comments_page.dart` でコメント削除時に `id` を `int` で扱っていましたが、Supabase の `id` は `uuid` (String) でした。

```dart
// 修正前: int として扱っていた
.eq('id', commentId.toString())

// 修正後: String(UUID) に統一
.eq('id', commentId)
```

flutter analyze で検出できなかったため、実行時エラーで気づきました。Supabase のカラム型と Dart の型を README や型定義で明示的に管理する重要性を再認識しました。

### ③ `home_tool_catalog.dart` の型安全性

カタログエントリを `Map<String, dynamic>` で管理していると IDE の補完が効かず追加時にミスが起きやすいです。`ToolCatalogEntry` クラスを定義して `const` リストにすることで、コンパイル時に型チェックが走り安全になりました。
