個人開発のライフマネジメントアプリ「自分株式会社」（Flutter Web + Supabase）を1人で作り続けている。

今週のテーマは「**Claude Code quota超過でも開発を止めない体制づくり**」。AI駆動開発を本格化させるにつれ、単一AIへの依存リスクが顕在化してきた。

## なぜMulti-AI Fallbackが必要か

Claude Codeは優秀だが、個人のMax planには月次quota上限がある。実際に今月、上限に達して数時間開発が止まった。Anthropic APIの障害統計を見ると週1回程度のインシデントが記録されており、「AIが落ちたら開発も止まる」という脆弱な体制だった。

**設計目標**:
- Claude Code token消費を月50%削減
- 他AIで代替可能なタスク率70%以上
- Anthropic API停止時も48時間以内に開発継続可能

## タスク別AI振り分けマトリクス

| タスク | Primary AI | Claude Codeの役割 |
|--------|-----------|----------------|
| 行補完 | GitHub Copilot | 不使用 |
| 500行超リファクタリング | Gemini Code Assist | 事前レビューのみ |
| SQL/アルゴリズム | OpenAI Codex | 仕様確認のみ |
| PR自動レビュー | Claude API (Gemini fallback) | 不使用 |
| アーキテクチャ判断 | **Claude Code 独占** | 主役 |

Claude Codeは「CEO/アーキテクト専任」として、判断・統合・memory管理だけを担当させる。

## Circuit Breakerパターンの実装

GHAスケジュールタスクにも同様の問題があった。Claude APIが落ちると全workflowがエラーになる。Circuit Breakerパターンで対処した。

```yaml
- name: Claude API circuit breaker check
  id: circuit_check
  run: |
    FAIL_RATE=$(python scripts/check_circuit.py --window 1h)
    if [ "$FAIL_RATE" -gt "50" ]; then
      echo "circuit_open=true" >> $GITHUB_OUTPUT
    fi

- name: Claude PR review
  if: steps.circuit_check.outputs.circuit_open != 'true'
  run: claude review $PR_NUMBER

- name: Gemini PR review (fallback)
  if: steps.circuit_check.outputs.circuit_open == 'true'
  run: gemini review $PR_NUMBER
```

Claude APIが不安定な時はGemini 1.5 Flashに自動フォールバック。

## 詰まったポイント

**環境変数名ミス**: `GOOGLE_AI_API_KEY` ではなく `GEMINI_API_KEY` が正しいキー名。GHA secretsの設定ミスにより、fallbackが発動しないことに気づくまで2時間かかった。

**Dart lint エラー**: 他AIが生成したコードに `avoid_dynamic_calls` 違反が混入。他AIのコードは必ず `flutter analyze` を通してからcommitするルールを整備した。
