## はじめに

「自分株式会社」は、個人の資産・収支・学習・健康・仕事を一元管理する Flutter Web アプリです。
バックエンドは Supabase (PostgreSQL + Edge Functions / Deno)、ホスティングは Firebase Hosting、
CI/CD は GitHub Actions で自動化しています。

今週 (2026-07-24 〜 2026-07-30) は **資産管理機能の大幅強化** と **IQ テストの仮説検証ループ** を同時並行で進めました。
AI 駆動開発 (Claude Code / Codex) を使ったスタイルで、週に 9 件の feat/fix をリリースできた実践ログを共有します。

https://my-web-app-b67f4.web.app/

## 今週の主要実装

### 1. 「今日やること」ToDoを資産管理に統合

資産管理画面に ToDoブロックを追加し、その入力欄には「細木数子 AI」キャラクターがコーチングメッセージを生成する仕組みを組み込みました。

```dart
// Edge Function 経由で細木数子スタイルのアドバイスを取得
final advice = await supabase.functions.invoke(
  'hosoki-advisor',
  body: {'context': todoText, 'date': today},
);
```

六星占術スタイルのキャラクター AI プロンプトで、運勢的な視点からその日の行動を後押しします。
Flutter の `AnimatedContainer` でメッセージが滑らかにフェードインする UX にしました。

### 2. 返済報告カードの画像を X に添付

毎月の返済記録を可視化したカードを **Supabase 公開バケット** にアップロードし、
`mediaUrl` として X (旧 Twitter) 投稿 API に渡す機能を追加しました。

```
Supabase Storage (public bucket)
  └─ repayment-cards/2026-07-30.png
        ↓ URL 取得
X API v2 (media upload → tweet)
```

### 3. 二重計上バグの根本解消

コード内に `¥80,000` をハードコードしていた資金移動ロジックが原因で、
毎月「幻の赤字」が表示されていた問題を解消しました。

```sql
-- ユーザーが明示的に設定した値のみを信頼する設計に統一
DELETE FROM scheduled_transfers WHERE type = 'hardcoded_80k';
```

### 4. セクション検索/ジャンプ機能

資産管理画面が縦に長くなってきたため、アプリバーに検索アイコンを追加し、
Flutter の `ScrollController` + `GlobalKey` + `animateTo` でスムーズジャンプを実現しました。

### 5. IQ テストの仮説検証ループ

「IQ テストの正答率が低い設問」を 10 件ピックアップし、
仮説を立て → 実測 → 修正 という **仮説検証サイクル** を回しました。

| # | 仮説 | 結果 |
|---|------|------|
| 9件 | 設問・解説・選択肢に改善余地あり | 修正完了 |
| 1件 | 問題ではなく学習不足が原因 | 元を維持 (反証) |

### 6. Stripe 全額返金 → ダウンロード権失効

全額返金後もダウンロードできる脆弱性を修正。
`refund.created` Webhook を Edge Function で受信し、`download_enabled` フラグを更新します。

```typescript
if (event.type === 'refund.created' && refund.amount === charge.amount) {
  await supabase
    .from('purchases')
    .update({ download_enabled: false })
    .eq('stripe_charge_id', charge.id);
}
```

### 7. 販売ファネル計測

`view_item → add_to_cart → begin_checkout → purchase` の各ステップを GA4 カスタムイベントで計測開始。

## 詰まったポイント

**Supabase 公開バケット URL の正規化**
`getPublicUrl()` が返す URL に自動クエリパラメータが付くことがあり、X API が `400` を返す場合がありました。
`Uri.parse(url).removeFragment()` で正規化して解決。

**Stripe Webhook の署名検証 (Deno)**
`Uint8Array` のエンコーディング差異でハマりましたが、
Stripe 公式の `constructEventAsync` を使うと Deno でも問題なく動作します。
