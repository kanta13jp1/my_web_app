## 実装詳細

### 1. マルチ月キャッシュフロー予測カード

複数月にわたるキャッシュフロー残高予測を追加しました。ホライゾン（3ヶ月/6ヶ月/1年）を切り替えられる UI と、最低残高を示す「安全ライン」を fl_chart で描画しています。

```dart
enum ForecastHorizon { threeMonths, sixMonths, oneYear }

final cashflows = await supabase
  .from('monthly_cashflow')
  .select('month, amount, category')
  .gte('month', DateTime.now())
  .lte('month', horizon.endDate);
```

v2 (#3419) では安全ラインを下回ったカテゴリへジャンプするレビューリンクも追加。

### 2. カテゴリ別予算 vs 実績 (#3421)

月初に設定した予算に対する実績乖離をカテゴリ別に表示する機能です。

```sql
SELECT
  b.category,
  b.budget_amount,
  COALESCE(SUM(t.amount), 0) AS actual_amount,
  b.budget_amount - COALESCE(SUM(t.amount), 0) AS remaining
FROM budgets b
LEFT JOIN transactions t
  ON t.category = b.category
  AND DATE_TRUNC('month', t.date) = DATE_TRUNC('month', NOW())
GROUP BY b.category, b.budget_amount;
```

Flutter 側は Riverpod で状態管理し、予算超過カテゴリは赤色でハイライト。

### 3. 削除伝播 — Tombstone パターン (#3400 / #3402 / #3411)

クロスデバイス同期における「削除」の伝播は、union マージだけでは実現できません。**Tombstone パターン**を採用しました。

```sql
CREATE TABLE asset_pref_tombstones (
  user_id UUID,
  item_key TEXT,
  deleted_at TIMESTAMPTZ DEFAULT NOW(),
  PRIMARY KEY (user_id, item_key)
);
```

マージ時に `tombstones.deleted_at > items.updated_at` であれば削除として扱います。GC は削除時刻順（#3411 で修正）で行い、audit 要件を満たしています。

### 4. X シェア + AI 自動対応パイプライン (#3390)

フィードバックを受け取った後、Claude API で自動返信文を生成するパイプラインです。

フロー：
1. Flutter → X 共有 URL 生成（ハッシュタグ付き）
2. X コメント → Webhook → Supabase Edge Function
3. Edge Function → Claude API → 返信文生成
4. `feedback_queue` テーブルへ DLQ 保存

PII 保護のため送信者メールは `user_id` に置換（#3413）。

### 5. 禁酒で借金完済チャレンジ (#3388)

今週いちばんユニークな機能。飲み機会をカレンダーで記録し、節約累積額から借金完済日を逆算します。

```dart
final savedAmount = opportunities
  .where((e) => e.skipped)
  .fold(0.0, (sum, e) => sum + e.estimatedCost);

final debtFreeDate = _calcDebtFreeDate(
  currentDebt: debtBalance,
  monthlyPayment: basePayment + (savedAmount / monthsElapsed),
);
```

## 詰まったポイント

### 表示設定 restore で削除済みセクションが復活する (#3422)

`asset_pref_mirror` から復元する際、tombstone で削除済みのセクションを上書きしてしまう不具合。tombstones を参照してフィルタリングすることで修正しました。

### 多端末同期のレース条件 (#3418)

restore と pull の競合は LWW (Last-Write-Wins) タイムスタンプの再調整で解決。フロント側で `updated_at` を必ず付与し、Edge Function 側でマージ判定します。
