## はじめに

「自分を会社として経営する」というコンセプトで、Flutter Web + Supabase を使ったライフマネジメントアプリを開発しています。

Notion・Evernote・MoneyForward・Slack・X・Amazon など**21社の競合サービス**が提供する機能を1つに統合し、さらに**人間の思考・行動・意思決定を補助するAI機能**を組み込んでいます。

https://my-web-app-b67f4.web.app/

本記事では、直近1週間で実装した機能群と、**Claude Code Scheduleによる完全自動化パイプライン**の構築について紹介します。

## 実装した主な機能

### 1. 見栄ガード — かっこつけない仕組み

「なぜそれをやるのか」を5段階の問いで掘り下げ、**見栄・承認欲求が動機の場合はアラートを出す**機能。

人間は意外と「かっこよく見られたい」という動機で行動していることが多いため、これを可視化するUIを設計しました。

```dart
// Supabase: self_image_checks テーブルに記録
// 動機スコアを0-100で数値化
```

### 2. 論理的意思決定ガード

「この決断は感情的か論理的か」を判定するチェックリスト:

- 3秒以内に決めていないか?
- 他の選択肢を3つ以上検討したか?
- 最悪のシナリオを考えたか?

```sql
-- Supabase: decision_checks テーブル
CREATE TABLE decision_checks (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  question text NOT NULL,
  logic_score int,  -- 0-100
  emotion_flags jsonb,
  created_at timestamptz DEFAULT now()
);
```

### 3. MAGIシステム (NERV風3視点判断)

エヴァンゲリオンのMAGIシステムをインスパイアし、**3つの視点でAIが判断を補強**する機能。

```
CASPER  → 人間・母親視点 (感情・共感)
BALTHASAR → 科学者視点 (データ・論理)
MELCHIOR  → 哲学者視点 (長期・価値観)
```

Edge Function `daily-judgment` でClaude APIを呼び出し、3視点の判定を生成します。

### 4. 浪費トラッキング

MoneyForwardとの差別化ポイント。**「投資か浪費か」を問いかけながら記録**します。

```dart
enum SpendingType { investment, waste, necessity }

// 浪費のみを集計してグラフ表示
// 投資(資産に変わる支出)は浪費として計上しない
```

### 5. 思考キャプチャ

GTDの「収集」フェーズに特化した機能。脳内に浮かんだ思考を**0.5秒でキャプチャ**するUIを目指しました。

### 6. 人生目標管理 (4階層ドリームツリー)

```sql
-- 夢 → 大目標 → 中目標 → 小目標 の再帰構造
CREATE TABLE life_goals (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  parent_id uuid REFERENCES life_goals(id),
  level int NOT NULL, -- 1=dream, 2=big, 3=medium, 4=small

```

## Claude Code Scheduleによる完全自動化

今回の開発で最も力を入れたのが、**Claude Code Scheduleを使った完全自動化**です。

| タスク | 頻度 | 内容 |
|---|---|---|
| `cs-check` | 毎時 | サポートチケット返信・バグ自動修正 |
| `daily-report` | 毎朝9時 | メトリクス取得・X自動投稿 |
| `blog-draft` | 毎日8時 | 技術ブログ下書き自動生成 ← この記事もAIが書いています |
| `pr-auto-review` | 3時間ごと | PRのセキュリティ・品質レビュー |

**この記事自体も、Claude Code Scheduleが自動生成した下書きをベースにしています。**

## 詰まったポイント

### GitHub Actions の main ブランチ保護問題

自動化タスクから `git push origin main` を直接実行するとブランチ保護に引っかかる問題。

**解決策**: ブランチ作成 → PR作成 → 自動マージ のフローに変更。

```bash
# ブランチを作成してPR経由でマージ
BRANCH="schedule/cs-check-$(date +%Y%m%d%H%M)"
git checkout -b "$BRANCH"
git push -u origin "$BRANCH"
gh pr create --title "自動: CS チェック" --base main --fill
```

### X投稿のJSONエスケープ

シェルスクリプト内で日本語テキストをJSONに埋め込む際の特殊文字問題。

```bash
# jq で安全にJSONを生成
JSON=$(jq -n --arg text "$TEXT" '{"text": $text}')
curl -X POST "$URL" -d "$JSON"
```
