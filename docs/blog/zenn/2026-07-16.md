「自分株式会社」(https://my-web-app-b67f4.web.app/) の今週の開発ログ。本番環境でしか再現しない2つのバグを修正した。

## バグ1: PostgRESTクエリタイムアウト (PR #4058)

X投稿パフォーマンスレポートを生成する `growth-hub` Edge Function が本番で断続的にタイムアウト。

**原因**: `x_metric_snapshots` テーブルへのクエリが `batchSize=50` で走っており、1バッチで最大50,000行スキャンが発生していた。

**修正**:

```typescript
// Before
const batchSize = 50;

// After — 7日×3時間おき収集=56行/投稿、10投稿で560行 < 1,000行ページ上限
const batchSize = 10;
```

さらに週次レポート専用の `buildXGrowthDataReportContext` 関数を切り出し、不要な historical benchmark データの読み込みを排除。エラーメッセージにもバッチ番号・ページ番号を付加して本番デバッグを容易にした。

**学び**: PostgRESTの1,000行ページ上限はレスポンスの制限であってDBスキャン量は制限しない。バッチサイズ × 最悪ケース行数を常に計算しておくこと。

## バグ2: FlutterのUXデッドエンド修正 (PR #4055)

給料日未設定のユーザーが週次投稿トグルをオンにすると SnackBar で「先に給料日を保存してください」と表示されて終了。解決への導線がなかった。

**修正**: エラーで止めるのではなく、その場で設定ダイアログを開いて続行。

```dart
// Before: 行き止まり
if (!_salaryDayConfigured) {
  ScaffoldMessenger.of(context).showSnackBar(...);
  return;
}

// After: ダイアログを開いて続行
if (!_salaryDayConfigured) {
  await _showSalaryDayDialog();
  if (!mounted) return; // async後はmountedチェック必須
  if (!_salaryDayConfigured) {
    ScaffoldMessenger.of(context).showSnackBar(...);
    return;
  }
}
```

「設定が必要です」より「今すぐ設定できます」の体験の方が完結率が高い。

## まとめ

- Supabase Edge Function: batchSize 50→10、専用コンテキスト関数に分離でタイムアウト解消
- Flutter Web: UXデッドエンドをゼロ摩擦フローに変換

どちらも開発環境では問題が顕在化しないタイプ。本番データ規模でのテストと UX フロー全経路チェックの重要性を改めて実感した。
