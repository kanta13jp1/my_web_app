## はじめに

「自分株式会社」は Notion・Evernote・MoneyForward・Slack・X など21の競合SaaSを1つに統合するAIライフマネジメントアプリです。Flutter Web + Supabase Edge Function で構築し、https://my-web-app-b67f4.web.app/ で公開中です。

今回は **ギタースタジオで録音したデータを公開した瞬間にXへ自動投稿するバイラルパイプライン** を実装しました。ユーザーがコンテンツを生み出すたびに自動でSNS拡散が走る仕組みです。

## 背景と課題

`guitar-recording-studio` Edge Function（録音・公開ギャラリー）と `post-x-update` Edge Function（X自動投稿）は既に存在していましたが、「録音を公開する」行為と「Xに投稿する」行為が完全に分断されており、ユーザーが手動でX投稿ボタンを押す必要がありました。

**目標**: 録音を `is_public: true` で保存した瞬間、バックエンドが自動的にXへ投稿する。

## 設計方針: fire-and-forget

X投稿の失敗で録音保存が失敗するのは論外です。そのため `fire-and-forget` パターンを採用しました。

```typescript
async function postPublicRecordingToX(recording: GuitarRecordingRow): Promise<void> {
  if (!SERVICE_ROLE_KEY || !SUPABASE_URL) return;

  const durationStr = recording.duration_display ?? formatDuration(recording.duration_seconds);
  const preset = (recording.preset ?? "").replace(/_/g, " ");
  const shareUrl = buildShareUrl(recording.id);

  const lines = [
    `🎸 新しい録音を公開しました！`,
    `「${recording.title}」`,
    `${durationStr} / ${preset}`.trim(),
    ``,
    shareUrl,
    APP_URL,
    `#buildinpublic #FlutterWeb #guitar`,
  ];
  let text = lines.join("\n");
  if (text.length > 280) {
    const shortTitle = recording.title.length > 20
      ? recording.title.slice(0, 20) + "…"
      : recording.title;
    text = [`🎸 「${shortTitle}」を公開しました！`, shareUrl, `#buildinpublic #guitar`].join("\n");
  }

  try {
    const resp = await fetch(`${SUPABASE_URL}/functions/v1/post-x-update`, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        "Authorization": `Bearer ${SERVICE_ROLE_KEY}`,
      },
      body: JSON.stringify({ text }),
    });
    if (!resp.ok) console.warn(`[guitar-recording-studio] X post failed: ${resp.status}`);
  } catch (e) {
    console.warn(`[guitar-recording-studio] X post error: ${e}`);
  }
}
```

キーポイントは3つです:

1. **try-catch で囲む** — X投稿の失敗を握り潰す
2. **await しない** — 呼び出し側は `postPublicRecordingToX(savedRow)` と書くだけで Promise を返すが await しない
3. **280字チェック** — ツイートテキストが長い場合は自動短縮

## saveRecording への組み込み

```typescript
const savedRow = data as GuitarRecordingRow;

// 公開録音ならX自動投稿 (fire-and-forget)
if (savedRow.is_public) {
  postPublicRecordingToX(savedRow); // awaitしない
}

return {
  success: true,
  recordingId,
  publicShareUrl: savedRow.is_public ? buildShareUrl(savedRow.id) : null,
  recording: mapRecordingRow(savedRow),
  xPosted: savedRow.is_public, // フロントに通知
};
```

`xPosted: true` をレスポンスに含めることで、Flutter側でスナックバーに「Xに自動投稿しました」と表示できます。

## 詰まったポイント

**post-x-update の認証方式**: `post-x-update` は `authorizeAutomationActor` という独自ヘルパーでサービスロールキーを検証しています。最初はJWTトークンで呼ぼうとしてエラーになりました。正解は `Bearer ${SERVICE_ROLE_KEY}` で直接呼ぶことでした。

**280字制限**: URLが長いため、タイトルが長いと超える場合があります。`text.length > 280` でフォールバック文字列に切り替えるロジックを入れました。

**m4a MIMEタイプ**: Supabase Storage への m4a アップロード時は `contentType: 'audio/mp4'` を明示する必要があります（`audio/m4a` は不正）。

**PostgREST スキーマキャッシュ**: 新テーブル追加後は `NOTIFY pgrst, 'reload schema'` をマイグレーション末尾に追加するのが確実です。

## まとめ

「ユーザーがコンテンツを公開する → 自動でSNS拡散」というバイラルループは、グロースエンジンの基本です。

- **fire-and-forget** で主処理を止めない
- **Edge Function間呼び出し** は SERVICE_ROLE_KEY + Bearer認証
- **280字チェック** で自動フォールバック

この実装により、毎日の録音 → X自動投稿 → 新規ユーザー流入という循環が回り始めます。
