AI をボタンで叩く設計には 3 つの落とし穴がある。本記事では Flutter Web × Supabase の個人開発アプリで「AI 予想ボタン」を廃止し、GitHub Actions の cron バッチへ移行した事例と、その副産物として生まれた **AiQuotaGuard サーキットブレイカー**を紹介する。

## 問題: UI 起点 AI の落とし穴

### ① 待機時間の UX 問題

「AI 予想を今すぐ実行」ボタンを押してから結果が出るまで 3〜8 秒かかっていた。競馬のレース直前に連打する行動が多発し、クォータの無駄遣いが深刻化した。

### ② クォータ枯渇による連鎖クラッシュ

ピーク時に OpenAI/Anthropic/Gemini のクォータが枯渇し、429 エラーが連続発生。フォールバックがなく、画面全体がクラッシュした:

```
ai-assistant: 400 → 429 → 429 → 429 (連続エラー)
```

### ③ 空状態での離脱

画面を開いた時点で予想が未生成だと "空の画面" になり、ユーザーの約 30% がそこで離脱した。

---

## 解決策 1: cron バッチへの移行

`horse-racing-update.yml` に毎時 cron を設定:

```yaml
on:
  schedule:
    - cron: '0 * * * *'  # 毎時自動実行
```

ワークフローが `fetch_horse_racing.py` → AI 予想生成 → Supabase UPSERT を自動実行する。ユーザーが画面を開いたときには予想が**すでに生成されている**。

Flutter 側の変更:

```dart
// Before: ボタンでトリガー
ElevatedButton(
  onPressed: _runAiPredictions,  // 削除
  child: const Text('AI予想を今すぐ実行'),
),

// After: レース番号バッジを追加 (ボタン不要)
Container(
  padding: const EdgeInsets.symmetric(horizontal: 8, vertical: 2),
  decoration: BoxDecoration(
    color: AppTheme.orange,
    borderRadius: BorderRadius.circular(12),
  ),
  child: Text('${race.raceNumber}R',
      style: const TextStyle(color: Colors.white, fontSize: 11)),
),
```

空状態メッセージ:

```
Before: 「右上の脳アイコンをタップして AI 予想を生成してください」
After:  「バッチ処理 (毎時 cron) で自動生成されます」
```

## 解決策 2: AiQuotaGuard サーキットブレイカー

他の AI 機能 (`ai-assistant` など) は UI 起点のままなので、クォータ枯渇時の連鎖クラッシュを防ぐサーキットブレイカーを `lib/services/ai_service.dart` に実装した:

```dart
class AiQuotaGuard {
  static DateTime? _cooldownUntil;
  static const _cooldownDuration = Duration(seconds: 60);

  static bool get isInCooldown {
    if (_cooldownUntil == null) return false;
    return DateTime.now().isBefore(_cooldownUntil!);
  }

  static Duration get remainingCooldown {
    if (_cooldownUntil == null) return Duration.zero;
    final r = _cooldownUntil!.difference(DateTime.now());
    return r.isNegative ? Duration.zero : r;
  }

  static void triggerCooldown() =>
      _cooldownUntil = DateTime.now().add(_cooldownDuration);

  static bool isQuotaError(dynamic error) {
    final msg = error.toString().toLowerCase();
    return msg.contains('429') ||
        msg.contains('quota') ||
        msg.contains('rate limit') ||
        msg.contains('too many requests');
  }
}
```

AI 呼び出しラッパー:

```dart
Future<String> callAiAssistant(String prompt) async {
  if (AiQuotaGuard.isInCooldown) {
    final secs = AiQuotaGuard.remainingCooldown.inSeconds;
    throw AIServiceException(
      errorType: 'RATE_LIMIT',
      message: 'AI サービスは一時的に制限中です。${secs}秒後に再試行してください。',
      retryAfter: secs,
    );
  }
  try {
    return await _invokeFunction('ai-assistant', {'prompt': prompt});
  } catch (e) {
    if (AiQuotaGuard.isQuotaError(e)) {
      AiQuotaGuard.triggerCooldown();
      rethrow;
    }
    rethrow;
  }
}
```

冷却中は API を呼ばず即座に返すため、クォータの無駄遣いも防げる。

## 結果

| 指標 | 移行前 | 移行後 |
|------|--------|--------|
| 予想表示までの待機時間 | 3〜8 秒 | **0 秒** |
| 重複リクエスト数/時 | 40〜60 件 | **0 件** |
| 429 連鎖クラッシュ | 月 3〜5 回 | **0 回** |
| 空状態での離脱率 | 約 30% | **5% 以下** |

---

## まとめ

- **ユーザーを待たせる** → バッチで事前生成
- **クォータを無駄遣いする** → cron で計画的に実行
- **連鎖クラッシュ** → サーキットブレイカーで 60 秒クールダウン

「ボタンを消す」のは機能削除ではなく、**UI からバッチへの責務移行**だ。
