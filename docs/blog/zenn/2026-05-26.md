## 背景：可処分残高が「不正確」だった問題

銀行残高 ≠ 可処分残高。家賃・光熱費・ローン返済が重なると実際に使えるお金はずっと少ない。この差分を自動計算してユーザーに見せることが今回のゴールです。

## アダプター層による分類設計

キャッシュフロー行を `fixedExpense` / `repayment` / `other` に分類するアダプター層を UI から分離しました。

```dart
DisposableBucket classify(CashflowRow row) {
  if (row.category == Category.loanRepayment ||
      row.category == Category.creditCardPayment) {
    return DisposableBucket.repayment;
  }
  if (row.paymentDay != null && row.isRecurring) {
    return DisposableBucket.fixedExpense;
  }
  return DisposableBucket.other;
}
```

家賃（25 日引き落とし）のような固定費は `fixedExpense`、クレジットカード・ローン返済は `repayment` へ。UI 側は分類ロジックを持ちません。

## インライン内訳表示への方針転換

最初にツールチップ方式で実装しましたが、タッチデバイスでの操作性が悪いため**インライン展開方式**に切り替えました。

```dart
Widget _buildBreakdown(DisposableBalanceSummary summary) {
  return Column(
    children: [
      _BreakdownRow(label: '固定費', amount: summary.fixedExpenseTotal),
      _BreakdownRow(label: '返済', amount: summary.repaymentTotal),
    ],
  );
}
```

Flutter Web はデスクトップ・モバイル両対応が必要なので、ホバー依存のツールチップより常時表示のインライン方式が適切です。

## auPay カード & Acom 返済の自動追跡

Supabase Edge Function で auPay カードの月次引き落としと Anthropic Acom 返済を `cashflow_entries` テーブルへ自動 upsert するようにしました。これにより AI ツールコストも含めた全キャッシュフローを一元管理できます。

今回の実装ポイントは「**分類ロジックをアダプター層に閉じ込める**」こと。UI の変更と分類ロジックの変更が独立して行えるようになり、テストも書きやすくなりました。
