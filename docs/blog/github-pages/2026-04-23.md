個人開発のライフマネジメントアプリ「自分株式会社」（Flutter Web + Supabase）の開発記録。

今週のテーマは「Claude Code quota超過でも開発を止めない体制づくり」。AI駆動開発を本格化させるにつれ、単一AIへの依存リスクが顕在化してきた。

## なぜMulti-AI Fallbackが必要か

Claude Codeは優秀だが、個人のMax planには月次quota上限がある。実際に今月、上限に達して数時間開発が止まった。Anthropic APIの障害統計を見ると週1回程度のインシデントが記録されており、「AIが落ちたら開発も止まる」という脆弱な体制だった。

**設計目標**:
- Claude Code token消費を月50%削減
- 他AIで代替可能なタスク率70%以上
- Anthropic API停止時も48時間以内に開発継続可能

## タスク別AI振り分けマトリクス

Claude Codeは「CEO/アーキテクト専任」として、判断・統合・memory管理だけを担当。実装タスクはGitHub Copilot / Gemini Code Assist / OpenAI Codexに分散させることでquota消費を抑える。

| タスク | Primary AI |
|--------|-----------|
| 行補完 | GitHub Copilot |
| 500行超リファクタリング | Gemini Code Assist |
| SQL/アルゴリズム | OpenAI Codex |
| アーキテクチャ判断 | Claude Code |

## Circuit Breakerパターン

GHAスケジュールタスクにCircuit Breakerを実装。Claude APIが不安定な時はGemini 1.5 Flashに自動フォールバックする。PR自動レビューが24時間365日止まらない体制になった。

## 今週の成果

- AI大学が152社到達（Hume AI・Glean追加）
- 9本のデッドEdge FunctionをHubに統合
- AppLifecycleObserverでpresence heartbeat制御実装
- `docs/AI_FALLBACK_RUNBOOK.md` 整備
