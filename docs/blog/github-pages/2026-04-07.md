## 今回実装したバイラルパイプライン

ギタースタジオで録音したデータを公開した瞬間にXへ自動投稿するパイプラインを実装しました。

### fire-and-forget パターン

X投稿の失敗で録音保存が失敗しないよう、fire-and-forget を採用しています。

```typescript
// 呼び出し側 — await しない
if (savedRow.is_public) {
  postPublicRecordingToX(savedRow);
}
```

内部では try-catch で囲み、失敗をログに残すだけで上位に伝播させません。

### Edge Function 間の認証

`guitar-recording-studio` から `post-x-update` を呼ぶ際は `SERVICE_ROLE_KEY` を Bearer トークンとして渡します。

```typescript
const resp = await fetch(`${SUPABASE_URL}/functions/v1/post-x-update`, {
  method: "POST",
  headers: { "Authorization": `Bearer ${SERVICE_ROLE_KEY}` },
  body: JSON.stringify({ text }),
});
```

### m4a MIMEタイプ対応

Supabase Storage への m4a アップロード時は `contentType: 'audio/mp4'` を明示する必要があります（`audio/m4a` は不正）。

```typescript
await supabase.storage.from('guitar-recordings').upload(filePath, blob, {
  contentType: 'audio/mp4',
});
```

## まとめ

- ユーザーが録音を公開 → バックエンドが自動でX投稿 → 新規ユーザー流入
- 主処理を止めない fire-and-forget 設計
- Edge Function 間は SERVICE_ROLE_KEY で認証
