## はじめに

「自分株式会社」は Flutter Web + Supabase で構築している AI 統合ライフマネジメントアプリです。2026 年 4 月 1 日現在、Supabase Edge Function は **234 本** に達しました。

この記事では Supabase の **100 関数制限** という壁を乗り越えた CI/CD 戦略と、同時期に実装したバイラル成長パイプラインについて解説します。

## 課題

GitHub Actions で `supabase functions deploy --all` を実行すると 100 本超で **402 エラー** が発生:

```
Error: Function limit exceeded (402)
```

## 解決: Tier 分割デプロイ

deploy-prod.yml を Tier 分割:

- **Tier 1A (core)**: 主要 API 30本 — 常時デプロイ
- **Tier 1B (viral)**: バイラル系 20本 — 常時デプロイ
- **Tier 2 (extended)**: 残り 184本 — 個別デプロイ

ポイントは **Tier 2 を事前削除してから Tier 1 をデプロイ**することで、関数カウントを 100 以下に維持します。

```yaml
- name: Remove stale Tier 2 functions
  run: supabase functions delete old-unused-function || true

- name: Deploy Tier 1A
  run: |
    for fn in schedule-daily-digest get-home-dashboard ai-assistant; do
      supabase functions deploy $fn
    done
```

## バイラル成長パイプライン

5 本の Edge Function で構成:

| 関数名 | 役割 |
|---|---|
| `viral-share-engine` | バイラル係数計算 |
| `x-media-post` | X への自動投稿 |
| `growth-automation-controller` | グロース優先度スコアリング |
| `landing-ab-test` | A/B テスト管理 |
| `viral-video-ad-generator` | AI 広告スクリプト生成 |

## その他のハマりポイント

- `config.toml` の `major_version` 衝突 → `major_version = 17` に固定 + `--include-all`
- マルチインスタンスのマイグレーション番号重複 → インスタンス別番号帯ルール策定
