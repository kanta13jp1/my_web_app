Flutter Web + Supabase で個人 SaaS「自分株式会社」を開発しています。今週 (2026-07-21〜28) は3つの大型フィーチャーをリリースしました。

## 今週のリリース

- **IQ テスト機能 (5領域)** — 論理推論・数的処理・空間認識・ワーキングメモリ・言語理解を25問で測定し、学習プランを自動生成 (PR #4353)
- **HexCiv 買い切り販売** — ¥500 の単品商品を Supabase で安全に販売する基盤 (PR #4364)
- **月次借金返済報告カード** — 返済コミュニティ向けに純関数設計で正確な進捗を可視化 (PR #4373)

## IQ テスト機能

5領域 × 難易度 1〜5 で各1問、計25問を出題し、難易度重みつき正答率を偏差IQ に換算します。

**設計のこだわり:**
- 未回答 = 不正解扱い (早く諦めるほど高得点になる穴を防ぐ)
- `IqCalibration` に換算定数を集約し「標準化ではない」と明示
- 信頼区間 (±X) を表示して誇張を防ぐ
- 領域別スコア → 学習プランの週あたり練習回数を自動決定

## HexCiv 買い切り販売

有料コンテンツ配信の最大リスクは「支払わずにダウンロードできてしまう」こと。3重ガードで防ぎます。

1. **バケットを非公開に固定** (`public = false`) — URL を知っていてもアクセス不可
2. **Edge Function で購入確認後に署名 URL (60秒) を発行** — 未購入者には 403
3. **`shop_purchases` に insert ポリシーを意図的に作らない** — Stripe Webhook 経由 (service role) のみ INSERT 可

また `is_active = false` デフォルトで、ファイルと Price が揃う前に購入導線が出るトラブルを防いでいます。

## 月次返済報告カード

SNS 投稿用カード生成機能。符号規約の不整合 (負値 vs 絶対値) が原因で「返済が進んでいるのに増加」と誤表示するバグを純関数設計で解決しました。センシティブ情報はフィールドに持たせない設計です。

## まとめ

Flutter Web + Supabase の組み合わせは個人開発で本番運用できる十分な強さがありますが、RLS・バケット設定・型設計を丁寧にやらないとセキュリティホールやバグの温床になります。
