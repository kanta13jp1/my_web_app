X（旧Twitter）に動画を投稿したことがある方なら、あの「自動ミュート再生」の壁を知っているはずだ。タイムラインに流れてくる動画は無音でスタートする。ユーザーが自分でミュートを解除しない限り、声は届かない。

自分株式会社では、Flutter Web + Supabase を使って「自社プロダクトのアップデートを動画で自動投稿するシステム」を運用しているが、この1週間でその動画投稿パイプラインを大きく強化した。

## 今週の主な変更

- **Cloud Run 上にキャプション焼き込みマイクロサービスを構築**（#3813）
- **動画の最初3秒をフックで始まるよう生成プロンプトを改善**（#3819）
- **Growth Hub に投稿パフォーマンスデータをLLMへ渡す仕組みを追加**（#3821）

## キャプション焼き込みサービス

Deno の Edge Function ではffmpegをin-processで実行できないため、超軽量なNode.jsマイクロサービスをCloud Runにデプロイした。

ffmpegの `subtitles` + `force_style` フィルタを使ってSRTをMP4に焼き込み、Supabase Storageに再アップロードする。日本語キャプションのため `fonts-noto-cjk` をDockerイメージに含めた点がポイントだ。

エラー時は元のmp4をキャプションなしで投稿する安全設計を採用した。

## 動画最初3秒の最適化

muted autoplayの最初3秒でトピックフックを話すよう変更：

```
'<topic>、30秒で要点だけ。'
```

これにより、視聴者が「見続けるかどうか」を判断する最初の3秒で、コンテンツの価値を即座に示せるようになった。

## Growth Hub LLM強化

投稿パフォーマンスデータ（バリアントランキング、メディア効果、リンク配置、スレッド長）をLLMに渡すことで、AIが過去の成功パターンを学習した上で次の投稿を生成するグロースループが完成しつつある。
