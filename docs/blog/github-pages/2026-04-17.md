AI をボタンで叩く設計には落とし穴がある。本記事では Flutter Web × Supabase の個人開発アプリで「AI 予想ボタン」を廃止し、GitHub Actions の cron バッチへ移行した事例と、副産物として生まれた **AiQuotaGuard サーキットブレイカー**を紹介する。

## 問題: UI 起点 AI の 3 つの落とし穴

- **① 待機時間**: AI 予想に 3〜8 秒。連打で重複リクエストが頻発
- **② 連鎖クラッシュ**: クォータ枯渇 → 429 → 画面全体がクラッシュ
- **③ 空状態での離脱**: 予想未生成画面で約 30% のユーザーが離脱

## 解決策

### cron バッチへの移行

```yaml
on:
  schedule:
    - cron: '0 * * * *'  # 毎時自動実行
```

ワークフローが AI 予想を事前生成 → Supabase UPSERT。画面を開いたときには予想が用意されている。**待機時間ゼロ**。ボタンも削除。

### AiQuotaGuard サーキットブレイカー

```dart
class AiQuotaGuard {
  static DateTime? _cooldownUntil;
  static const _cooldownDuration = Duration(seconds: 60);

  static bool get isInCooldown => _cooldownUntil != null &&
      DateTime.now().isBefore(_cooldownUntil!);

  static void triggerCooldown() =>
      _cooldownUntil = DateTime.now().add(_cooldownDuration);

  static bool isQuotaError(dynamic e) =>
      e.toString().toLowerCase().contains('429') ||
      e.toString().toLowerCase().contains('quota');
}
```

429 検知 → 60 秒クールダウン → その間の呼び出しは即座にエラー返却（API を叩かない）。

## 結果

| 指標 | 移行前 | 移行後 |
|------|--------|--------|
| 表示待機時間 | 3〜8 秒 | **0 秒** |
| 429 連鎖クラッシュ | 月 3〜5 回 | **0 回** |

「ボタンを消す」のは UI からバッチへの責務移行。Flutter × Supabase AI アプリの参考になれば幸いです。
