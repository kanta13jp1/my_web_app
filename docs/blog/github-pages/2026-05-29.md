個人開発で最も時間を奪われるのは「CI が詰まって PR がマージできない」状況です。

Flutter Web + Supabase + GitHub Actions で構成された「自分株式会社」では、ユーザー数 37 名・機能リクエスト 53 件を抱えながら日々開発を続けています。AI エージェント（Claude Code + Codex CLI）を使って開発速度を上げているぶん、CI ゲートの詰まりが発生すると一気に手が止まります。

今週（2026-05-29 週）は **v21 5層構造防止仕様 (Z-DD)** を策定し、**同日中の自然回復** を初めて実証しました。

## PR Gate 詰まりのパターン分類

GitHub Actions の PR Gate が詰まる原因は大きく3種類です。

| パターン | 原因 | 頻度 |
|----------|------|------|
| Body Patch 漏れ | PR 作成時に Declaration Body が空になる | 高 |
| Close/Reopen ループ | ゲート判定キャッシュが古い状態で固着 | 中 |
| Concurrency race | 複数の bot が同一 PR を同時操作 | 低 |

## Z-DD: 5層構造防止仕様

v21 で導入した Z-DD (Zero-Drift Declaration) は以下の5層で構成します。

```
Layer 1: PR テンプレート強制 (.github/pull_request_template.md)
Layer 2: bot 作成 PR への Body Patch workflow
Layer 3: ゲートチェック前の Declaration 存在確認
Layer 4: Close/Reopen による強制リフレッシュ
Layer 5: 失敗後 72h 以内の自動リトライ (指数バックオフ)
```

**Layer 4 の Close/Reopen パターン**が今回の核心です。

```yaml
- name: Close and reopen PR to refresh gate
  env:
    GH_TOKEN: {% raw %}${{ secrets.GITHUB_TOKEN }}{% endraw %}
  run: |
    gh pr close $PR_NUMBER
    sleep 3
    gh pr reopen $PR_NUMBER
```

## WBS 自動リバランス

Codex CLI が asset-management ロードマップの WBS を自動リバランスしました。Claude Code との役割分担（Codex=非同期実装、Claude Code=設計判断）で人間 1 人が複数人分の速度を維持しています。

## まとめ

今週の教訓：**CI ゲートの堅牢化は AI 導入と同時に行うべき**。
