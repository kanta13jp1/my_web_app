## はじめに

個人開発の SaaS「自分株式会社」([https://my-web-app-b67f4.web.app/](https://my-web-app-b67f4.web.app/)) を Flutter Web + Supabase で運営しています。
Notion・Evernote・MoneyForward・Slack・X・Amazon など **21 競合の機能を 1 つに統合**するというコンセプトです。

ところが、開発を続けるうちに **Edge Function が 94 本**になってしまい、デプロイに 30 分以上かかる問題が発生しました。

## 解決策: Hub + Action 分岐パターン

核心は「1つの EF が `action` パラメータで複数の処理を担う」Hub パターンです。

```typescript
// supabase/functions/ai-hub/index.ts
serve(async (req) => {
  const { action, ...params } = await req.json();
  switch (action) {
    case "university_streaks_get":    return handleStreaksGet(supabase, params);
    case "university_streaks_update": return handleStreaksUpdate(supabase, params);
    case "university_badges_issue":   return handleBadgesIssue(supabase, params);
    // 30+ actions
  }
});
```

## 結果

| 指標 | Before | After | 改善率 |
|------|--------|-------|--------|
| EF 本数 | 94本 | 15本 | -84% |
| デプロイ時間 | ~30分 | ~8分 | -75% |
| テスト本数 | 33本 | 74本 | +124% |

## AI 大学: 18 社体制

同時並行で AI 大学のプロバイダーも 9社 → 18社に拡張。
Hugging Face・Nvidia NIM・IBM watsonx・Sakana AI・Baidu ERNIE を追加しました。

各プロバイダーのコンテンツは GitHub Actions が 2 時間毎に RSS で自動更新します。

## まとめ

「制約がアーキテクチャを整理する」を実感した週でした。
EF ハードキャップ（50本以下）を設けたことで、むしろコードベースが健全になりました。
