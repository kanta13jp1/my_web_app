ここ1週間、「自分株式会社」こと個人プロジェクト [my-web-app](https://my-web-app-b67f4.web.app/) で個人資産管理モジュールの開発を集中的に進めた。

## 今週実装した機能

| 機能 | 概要 |
|------|------|
| 純資産パネル | 前月比±¥/±% + 直近6ヶ月スパークライン |
| 月次キャッシュフローパネル | 月収・月支出・累積キャッシュフロー |
| 統合アラートパネル | 異常検知 + リマインダー統合 |
| 負債マスタ ドル建て入力 | 為替自動換算（JPY/USD） |
| 資金繰り盲点修正 | 引落元種別フィルタ欠落バグ修正 |
| Google Fonts廃止 | LCP改善（ランタイム読み込み排除） |

## 実装のポイント

### 純資産パネル

集計ロジックをSupabase側のPostgreSQL Viewに寄せ、FlutterはシンプルにViewを参照するだけにした。この設計により、将来のモバイルアプリ展開でも同じロジックが使える。

### 資金繰りの盲点修正

引落元がクレジットカード等の場合に資金繰り計算から支払いが除外されていたバグ。`source_account_type`フィルタを追加して修正した。財務数字の正確性はアプリへの信頼に直結するため、優先度高で対応した。

### Google Fonts廃止によるLCP改善

`index.html`のランタイムフォント読み込みを廃止し、フォントをビルド成果物に含める形に変更。モバイル回線でのファーストビュー表示が体感できるレベルで改善した。

## 詰まったポイント

**PostgREST 1000行上限**: デフォルト上限でWBSタスクの全件集計が破綻。Supabase側aggregate Viewで対応。

**Statement Timeout**: `agent_memories`クエリが本番で500msタイムアウト。インデックスを活用するようクエリを書き直して解消。

## まとめ

Flutter + Supabase + Claude Code（AI駆動開発）の組み合わせで、一週間に6機能を実装できた。

今週の共通テーマは「数字の正直さ」。財務ダッシュボードでは、不正確な数字を正しそうに見せることが最大のリスク。警告表示・バグ修正・正確なフィルタリングを優先した。
