This week I shipped several features to improve disposable balance accuracy in my personal finance app [自分株式会社](https://my-web-app-b67f4.web.app/).

## What I Built

**feat: show disposable balance breakdown inline**
Added inline fixed-expense and repayment breakdowns for the disposable balance card. Validated locally with Flutter 3.38.10 analyze/test/build.

**feat: add auPay card funding transfer (#3028)**
Auto-tracks auPay card monthly settlement as a cashflow entry in Supabase.

**feat: add Anthropic Acom repayment cashflow (#3027)**
Logs Anthropic Acom (deferred payment) repayments as recurring cashflow rows, enabling AI tool cost tracking alongside other fixed expenses.

**fix: map cashflow fixed payments to disposable balance**
Routes fixed payment-day rows (rent, utilities) into `fixedExpense` bucket and card/loan payments into `repayment` bucket. Adds deterministic test coverage for the 25th-of-month rent case.

## Key Design Decision: Adapter Layer

The core pattern here is separating classification logic from UI:

```dart
DisposableBucket classify(CashflowRow row) {
  if (row.category == Category.loanRepayment ||
      row.category == Category.creditCardPayment) {
    return DisposableBucket.repayment;
  }
  if (row.paymentDay != null && row.isRecurring) {
    return DisposableBucket.fixedExpense;
  }
  return DisposableBucket.other;
}
```

The UI widget receives pre-classified data — no classification logic leaks into the widget tree.

## Lesson Learned: Tooltip → Inline

I initially shipped tooltips for the breakdown, then reverted and switched to inline display. Tooltips work on desktop (hover) but require long-press on touch devices, which degrades mobile UX. For a Flutter Web app targeting both desktop and mobile, always-visible inline display wins.
