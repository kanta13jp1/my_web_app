On May 25, 2026, Anthropic announced **"Dreaming"** — a research preview for automatically consolidating AI agent memories across sessions (duplicate merge + stale entry pruning).

My reaction: **"I've been running this for 6 months."**

As the sole developer of [自分株式会社 / Jibun Inc.](https://my-web-app-b67f4.web.app/) (Flutter Web + Supabase + Firebase Hosting), I fully integrated Andrej Karpathy's "Second Brain" methodology into my SaaS development workflow. The centerpiece: a memory hygiene pipeline that does exactly what Anthropic just announced.

## Karpathy's 4-Cycle System — 100% Dogfooded

Karpathy's Second Brain runs on four phases:

```
Ingest → Compile → Query → Lint
```

I've implemented all four in my repository. As of May 2026, I'm at "part 132" of continuous dogfood usage.

## The `[MEMORY-DECAY]` Rule

Injected into every Claude Code turn via `~/.claude/hooks/inject-rules.txt`:

```
[MEMORY-DECAY]
- entries with 0 references for 30+ days → consolidate candidate
- 200+ entries → split into MEMORY_<period>.md
- monthly cleanup via consolidate-memory skill
```

This is **functionally identical** to Anthropic Dreaming's "duplicate merge + stale entry prune."

## Automated Lint (`scripts/knowledge_vault_lint.py`)

Weekly cron runs detect:
- Orphan notes (unreferenced files)
- Broken wikilinks
- Duplicate H1 titles
- Missing index entries
- **Health Score out of 100**

This week: **87/100** (0 major issues)

## Automated Compile (`scripts/wiki_compile.py`)

- Scans all Atomic Notes in `memory/vault/`
- Auto-regenerates `docs/concepts/` concept pages
- Auto-updates `docs/INDEX.md` master index

CLAUDE.md was once 463 lines. Now it's **80 lines** — a pointer hub. Everything else is in `docs/`. Karpathy KPI achieved.

## Head-to-Head: Dreaming vs DIY

| Dimension | Anthropic Dreaming | My Implementation |
|---|---|---|
| Duplicate detection | API-based (research preview) | `knowledge_vault_lint.py` + skill |
| Stale entry pruning | Built-in | `[MEMORY-DECAY]` 30-day rule |
| Audit trail | Audit logs API | Git commit history |
| **Availability** | **May 2026 research preview** | **Nov 2025+ (6 months ahead)** |
| Target user | Enterprise teams via API | Solo CEO, 2-instance fleet |

The key difference is **scope**. Anthropic builds for enterprise teams via API. My implementation is **offline-first, filesystem-based, auditable via git**, designed for a single person running a full company.

## Lessons Learned

**1. Memory rot is real.** MEMORY.md grew past 200 entries and reference quality dropped. The fix: treat it like a bookshelf — archive what you haven't touched in 30 days.

**2. Order matters: Lint before Compile.** Running Compile before Lint introduced broken wikilinks into the fresh index. Correct sequence: Lint → Fix → Compile. Now enforced by GHA cron.

**3. Long system prompts are waste.** 463 lines of CLAUDE.md = wasted tokens on irrelevant context every turn. Karpathy's point: "the right information at the right time." 80-line pointer hub + on-demand docs retrieval = dramatically better.

## Conclusion

The indie dev's edge is **speed + dogfood**. Build what you need, use it yourself, stay 6 months ahead.
