## 本文（統合版・全プラットフォーム共通）

個人開発の SaaS「自分株式会社」では、資産・負債管理機能に AI アシスタントを組み込んでいます。今週は AI へのプロンプトを大幅に強化し、「不明支出の自動トラッキング」と「AI Hub の maxTokens マルチプロバイダー対応」を実装しました。

### はじめに

Flutter Web + Supabase + Claude AI という構成で個人 SaaS を開発しています。今週実装した主な機能は3つです：

1. **構造化プロンプトコンテキスト** — コードの文脈を AI に渡す仕組み
2. **不明支出の自動トラッキング** — 給与明細との差分から自動分類
3. **AI Hub maxTokens マルチプロバイダー対応** — Google/OpenAI の差異を Edge Function で吸収

### 実装方法

#### 構造化された実装コンテキストをプロンプトに埋め込む

`AssetManagementImplementationContext` クラスを新設しました。ファイルパス、コードのサマリー、AI への指示（`improvementUse`）をセットで管理し、プロンプトに埋め込みます。

```dart
class AssetManagementImplementationContext {
  final String kind;
  final String title;
  final String path;
  final String summary;
  final String excerpt;
  final String improvementUse;
}
```

これにより AI は「残高が少ない」という一般論ではなく、「`_buildAssetManagementDeveloperRequestList` の表示項目に優先度バッジを追加すべき」といった具体的な開発タスクを提案できます。

#### AI Hub Edge Function の maxTokens マルチプロバイダー対応

Supabase Edge Function (Deno) で、プロバイダーごとのパラメーター名の差異を吸収します：

```typescript
function applyProviderGenerationOptions(
  providerId: string,
  requestBody: Record<string, unknown>,
  options?: ProviderCallOptions,
): Record<string, unknown> {
  const maxTokens = options?.maxTokens;
  if (!maxTokens) return requestBody;

  if (providerId === "google" || providerId === "google_flash_lite") {
    return {
      ...requestBody,
      generationConfig: {
        ...(requestBody.generationConfig as object ?? {}),
        maxOutputTokens: maxTokens,
      },
    };
  }

  return { ...requestBody, max_tokens: maxTokens };
}
```

- Google Gemini: `generationConfig.maxOutputTokens`
- OpenAI 互換: `max_tokens`

Flutter 側は統一インターフェースで複数プロバイダーを制御できます。

#### 不明支出の自動トラッキング

`salary_spending_breakdown_service.dart` に差分計算ロジックを追加し、給与明細ベースの「使途明確支出」と「実際の残高減少」の差分を自動で不明支出として記録します。

### 詰まったポイント

**finish_reason の正規化**

Google は `finishReason: "MAX_TOKENS"`、OpenAI は `finish_reason: "length"` と、同じ意味でフォーマットが違います。Edge Function 側に正規化を集約しました：

```typescript
function isProviderOutputLengthLimited(reason: string | null): boolean {
  const normalized = reason?.toLowerCase().replace(/[_\s-]+/g, "") ?? "";
  return normalized === "length" || normalized === "maxtokens" ||
    normalized === "maxoutputtokens";
}
```

**プロンプトコストの管理**

実装コンテキストを埋め込むとトークン数が増えます。`normalizeMaxTokens` で 64〜8192 の範囲にクランプし、不必要な長文生成を防いでいます。

### まとめ

今週の実装で AI 資産管理アシスタントが大きく改善しました：

- **プロンプトへの実装コンテキスト埋め込み**: AI が「このコードの文脈」を理解した具体的な提案を生成
- **不明支出の自動トラッキング**: 手動入力不要で月次収支の全体像を把握
- **マルチプロバイダー対応 maxTokens**: Google / OpenAI 互換プロバイダーを統一インターフェースで制御

Supabase Edge Functions (Deno) は AI プロバイダーのファサードとして機能させやすく、プロバイダー切り替えをアプリ側に影響させない設計として非常に有効なパターンです。
