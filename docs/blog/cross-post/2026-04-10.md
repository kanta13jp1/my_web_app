## 本文（日本語版・共通）

「コードを書くだけで手一杯で、技術ブログを書く時間がない」

これはほぼすべての個人開発者が抱える悩みです。特に一人で21競合SaaSを超えるアプリを開発している場合、ブログどころか休む時間もありません。

私が開発している **自分株式会社**（https://my-web-app-b67f4.web.app/）は、Notion・Evernote・MoneyForward・Slack・Amazon など21競合を1つに統合する Flutter Web + Supabase のAIライフマネジメントアプリです。

今週、このアプリに「技術ブログ自動生成・自動クロスポスト」システムを実装しました。

### 全体アーキテクチャ

```
Claude Code Schedule (毎日 08:00 JST)
  ↓ git log で直近7日のコミット確認
  ↓ AI がブログ下書きを生成 → docs/blog-drafts/YYYY-MM-DD.md
  ↓ Zenn / GitHub Pages / クロスポスト版も同時生成
  ↓
Supabase REST API → blog_posts テーブルに draft 登録
  ↓
blog-auto-publisher Edge Function (Deno)
  ↓ Qiita API → 投稿
  ↓ dev.to API → 投稿
  ↓ status = "posted" に自動更新
```

### Qiita API 投稿実装

```typescript
async function publishToQiita(title, body, tags) {
  const res = await fetch("https://qiita.com/api/v2/items", {
    method: "POST",
    headers: {
      "Authorization": `Bearer ${QIITA_ACCESS_TOKEN}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      title,
      body,
      tags: tags.slice(0, 5).map(t => ({ name: t.slice(0, 20) })),
      private: false,
    }),
  });
  return { url: (await res.json()).url };
}
```

### dev.to API 投稿実装

```typescript
async function publishToDevto(title, body, tags) {
  const res = await fetch("https://dev.to/api/articles", {
    method: "POST",
    headers: { "api-key": DEVTO_API_KEY, "Content-Type": "application/json" },
    body: JSON.stringify({
      article: {
        title,
        body_markdown: body,
        tags: tags.slice(0, 4),
        published: true,
      },
    }),
  });
  return { url: (await res.json()).url };
}
```

### 詰まったポイント

- **Qiita タグ制約**: 最大5タグ・各20文字以内 → `slice()` で対応
- **スキーマ差異**: `content_preview` カラムが未作成 → マイグレーション追加
- **GITHUB_TOKEN とブランチ保護**: 直接 push は保護のないブランチのみに限定

## 英語版本文（dev.to / Medium / Hashnode / Substack 向け）

Building in public means shipping fast and writing about it. But when you're a solo developer building an app that competes with 21 SaaS products, there's no time to write blog posts manually.

So I automated it.

**Jibun Inc.** (https://my-web-app-b67f4.web.app/) is an AI-powered life management app built with Flutter Web + Supabase. This week, I implemented a fully automated blog pipeline that generates posts daily and publishes them to Qiita and dev.to.

### Architecture

```
Claude Code Schedule (daily 08:00 JST)
  → git log to find recent commits
  → AI generates blog draft
  → Saves to docs/blog-drafts/YYYY-MM-DD.md
  → Also generates Zenn / GitHub Pages / cross-post versions
  ↓
Supabase REST API → insert draft into blog_posts
  ↓
blog-auto-publisher Edge Function (Deno)
  → Publishes to Qiita API
  → Publishes to dev.to API
  → Updates blog_posts.status = "posted"
```

### Key Implementation: Qiita API

```typescript
const res = await fetch("https://qiita.com/api/v2/items", {
  method: "POST",
  headers: { "Authorization": `Bearer ${QIITA_ACCESS_TOKEN}` },
  body: JSON.stringify({
    title, body,
    tags: tags.slice(0, 5).map(t => ({ name: t.slice(0, 20) })),
    private: false,
  }),
});
```

### Key Implementation: dev.to API

```typescript
const res = await fetch("https://dev.to/api/articles", {
  method: "POST",
  headers: { "api-key": DEVTO_API_KEY },
  body: JSON.stringify({
    article: { title, body_markdown: body, tags: tags.slice(0, 4), published: true },
  }),
});
```

### Lessons Learned

1. Qiita enforces max 5 tags, 20 chars each — use `slice()`
2. Schema drift between docs and actual DB — always verify with a migration
3. GITHUB_TOKEN can't bypass branch protection — limit CI commits to unprotected branches
