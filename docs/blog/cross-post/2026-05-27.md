# Claude Code 2.1.152 × Codex CLI 0.134.0 — AI ツール更新を自動検知して開発ワークフローに即反映する仕組み

> 個人財務・生産性アプリ「自分株式会社」(https://my-web-app-b67f4.web.app/) の開発レポート。Flutter Web × Supabase で構築中。

---

## はじめに

Claude Code / Codex CLI / Cursor などのツールは週に複数回アップデートされます。これを手動で追うのをやめ、**毎日自動で公式ソースを監視する `ai-tool-watch` pipeline** を構築しました。

## ai-tool-watch の仕組み

`scripts/ai_tool_watch.py` が GitHub Actions daily cron で 8 つの公式ソースを監視。変化があれば `latest-report.md` を更新し、担当 instance へのルーティング handoff ファイルを自動生成します。

## 2026-05-27 の検知内容

| ツール | バージョン | 変更内容 |
|---|---|---|
| Claude Code | 2.1.152 | Hooks reference 更新 |
| Codex CLI | 0.134.0 pre | `--profile` フラグを CLI/TUI/sandbox で統一 |
| Cursor | 3.5 | `/loop` skill 追加 |
| Gemini Code Assist | 2.82.0 | agent mode 移行完了 |

## 2-instance fleet へのルーティング設計

```
Claude Code #1 → hooks / architecture / cross-instance 調整
Codex #1       → scoped 実装 / CI repair / Edge Functions / GHA
```

Claude Code の Hooks 更新は `hooks` グループ → Codex #1 にルーティング。スコープが明確な変更はクリーン worktree で安全に実装できます。

## Prompt Caching で 88% コスト削減

Opus 4.7 で 2 instance を回すとキャッシュなしでは月 $15,625。5 分 ephemeral キャッシュで $38/日（88% 削減）に収まっています。

```
break-even = (write_cost - read_cost) / read_cost = 11.5 hits
→ 1 セッション 50 ターンなら余裕でペイ
```
