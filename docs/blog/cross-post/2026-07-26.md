## Medium / dev.to / Hashnode 用 (英語)

**Title:** How AI Auto-Optimized My CI/CD: Saving 270 GitHub Actions Minutes/Month in a Flutter Project

**Tags:** flutter, github-actions, cicd, ai, supabase, buildinpublic

**Body:**

I'm building a personal SaaS called "Jibun K.K." (自分株式会社 - "My Own Corporation") using Flutter Web + Supabase. This week, something interesting happened: Claude Code (an AI coding assistant) automatically optimized my CI/CD pipeline without explicit instructions.

**What changed:**

1. **Flutter pub cache added to deploy workflows** — `deploy-dev.yml` and `deploy-staging.yml` were missing the pub cache that `ci.yml` already had. Claude detected this inconsistency and fixed it. Result: `flutter pub get` dropped from 30-60s to 3-5s, saving ~270 ubuntu-minutes/month.

2. **MCP Smoke test cancel handling fixed** — The stateless HTTP probe had `cancel-in-progress: false` causing unnecessary resource usage. Also, cancelled jobs were incorrectly recorded as `STATUS="critical"`, triggering false alerts. Both issues fixed.

3. **grill-me skill added** — A new Claude Code skill that interrogates your plan before implementation to surface hidden assumptions. Helps prevent "built the wrong thing" mistakes.

**Key takeaway:** AI-driven autonomous development is powerful for indie developers. The ability to spot cross-workflow inconsistencies ("ci.yml has it, deploy.yml doesn't") is something AI excels at. But human review of AI-generated changes remains essential.
