```
1/ 自分株式会社の Supabase Edge Function が 94本になってしまった話。
Action分岐パターンで 15本まで削減した実装記録🧵

#FlutterWeb #Supabase #buildinpublic

2/ 問題: 機能追加のたびに「1機能 = 1 EF」で増やした結果、
- デプロイ時間: 30分以上
- 管理コスト: 爆増
- CI/CD: 見通せない
という状況に…

3/ 解決策は「Action分岐パターン」。
1つの Hub EF が action パラメータで分岐する設計。

POST /ai-hub
{ "action": "university_streaks_update", ... }

これだけ👆

4/ Hub 構成:
- core-hub (12本分)
- ai-hub (18本分)
- growth-hub (9本分)
...合計 15本で 94本分の機能をカバー✅

5/ Flutter 側も統一:
旧: 94個の URL を個別管理
新: callHub('ai-hub', 'action名', params) で統一

可読性が劇的に改善🙌

6/ 詰まったポイント①: Deno の shared モジュール解決
→ supabase/functions/_shared/ に統一して解決

7/ 詰まったポイント②: テスト戦略
→ HTTP レイヤーは E2E に任せ pure-logic テストに集中
→ 今週 41本テスト追加で合計 74本体制へ📈

8/ 同時進行: AI大学を 9社 → 18社に拡張
- Hugging Face
- Nvidia NIM
- IBM watsonx
- Sakana AI
- Baidu ERNIE

9/ 今週の成果まとめ:
EF: 94本 → 15本 (-84%)
デプロイ: 30分 → 8分 (-75%)
テスト: 33本 → 74本 (+124%)

10/ 「制約があるからアーキテクチャが整う」

ハードキャップを設けて良かった。
サービスはこちら: https://my-web-app-b67f4.web.app/

詳細はブログで: [リンク]
#FlutterWeb #Supabase #buildinpublic
```
