### ハイライト①: クロスブラウザ マイク権限ハンドリング

Flutter Webでの最大の壁は「ブラウザごとに異なるマイク権限エラー」です。エラーを **3種類** に分類することで解決しました。

```dart
try {
  final stream = await _requestMicrophone();
} catch (e) {
  final msg = e.toString().toLowerCase();
  if (msg.contains('notallowederror') || msg.contains('permission denied')) {
    // iOS Safari / Android Chrome / デスクトップ向け許可手順を表示
    _showPermissionGuide(PermissionErrorType.notAllowed);
  } else if (msg.contains('notfounderror') || msg.contains('devicenotfound')) {
    // マイクが接続されていない / 認識されていない
    _showPermissionGuide(PermissionErrorType.notFound);
  } else if (msg.contains('notsupportederror')) {
    // HTTP接続など、安全でないコンテキスト
    _showPermissionGuide(PermissionErrorType.notSupported);
  }
}
```

これだけで「マイクが使えない」という一言エラーから、ユーザーが自己解決できるUXになりました。

### ハイライト②: Supabase guitar_recordings テーブル + RLS 2層設計

```sql
CREATE TABLE guitar_recordings (
  id        uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id   uuid REFERENCES auth.users(id) ON DELETE CASCADE NOT NULL,
  title     text NOT NULL,
  audio_url text,
  is_public boolean DEFAULT false,
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now()
);

ALTER TABLE guitar_recordings ENABLE ROW LEVEL SECURITY;

-- オーナーは全操作可能
CREATE POLICY "owner_all" ON guitar_recordings
  FOR ALL USING (auth.uid() = user_id);

-- 公開データは全ユーザー参照可
CREATE POLICY "public_select" ON guitar_recordings
  FOR SELECT USING (is_public = true);
```

この2層RLS設計はSNS系機能（公開/非公開切り替え）の王道パターンです。

### 詰まったポイント

**① MediaRecorder の Dart null safety エラー**

```
The argument type 'String?' can't be assigned to parameter type 'String'.
```

```dart
// 修正
final mimeType = _getSupportedMimeType() ?? 'audio/webm';
```

**② RLSポリシーの順序問題**

`ENABLE ROW LEVEL SECURITY` の前にポリシーを作成すると無効になるケースがある。
→ 必ず `ENABLE` → `CREATE POLICY` の順番で記述。

**③ updated_at トリガーの重複エラー**

```sql
-- 対処法
DROP TRIGGER IF EXISTS set_updated_at ON guitar_recordings;
CREATE TRIGGER set_updated_at
  BEFORE UPDATE ON guitar_recordings
  FOR EACH ROW EXECUTE FUNCTION moddatetime(updated_at);
```
