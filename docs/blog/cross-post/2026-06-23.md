## 本文（共通）

### はじめに

「自分株式会社」というコンセプトで、自分自身の収支・資産・負債をSaaSのように管理するFlutter Webアプリを個人開発しています。

- **技術スタック**: Flutter Web + Supabase (PostgreSQL + Edge Functions/Deno) + Firebase Hosting + GitHub Actions
- **プロダクト**: https://my-web-app-b67f4.web.app/
- **開発スタイル**: Claude Opus 4.8とのAI駆動開発（全PRにCo-author参加）

今週は **資産管理ページ（Asset Management）** のUX改善を中心に4件のPRをマージしました。

---

### 実装内容

#### 1. 収入¥0 時に手入力収入導線（CTA）を追加 (#3599)

**問題**: 収支サマリーカードで当月収入が¥0だと常に赤字に見えてしまう。「収入」手入力ができることに気づかないユーザーが多かった。

**解決**: 収入¥0のときだけ「収入を記録する」CTAを表示。タップで収支カードへスクロールし、種別を「収入」にプリセット。

```dart
// asset_management_page.dart
if (totalIncome == 0) {
  return AssetIncomeCtaWidget(
    onTap: () => _scrollToIncomeEntry(presetType: '収入'),
  );
}
```

Widgetスモークテスト2件追加（表示・非表示の両パターン）。

---

#### 2. カード請求負債の確認手順改善 (#3617)

`includedInCard` の負債はカード明細で確認するのが正しい。`buildBaseGuide` / `buildAiPrompt` に `billingCardName` を追加し、自動分岐。

```dart
String buildBaseGuide({String? billingCardName}) {
  if (billingCardName != null && billingCardName.isNotEmpty) {
    return _buildCardStatementGuide(billingCardName);
  }
  return _buildBankGuide(); // 直接引き落とし用（従来手順）
}
```

---

#### 3. アコムショッピング枠のAnthropic分を修正 (#3620)

Anthropicサブスク費用¥40,000をアコムショッピング枠経由として正しく分類。
- 修正前: 現金支出として二重計上 → 誤アラート
- 修正後: `includedInBillingAccount: true` でカード請求に統合

---

#### 4. CI/CD: cancel-in-progress 最適化 (#3621)

```yaml
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true
```

連続プッシュ時の古いCIランをキャンセル。CI待ち時間とコストを削減。

---

### 詰まったポイント

**Flutter Widgetテストと Key 付与**: ドロップダウンに `Key` を付与しないとテストから要素を特定できず誤マッチが起きます。Flutter Widgetテストでは `Key` を積極的に使いましょう。

**AIへのコンテキスト共有の重要性**: Claude Opus 4.8に依頼する際、ドメイン知識（アコムの仕組み、includedInBillingAccountの意味）を事前に共有しないと엉뚱な提案になることがありました。「なぜそうなっているか」のコンテキストを先に渡すことが成功の鍵です。
