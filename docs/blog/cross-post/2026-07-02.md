## 本文 (クロスポスト共通)

自社サービス「自分株式会社」のバイラル動画広告生成機能を大幅に改善しました。ElevenLabs API が不安定なとき、従来は品質の低い音声にフォールバックしていた問題を解決します。

### 問題

Supabase Edge Function (Deno) で動くバイラル動画生成では、以下の流れで処理します：

1. ElevenLabs API → 高品質 AI 音声生成
2. 生成音声 → Hedra でプレゼンター動画生成

問題は **ElevenLabs 失敗時のフォールバックが条件付き**だったことです。`requiresUploadedAudio` フラグが立っていない場合や、クォータ超過・ネットワークエラーでは、OpenAI TTS へのフォールバックが実行されず、品質の低い Hedra 内蔵 TTS に直行していました。

### 解決策: 無条件フォールバック + speech_chain

#### 1. OpenAI TTS を無条件フォールバックに昇格

```typescript
const speechChain: string[] = [];

try {
  // ElevenLabs で音声生成
} catch (error) {
  speechChain.push(`elevenlabs=${providerErrorMessage(error)}`);
  
  // OpenAI TTS: ElevenLabs 失敗時の無条件フォールバック
  if (OPENAI_API_KEY) {
    try {
      const openAiAudio = await createOpenAiSpeechAsset(/* ... */);
      return await createHedraVideoFromUploadedAudio(/* ... */);
    } catch (openAiError) {
      speechChain.push(`openai_tts=${providerErrorMessage(openAiError)}`);
    }
  }
  
  // 最終手段: Hedra 内蔵 TTS
  console.warn("Premium speech failed", speechChain.join(" | "));
}
```

フォールバック優先順位:
1. ElevenLabs（メイン）
2. ElevenLabs フォールバック音声（条件付き）
3. **OpenAI TTS（無条件フォールバック）** ← 今回の追加
4. Hedra 内蔵 TTS（最終手段）

#### 2. speech_chain 診断ログ

各プロバイダーの失敗理由を1つの配列に蓄積し、最終ログに連結して出力：

```
elevenlabs=quota_exceeded | fallback_voices=voice_not_found | openai_tts=OPENAI_API_KEY not configured
```

この1行で、なぜ Hedra TTS になったかの全経緯が把握できます。

### 成果

- **可用性向上**: ElevenLabs 障害時に自動フォールバック、高品質音声を維持
- **診断性向上**: `speech_chain` で音声切り替え経緯をログ1行で把握
- **コード明確化**: フォールバック条件のネストを整理

マルチ AI プロバイダー構成での「診断可能なフォールバック」パターンとして汎用的に応用できます。
