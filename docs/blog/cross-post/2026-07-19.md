## 本文（統合版）

### はじめに

ここ1週間、「自分株式会社」こと個人プロジェクト https://my-web-app-b67f4.web.app/ で、個人資産管理モジュールの開発を集中的に進めた。

「自分株式会社」とは、自分の人生を一つの会社として捉えるコンセプトのもと、時間・資産・タスク・目標を一元管理するFlutter Webアプリ。Supabase（PostgreSQL + Edge Functions）をバックエンドに、Firebase Hostingで配信している。

### 今週実装した機能

| 機能 | PR | 概要 |
|------|-----|------|
| 純資産パネル | #4215 | 前月比±¥/±% + 直近6ヶ月スパークライン |
| 月次キャッシュフローパネル | #4194 | 月収・月支出・累積キャッシュフロー |
| 統合アラートパネル | #4201 | 異常検知 + リマインダーを1箇所に集約 |
| 負債マスタ ドル建て入力 | #4200 | 為替自動換算（JPY/USD） |
| 資金繰り盲点修正 | #4223 | 引落元種別フィルタ欠落バグ |
| Google Fonts廃止 | #4216 | LCP改善（ランタイム読み込み排除） |

### 実装方法

#### 純資産パネル

純資産 = 総資産 − 総負債 をリアルタイムで可視化。集計ロジックはSupabase側のPostgreSQL Viewに寄せ、Flutterはシンプルに値を受け取るだけにした。前月比の計算もDB側で完結させることで、将来のモバイルアプリ展開でも同じロジックが使える。

```dart
final netWorthHistory = await supabase
  .from('monthly_net_worth_summary')
  .select('month, net_worth')
  .order('month', ascending: true)
  .limit(6);
```

スパークラインは`fl_chart`ライブラリを使用。月次データをLineChartDataにマッピングして描画した。

#### 月次キャッシュフローパネル

月収・月支出・累積キャッシュフローを1パネルで確認できるダッシュボード。収入予定が未登録の場合は過大に厳しい数字が表示されてしまう問題があったため、ユーザーへの正直な告知カードを追加した。

```dart
if (expectedIncome == null || expectedIncome == 0) {
  return CashflowWarningCard(
    message: '収入予定が未登録のため、資金繰りの数字が実態より厳しく表示されています',
  );
}
```

#### 負債マスタ ドル建て入力 + 為替自動換算

サブスクなどドル建て負債を入力する際に、現在の為替レートで自動的にJPY換算する機能。Edge Functionsで定期取得した為替レートをSupabaseにキャッシュし、クライアントはキャッシュ値を参照する設計にした。

```typescript
// Edge Function: 為替レート取得 + キャッシュ
const rate = await fetchUsdJpyRate();
await supabase.from('exchange_rate_cache').upsert({
  pair: 'USD_JPY',
  rate,
  updated_at: new Date().toISOString(),
});
```

#### 資金繰りの盲点修正

引落元がクレジットカード等（現金・預金口座以外）の場合、資金繰り計算から支払いが消えていたバグを修正。`source_account_type`によるフィルタ条件を追加した。

```sql
-- 修正後: 口座引落のみ資金繰りに反映
SELECT * FROM payments
WHERE date BETWEEN $1 AND $2
  AND source_account_type IN ('cash', 'bank_account');
```

財務数字の正確性はアプリへの信頼に直結するため、優先度高で対応した。

#### Google Fonts 廃止

`index.html`に直書きされていたGoogle Fonts `<link>`タグを削除。フォントをビルド成果物に含める形に変更した。LCP（Largest Contentful Paint）が改善し、モバイル回線でのファーストビュー表示が体感できるレベルで速くなった。

### 詰まったポイント

**1. PostgREST 1000行上限**

WBSタスクを全件取得しようとしたとき、PostgRESTのデフォルト上限1000行で集計が破綻していた（PR #4207）。Supabase側でaggregate Viewを作成して返す方式で対応した。

**2. agent_memories Statement Timeout**

`agent_memories`テーブルへのクエリが本番環境で statement timeout（500ms）に引っかかっていた（PR #4204）。既存インデックスを活用するようにクエリを書き直し、実行計画を確認してから本番適用した。

**3. AI要約の生成中表示**

AI要約のリクエスト中に空白が表示されていた問題（PR #4214）。生成中インジケーターを追加し、`maxTokens`の設定も見直してレスポンスが途中で切れないようにした。

### まとめ

一週間で6機能を実装・修正できたのは、Flutter + Supabase の組み合わせによる開発速度の高さと、Claude Codeを使ったAI駆動開発のおかげだ。

今週の共通テーマは**「数字の正直さ」**。資金繰りや純資産といった財務数字は、間違った数字を「正しそうに」見せてしまうとユーザーの判断を誤らせる。収入未登録の警告表示、資金繰り盲点の修正、正確なフィルタリング── どれも「数字の正直さ」という軸で優先した改善だ。

今後は、資産推移のAI分析（異常検知・アドバイス生成）や、複数通貨対応の強化を進めていく予定。
