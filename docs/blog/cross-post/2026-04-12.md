## はじめに

「AIで競馬予想ができたら面白い」という発想から始まったこの機能を、今週 Flutter UI まで含めた **完全自動化パイプライン** として本番リリースしました。同じ週に **AI大学のプロバイダー数が40社を突破** するというダブル達成となりました。

---

## 競馬AI予想パイプライン — 設計と実装

### アーキテクチャ

```
JRA データ → tools-hub(today) → tools-hub(predict_all) → horse_results テーブル → Flutter UI
```

バックエンドは Deno Edge Function の **tools-hub** に集約。EF 総数 50本以下のハードキャップを守るため、新機能は `action` パラメータ追加で対応しています。

### Flutter UI — 3タブ構成

- **今日のレース**: ExpansionTile でレースカード展開、グレード色バッジ（G1=赤/G2=青/G3=緑）
- **予想履歴**: 過去のAI予想一覧、日付フィルタ付き
- **的中率**: ヒット率%・総予想数・的中数・最高払戻し金額（`NumberFormat('#,###')` で3桁区切り）

### 詰まったポイント

**① GitHub Actions からの 401 エラー**

スケジューラから呼び出す action を誤って認証必須ゾーンに配置していた。`NO_AUTH_ACTIONS` リストに移動して解消。

**② horse_results クエリのタイムアウト**

全件一括 SELECT → タイムアウト。個別クエリを `Promise.all` で並行実行する方式に変更。

**③ deploy-prod SQLSTATE 42P10**

`ai_university_content` テーブルの `(provider, category)` に `UNIQUE` 制約が不足していた。マイグレーションで制約追加して解消。

## AI大学 40社体制 — DB駆動アーキテクチャ

今週追加: **Luma AI / Kling AI / Pika Labs / AssemblyAI / Twelve Labs / Cohere**（34社→40社）

`ai_university_content` テーブルから動的にタブを生成するため、**新プロバイダー追加にコード変更不要**。データを INSERT するだけでUIに反映されます。
