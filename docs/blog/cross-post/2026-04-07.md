## 本文

「自分株式会社」は Notion・Evernote・MoneyForward・Slack・X など21の競合SaaSを1つに統合するAIライフマネジメントアプリです。Flutter Web + Supabase Edge Function で構築し、https://my-web-app-b67f4.web.app/ で公開中です。

今回は **ギタースタジオで録音したデータを公開した瞬間にXへ自動投稿するバイラルパイプライン** を実装しました。

### 背景と課題

`guitar-recording-studio` Edge Function と `post-x-update` Edge Function は既に存在していましたが、2つの行為が完全に分断されており、ユーザーが手動でX投稿ボタンを押す必要がありました。

**目標**: 録音を `is_public: true` で保存した瞬間、バックエンドが自動的にXへ投稿する。

### 設計方針: fire-and-forget

```typescript
async function postPublicRecordingToX(recording: GuitarRecordingRow): Promise<void> {
  // ...ツイートテキスト生成 (≤280字)...
  try {
    const resp = await fetch(`${SUPABASE_URL}/functions/v1/post-x-update`, {
      method: "POST",
      headers: { "Authorization": `Bearer ${SERVICE_ROLE_KEY}` },
      body: JSON.stringify({ text }),
    });
    if (!resp.ok) console.warn(`X post failed: ${resp.status}`);
  } catch (e) {
    console.warn(`X post error: ${e}`);
  }
}
```

呼び出し側は `await` しないため、X投稿の成否にかかわらず録音保存レスポンスはすぐに返ります。

### saveRecording への組み込み

```typescript
if (savedRow.is_public) {
  postPublicRecordingToX(savedRow); // awaitしない = fire-and-forget
}

return {
  success: true,
  xPosted: savedRow.is_public, // フロントに通知
};
```

### 詰まったポイント

1. **post-x-update の認証**: `Bearer ${SERVICE_ROLE_KEY}` で直接呼ぶ（JWTトークン不可）
2. **280字制限**: タイトルが長い場合の自動フォールバック実装が必要
3. **m4a MIMEタイプ**: Supabase Storage は `contentType: 'audio/mp4'` を明示（`audio/m4a` は不正）
4. **PostgREST スキーマキャッシュ**: 新テーブル追加後は `NOTIFY pgrst, 'reload schema'` が必須

### まとめ

- **fire-and-forget** で主処理を止めない
- **Edge Function間呼び出し** は SERVICE_ROLE_KEY + Bearer認証
- **280字チェック** で自動フォールバック

この実装により、毎日の録音 → X自動投稿 → 新規ユーザー流入という循環が回り始めます。
