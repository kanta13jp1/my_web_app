## 本文（統合版）

### はじめに

個人開発している資産管理SaaS「自分株式会社」に、定期取引の自動検出機能を実装しました。

「毎月同じ引落しが複数口座に散らばっていて今月どれが未払いか分からない」という自分自身の課題から生まれた機能です。PR #3475（v1）→ #3478（v2a）→ #3479（v2b）と3段階で進化しました。

### 実装方法

#### v1: 基本検出 (#3475)

過去の取引履歴から「同一ラベル・同一金額が4ヶ月以上毎月出現」するパターンを純粋関数で検出。

```dart
List<RecurringTransactionSuggestion> detectRecurring(
  List<TransactionEntry> history,
  DateTime now,
) { ... }
```

#### v2a: 隔月cadence + 口座prefill (#3478)

「2ヶ月に1回」の支払いにも対応。`bimonthlyEven`（偶数月）/ `bimonthlyOdd`（奇数月）を判定。引落元口座の最頻出を登録フォームに自動入力。

#### v2b: 無視機能 + 単調増加セット (#3479)

「無視」ボタンを追加。無視セットを**単調増加セット**として設計し、マルチデバイス同期は union のみで完結（tombstone不要）。

#### マルチデバイス同期: Last-Write-Wins (#3480)

union マージではチェック解除が伝播しないバグを修正。`updatedAt` タイムスタンプで最新端末の状態を優先するLWW方式に拡張。旧データ後方互換は `updatedAt == null` 時に union フォールバック。

#### アクセシビリティ (#3482)

`RecurringFixedCostCard` に `MergeSemantics` を追加。スクリーンリーダー（NVDA/VoiceOver/TalkBack）対応を強化。

### 詰まったポイント

- **LWW vs CRDT**: チェック解除（削除操作）があると union では不十分。最後に操作した端末を正とするLWWが今回のユースケースに合致
- **無視セットの設計**: 「無視解除」は v2b で省略し単調増加に。同期ロジックが大幅に単純化
- **隔月の誤検知**: 検出窓を6ヶ月に広げ「対となる月の観測が0件」条件を追加して抑制
