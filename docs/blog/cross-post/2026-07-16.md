# Supabase Edge Functionの本番タイムアウトをバッチサイズ削減で解決 + FlutterのUXデッドエンド修正

> 自分株式会社 (Flutter Web + Supabase) 週次開発ログ 2026-07-16

---

## はじめに

Flutter Web + Supabase で作った SaaS「自分株式会社」(https://my-web-app-b67f4.web.app/) の今週の開発ログ。

本番環境でしか再現しない2件のバグを修正した。どちらも「開発環境では問題なし」なので発見が遅れたが、修正そのものはシンプルだった。

---

## バグ1: PostgREST クエリタイムアウト

**問題**: X 投稿パフォーマンスレポートを生成する Edge Function が本番で断続的にタイムアウト。

**原因**: `batchSize=50` で `x_metric_snapshots` をスキャンすると最大 50,000 行のクエリが走り、production の statement timeout を超えた。

**修正**:
- `batchSize` を 50 → 10 に削減（7日×3時間おき収集なら 10投稿×56行=560行でページ内に収まる）
- 週次レポート専用の `buildXGrowthDataReportContext` 関数を切り出し、不要な historical benchmark データの読み込みを排除
- エラーメッセージにバッチ番号・ページ番号を付加して本番ログのデバッグを容易化

```typescript
// batchSize: 50 → 10
const batchSize = 10; // 7日×3h収集 = 56行/投稿、10投稿で560行 < 1,000行ページ上限
```

## バグ2: Flutter Web UX デッドエンド

**問題**: 給料日未設定のユーザーが週次投稿トグルをオンにすると SnackBar でエラーを出して終了。次のアクションへの導線がない「行き止まり」状態。

**修正**: エラーで止めず、その場で設定ダイアログを開いて設定完了後にフローを続行。

```dart
if (!_salaryDayConfigured) {
  await _showSalaryDayDialog(); // その場で設定
  if (!mounted) return;          // async後は必須チェック
  if (!_salaryDayConfigured) {
    ScaffoldMessenger.of(context).showSnackBar(...); // それでも未設定なら中断
    return;
  }
}
// 設定済みなら続行
```

---

## まとめ

- **Supabase Edge Function**: batchSize 削減 + ユースケース専用関数で本番タイムアウト解消
- **Flutter Web**: UX デッドエンドをゼロ摩擦フローに変換

PostgREST を使う際は「最悪ケース行数 × batchSize」の計算を忘れずに。Flutter の `async/await` 前後では `mounted` チェックを省略しないこと。
