# クロスポスト用 統合版 — 2026-06-17

## 本文 (各プラットフォーム共通)

Flutter Webで作っている自分株式会社アプリ（https://my-web-app-b67f4.web.app/）の資産管理ページで、家賃/KDDI/水道/ガスの固定費が約8箇所にハードコードされていました。今週、データ駆動モデルとUIウィジェットを実装してこの問題を解決しました。

### 実装ハイライト

**1. データモデル設計 (PR #3452)**

```dart
class AssetRecurringFixedCost {
  final String id;
  final String name;       // 家賃、KDDI など
  final double amount;     // 月額
  final int transferDay;   // 振替日 (1〜28)
  final String period;     // monthly / bimonthly
  final String? sourceAccount;
}
```

**2. 端末間ミラー同期**
Supabase の `asset_pref_mirror` に全量 upsert。ローカル優先・サーバーフォールバック方式。

**3. UIウィジェット (PR #3457)**
`RecurringFixedCostCard` + `RecurringFixedCostEditorDialog` を独立ウィジェットとして切り出し、単体テスト可能に。

**4. キャッシュフロー予測 v2 (PR #3419)**
ホライゾン 3/6/12ヶ月切替 + 安全証拠金ライン + カテゴリ別予算実績比較。

### 詰まったポイント
- ミラー同期の「ローカル優先 vs サーバー優先」問題 → ローカル登録がある場合は上書きしない安全側を採用
- 寛容な `fromJson`: 空名称・金額0以下・振替日範囲外は黙って破棄
- テスト専用注入: `debugInitialRecurringFixedCosts` パラメータでWidgetTestを書きやすく

アプリ: https://my-web-app-b67f4.web.app/
