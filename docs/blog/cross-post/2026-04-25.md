## Qiita 用

**タグ**: `Flutter` `Supabase` `Dart` `Web` `認証`

Flutter Web + Supabase を組み合わせたアプリで、匿名ユーザーが `initState()` でデータフェッチを行うと Supabase RLS により 401 エラーが大量発生します。「自分株式会社」では 16 ページに渡ってこの問題を一括修正しました。

**解決パターン**:

```dart
Future<void> _loadData() async {
  final user = Supabase.instance.client.auth.currentUser;
  if (user == null) return;
  // 認証済み処理
}
```

ポイントは3つ：① `initState` 先頭でガード、② ユーザーアクションには SnackBar フィードバック、③ Supabase RLS は二重安全網として維持。

**Title**: How I Eliminated 401 Errors for Anonymous Users Across 16 Flutter Pages

When building Flutter Web apps with Supabase, anonymous users trigger unnecessary 401 errors on pages that make API calls in `initState()`. Here's the simple guard pattern that fixed 16 pages at once:

```dart
Future<void> _loadData() async {
  final user = Supabase.instance.client.auth.currentUser;
  if (user == null) return; // Skip for anonymous users
  // Authenticated user logic here
}
```

Key takeaways:
- Always check `mounted` after async operations before calling `ScaffoldMessenger`
- Keep Supabase RLS policies as a security double-layer
- For user actions, show a friendly SnackBar instead of silently failing
