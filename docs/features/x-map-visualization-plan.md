# X投稿の地図可視化機能（実装方針メモ）

## 結論
可能です。段階的に実装すれば、既存アプリに安全に追加できます。

## 目的
- X投稿を地図上のピン/クラスタで可視化する
- 地点ごとの最新投稿一覧を表示する
- 「この地点から投稿する」導線で投稿を促進する

## MVP（最小構成）
1. 地図画面を追加（Leaflet / Mapbox / Google Mapsいずれか）
2. 投稿データテーブルを作成
   - `id`
   - `x_post_id`
   - `text`
   - `author_name`
   - `author_handle`
   - `posted_at`
   - `latitude`
   - `longitude`
   - `place_label`
   - `hashtags`
3. ハッシュタグベースの収集
   - 例: `#五月祭 #mayfesvibe`
4. ピン表示
   - 一定距離内をクラスタリング
5. 位置連動のタイムライン
   - 現在の地図範囲内の投稿を一覧表示

## 収集方式
- **公式API連携**: X APIの利用規約に沿って収集（推奨）
- **ユーザー投稿連携**: アプリから投稿ボタン経由で位置情報つき投稿を促す

> 注意: スクレイピングは規約や安定性の観点で非推奨。公式API中心に設計する。

## 実装ステップ
### Phase 1: 画面とデータモデル
- 地図ページUI追加
- 投稿モデル/リポジトリ作成
- ダミーデータでピン表示

### Phase 2: API連携
- バックエンドでX API収集ジョブを定期実行
- 投稿の位置正規化（建物コード → 緯度経度変換）

### Phase 3: UX改善
- フィルター（時間帯/タグ/カテゴリ）
- 混雑可視化（ヒートマップ）
- 通報/非表示フロー

## 想定リスク
- API制限・料金
- 投稿の位置精度不足
- 不適切投稿のモデレーション

## 回避策
- 収集失敗時はキャッシュ表示
- 位置は「建物/エリア単位」を基本にして誤差を吸収
- NGワード/手動モデレーション導入

## 目安工数（MVP）
- フロント地図表示: 1〜2日
- データ保存/API連携: 2〜4日
- 運用/監視/モデレーション最小構成: 1〜2日
- 合計: 4〜8日

## 次アクション
- 利用する地図基盤（Leaflet/Mapbox/Google Maps）を決定
- 必須ハッシュタグ・表示ルールを確定
- 投稿の位置付与方式（GPS/会場コード）を確定
