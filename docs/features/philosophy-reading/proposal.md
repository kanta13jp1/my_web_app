# 哲学書の読書管理 — 実装レビュー用仕様案

作成日: 2026-10-11 / 状態: 2026-10-11 利用者承認済み。実装内容と検証は implementation.md を参照。本番反映は未実施。

## 利用者の目標

「すべての哲学書を読破する」を長期目標として保持する。まず著者一覧を整備し、次に著作一覧を増やし、日々の読書ページ数・理解度・感想を蓄積する。世紀・国／地域・ジャンルで探索できるようにする。研究開発部門の自己投資と知識の蓄積を支える機能とする。

世界中の哲学書の完全な集合は初期段階で確定しない。「世界の哲学書の何％」とは表示せず、「収録済み著作 120 件のうち読了 8 件」のように対象を明示する。対象を追加した時点で母数が変わったことも示す。初期候補は完全な著者名簿ではなく、拡張可能な調査の出発点とする。

## 既存機能と変更の入口

- 既存 `/reading-list` を拡張する。類似ページを新設して導線を分散させない。
- `lib/pages/reading_list_page.dart`: tools-hub の `reading.list` / `reading.add` を呼ぶ。現在はタイトル・著者の追加と一覧表示。
- `supabase/functions/tools-hub/index.ts`: reading レコードを hub_data に保存する。
- `reading.mark_read` は既存メタデータの保持と所有者条件を要確認。実装前に最新 main 上で再確認し、所有者を含む条件と安全な部分更新に修正する。
- 既存記録は削除・上書きせず移行する。文字列の著者名が一致しただけで、確定した著者へ自動統合しない。

## 画面と操作

### 著者一覧

名前・別名・活動世紀・国／地域・思想の伝統を表示。検索と分類フィルタを組み合わせる。著者を開くと著作一覧と「収録済み X 著作 / 読了 Y 著作」を表示する。著作未調査の著者は「著作を調査中」と表示し、著作ゼロを読破扱いしない。

### 著作一覧

著作名・原題・著者／関係者・成立世紀・複数ジャンル・読書状況を表示。著者画面からも全体画面からも開ける。ジャンル初期案は倫理学、認識論、形而上学、論理学、政治哲学、美学、宗教哲学、言語哲学、科学哲学。儒家・道家・仏教・現象学等は「思想の伝統」として別軸にする。

「国／地域」は現代国籍の断定に使わない。古代ギリシア・古代中国・南アジアなど歴史的地域を表示し、現在の国への対応は別の任意情報とする。複数地域・複数ジャンルを許す。

### 本の詳細と読書記録

1. 著作を選び、読む版を登録する。訳者・出版社・出版年・言語・ISBN・巻・総ページ数は必要な範囲で入力する。
2. 「読書を始める」で読書回を作成する。再読は別の読書回にし、前回の感想や理解度を保持する。
3. 「記録を追加」で日付、今回読んだページ区間またはページ数、理解度、感想、疑問、重要な概念を入力する。
4. 記録は後から編集・削除できる。失敗時は入力を保持し、保存できたように表示しない。
5. 「読了」は利用者が設定する。理解度が低くても読了でき、ページの入力だけで読了を自動断定しない。

理解度は未評価または 1〜5 の自己評価。1: ほとんど理解できなかった、2: 一部を理解した、3: 要点を理解した、4: 自分の言葉で説明できる、5: 他の思想と比較して説明できる。読了と理解度を分け、理解度の過去の変化を残す。感想は非公開が初期値で、初期実装に公開投稿は含めない。

状態は未読・読書中・読了・中断。読み直しは新しい読書回。総ページ数不明の本も記録可能にする。

## データの分離案（Claude Code #1 のレビュー対象）

| 対象 | 主な情報 | 所有と扱い |
| --- | --- | --- |
| Author | 安定 ID、名前、別名、生没年の範囲、活動世紀、地域、伝統、出典、確認状態 | 編集管理された共通目録 |
| Work | 安定 ID、原題・日本語表示名、成立時期の範囲、ジャンル、出典、残存状態 | 共通目録。著者未確定を許す |
| WorkContributor | 著作 ID、著者 ID、役割、帰属の確度 | 本人著作・弟子編集・伝統的帰属等を区別 |
| Edition / Volume | 著作 ID、訳者、出版社、出版年、言語、ISBN、巻、総ページ数 | 共通の確認済み版と利用者の私的な版を区別 |
| ReadingCycle | user_id、著作・版 ID、状態、開始・読了日、再読回 | 利用者本人だけが操作 |
| ReadingEntry | user_id、読書回 ID、日付、ページ区間／数、理解度、感想・疑問、更新履歴 | 利用者本人だけが操作 |
| ReadingGoal | user_id、目標文、対象集合／分類、目録バージョン | 利用者本人が対象を選べる |

名称は概念案。新規テーブルを採るか既存 hub_data を活用するかはレビューで決める。共有目録と私的記録の権限を混ぜない。user_id はクライアント入力を信用せず認証済み本人から決定する。親の読書回・版へのアクセスも検証する。

成立世紀は著者の生年から推測して固定しない。著者一覧は活動世紀、著作一覧は成立世紀、版は出版年を使う。複数世紀にまたがる場合はどちらでも検索できる。紀元前と紀元後を区別し、年ゼロを表示しない。不明を選べる。近似・諸説を注記する。

## ページ数と進捗

- 今回の読書量（再読を含む延べページ数）と、初回読了に向けたページ到達／範囲を区別する。
- ページ区間は版の中で管理し、同じ区間の再読を二重に読了率へ加算しない。
- ページ数だけ入力した記録は読書量に加算し、未指定の区間を推測しない。
- 範囲指定は開始 ≤ 終了、正の整数、既知の総ページ数以内。総ページ数の変更で既存記録が矛盾した場合は確認を要求する。
- 電子書籍や総ページ数不明の場合は件数・状態を示し、ページ進捗率を計算しない。
- 異なる版のページを合算して一つの読了率にしない。合本・分冊の著作完了判定を定義するまで、明示的な読了操作を基本とする。
- 著作の読了件数は異なる版や再読で重複しない。読書量と読書回数は別集計。
- フィルタ結果と全体の分母を区別。空集合は 0/0・対象なしで、100% と表示しない。

## 目録の整備順序

1. 出典付き著者候補を登録し、重複名・別名・年代・地域を確認する。
2. 著者ごとに代表著作を登録する。本人著作・伝承・編集・帰属不確定を区別する。
3. 代表著作から全著作調査へ拡張する。現存・断片・散逸・未翻訳・入手可能性を記録し、読めない著作を未達として強制しない。
4. 出版社や図書館の書誌情報で日本語版・訳者・巻・ページ数を確認する。初期候補に架空の ISBN や総ページ数を埋めない。
5. 共通目録の変更はレビュー経由。利用者は私的な著者・著作・版を追加できるが、それで全利用者の目録を変更しない。

初期候補は別添 CSV の 13 人。西洋・中国・インド・日本を含む小さな検証用集合であり、中世、イスラーム、アフリカ、ラテンアメリカ、現代哲学等の追加が必要。代表著作候補は次の調査の入口であり、全著作一覧ではない。

## 段階的な実装と検証

### 第1段階: 著者・著作の閲覧と分類

既存ルートへの統合、著者／著作切替、名前・別名検索、分類の複合フィルタ、出典表示、調査中・不明状態。共通目録管理と私的追加の境界を決める。

### 第2段階: 私的な読書記録

版の登録、読書回、記録の追加・編集・削除、理解度・感想、既存読書リストの保持。認証・権限・スキーマを人が確認した後に staging で検証する。

### 第3段階: 目標と進捗

収録済み対象に対する読了数、分類別集計、著者別進捗、再読履歴、目録の追加による母数変更。全著作調査を継続できる運用を整える。

受け入れ条件:

- 著者を選ぶと、その著者に関連する著作だけが表示される。共著・編集役割も表示。
- 複数世紀・地域・ジャンルの複合検索、不明・紀元前をテストする。
- 未ログインで私的記録を保存できない。A が B の記録を取得・更新・削除できない。親 ID の差し替えも拒否される。
- 古いタイトル・著者・URL・追加メタデータが状態更新や移行で失われない。
- 総ページ数の超過、負数、小数、重複範囲、再読、未知総ページ数、異なる版を検証する。
- 理解度・感想の履歴と保存後の再取得が一致する。二重送信・通信失敗・編集競合で記録を失わない。
- 320px 幅でも入力と保存ボタンが利用できる。キーボード操作と読み上げラベルを確認する。
- Flutter/Dart、Edge Function、migration/RLS の検証は exact SHA の GitHub Actions と PR CI。ローカルに依存関係やビルドを作らない。
