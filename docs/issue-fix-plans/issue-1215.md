## Current Context

```text
﻿## 背景
エンタープライズ向けのClaude Apps（SlackやAsana連携）では、意図しないメッセージ送信やデータ更新を防ぐため、アクション実行前に必ずユーザーの明示的な同意を求めるガードレール（Consent Prompts）が実装されています。

## 要望
my_web_appのオーケストレーション機能を通じてSlackへの通知や外部SaaSのデータを更新する際、実行前に変更内容のプレビューを表示し、ユーザーの承認（Human-in-the-loop）を必須とするセキュリティステップを追加します。

## 受け入れ条件
- AIが外部システムへの更新（メッセージ送信やタスク起票など）を判断した際、処理が自動実行されずに一時停止状態になること。
- my_web_appの画面上に、実行予定のアクション内容やデータ差分がプレビュー表示されること。
- ユーザーが「承認」「拒否」「修正して再実行」の3つのアクションから選択できること。
- 管理者設定画面から、チーム単位で利用可能な外部SaaS連携のオン・オフを制御できること。

## 実装メモ
MCP（Model Context Protocol）のアーキテクチャや認証の仕組みを参考に、ツール呼び出しのリクエストを直ちに実行せずDB上で「承認待ち」ステータスとして保持し、ユーザーのアクションをトリガーにして非同期に処理を再開するフローを構築します。
```
