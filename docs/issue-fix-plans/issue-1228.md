## Current Context

﻿## 背景
Tinkerアーキテクチャの最大の価値は、複雑なコンピューティングやインフラ管理を完全に抽象化し、ユーザーがデータや評価（Evals）のみに集中できるように設計されている点にあります。このUX思想をアプリに転用します。

## 要望
情報収集やタスク細分化などの「作業」をシステム側のバックグラウンド処理に隠蔽し、ユーザーには「A案かB案か」「このアウトプットは基準を満たしているか」という最終決断（評価）の承認のみを求める洗練された画面を新設します。

## 受け入れ条件
- AI役員が自動生成した選択肢に対し、ワンタップまたはスワイプのみで承認・否認を決定できるシンプルなUIであること。
- 承認・否認の理由を任意で補足入力（テキスト）できる仕組みがあること。
- ユーザーの決断完了後、後続のスケジュール登録などの面倒な処理が自動的に実行されること。
- バックグラウンドで進行中のAI作業プロセスが、画面の邪魔にならない形で視覚的に確認できること。

## 実装メモ
Flutter Webでカード型の直感的なスワイプUIを実装。ユーザーの承認アクションをトリガーに、Supabase Edge Functionsを呼び出してカレンダー連携やタスク分解などの自動化処理を一括で実行させる。
