# 支出の分類候補・要確認

1. my_web_appへログインします。
2. 資産管理（`/asset-management`）を開きます。
3. 「④収支の記録」で支出を選びます。
4. 「内容」に店名や品目を入力します。端末内のキーワード辞書に一致すると、分類候補と「要確認」を表示します。一致しない場合は候補を絞れないと表示します。
5. 候補を明細や用途と照合します。このパネルから記録を保存したり、金額・カテゴリを確定したりすることはありません。既存の「浪費カテゴリ」や「追加」は従来どおり利用者が操作します。

## AI候補

既存のJev接続が利用可能な構成だけに「AIにも候補を聞く」を表示します。送信先ホストを表示し、利用者が押した場合のみ入力内容を送信します。入力中の自動送信はありません。ログイン済みの通常ビルドでは、ai-hubの `expense.jev_suggest` を経由してTypeSafe AIへ送信します。匿名セッションは利用できません。キーはSupabaseの `JEV_API_KEY` Secretだけに保存し、ブラウザへ渡しません。500文字まで、ユーザーごとに1分3回・UTC日付ごと20回、全体でUTC日付ごと200回に制限します。上限判定のDB障害時も外部APIを呼びません。失敗した呼び出しも予約した回数を消費し、自動再試行しません。ローカル接続を明示設定した場合は従来の経路を維持します。

失敗時は端末内ルールに戻り、理由を表示します。内容変更後の古い応答は破棄します。ルールの固定スコアは画面に出しません。AIの確信度も正答率ではなく、すべての候補が要確認です。店名だけで用途や税務上の扱いは確定できません。

## 検証

`test/widgets/expense_classification_review_test.dart` は入力更新、未一致・空欄、明示的送信、通信失敗からの再試行、古い応答、破棄後の応答、幅320px・文字倍率2を確認します。外部AIの返答はテスト用HTTPレスポンスです。実サービスの精度・速度検証ではありません。

CIと本番デプロイの結果はIssue #5452に紐づくPRで追跡します。ブラウザ実画面の未検証部分は、ウィジェットテスト結果と区別して記録します。

## サーバー運用

固定12カテゴリの候補だけを返します。任意URL・任意プロンプトへの代理転送や会計データ保存は行いません。上流5秒・画面8秒のタイムアウトを設定。無効化する場合はサーバーのJEV_API_KEY Secretを削除すると、画面は端末内ルールへ戻ります。Secret未設定でもアプリの入力・保存機能は利用できます。

Issue #5459でクラウド接続を追跡。Deno契約テスト、Flutterクライアント/ウィジェットテスト、Postgres上の並列30要求と権限・上限・期間切替をCIで確認します。
