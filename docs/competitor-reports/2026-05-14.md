## 詳細セクション (= 重大シグナルのみ深掘り)

### 1. Cursor 3.3 PR Review + Build in Parallel — 自社 2-instance routing matrix 直接圧

Cursor 3.3 (5/7) の新機能 4 つが 自社 fleet 戦略の 正面競合軸:

1. **PR Review tab** = PR 作成 → merge を 1 IDE 内完結 (= 自社 GitHub UI + Win Claude/Codex 2-instance 切替の friction 完全圧縮)
2. **Build in Parallel** = async subagent で plan の独立部分を並列実行 (= 自社 cross-instance-pr md doc + git log audit trail 設計を 1-click async 化)
3. **Split changes into PRs** = built-in quick action で logical slice 分割 + 承認 (= 自社 PR cascade 設計の自動化)
4. **Quick-action pills + Explore subagent config** = skill / model 切替 friction 圧縮

**自社軸 impact**: 自社の 2-instance (= Win Claude 設計 / Win Codex 実装) hand-off は md doc + WBS update + cross-instance-pr で audit trail 充実だが、Cursor 3.3 は **1 IDE 内 async subagent で同等成果を friction 0 で達成**. 差別化軸 = (a) WBS 5正本管理 + Notion 同期 (= multi-context governance) + (b) GHA cron 30+ workflow 自動化 (= 24/7 routine ops) + (c) docs/PHILOSOPHY 9 原則 + 12 軸 principle (= AI dev tool 単体では replicate 不能) に集中.

### 2. Devin Review REST API + e2e Desktop Test — 自社 cross-instance-pr に REST 化圧力

5/8 Devin Review REST API GA = **Devin が PR review を programmatically trigger 可能**. 自社 cross-instance-pr は md doc + git log + WBS update の 3 正本管理だが、REST API 化されると friction 差が一気に拡大.

**e2e desktop test via computer use** = Linux desktop app の任意 GUI 操作 + 録画再生で test 可能. 自社 Playwright MCP + Claude Preview + Claude in Chrome の 3 経路を統合した形.

**自社軸 reinforce**: 自社差別化 = (a) WBS-SYNC enforcement (= [WBS-SYNC] rule) + (b) memory file Karpathy 4 サイクル + (c) NotebookLM 0 トークン research (= md doc audit trail と組合せで Devin REST API では replicate 困難).

### 3. Replit Agent 4 Design Canvas — 自社 design-skills + LP + 動画統合戦略 正面競合

Replit Agent 4 (= 5/3 採択時点で記録済 / 継続強化) の Design Canvas は **無限ボード上で web/mobile/LP/deck/video を同一 project で生成 + 直接編集 が即コード反映**. 自社の (= design-skills + Figma MCP + 動画パイプライン + AI 大学 + LP) の 5 軸統合戦略と完全に同軸.

**自社軸 reinforce**: 自社差別化 = (a) Flutter Web + Supabase の **production deployment 軸** (= Replit は app builder 軸 / production fleet ops 不在) + (b) 21 競合機能統合 + (c) 6 部署設計 + (d) 自分株式会社 CEO 感ペルソナ (= product narrative 差別化).

### 4. GitHub Copilot 5/12-5/13 連続更新 — Remote Session Monitoring 路線継続

5/12 Code Review コメント改善 + 5/13 Agent Tasks REST API public preview. 5/6-5/9 の 4 連続更新 (= 5/10 discovery 採択理由) に続く 5/12-5/13 で 「single-tool 内 multi-vendor critic + cloud agent REST + remote ops」優位が **5月通月 高頻度更新** で確立.

**自社軸 reinforce**: 自社差別化 = (a) WBS 5 正本 + Notion 同期 + cross-instance-pr md doc + Slack + worktree+branch の **5 正本 governance** (= Copilot single-tool では replicate 不能) + (b) 12 軸 principle docs (= product 設計判断の哲学).

### 5. Money Forward Consumption Tax AI Agent — 自社 B/S 機能 JP 特化軸

Money Forward が 「Consumption Tax Category Check Agent」 GA + 「自律 AI Agent」suite 化を加速. **JP インボイス制度特化 = 自社未対応 領域差圧**.

**自社対応案**: 自社の **B/S 機能 + 6 部署設計** は 「自分株式会社 = 個人 CEO」 narrative で Money Forward (= 法人会計 SaaS) と用途軸が異なるため正面競合せず、`docs/PHILOSOPHY.md` の 「商品=価値 / 資産負債 / IPO」 9 原則で 個人レベル B/S 設計を維持で十分.

### 6. Notion Plan Mode — 自社 EnterPlanMode / EF-FIRST 設計 同軸

Notion Plan Mode (5/7) = **agent が複雑作業前に明確化質問 + 詳細計画**. 自社の EnterPlanMode tool + `[EF-FIRST]` rule (= 複雑ロジックは EF へ) と完全に同軸.

**自社軸 reinforce**: Plan-then-build 哲学が 業界 標準化 = 自社 12 軸 principle (特に `docs/AI_DEV_PRINCIPLES.md` の deny-by-default / quality-gate) は 業界 早期採用済の優位.
