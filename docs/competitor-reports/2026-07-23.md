## 詳細セクション

### 🔴🔴 Claude Code 2.1.218 — 「非対話セッションで ultrareview が黙ってローカル実行されていた」

**一次 (verbatim / [anthropics/claude-code releases](https://github.com/anthropics/claude-code/releases))**:

> Fixed `/code-review ultra` silently running a local review in non-interactive sessions — it now launches the cloud review

本環境の CLAUDE.md セッション指針は `/code-review ultra` を明記しており、かつ scheduled task は**すべて非対話**で走る。つまり **2.1.170 のままでは、非対話の場で ultra を指示しても「クラウドレビューが走ったつもりでローカルレビューだった」**という状態が成立しうる。これは「緑に見えて実は評価していない」系の失敗 (`feedback_cs_check_cache_dead_green_workflow` / `feedback_empty_violation_list_is_not_compliance` と同型) で、**本レポート自身の生成環境がその条件を満たしている**。

同リリースの本環境該当項目:

| 項目 | 一次の記述 | 本環境の該当理由 |
|---|---|---|
| agent hooks の信頼境界 | hooks now require the agent file's own folder to have accepted workspace trust | `.claude/agents` + `~/.claude/hooks/inject-rules.txt` を毎ターン運用 |
| `context: fork` skill | 既定で background 実行へ変更 (opt out = `background: false`) | 手動 skill を多数運用中 = **挙動が変わる** |
| ネスト深いツリー削除の crash | maximum call stack exceeded の修正 | `/pr-merge` → `worktree_release.ps1` で worktree 撤去が routine |
| auto mode の判定変更 | dangerous-rm / background-`&` / suspicious-Windows-path は permission dialog を出さず classifier が判定 | **[SUBAGENT-GUARD] の deny-by-default 解釈に影響** |
| `/ultrareview` 引数 | descriptive argument ("review my auth changes") での失敗を修正 | CLAUDE.md 記載の運用コマンド |

⚠️ **過大評価しない点**: 同リリースには「Windows パスの `\u` 前置 segment (例 `C:\Users\unicorn`) が CJK 文字に化けてファイルが参照不能になる」修正もあるが、**トリガーは小文字 `\u` の segment**であり、本リポジトリの `C:\Users\kanta\GitHub\my_web_app` は `Users` が大文字 U、他 segment も `u` 始まりではない。**直撃と断定できる証拠はない**ため、クラスとしての記録に留める。

**バージョン差の実測**: ローカル `claude --version` = **2.1.170** / npm published = **2.1.218**。7-21 レポートで最優先 (アクション #0) に置いてから **3 日連続で未着手**。⚠️ 自動更新失敗時に `claude.exe` を復元する修正は 2.1.217 側にあり**旧アップデータには無い**ため、更新は「失敗すると実行ファイルが失われうる」前提で行う (7-22 既報)。
