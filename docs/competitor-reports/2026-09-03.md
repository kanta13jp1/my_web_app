## ★★★1. 2026-07-31 レポートの main 未着地インシデント

`git log --oneline --grep="docs(competitor-monitoring)"` で最新の実データコミットが `2026-07-31 daily report + discovery: Hint` (`cc6f5c69c`) と分かったが、`git merge-base --is-ancestor cc6f5c69c HEAD` は `false`。実体を辿ると、このコミットはローカルのみに存在するブランチ `codex/rescue-compmon-20260731-20260818`（1 コミットのみ、origin 未 push、最終更新 2026-07-31 15:48 JST）にのみ存在していた。ブランチ名から、過去に別インスタンス（Codex 系）がこの孤立コミットの存在に気づき「rescue」ブランチを作って退避させたが、そのまま main へのマージや PR 化はされずに終わったと推測される。

結果として、main の `_competitors.json` は 2026-07-30 時点の内容のまま 34 日間更新されず、以下が失われていた：

- 会社リストが 28 社のまま（Hint が欠落）
- Tomo の `category` フィールドに古い退役 trigger 文言（`2026-08-23 までに新規シグナル 0 なら退役`）が残存 — 07-30 に「App Store 実測で根拠喪失＝解除推奨」と判定済みだったにもかかわらず、その解除が JSON に反映されていなかった

🔑 **教訓**: `docs(competitor-monitoring)` のコミットが存在すること自体は、main に着地したことの証明にならない。`git merge-base --is-ancestor <commit> HEAD` で毎回確認するのが安全。またこの種の日次自動化は「今日ちゃんと push できたか」を次回セッションの Step 0 で軽く検算する価値がある。
