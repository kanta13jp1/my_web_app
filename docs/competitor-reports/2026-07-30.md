## ★8. 疑った「GHA cron が承認保留で沈黙停止」は誤警報だった

`gh run list --workflow=competitor-monitoring.yml` の最新が **2026-07-28T22:54Z** で 7-29 分が見当たらず、昨日の ★★2 (= **GitHub Actions が「悪意ある可能性」の workflow を 7-28 施行で承認保留 / 無人 cron が保留されると沈黙停止**) が的中したと読みかけた。

- cron 定義 = `"0 22 * * *"` (毎日 07:00 JST) / 実発火は GHA 遅延で 22:5x UTC
- → **本日分は約 40 分後で未到来**。欠落ではない。workflow state も `active`、pending/action_required の run も存在しない。

🔑 昨日「**実際に保留された事実は未確認 = 「起こりうる」であって「起きた」ではない**」と自分で線を引いておいたことが、翌日そのまま誤診を防いだ。並びの欠落を見た瞬間に「予測が当たった」と書く誘引は強い。**時計を確認するだけで解ける仮説を、確認せずに結論にしない。**

### 付随: 上書き競合は GHA が先着した (実測 / 予定と逆の結果)

workflow の Step 5 には手動レポート保護がある (verbatim `# 既存ファイルがあれば上書きしない (手動レポートを保護)` / 判定は `<!-- generated-by: github-actions -->` の有無)。当初は「本 report を run より先に push すれば保護が効く」と見込んだが、**実際には GHA が先着した**:

| 時刻 (UTC) | 出来事 |
|---|---|
| 22:26 | commit 実行 → **pre-commit quality gate が 423 秒** (7 分) |
| 22:44 | push 開始 → **pre-push full quality gate** |
| ~22:5x | **GHA run が着地** = `1deaa4126 自動: 競合レポート 2026-07-30 (static-template)` |
| 22:58 | push が `[remote rejected] ... cannot lock ref 'refs/heads/main'` で失敗 |

→ rebase して **本 report を GHA 版の上へ載せ、GHA が唯一生成できていた可用性チェック表を付録として保全**した (7-29 と同じ扱い)。

🔑 **教訓 2 つ**:

1. **品質ゲートの所要時間が着地順序を決める。** 「先に push すれば保護が効く」は、gate が 7〜14 分かかる環境では成立しない。cron と同じ時間帯に手動生成物を出す設計自体が競合を生む (本 task の cron は 22:00 UTC 指定 / 本 task の実行も同じ朝)。
2. **`PUSH_EXIT=0` は嘘だった。** `git push ... | tail -25` としたため `$?` は **tail の終了コード**を拾い、push が `remote rejected` で失敗しているのに `PUSH_EXIT=0` と表示された。`git status` / `git log origin/main` で実体を確認するまで「成功」に見えた。**パイプ越しの exit code を成否判定に使わない** (`feedback_prepush_full_gate_oom` の「127 がバイナリ不在と同値に化ける」と同じ罠の別形)。
