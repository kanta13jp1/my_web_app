## ★★2. GitHub Actions が「悪意ある可能性」の workflow を承認保留 — 本日施行・自社は対象

**一次**: [GitHub Changelog 2026-07-28](https://github.blog/changelog/2026-07-28-github-actions-holds-potentially-malicious-workflows-for-approval/)

- 悪意ある可能性があると判定された workflow run は、実行前に**保留**される
- 解除には **write 権限を持つ collaborator が認証済み web セッションで承認**する必要がある
- **public リポジトリ (github.com) のみ**。GitHub Enterprise Server は対象外
- **設定不要で自動適用** (opt-out の記載なし)

**自社の該当性 (実測)**:

```
gh repo view --json visibility → {"isPrivate":false,"visibility":"PUBLIC"}
ls .github/workflows/*.yml    → 107
```

→ **該当する**。public + 107 workflow + 5 daily cron + 30 種超の自動化という構成は、この機能の影響を最も受ける側。

**効く場所**: 無人運用が前提の cron (`ai-tool-watch` / `safety` / `residuals` / `crosscheck` / `wiki-compile` / `worktree-sweep`) が保留された場合、**人が承認するまで永久に止まる**。しかも保留は「実行されなかった」のと外形が似る。
memory の `feedback_pr_ci_not_triggered_diagnose` が扱う「run 0 件 / `action_required`」の診断に、**新しい第 3 の原因**が加わったことになる (従来は ①bot push の anti-recursion ②`mergeable=CONFLICTING`)。

⚠️ 現時点で自社 workflow が実際に保留された事実は**確認できていない** — 施行は昨日で、直近 run は正常に完走している。「起こりうる」であって「起きた」ではない。ただし判定基準が公開されていない以上、**保留を検知する手段を持つこと**自体が対策になる。

**一次**: [MCP Specification 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28)

- **Stateless, self-contained requests** (ステートレス core)

- 拡張は**常に opt-in**で、初期化時に client / server 双方の明示的サポートをネゴシエート
- 主要拡張: **Tasks** (長時間処理の非同期実行 / ポーリング・実行中入力・永続ハンドル) / **MCP Apps** (会話内インライン UI) / **Skills over MCP**

仕様側の Security and Trust & Safety 節が「**ツールの説明 (annotations) は信頼できるサーバから得たものでない限り untrusted として扱う**」を明文化した。自社の deny-by-default 方針と同方向で、**独自規律だった部分が仕様の標準要件に降りてきた**。差別化は「原則を持っていること」から「運用で守れていること」へ移る (昨日の memory 同軸の議論と同じ構図)。
