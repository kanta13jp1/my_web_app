# Playwright Test Agents

Issue: #1793

This repository uses the Playwright 1.62.1 planner, generator, and healer agent
definitions for bounded maintenance of public Playwright tests. The checked-in
files under `.codex/agents/` are the Windows output shape of:

```powershell
npx --no-install playwright init-agents --loop=codex --project=chromium
```

Regenerate all three definitions whenever `@playwright/test` changes, and
review the generated diff before committing it. Do not hand-edit only one
definition because their MCP tool contracts are versioned together.

## Workflow

1. Planner: explore one named public flow from `test/e2e/seed.spec.ts` and save
   a human-readable plan under `specs/`.
2. Generator: convert the approved plan into ordinary Playwright TypeScript
   under `test/e2e/generated/`.
3. Healer: diagnose a failing generated test and propose the smallest locator,
   assertion, or timing repair.
4. Lead: inspect the diff, run deterministic Playwright CI, and decide whether
   the result is a test repair or a product defect.

Agent output is a proposal. It never bypasses normal review, CI, deployment, or
repository ownership rules.

## Guarded delegation packet

Use one agent at a time for this flow. Do not start a local child worker, dev
server, package install, or browser when the resource route is
`CLOUD_REQUIRED`.

| Agent | Purpose | Scope | Budget and return contract |
| --- | --- | --- | --- |
| planner | Produce a plan for one public flow. | Read-only; public unauthenticated pages only; no persistent browser profile or secrets. | 10 minutes and one plan; return visited routes, plan path, assumptions, and unresolved risks. |
| generator | Produce one maintainable test from one approved plan. | MCP may write only `test/e2e/generated/**`; no app, workflow, dependency, or production-data changes. | One test file; return changed files, selectors/assertions, and validation not yet run. |
| healer | Repair one failing generated test. | Workspace writes limited to that test and its matching `specs/**` plan. | At most two repair attempts; return root cause, exact diff, rerun result, and remaining risk. |

If the healer emits `test.skip()`, `test.fixme()`, increases retries, weakens
an assertion, or cannot pass after two attempts, treat the result as a failure
or product defect. Do not count it as healed.

## Deterministic test lane

The seed deliberately disables JavaScript and targets the crawlable public shell
to avoid authentication, mutable data, and Flutter hydration variance. The
generated flow verifies:

- the public WBS entry is visible;
- the no-signup link is accessible by role and name;
- the destination preserves `lp_intent=trial`;
- meaningful landing-page headings remain visible.

Run the bounded lane with:

```powershell
npm run e2e:agents -- --project=chromium
```

The regular `e2e:smoke` script also includes this generated test, so the
existing cloud minimal-E2E workflow repeats it and preserves the normal
Playwright report. A human reviews every generated or healed diff before merge.

## Safety notes

- Use the isolated test MCP server generated by Playwright; do not attach these
  agents to a pre-existing authenticated browser profile.
- Keep planning and generation on public read-only routes unless the Issue and
  lead explicitly authorize a narrower authenticated fixture.
- Do not enter credentials, payment data, or production secrets.
- Do not let agent output merge, deploy, or mutate production data.
- Record subagent purpose, scope, budget, result, validation impact, and cleanup
  impact in the PR or Issue whenever an agent is actually run.
