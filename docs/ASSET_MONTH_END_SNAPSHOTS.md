# 月末の記録残高の自動保存

## 動作と区別

サイトを閉じていても、Postgres内のジョブが日本時間の月初0:05と0:35に直前月の記録残高を保存する。`asset_month_end_snapshot_settings` を本人が有効化したユーザーだけが対象。既定は無効。無効化しても過去の記録は保持する。

`cfo_assets` から境界時刻より前の最新記録を口座名ごとに選ぶ。口座別の観測時刻と、対象月より古い観測かどうかを残す。銀行照合済みの月末残高という意味ではない。未登録口座・改名や廃止済み口座を自動で認識することはできないため、口座一覧の点検が必要。

自動保存は `asset_month_end_balance_snapshots` に保存し、既存の手動 `asset_liability_monthly_snapshots` を上書きしない。同じユーザー・月は主キーで一意になり、再実行しても既存値は変更しない。月初以外は何もしない。古い月の推定補完はしない。未取得月はゼロとしてグラフや差額に含めない。

## 画面への組込み

`AssetMonthEndSnapshotCard(service: AssetMonthEndSnapshotService(client), monthKeys: [...])` を資産管理の手動履歴に隣接して配置する。年をまたぐ直近月キーは呼出側で指定する。カードは横スクロールする比較表・有効化設定・部分更新・エラーと再試行を持つ。このPRでは既存ページを変更しない。既存月次レポートの支払集計や手動履歴とは統合せず、別の根拠として表示する。

## 有効化前の確認

この変更はレビュー用。マイグレーション適用と本番有効化は別途承認が必要。スキーマ・RLS・権限の人による確認を行い、ステージングで以下を確認する。

- pg_cronが有効で、`asset-month-end-balances` が一件だけ登録されていること。UTC 15:05/15:35（JST翌日0:05/0:35）。pg_cronがなければNOTICEで未登録を明示する。
- 既存の `monthly-asset-report.yml` はレポート生成で、今回の残高保存とは別。変更・追加のGitHub定期ジョブは不要。
- 本人の有効化設定・本人だけの読取・他人の記録不可視。一般ユーザーは捕捉関数や保存済みチェックポイントを変更できないこと。
- 月末境界の記録選択・古い口座の警告・欠損月・再実行時の不変性。初月以前の記録がないことを異常なゼロと扱わないこと。
- ジョブ失敗は `cron.job_run_details` で監視する。月初の二回とも失敗した月は未取得として残し、推測で後日埋めない。

既存の口座記録は観測日時を利用者が指定できるため、遡及修正の監査履歴そのものではない。チェックポイント保存後の原記録修正を反映しないことは意図した仕様。

## 検証

専用GitHub Actionsで実Postgresに最小ソーススキーマとマイグレーションを適用し、JST境界、年越し、古い観測、オプトイン、重複、変更不可、RLSを検証。cron登録のみスタブで確認し、実際の時刻発火はステージングで別途確認する。Flutterでは欠損維持・狭い画面・有効化・再試行を検証する。実利用者の残高はテストや公開差分に含めない。

参照: [Supabase Cron](https://supabase.com/docs/guides/cron)、[Cron Quickstart](https://supabase.com/docs/guides/cron/quickstart)。
