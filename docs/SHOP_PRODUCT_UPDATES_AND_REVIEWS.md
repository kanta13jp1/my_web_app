# 商品の更新情報・アプリケーションバージョン・口コミ

Status: implementation proposal, not deployed. Human schema/RLS review and
production approval are required before shipping.

## 利用者向け仕様

- 商品詳細上部に「配布版 v…」を表示。サイト自身のビルド番号とは区別する。
- 「更新情報」「口コミ・評価」から各セクションへ移動する。
- 更新履歴は公開承認済みだけを表示し、最新20件を取得する。公開日不明は「未記録」。
- 配布ファイルのSHA256が一致する更新記録に「現在の配布内容」を表示する。
- 口コミは公開閲覧可能。平均星評価と件数は公開中の評価だけで計算する。
- 投稿はログイン済み・支払済み購入者のみ。1商品1アカウント1件。
- 星1〜5を必須、本文は任意・2000文字まで。編集と削除を提供する。
- 氏名・メール・ユーザーIDを公開一覧に含めない。本文への個人情報記載は警告する。
- 「投稿時の配布版」はサーバーが記録する。実際にプレイした版の保証ではない。
- 運営者による非公開化だけでは、投稿日時や投稿時版を更新しない。
- 読込失敗を0件と扱わない。保存エラーではフォームを残して再試行を案内する。
- 返金後の編集は不可。ただし本人の投稿削除は可能。
- 星の操作対象は44×48px。選択値を文章でも表示し、状態をliveRegionへ通知する。
- ダイアログ内で最初の星へフォーカスし、Tab/Enter/Spaceで選択、Escapeで閉じる。

## データと権限

```text
ログイン済み購入者
  └─ invoker RPC + paid購入行のRLS確認
       ├─ 非公開schema：owners（user_id ↔ review_id）
       └─ 公開schema：reviews（星・本文・投稿時版、アカウントIDなし）
            └─ 公開一覧・平均・10件ずつのカーソル表示

運営者が検証した版・公開日・変更内容
  └─ releases（初期は非公開）
       └─ 公開フラグ + 未来日時を除外 → 商品の更新履歴
```

所有情報はAPI非公開の `shop_review_private` schemaに保存しRLSを適用。
公開表の複合外部キーで商品と所有者を結合する。RPCはすべてSECURITY INVOKER。
列単位GRANTにより、購入者が公開状態・版・日時・商品を偽造することを禁止する。
Supabase APIのexposed schemasに `shop_review_private` を追加してはならない。
匿名の口コミは作らず、メールや購入明細を公開クエリへJOINしない。

## 運営手順（未実行）

1. 人間が差分とRLS試験結果を確認する。既存の購入・配布・計測PRとの競合も解消する。
2. 本番承認後、既存のリリース手順で新規migrationだけを適用する。
3. 商品ページをdeployし、同じcommitの本番表示を確認する。
4. 各リリースに安定したrelease_key、商品version、検証済みSHA256、短い見出し、
   事実に基づくnotes_jaを登録する。確認できた公開日時だけpublished_atに入れる。
5. 運営レビュー後にis_publishedをtrueにする。過去記録は上書きしない。
6. 不適切な口コミは、管理者のservice-role権限でis_visible=falseにして非公開化する。
   本人が本文を編集しても自動で再公開しない。管理画面・通報ワークフローは別途。

本migrationの初期表示は確認済みHexCiv配布物のSHA256が一致する場合だけ作成する。
価格、Stripe、商品ファイル、購入権利は変更しない。口コミAPIを利用した有料処理はない。
本番では試験用の架空口コミを投稿しない。

## 検証

- `Shop Community Validation`: PostgreSQL16の使い捨てDBで実migrationとRLSを実行。
- Dartモデル/VMテスト：入力、二重送信、失敗、再読込、認証切替、ページング、dispose。
- Widgetテスト：公開情報、未購入/未認証、投稿編集削除、360px幅、長文、エラー。
- 既存の商品・購入・ダウンロード画面テストを同時実行。
- 最終SHAの全体CI、Claude/人間レビュー、本番API統合確認は別途リリースゲート。

2026-09-12のmain方針（PR #5399）でDesignプラグイン監査は推奨へ変更された。
未実施を合格とは扱わない。文字200%/360px、キー操作、主要色の数値コントラスト、
Semanticsを決定的テストで確認し、実NVDA等の支援技術と認証付きブラウザ確認は別記する。
認証・schema/RLSの明示的な人間レビューや本番承認は引き続き必要。

CIは本番秘密情報を使わない。DB fixtureは実Supabaseの認証/Storageをローカルな
最小定義で置き換えるため、PostgREST経由の本番結合確認を代替するものではない。
