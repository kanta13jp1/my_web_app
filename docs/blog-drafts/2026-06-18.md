### はじめに

個人開発している資産管理SaaS「自分株式会社」に、ここ数日で定期取引の自動検出機能を一気に実装しました。「毎月同じ引落しが複数口座に散らばっていて把握が大変」という自分自身の課題を解決するためです。

実装は3ステップに分かれており、PR #3475（v1 基本検出）→ #3478（v2a 隔月対応・口座prefill）→ #3479（v2b 無視機能・ミラー同期）と段階的に進化しました。さらに並行して端末間同期バグの修正（#3474, #3480）とアクセシビリティ対応（#3482）も行いました。

本記事ではその設計判断と実装のポイントをまとめます。

### 実装方法

#### v1: 基本的な定期取引検出 (#3475)

最初のバージョンでは、過去の取引履歴から「同一ラベル・同一金額が毎月繰り返す」パターンを検出します。検出ロジックのコアは純粋関数として切り出し、テストしやすい設計にしました。

```dart
}
```

検出結果は `AssetRecurringTransactionSuggestionCard` として資産管理ページに表示し、ワンタップで定期固定費として登録できます。

#### v2a: 隔月cadence検出 + 引落元口座の自動prefill (#3478)

「2ヶ月に1回」の支払い（分割払いなど）も検出対象にしました。

- **隔月検出**: 観測月が「偶数月のみ」か「奇数月のみ」に集中していれば `bimonthly even/odd` と判定
- **検出窓拡大**: 毎月=4ヶ月以上 → 隔月=3ヶ月以上（6ヶ月分を参照）
- **口座prefill**: 各観測に引落元口座名を付与し、最頻出を `suggestedSourceName` として登録ダイアログに自動入力

```dart
enum RecurringCadence { monthly, bimonthlyEven, bimonthlyOdd }

RecurringCadence? inferCadence(List<int> months) {
  final evenMonths = months.where((m) => m % 2 == 0).length;
  final oddMonths  = months.where((m) => m % 2 == 1).length;
  if (evenMonths >= 3 && oddMonths == 0) return bimonthlyEven;
  if (oddMonths  >= 3 && evenMonths == 0) return bimonthlyOdd;
  if (months.length >= 4) return monthly;
  return null;
}
```

#### v2b: 「この候補を無視」の永続化 + ミラー同期 (#3479)

検出候補の中には「知ってるけど登録したくない」ものも出てきます。「無視」ボタンを追加し、その状態を**単調増加セット**として永続化しました。

```
ローカル SharedPreferences (asset_recurring_ignored_v1)
  ↕ union
Supabase テーブル (recurring_suggestion_ignored)
```

単調増加セット（tombstoneなし）の設計にしたため、マルチデバイス同期は単純な union で安全に行えます。削除操作がない（「無視」は追加のみ）ため、CRDT的にシンプルな実装で競合解決が不要です。

#### マルチデバイス同期バグ修正: Last-Write-Wins (#3480)

#3474 で実装した月次state の union マージには盲点がありました。

**問題**: チェック解除（支払済みのキャンセル）を別端末から操作しても、union は「あった方を優先」するため解除が伝播しない。

**解決策**: `AssetLiabilityMonthlyState` に `updatedAt` タイムスタンプを追加し、**Last-Write-Wins (LWW)** に切り替えました。

```dart
// 競合解決ロジック
AssetLiabilityMonthlyState merge(
  AssetLiabilityMonthlyState local,
  AssetLiabilityMonthlyState remote,
) {
  if (local.updatedAt != null && remote.updatedAt != null) {
    // LWW: 新しい方の状態全体を採用
    return local.updatedAt!.isAfter(remote.updatedAt!) ? local : remote;
  }
  // 旧データとの後方互換: union フォールバック
  return local.mergeWith(remote);
}
```

`updatedAt` は永続化キー `asset_liability_state_updated_at_v1`（ローカル）と `state_updated_at`（Supabase jsonb）の双方に保存し、ローカル SharedPreferences の key も既存 key と分けることでマイグレーション不要にしました。

#### アクセシビリティ対応 (#3482)

Flutter の `Semantics` / `MergeSemantics` を `RecurringFixedCostCard` に追加しました。

- 各行の名称+内訳を `MergeSemantics` で1ノードに集約
- 編集・削除ボタンを「〇〇 を編集」「〇〇 を削除」と文脈化
- スクリーンリーダー（NVDA / VoiceOver / TalkBack）向けのQAチェックリストを更新

### 詰まったポイント

**1. LWW vs CRDT の選択**

最初は「union = CRDT的で正しい」と思っていましたが、チェック解除（削除操作）があると union では不十分でした。「チェック」「解除」どちらの操作も単一ユーザーの操作として扱い、最後に操作した端末を正とする LWW が今回のユースケースには合っていました。

**2. 無視セットの設計**

当初は「無視解除」機能も考えましたが、実装を単純化するため v2b では意図的に省略。単調増加セット（tombstone なし）にすることで、Supabase との同期ロジックが `INSERT ... ON CONFLICT DO NOTHING` だけで完結します。

**3. 隔月検出の誤検知**

「直近3ヶ月すべてが偶数月だった」場合に bimonthly even と誤判定するケースを発見。検出窓を6ヶ月に広げ、「対となる奇数月の観測が0件」という条件を追加して誤検知を抑制しました。
