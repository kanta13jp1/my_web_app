## 本文下書き

### はじめに

「自分株式会社」という個人開発のライフマネジメントアプリを Flutter Web + Supabase で開発しています。Notion・Evernote・MoneyForward・Slack・X など21の競合サービスの機能を1つに統合するという野心的なプロダクトです。

今週は特に大きなマイルストーンをいくつか達成しました。

- **AI大学 4層ドリルダウンUI** の実装完了 (学部→学科→科目→講師)
- **Build in Public 自動化** (週次クーロン + SNS投稿パイプライン)
- **AI第二の脳 Ingest pipeline** の実装 (#974)
- **テーマ切り替えUI Phase 2** — 10種類のテーマカタログ

これを実現したのは、Claude Code・Codex・Gemini・GitHub Copilot という**12インスタンスのAIエージェントが並列稼働する開発体制**です。今回はその裏側を紹介します。

---

### 実装方法

#### 1. AI大学 — 4層ドリルダウンUI

「AI大学」は、様々なAIプロバイダー (OpenAI, Anthropic, Google, など) の学習コンテンツを体系的に提供する機能です。

今週、UI を大幅に刷新しました。

```
学部一覧 → 学科選択 → 科目一覧 → 講師・教材詳細
```

この4層構造を Flutter の `Navigator.push` + `GoRouter` で実装。各層はそれぞれ独立したページコンポーネントとして設計し、Supabase の Row Level Security (RLS) で各ユーザーの閲覧権限を制御しています。

```dart
// 学科選択ページの遷移例
GoRoute(
  path: '/ai-university/:facultyId/departments',
  builder: (context, state) => AiUniversityDepartmentPage(
    facultyId: state.pathParameters['facultyId']!,
  ),
),
```

Supabase の Edge Function (`ai-university-update`) が毎日自動で新しいAIプロバイダー情報を取得・更新し、コンテンツが常に最新状態に保たれます。

#### 2. Build in Public 自動化

「Build in Public」は、開発の進捗を公開して透明性を高める開発スタイルです。今週、これを**完全自動化**しました。

**Phase 1 (Win版#132 part 112)**:
- GitHub Actions の週次クーロンで開発実績を自動集計
- Supabase の `development_achievements` テーブルから直近7日間の実績を取得
- X (Twitter) の `post-x-update` Edge Function 経由で自動投稿

**Phase 2 (Win版#132 part 113)**:
- 週次クーロンが完全稼働
- 投稿フォーマットの最適化 (ハッシュタグ: #FlutterWeb #BuildInPublic #IndieHacker)

これにより、手動でSNS更新する作業がゼロになりました。

#### 3. AI第二の脳 Ingest Pipeline

最も技術的に興味深い実装が、**AI第二の脳 Ingest pipeline** (#974) です。

概念: 開発中の全ての学習・意思決定・成功/失敗パターンを構造化データとして蓄積し、NotebookLM (Master Brain) と連携して「過去の意思決定を検索・参照できる」システムを構築する。

実装の核心は3層メモリシステムです:

| 層 | ツール | 用途 |
|---|---|---|
| L1: セッション内 | claude-mem (SQLite + Gemini圧縮) | 全ツール使用を自動記録 |
| L2: セッション間 | auto-capture hooks (mdファイル) | git commit履歴・インスタンス間共有 |
| L3: プロジェクト横断 | NotebookLM Master Brain | 深い調査・長期アーキテクチャ知識 |

MCP Auth Audit Log (`feat(mcp): persist auth audit log`) も同時実装し、セキュリティイベントの永続化も完了しました。

#### 4. テーマ切り替えUI Phase 2

Flutter Web のテーマ管理に `ThemeProvider` (Riverpod) を使い、10種類のカラーパレットを実装しました。

- ダーク/ライトモード切り替え
- インディゴ・オレンジ・グリーン・パープル等 10 テーマ
- `ThemeSelectorPage` でビジュアルプレビュー表示

### 詰まったポイント

#### マイグレーションのタイムスタンプ衝突

複数のAIインスタンスが並列で開発すると、`supabase/migrations/` のファイル名に使うタイムスタンプが衝突する問題が頻発しました。

```
ERROR: duplicate key value violates unique constraint "schema_migrations_pkey"
Key (version)=(050000) already exists.
```

対策として、各インスタンスに「タイムスタンプ帯域」を割り当てました:

- VSCode版: `YYYYMMDD01xxxx`
- PowerShell版: `YYYYMMDD02xxxx`
- Codex#1: `YYYYMMDD03xxxx`

これで衝突が完全に解消。`fix(migrations): resolve 050000/060000 timestamp collision` の2件のコミットで修正完了。

#### CIのrace condition

`ci-auto-fix.yml` で修正コミットをpushする際、別インスタンスが同時にpushしていると競合が起きていました。

```yaml
# 修正前: push が失敗してもエラーを無視していた
- run: git push origin HEAD

# 修正後: push前にrebaseで同期
- run: |
    git pull --rebase origin main
    git push origin HEAD
```

シンプルな修正ですが、12インスタンス並列環境では必須の対応でした。

#### WBS進捗チェックの時刻依存バグ

GitHub Actions のcronで動くWBSチェックが、`status='completed'` のタスクをも「遅延」と判定していたバグを修正。`time-relative check` の条件式に完了ステータスの除外を追加しました。
