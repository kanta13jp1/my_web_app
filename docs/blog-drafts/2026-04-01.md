### はじめに

「自分株式会社」は Flutter Web + Supabase で構築している AI 統合ライフマネジメントアプリです。Notion・Slack・MoneyForward など 21 の競合サービスが持つ機能を 1 つのアプリに凝縮することを目標にしています。

2026 年 4 月 1 日現在、Supabase Edge Function は **234 本** に達しました。集中タイマー、AI 文章アシスタント、バイラル広告生成、バーチャルペット、AR ナビゲーションなど、毎日 5〜10 本ペースで拡張し続けています。

しかし、ここに至るまでには **「Supabase の 100 関数制限」** という大きな壁がありました。この記事では、その問題をどう解決し、234 本体制を CI/CD で安定運用できるようにしたか、その全記録を共有します。

---

### 課題: Supabase 100 関数制限と 402 エラー

Supabase の Free/Pro プランには、デプロイできる Edge Function 数に上限があります。GitHub Actions で `supabase functions deploy --all` を実行すると、100 本を超えた時点で **402 エラー** が返ってきてデプロイが失敗するようになりました。

エラーログ:

```
Error: Function limit exceeded (402)
Deploy failed: too many functions
```

当初の `deploy-prod.yml` は単純に全関数をデプロイしていたため、本数が増えるにつれて CI/CD が壊れ続けていました。

---

### 解決策: Tier 分割デプロイ戦略

解決のために採用したのが **Tier 分割デプロイ** です。

#### アーキテクチャ

```
deploy-prod.yml
├── Tier 1A (core): 主要 API 30本 — 常時デプロイ
├── Tier 1B (viral): バイラル系 20本 — 常時デプロイ
└── Tier 2 (extended): 残り 184本 — 手動 or 個別デプロイ
```

`deploy-prod.yml` の該当箇所:

```yaml
- name: Deploy Tier 1A (core functions)
  run: |
    for fn in schedule-daily-digest get-home-dashboard ai-assistant \
               post-x-update health-check daily-judgment \
               get-support-tickets reply-support-request \
               notify-feature-request development-achievements; do
      supabase functions deploy $fn
    done

- name: Remove stale Tier 2 functions to avoid 402
  run: |
    # 古い Tier 2 を事前削除してから Tier 1 をデプロイ
    supabase functions delete old-unused-function || true
```

ポイントは **「古い Tier 2 を先に削除してから Tier 1 をデプロイする」** 手順です。これにより Supabase 側の関数カウントが 100 以下に収まり、402 エラーが解消しました。

### バイラル成長パイプラインの実装

同時期に実装したのが **バイラル成長パイプライン** です。次の 5 本の Edge Function で構成されています。

| 関数名 | 役割 |
|---|---|
| `viral-video-ad-generator` | AI で動画広告スクリプト生成 |
| `viral-share-engine` | SNS シェア最適化・バイラル係数計算 |
| `x-media-post` | X (Twitter) へのメディア付き自動投稿 |
| `growth-automation-controller` | グロース施策の優先度スコアリング |
| `landing-ab-test` | LP の A/B テスト管理 |

Flutter 側には `ViralAdCampaignPage` を追加し、管理者がワンクリックでキャンペーンを起動できるようにしました。

```dart
// lib/pages/viral_ad_campaign_page.dart (抜粋)
ElevatedButton(

    );
    setState(() => _shareScore = result.data['viralCoefficient']);
  },
  child: const Text('キャンペーン起動'),
)
```

### 詰まったポイント

#### 1. `config.toml` の `major_version` 衝突

Supabase CLI のバージョンが異なる環境（ローカル PC、GitHub Actions、Claude Code Web）で同時に `supabase db push` を実行すると、`config.toml` の `major_version` フィールドが衝突してマイグレーション失敗が起きました。

対策: `major_version = 17` に固定し、push 時は常に `--include-all` フラグを付けるように統一しました。

```yaml
- name: Push DB migrations
  run: supabase db push --include-all
```

#### 2. マイグレーションファイルの番号重複

複数の Claude Code インスタンスが並行してマイグレーションファイルを生成すると、同じ番号帯のファイルが重複して生成される問題が発生しました。

対策: `CLAUDE.md` にインスタンス別の番号帯ルール (`MULTI_INSTANCE_COORDINATION`) を追記し、各インスタンスが異なる番号帯を使うように規約化しました。

```
PS#1〜PS#5:  000010〜000050
PS#6〜PS#10: 000060〜000140
Web/VSCode:  000900〜
```
