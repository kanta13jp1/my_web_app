### はじめに

「自分株式会社」——個人開発者の私が、Notion・Evernote・MoneyForward・Slack・Amazonなど**21競合の機能を1つのアプリに統合する**という、少し無謀なプロジェクトを始めてから1年以上が経ちました。

今週の開発で大きなマイルストーンをいくつか達成しました。

- **AI大学機能が320社突破** (AutoGen / DSPy / Haystack / CrewAI を追加)
- **競合比較ページが240社対応** に拡張
- **12インスタンス並行開発体制** が本格稼働
- **T-1ブログシリーズ累計138本** 投稿完了

この記事では、特に「AI大学」機能の設計と、Flutter Web + Supabase でスケーラブルに運用する方法を共有します。

### AI大学とは何か

AI大学は「自分株式会社」の中核機能の一つです。世界中のAIツール・フレームワーク・プロバイダーを網羅したデータベースで、ユーザーが「どのAIをどう使うべきか」を学べるプラットフォームです。

```
現在の収録数: 320社 (前週比 +4社)
今週追加:
  - AutoGen (Microsoft): マルチエージェントフレームワーク
  - DSPy (Stanford): プログラマティックLLMパイプライン
  - Haystack (deepset): 検索拡張生成(RAG)フレームワーク
  - CrewAI: エージェント協調フレームワーク
```

データはSupabase PostgreSQLに蓄積され、GHA (GitHub Actions) のスケジュールタスクが毎日自動更新します。

### 実装方法

#### データ設計 (Supabase)

AI大学のコアはSupabaseのマイグレーションファイルで管理しています。

```sql
-- 新プロバイダー追加の例 (Codex#1が担当)
INSERT INTO ai_providers (name, category, description, url, tags)
VALUES
  ('AutoGen', 'multi-agent', 'Microsoftのマルチエージェントフレームワーク',
   'https://microsoft.github.io/autogen/', ARRAY['python', 'llm', 'agent']),
  ('DSPy', 'llm-pipeline', 'StanfordのプログラマティックLLMパイプライン',
   'https://dspy-docs.vercel.app/', ARRAY['python', 'optimization', 'rag'])
ON CONFLICT (name) DO UPDATE SET
  description = EXCLUDED.description,
  updated_at = now();
```

追加ルールは `CLAUDE.md` の AI振り分け早見表で明確に定義されており、**AI大学 provider 追加は Codex#1 専任**としています。Claude Code はアーキテクチャ判断のみを担います。

#### 12インスタンス並行開発体制

今週の開発を支えたのは、12インスタンスの並行開発体制です。

```
Claude Code × 10 (VSCode版/Win版/PS#1-6/WEB版/スマホ版)
Codex CLI  × 2  (横断調査/CI運用)
```

各インスタンスは独立した git worktree で作業し、main ブランチへの直接コミットは禁止しています。

```bash
# 各インスタンスの作業ディレクトリ
.claude/worktrees/instance-vscode   # UI/design専任
.claude/worktrees/instance-win      # Windows環境
.claude/worktrees/instance-ps1 ~ ps6  # 各担当領域
```

### 詰まったポイント

#### 1. Comparison Pageのスケール問題

240社のデータを Flutter の `Map` で管理すると、重複キーが静かに上書きされる問題がありました。Dart の `Map` は後から挿入した値が勝つため、CI の `equal_keys` ルールでも検出が難しいケースがあります。

**解決策**: `collision patrol` スクリプト (PS#5) で定期的にキー衝突を自動スキャン。今週は4件 → 8件を修正完了。

#### 2. AI大学の更新頻度とトークン消費

320社のデータを毎日手動更新するのは現実的ではありません。GHA スケジュールタスク (`ai-university-update.yml`) で Claude Code **非依存**設計にしています。

```yaml
# .github/workflows/ai-university-update.yml
schedule:
  - cron: '0 9 * * *'  # 毎日 JST 18:00
```

Claude Code quota 超過時でも GHA は継続稼働するため、自動更新は停止しません。

#### 3. マルチインスタンス間の衝突防止

12インスタンスが同時に同じファイルを編集するリスクがあります。これは `docs/MULTI_INSTANCE_FLEET.md` で役割分担を明確化し、`instance-constraints.md` で制約を記録することで回避しています。
