### はじめに

「自分株式会社」という個人プロジェクトを運営しています。Flutter Web + Supabase で作ったSaaSで、現在37名のユーザーがいます。このプロジェクトで最近力を入れているのが、**AI駆動の自律運用基盤**です。

今週だけで68件以上のコミットが積み重なりましたが、その大半は人間が書いたものではありません。GitHub Actionsと複数のAIエージェントが協調して、自動的にリポジトリを更新し続けています。

### 実装した自動化の全貌

#### 1. Karpathy 4サイクル — 知識管理を完全自動化

Andrej Karpathyが提唱する「Ingest → Compile → Query → Lint」という4サイクルを、このプロジェクトに実装しました。

- **Ingest**: `scripts/memory_ingest.py` が会話ログや開発メモをSupabaseに取り込む
- **Compile**: `scripts/wiki_compile.py` が `docs/concepts/` 以下の40以上のコンセプトファイルと `docs/INDEX.md` を自動生成
- **Query**: NotebookLM CLIを使ったゼロトークンリサーチ（APIコストなし）
- **Lint**: `scripts/knowledge_vault_lint.py` が知識ベースの品質を維持

毎日のwiki compileが動くたびに、40以上のMarkdownファイルが更新されます。人間がドキュメントを書かなくても、コードと会話が積み重なるだけで知識ベースが成長していく設計です。

#### 2. AI大学 — マルチAIプロバイダーのコンテンツ管理

「AI大学」はこのサービスのコアフィーチャーの1つで、Claude Code、Codex、Gemini Code Assistなど複数のAIツールの情報をキュレーションして提供しています。

毎時間、GitHub Actionsがトリガーされ、最新のAI動向を取り込んでSupabaseのデータベースを更新します。今週は「Alibaba Qoder」が次回の追加候補として発見されました（クールダウン期間中のため6月9日に追加予定）。

評価フレームワークとして「役割特化 vs 汎用コーダー重複」の観点を導入しており：
- **Qodo / Semgrep Assistant**: PRレビュー・セキュリティ特化 → 優先度高
- **Playwright MCP**: ブラウザ実行能力の付加 → ROI高
- **Jules / OpenHands**: 非同期別レーンエージェント → 次期候補

#### 3. 競合21社の毎日監視

notion、evernote、moneyforward、slack、chatwork、X、claude-codeなど21社を毎日自動監視しています。competitor-monitoringワークフローが日次レポートを生成し、`docs/daily-reports/` に保存します。

```yaml
# GitHub Actions excerpt
- name: Competitor discovery
  run: python scripts/competitor_monitor.py --cooldown-check
```

クールダウン機能を実装しており、同じ競合を連続でレポートしないよう制御しています。

#### 4. インフラヘルスチェックとコスト監査

毎時間インフラの死活監視を行い、週次でCI/CDコストを監査しています。今週のコスト監査結果：GitHub Actions使用量は計画内に収まっており、Claude Code quota超過時のfallbackとしてCodex CLI / Gemini Code Assistへの自動切り替えも機能しています。

### 詰まったポイント

#### マルチインスタンス間の調整

最大の課題は、複数のAIエージェントが同一リポジトリに同時コミットしたときのコンフリクトです。

解決策として**インスタンス分離ポリシー**を実装しました：
- L1: Antigravity + Gemini（探索）
- L2: VSCode + Codex（実装）
- L3: VSCode + Claude（設計）

各レーンが触るファイルの範囲を`docs/SUBAGENT_ORCHESTRATION_POLICY.md`で定義し、コンフリクトを最小化しています。

#### Supabase + Flutter Webのリアルタイム同期

SupabaseのRealtime機能とFlutter Webの組み合わせで、複数のGitHub Actionsが更新したデータをブラウザにリアルタイム反映させています。Edge Functions（Deno）を中間層に挟むことで、サービスキーを直接フロントエンドに渡さない設計にしています。

#### PR保護ルールとbot push

GitHub branch protection ruleの`GH006`エラー（直接pushの禁止）を回避するため、一部のworkflowはorphan branchを経由してからmainにマージする方式を採用しています。これが溜まってきたときの定期クリーンアップも自動化しました（`/blog-publish-cleanup` skill）。

### まとめ

1人で運営するSaaSでも、適切な自動化基盤を作れば「寝ている間に競合調査が終わり、朝起きたらAI大学が更新されている」という状態を実現できます。

重要なのはKPIをシンプルに保つことです。CLAUDE.mdを463行から80行に削減し（Karpathy 80行KPI）、詳細は各`docs/`ファイルに分散させました。AI agentがコンテキストを効率よく読めるように、ファイル構造を設計することが重要でした。

FlutterとSupabaseの組み合わせ、そしてClaude Codeによる自律開発の世界は、インディー開発者にとって前例のない生産性をもたらしてくれています。
