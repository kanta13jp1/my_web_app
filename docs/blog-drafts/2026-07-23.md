### はじめに

「AIが仮説を立て、AIがコードを書き、AIが結果を測定する」——この一文が、直近1週間の自分株式会社の開発ログを一言で表しています。

Flutter Web + Supabase で構築したSaaS「自分株式会社」(https://my-web-app-b67f4.web.app/) では、ランディングページ(LP)のグロース施策をほぼ全自動化しました。Claude Code と Codex を組み合わせた AI Fleet が、毎日仮説を生成し、コードを実装し、A/Bテスト結果をレポートする——そんな開発サイクルが実際に回っています。

今週の主なリリースをまとめながら、その仕組みを紹介します。

---

### 実装方法

#### 1. 10仮説を一次指標で同時測定 (#4321)

`fix(lp): measure ten hypotheses by primary metric` というコミットが示すように、LPには現在10本の仮説が同時走行しています。各仮説にはユニークなファネルIDが割り当てられ、Supabase の Edge Function がイベントを受け取るたびに該当仮説のコンバージョン率を更新します。

```dart
// LP仮説ファネルのイベント記録
await supabase.from('lp_funnel_events').insert({
  'hypothesis_id': hypothesisId,
  'event_type': 'primary_conversion',
  'user_id': userId,
  'created_at': DateTime.now().toIso8601String(),
});
```

これらのデータは `feat(analytics): automate LP hypothesis decision report (#4296)` で自動レポート化されており、毎日Claudeがどの仮説を続けるか・打ち切るかを判断します。

#### 2. ワンタップトライアル (#4318)

`feat: add one-tap trial for first-user traffic` は今週最もインパクトの大きかった変更です。初回訪問ユーザーに対して、メールアドレス入力なしでアプリを体験できる「ゲストトライアル」フローを追加しました。

設計のポイントは3つです：

- **セッション保持**: `fix: preserve landing signup completion across auth redirects (#4307)` で、OAuthリダイレクト後もオンボーディング状態を維持
- **ソーシャルプルーフの先行ロード**: `fix: preload LP social proof independently of analytics (#4311)` で、分析スクリプトの遅延に関係なくユーザーの信頼獲得要素を即座に表示
- **信頼・初期価値の保持**: `fix: preserve LP trust and first-value onboarding` でLP→アプリ遷移時の文脈断絶を防止

#### 3. 自律オペレーションコンソール「OMOCHA WORKS」

`feat: 自律オペレーションコンソール (OMOCHA WORKS) を追加` は、AI Fleetの稼働状況をリアルタイムで俯瞰できるダッシュボードです。Claude Code / Codex / Geminiのどのエージェントがどのタスクを担当しているかを一画面で確認でき、過去のPR・コミット・Cronジョブの結果も集約されます。

#### 4. 証券評価額の月次履歴追跡 (#4295)

`feat(asset): 証券評価額の月次履歴を記録し推移系列サービスを追加` は、「自分株式会社」の"資本=時間"哲学を数値化する機能です。保有資産の評価額を月次でスナップショット保存し、時系列グラフで可視化します。

### 詰まったポイント

#### Flutterの`require_trailing_commas`との格闘

`fix: 残存する require_trailing_commas 2件を解消 (flutter analyze ゲート)` というコミットが示すように、CIの`flutter analyze`ゲートがコンマ漏れで落ちる問題が発生しました。原因はAIが生成したコードのlint違反です。

解決策は `ci-auto-fix.yml` で `dart fix + dart format + deno fmt` を自動実行するワークフローを追加すること (`fix: CI自動修復 dart fix + format + deno fmt`)。AIが書いたコードのフォーマット問題をAIが自動修正する仕組みを整えました。

#### LPのQAトラフィック混入

`fix(analytics): exclude LP QA traffic (#4298)` で、開発チーム自身のアクセスがコンバージョン率を汚染していた問題を修正。IPベースのフィルタリングとUserAgentの組み合わせで精度を改善しました。

---

### まとめ

今週の開発で改めて実感したのは、**AI駆動開発における「測定の自動化」の重要性**です。仮説を立てることも実装することも、今やAIが担えます。しかし「どの仮説が効いたか」を正確に測定し、次の行動につなげるループを設計するのは、まだ人間の仕事として残っています——いや、それこそが最も価値ある仕事かもしれません。

自分株式会社では引き続き「AI Fleet × Flutter Web × Supabase」の組み合わせで、ソロ開発者が大企業と競えるSaaS開発を追求していきます。
