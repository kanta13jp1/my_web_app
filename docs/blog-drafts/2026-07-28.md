### はじめに

Flutter Web + Supabase で個人 SaaS「自分株式会社」を開発しています。今週 (2026-07-21〜28) は機能フリーズせず3つの大型フィーチャーをリリースしました。

- **IQ テスト機能 (5領域)** — 論理推論・数的処理・空間認識・ワーキングメモリ・言語理解を25問で測定し、学習プランを自動生成
- **HexCiv 買い切り販売** — ¥500 の単品商品を Supabase で安全に販売する基盤
- **月次借金返済報告カード** — 返済コミュニティ向けに純関数設計で正確な進捗を可視化

どれも「設計の失敗が起きやすいポイント」があったので、詰まったところを中心に共有します。

---

### 実装方法

#### 1. IQ テスト (5領域 / #4353)

5領域 × 難易度 1〜5 で各1問、計25問を出題します。採点ロジックは次の通りです。

```dart
// 難易度重みつき正答率 → 偏差IQ (平均100, SD=15)
final weightedScore = answers.entries.fold(0.0, (acc, e) {
  final q = questions[e.key];
  return acc + (e.value.isCorrect ? q.difficulty : 0) / q.difficulty;
});
final iq = 100 + 15 * ((weightedScore / maxWeight - 0.5) / 0.15);
```

ポイントは「未回答 = 不正解」扱いです。早く終わらせるほど高得点になる抜け穴を防ぎます。ワーキングメモリ問題は刺激を数秒表示して隠すタイマー制御が必要で、Flutter の `Timer` と `StatefulWidget` の組み合わせで実装しました。

得られた5領域スコアは学習プランの入力にそのまま流し込みます。偏差が大きい領域は週あたりの練習回数を増やす自動調整です。

#### 2. HexCiv 買い切り販売 (#4364)

有料コンテンツ配信で一番危ないのは「支払わずにダウンロードできてしまう」ミスです。今回は3重のガードを設けました。

**① バケットを非公開に固定**

```sql
-- Supabase Storage: product-downloads バケット
-- public = false で URL 知識だけではアクセス不可
```

**② RLS で purchase 確認後のみ署名 URL 発行**

Edge Function 内で `shop_purchases` に購入行があるかチェックし、あれば `createSignedUrl()` を返します。購入行がなければ 403 を返して終了。

**③ shop_purchases に insert ポリシーを意図的に作らない**

利用者トークンで購入行を直接 INSERT できると「タダ乗り」が成立します。INSERT は Edge Function (service role) 経由のみとし、Stripe Webhook で決済確認後に書き込む設計にしました。

また商品の `is_active` フラグはデフォルト `false` にしています。ファイルと Stripe Price が揃う前に購入導線が出ると「買えたのに落とせない」状態が起きるためです。

#### 3. 月次返済報告カード (#4373)

借金返済コミュニティ向けに、SNS 投稿用カードを生成する機能です。設計の核は **符号規約の統一** でした。

ワークブックの負債 balance は「負値」で格納されていますが、履歴ストアの前月残高は「絶対値」で持っていました。正規化しないと返済が進んでいるのに「増加」と誤表示します。修正は `DebtProgressCardService` に変換ロジックを集約し、型で開示範囲を固定する純関数設計で解決しました。

センシティブ情報 (年収・口座残高・借入先名) はフィールドとして持たせず、UI 側の書き忘れに依存しない構造にしています。

### 詰まったポイント

**IQ スコア換算の「意味」問題**

偏差IQ は規準集団による標準化が必要ですが、個人開発で規準データを持つのは現実的ではありません。そこで `IqCalibration` クラスに換算定数を集約し、「標準化ではないスコアである旨を明示する」という誠実な設計にしました。信頼区間も表示して「±X の範囲」として提示しています。

**Supabase Storage の署名 URL 有効期限**

`createSignedUrl()` の有効期限を長くするとキャッシュ共有リスクが上がります。今回はダウンロード用途なので60秒に設定し、ダウンロード開始後は無効になるようにしました。

**符号の不整合は型で防ぐ**

負値と絶対値が混在すると計算バグが見つけにくい。Dart の `typedef` や sealed class で表現の違いを型レベルで表現し、混入を防ぐのが有効です。

### まとめ

今週の3フィーチャーに共通するのは「セキュリティと誠実さ」です。

- 有料コンテンツは「買わなくても取れる穴」を潰す
- IQ スコアは「標準化ではない」と明示する
- 返済カードは「センシティブ情報をフィールドに持たない」

Flutter Web + Supabase の組み合わせは個人開発で十分本番運用できる強さがありますが、RLS・バケット設定・型設計を丁寧にやらないとセキュリティホールやバグの温床になります。設計の勘所を意識しながら来週も継続します。
