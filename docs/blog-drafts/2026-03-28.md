### はじめに

Notionのロードマップ分析で明確になった「短期で埋めるべきギャップ」の一つが**テンプレート機能**だ。自分株式会社には既に `template_marketplace_page.dart` というファイルが存在していたが、日報1つしか入っていないほぼ空のページだった。

今日はこの問題を解決し、18種類のテンプレートを持つ本格的な「テンプレート広場」と、Notionが2年以上前から提供している**ノートのバージョン履歴**機能を実装した。

### テンプレート広場の設計

#### カテゴリ設計

以下の5カテゴリで18テンプレートを整理した:

| カテゴリ | 枚数 | 代表テンプレート |
|----------|------|-----------------|
| 日次記録 | 3 | 日報、朝の計画、夜の振り返り |
| ビジネス | 4 | 会議メモ、プロジェクト概要、OKR、週次レビュー |
| 思考・アイデア | 3 | ブレインストーミング、メリデメ分析、読書ノート |
| 学習・成長 | 3 | 学習ログ、目標設定(SMART)、習慣トラッカー |
| 個人・生活 | 2 | 旅行計画、月次家計簿レビュー |
| 技術・開発 | 3 | バグレポート、技術仕様書、スプリント振り返り(KPT) |

#### Flutter実装のポイント

```dart
class _TemplateEntry {
  final String id;
  final String category;
  final String title;
  final String description;
  final String content;
  final IconData icon;
  final Color color;

  const _TemplateEntry({ ... });
}
```

`const` で定義されたテンプレートリストは、アプリ起動時に余分なメモリ確保が発生しない。`ChoiceChip` でカテゴリ絞り込みを実装し、選択したテンプレートは `NoteEditorPage` に `initialTitle` と `initialContent` を渡してノート作成画面を開く。

ゲーミフィケーションとの連携も忘れずに:

```dart
void _useTemplate(BuildContext context, _TemplateEntry t) {
  Provider.of<GamificationService>(context, listen: false)
    .awardPoints(10, reason: 'Used Template: ${t.title}');
  // ...
}
```

テンプレートを使うたびに10ポイント付与される。

### ノートバージョン履歴の設計

#### Supabaseテーブル

```sql
CREATE TABLE IF NOT EXISTS note_versions (
  id       uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  note_id  uuid NOT NULL REFERENCES notes(id) ON DELETE CASCADE,
  user_id  uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  title    text NOT NULL DEFAULT '',
  content  text NOT NULL DEFAULT '',
  saved_at timestamptz NOT NULL DEFAULT now()
);
```

RLS（Row Level Security）で自分のノートの履歴しか見られないよう制限。`note_id + saved_at DESC` のインデックスで最新順の取得を高速化した。

#### バージョン保存のトリガー

バージョンは**手動保存時のみ**記録する設計にした。自動保存のたびに記録すると履歴が膨大になるためだ:

```dart
Future<void> _saveManually() async {
  // ...
  await _autoSaveService.saveImmediately(_saveNoteWithoutClosing);
  await _saveVersionSnapshot(); // バージョンスナップショットを追加
  // ...
}

Future<void> _saveVersionSnapshot() async {
  final noteId = _currentNoteId;
  if (noteId == null) return; // 新規ノートは保存後に記録
  // ...
  await _supabase.from('note_versions').insert({
    'note_id': noteId,
    'user_id': user.id,
    'title': _titleController.text.trim(),
    'content': _contentController.text.trim(),
    'saved_at': DateTime.now().toUtc().toIso8601String(),
  });
}
```

#### 復元フロー

1. AppBarの🕐ボタンをタップ（既存ノートの場合のみ表示）
2. BottomSheetで最新30件の履歴を一覧表示
3. 「復元」ボタンをタップ → 確認ダイアログ
4. 現在の内容を先にバージョンとして保存してから復元実行

```dart
// 復元前に現在の状態をスナップショット
await _saveVersionSnapshot();
setState(() {
  _titleController.text = v['title'] as String? ?? '';
  _contentController.text = v['content'] as String? ?? '';
});
_autoSaveService.triggerAutoSave(_saveNoteWithoutClosing);
```

### 詰まったポイント

**テンプレートの `const` 化**: Dart の `const` コンストラクタは全フィールドが `const` である必要がある。`Color(0xFF...)` は `const` なので問題ないが、動的な値（例えば `DateTime.now()` を含む文字列）は `const` にできない。テンプレートの `content` に `${DateTime.now()}` を入れていた初期案を断念し、シンプルなプレースホルダー文字列に変更した。

**`ModalBottomSheet` のネストした `Navigator.pop`**: バージョン履歴シート内の復元確認ダイアログで `Navigator.pop` を呼ぶと、シートが先に閉じてしまう問題があった。`showDialog` の builder 内では `context` の参照をきちんと管理する必要がある。
