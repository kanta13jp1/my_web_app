# 個人開発 SaaS 収益化戦略 — Free→Paid 転換率を上げる設計

「無料ユーザーが多いのに収益が上がらない」は設計の問題。転換率を上げるための具体的な戦術を整理する。

## SaaS 収益化の基本構造

```
個人開発 SaaS の典型的な問題:
  MAU: 500
  Free: 490 (98%)
  Paid: 10  ( 2%)
  MRR: ¥29,800 (平均¥2,980/月)

目標:
  転換率 2% → 5% で MRR 2.5倍
  転換率 5% → 10% で MRR 5倍
```

## 戦術1: フリープランに「天井」を作る

```
悪い設計 (転換率が上がらない):
  Free = 機能制限なし・広告あり
  Paid = 広告なし + おまけ機能
  → ユーザーが Paid に切り替える理由がない

良い設計 (転換が自然に起きる):
  Free = コア機能 × 制限量 (3プロジェクト/100件まで等)
  Paid = 制限解除 + パワーユーザー向け機能
  → ヘビーユーザーが「自然と」壁に当たる
```

**制限の設計例**:

```
プロジェクト数:   Free 3 / Pro 無制限
月次レポート:     Free 直近1ヶ月 / Pro 12ヶ月
AI 生成回数:      Free 10回/月 / Pro 500回/月
エクスポート:     Free ✗ / Pro CSV/PDF
チームメンバー:   Free 1名 / Pro 5名
```

## 戦術2: Upgrade モーメントを作る

```dart
// 制限に当たったときに Upgrade 誘導
Widget buildProjectList() {
  final isAtLimit = _projects.length >= 3 && !_isPro;
  
  return Column(
    children: [
      ..._projects.map((p) => ProjectTile(project: p)),
      if (isAtLimit)
        UpgradePromptCard(
          message: 'プロジェクト上限 (3/3) に達しました',
          ctaText: 'Pro にアップグレードして無制限に',
          onTap: () => Navigator.push(
            context,
            MaterialPageRoute(builder: (_) => const UpgradePage()),
          ),
        ),
    ],
  );
}
```

**モーメントの例**:

```
✅ 制限到達時の即時表示 (最も効果が高い)
✅ 月次レポートで「Pro なら12ヶ月分表示できます」
✅ エクスポートボタンを非活性化 + ツールチップで誘導
✅ 高頻度ユーザーへのメール (使用量 80% 到達時)
```

## 戦術3: 年払いで LTV を上げる

```
月払い: ¥980/月 → 年間 ¥11,760
年払い: ¥7,800/年 (34% off) → 初年度 ¥7,800

ユーザーにとって: 年¥3,960 の節約
自分にとって: 解約率 大幅低下 + キャッシュフロー前倒し

実装: Stripe の yearly price + coupon
```

## 戦術4: 14日トライアルで Paid を先に体験させる

```
フリーミアム (一般的):
  Free → 壁に当たる → Upgrade
  問題: Paid の価値を体験する前に諦める

リバーストライアル:
  Paid (14日無料) → 終了 → Free にダウングレード or 継続
  利点: 最初から全機能を体験 → 「失う痛み」が転換を後押し
```

## 戦術5: 価格の表示方法

```
❌ 悪い例:
  スタンダード ¥980/月
  プロ ¥1,980/月

✅ 良い例:
  スタンダード ¥980/月
  プロ ¥1,980/月  ← 最も人気 (バッジ)
  ビジネス ¥4,980/月

3択で中間を選ばせる (松竹梅の法則)
「最も人気」バッジで社会的証明
```

## KPI: 転換率を上げる測定指標

```
転換率 = Paid ÷ (Free + Paid) × 100

関連指標:
  Activation Rate: 登録後7日でコア機能を使った割合
  Engagement Score: 週次アクティブ日数
  Feature Adoption: Pro 機能への接触率

→ Activation Rate が高いユーザーほど転換率が高い
→ 上記 3 指標を Supabase で計測し、週次で確認
```

## まとめ

```
制限設計    → Free に天井を作る (量・期間・チーム)
モーメント  → 壁に当たったその瞬間に誘導
年払い      → LTV 向上 + 解約率低下
トライアル  → リバーストライアルで価値を先体験
価格表示    → 3択 + 「最も人気」バッジ
```

転換率 2% → 5% で MRR は 2.5 倍になる。大量流入より「既存ユーザーの転換」の方が即効性が高い。
