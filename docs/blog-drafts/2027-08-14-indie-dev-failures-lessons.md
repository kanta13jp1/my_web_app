# 個人開発の失敗から学んだ10のこと — 3つのプロダクトが教えてくれた現実

3つのプロダクトを作って、2つを畳んだ。失敗した理由と、そこから学んだことを正直に書く。

## 失敗プロダクト1: タスク管理アプリ

```
作った期間: 3ヶ月
ユーザー数: 12人 (友人含む)
終了理由: Notion の方が明らかに優れていた
```

### 教訓1: 競合を先に使い倒す

Notion を「なんとなく知っている」だけで作り始めた。3ヶ月後に Notion を改めて触ったとき、自分が作ったものが完全に劣っていると気づいた。

**今やっていること**: 競合21社のデータベースを作り、毎月使い比べる。

### 教訓2: 「自分が使う」から始める

自分がそのプロダクトを毎日使っているか? 使っていないなら、誰も使わない。

## 失敗プロダクト2: 家計簿自動化ツール

```
作った期間: 2ヶ月
ユーザー数: 45人 (Product Hunt で拾った)
終了理由: MoneyForward の API 連携が壊れ、修正コストが収益を超えた
```

### 教訓3: 外部依存のリスクを定量化する

「他社のAPIに依存する」= 「他社の都合で死ぬリスクがある」。API 変更1回で2ヶ月分の作業が消えた。

**今やっていること**: 外部 API 依存は最小化。コアロジックは自社コントロール。

### 教訓4: 収益化は早く始める

「まずユーザーを増やしてから」は罠。無料で45人集めたが、有料移行は2人。早期に価格設定とゲートを作るべきだった。

### 教訓5: 撤退条件を事前に決める

```
撤退条件 (今は明文化している):
  - 3ヶ月で MRR 10,000円未満
  - 月のアクティブユーザーが 3ヶ月連続減少
  - 技術的負債の修正に開発時間の 50%+ を使っている
```

## 現プロダクト (自分株式会社) での適用

```
失敗1から学んだ: 競合21社を毎月使い込む + AI大学でデータベース化
失敗2から学んだ: 外部API依存を Edge Function でラップして切り替え可能に
失敗1・2から: Day 1 から有料プランを設計
```

### 教訓6: MVP は「動く」ではなく「売れる」

最初の MVP に決済フローを含める。Stripe を後付けするより、最初から設計する方が楽だった。

### 教訓7: ユーザーインタビューを先にやる

5人に話を聞いてから作り始めると、3ヶ月の無駄が防げた。

### 教訓8: データで判断する

```
感覚で判断: 「使いやすいはず」
データで判断: セッション時間 8分 / 直帰率 34% / DAU 推移
```

Supabase Analytics と GHA Schedule で毎日自動集計するようにした。

### 教訓9: 一人でやりすぎない

```
自分がやること:   設計・判断・ユーザー対応
AIに任せること:   実装・テスト・ドキュメント
GHAに任せること:  デプロイ・モニタリング・レポート
```

個人開発でも「分業」の発想が必要だった。

### 教訓10: 継続できる規模を保つ

```
❌ やりすぎた時期: 週60時間開発 → 3週間でバーンアウト
✅ 今の水準:       週20時間開発 → 1年以上継続中
```

持続可能なペースが、長期的に最も多くのアウトプットを生む。

## まとめ

```
失敗から学んだ最重要3つ:
  1. 競合を徹底的に使い込んでから作る
  2. 撤退条件を先に決める
  3. 持続可能なペースを守る
```

失敗は恥ずかしくない。同じ失敗を繰り返すのが問題。失敗を記録して、次に活かすことが個人開発の核心だと思う。
