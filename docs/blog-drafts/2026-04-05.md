### 1. TableCalendarによる月次カレンダービュー

#### なぜ今カレンダーか

Notionの機能ギャップ分析（現在カバー率94%）の中で「カレンダービュー」は長期ロードマップに位置づけられていましたが、既存の `calendar-events` Edge Functionと `table_calendar: ^3.1.2` パッケージが既に揃っていたため実装コストが低いと判断しました。

#### 実装の核心：O(1)イベントマッピング

```dart
final Map<String, List<Map<String, dynamic>>> _eventsByDate = {};

static String _dateKey(DateTime d) =>
    '${d.year}-${d.month.toString().padLeft(2, '0')}-${d.day.toString().padLeft(2, '0')}';
```

`TableCalendar` の `eventLoader` は `DateTime day` を受け取るため、`YYYY-MM-DD` 文字列をキーにしたMapに変換します。これにより O(1) で日付別イベントを取得できます。

#### ページ変更時の遅延フェッチ

```dart
onPageChanged: (focusedDay) {
  _focusedDay = focusedDay;
  _fetchMonth(focusedDay);
},
```

ページスワイプ時のみ対象月のデータをフェッチ。既取得月は `_eventsByDate` に蓄積するため、戻ったときの再取得を回避できます。

#### カラーピッカーを外部パッケージなしで実装

```dart
Wrap(
  spacing: 8,
  children: colors.map((c) => GestureDetector(
    onTap: () => setDialogState(() => selectedColor = c),
    child: Container(
      width: 28, height: 28,
      decoration: BoxDecoration(
        color: Color(int.parse('FF${c.replaceFirst('#', '')}', radix: 16)),
        shape: BoxShape.circle,
        border: selectedColor == c
            ? Border.all(color: Colors.black87, width: 2.5)
            : null,
      ),
    ),
  )).toList(),
),
```

5色のカラーピッカーを外部依存なしで実装。`flutter_colorpicker` などを追加しなかったのは、pubspec.yaml の依存増加を防ぐためです。

### 2. ギタースタジオ — リアルタイムメーター + 録音共有

#### Web Audio API でリアルタイムレベルメーター

ブラウザの `MediaRecorder API` で録音中に `AnalyserNode` からリアルタイムの音量を取得し、Flutter の `AnimatedContainer` で視覚化しています。

```dart
// AudioContext → AnalyserNode → 16msごとにレベル更新
_timer = Timer.periodic(const Duration(milliseconds: 16), (_) {
  if (!mounted) return;
  setState(() => _audioLevel = _analyser.getLevel());
});
```

`mounted` チェックは `async gap` 後の `BuildContext` 使用に必須です。`flutter analyze` の `use_build_context_synchronously` ルールが検出してくれます。

#### share_plus で録音URLをシェア

```dart
import 'package:share_plus/share_plus.dart';
// cross_file は share_plus が再エクスポートするため直接importは不要

await SharePlus.instance.share(
  ShareParams(
    text: '自分のギター録音を聴いてください！\n$publicUrl',
    subject: recording['title'] ?? '録音',
  ),
);
```

`cross_file` を直接インポートすると `unnecessary_import` エラーになります。`share_plus` が内部で再エクスポートしているため不要です。

### 3. 管理者ユーザープロフィール編集 + PATCH API

#### user-profile-manager Edge Function の拡張

管理者がユーザーの表示名・アバターURLを編集できるPATCH APIを追加しました：

```typescript
case "PATCH":
  const { user_id, display_name, avatar_url } = await req.json();
  const { error } = await adminClient
    .from("profiles")
    .update({ display_name, avatar_url, updated_at: new Date().toISOString() })
    .eq("id", user_id);
  if (error) return jsonError(error.message, 400);
  return jsonSuccess({ message: "updated" });
```

Flutter側では `AlertDialog` + `TextFormField` で編集UIを実装し、更新後に一覧を再フェッチします。

### 4. QUOTA GUARD — Edge Function上限の自動監視

Supabase Freeプランのデプロイ上限は94です。Claude Code Scheduleによる自動CSチェック（毎時実行）に **QUOTA GUARD** ロジックを追加しました：

```
デプロイ数が 94 に達している場合:
→ 新規 Edge Function の追加を禁止
→ 既存 Function へのアクション追加 or フロントエンド実装のみ許可
```

この制約が今日の「ギャラリー機能を既存Functionのアクション追加で実装する」という設計判断を生みました。制約は創造性を生む、という典型例です。

### 詰まったポイント

#### `withOpacity` → `withValues` への移行

Flutter 3.x で `Color.withOpacity()` が deprecated になっています：

```dart
// 旧: deprecated
color: Colors.white.withOpacity(0.1),

// 新: recommended
color: Colors.white.withValues(alpha: 0.1),
```

`flutter analyze` が検出してくれますが、プロジェクト全体に散らばっているため地道に修正が必要です。
