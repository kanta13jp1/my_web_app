## 本文下書き

### はじめに

「自分株式会社」は Notion・Evernote・Slack など 21 競合の機能を 1 つに統合したAIライフマネジメントアプリです。Flutter Web + Supabase で開発を続けており、今回は **友達招待システム（ReferralShareCard）** と **Edge Function UI 自動連携** という 2 つの機能を同日に実装しました。

グロース施策として「友達を招待したら特典がもらえる」仕組みは定番です。しかし、Flutter Web でそれをきれいに実装しようとすると、紹介コード生成・共有 UI・Supabase との連携など意外と考えることが多い。今回の実装ログをまとめます。

---

### 実装方法

#### 1. ReferralShareCard の設計

`ReferralShareCard` はホーム画面に配置するウィジェットで、以下の役割を持ちます:

- ログイン中ユーザーの **紹介コード** を表示（Supabase の `profiles` テーブルから取得）
- **コピーボタン** でクリップボードにコピー
- **シェアボタン** で `https://my-web-app-b67f4.web.app/?ref=<code>` の招待 URL を SNS へ共有
- 招待経由の新規登録数を表示（`referral_count` カラム）

```dart
// lib/pages/home_page.dart (抜粋)
ReferralShareCard(
  userId: currentUser.id,
  referralCode: profile.referralCode,
  referralCount: profile.referralCount,
),
```

Supabase 側では `profiles` テーブルに `referral_code text UNIQUE` と `referred_by uuid` カラムを追加し、新規サインアップ時に `?ref=` パラメータを読み取って `referred_by` をセットする Edge Function (`growth-acquisition-signal`) を用意しました。

#### 2. Edge Function UI 自動連携

今回の実装でもう一つ面白かったのが、**Edge Function ごとに専用の UI ページを自動的に連携する仕組み** です。

`lib/data/home_tool_catalog.dart` にツールカタログを定義し、各エントリに `functionName`・`route`・`icon` を持たせます。新しい Edge Function を追加したら、このカタログにエントリを 1 行追加するだけで、ホーム画面のカードと `/functions/<name>` ルートが自動で生成されます。

今回追加した 3 つの Edge Function UI:

| Edge Function | ページ | 用途 |
|---|---|---|
| `memo-reactions` | `/memo-reactions` | 公開メモの絵文字リアクション一覧 |
| `note-comments` | `/note-comments` | ノートのコメント CRUD |
| `growth-acquisition-signal` | `/growth-acquisition-signal` | 招待経由の獲得シグナル |

`main.dart` にルートを追加し、`home_tool_catalog.dart` にエントリを追記するだけ。673 行のコードを追加しましたが、パターンが統一されているため迷いなく書けました。

#### 3. UUID バグ修正

`note_comments_page.dart` でコメント削除時に `id` を `int` で扱っていましたが、Supabase の `id` は `uuid` (String) です。型ミスマッチによるランタイムエラーを修正しました。

```dart
// 修正前
.eq('id', commentId.toString()) // commentId が int

// 修正後
.eq('id', commentId) // commentId を String(UUID) に統一
```

### 詰まったポイント

**① 招待 URL の `?ref=` パラメータを Flutter Web で読む方法**

Flutter Web では `Uri.base.queryParameters['ref']` で URL パラメータを取得できます。ただし、Firebase Hosting の rewrite ルールで SPA としてルーティングしている場合、クエリパラメータはそのまま Flutter に渡されます。`main.dart` の初期化時に一度だけ読み取って状態管理に乗せるのがシンプルです。

**② `home_tool_catalog.dart` の型安全性**

カタログエントリを単なる `Map<String, dynamic>` で管理していると IDE の補完が効かず、追加時にミスが起きやすい。`ToolCatalogEntry` クラスを定義して `const` リストにすることで、コンパイル時に型チェックが走り安全になりました。

### まとめ

今回の実装で「友達招待 → 獲得シグナル記録 → 管理者確認 UI」という招待フローが一本つながりました。Edge Function UI の自動連携パターンも確立できたので、今後新しい Edge Function を追加するコストが大幅に下がります。

友達招待システムはグロースの定番施策ですが、実装してみると「コードの一意性保証」「招待元ユーザーへの通知」「不正招待の検出」など課題も出てきます。次のセッションではこのあたりを強化していく予定です。
