## 本文下書き

### はじめに

個人開発で「自分株式会社」というFlutter Webアプリを作り続けています。メモ・タスク・成長記録を一元管理するパーソナルOS的なツールです。

今週は特に大きな変化がありました。**「AIが読めるパブリックメモ」** と **「Xへの自動投稿品質を上げるアンチスロップ制約」** の2本柱を実装しました。個人開発でここまでやるか？という自問もありつつ、全部自分のためなのでモチベーションは切れません。

---

### 実装方法

#### 1. AIが読めるパブリックメモAPI (public-memo AI-friendly payload)

これまでパブリックメモはブラウザ向けのHTMLページしか提供していませんでした。AIやボットがメモの内容を取得しようとすると、HTMLをスクレイピングするしかなかった。

今週の実装では、`format=json` または `format=txt` クエリパラメータを渡すことで、AI・ボット向けの構造化データを返すエンドポイントを追加しました。

```
GET /public-memo/{id}?format=json
→ { "title": "...", "body": "...", "tags": [...], "related": [...] }

GET /public-memo/{id}?format=txt
→ プレーンテキスト (LLMプロンプトに直接貼り付け可能)
```

さらに `search` と `related` アクションも追加。メモ同士の関連を自動探索できるようになりました。URLが `&` でエスケープされていた不具合 (`&amp;` 問題) も同時に修正しました。

Supabase Edge Function (Deno) の実装イメージ:

```typescript
// core-hub/memo.public.view
const format = req.url.searchParams.get('format') ?? 'html'
const action = req.url.searchParams.get('action') ?? 'view'

if (format === 'json') {
  return new Response(JSON.stringify(payload), {
    headers: { 'Content-Type': 'application/json' }
  })
}
if (format === 'txt') {
  return new Response(toPlainText(payload), {
    headers: { 'Content-Type': 'text/plain' }
  })
}
```

HEAD リクエストと空ボディ POST にも対応し、匿名でのメモアクション (いいね・クリップ) も正常動作するよう修正しました。

#### 2. X投稿のアンチスロップ制約 (R12 Thread Coherence)

Xへの自動投稿機能を実装してから気づいたこと: **AIが生成する文章はスロップ (slop) になりやすい**。

「〜ですね！」「素晴らしい〜」「ぜひチェックしてみてください！」といった空虚な言葉が入り込み、読む価値のない投稿になる。

対策として、今週は以下の制約をプロンプトに組み込みました:

- **Feature facts**: 具体的な機能名・数値を必ず含める
- **First-person**: 一人称 (私は/今週/実装した) で書く
- **Banned phrases**: 禁止フレーズリスト (「〜ですね」「素晴らしい」「ぜひ」等) を明示的に除外
- **Poll subject-lock**: Xポールの選択肢は投稿テーマと一致させる (R13b)
- **Relevance gate**: スレッドの各ツイートがメイントピックと関連しているかチェック
- **Feature budget**: 1スレッドで扱うトピックを最大3つに制限

結果として、投稿の実在感と読了率が改善しました (計測は `media_type` × `Media lift` のA/Bテストで進行中)。

#### 3. グロースハブの計測強化

X投稿のパフォーマンスをアプリ内で可視化するために、以下のメトリクスを追加取得するよう実装しました:

- **ブックマーク数** (save-worthy コンテンツの指標)
- **プロフィールクリック数** (フォロワー転換の前段指標)
- **URL クリック数** (アプリへの流入計測)

これらをグロースハブ画面に表示し、どの投稿タイプ・メディア種別がフォロワー獲得に繋がるかをA/Bで計測できるようにしました。

さらに、毎朝自動でXの成長レポートをまとめる **daily X briefing cron** も追加。前日の指標サマリーをアプリ内に自動生成します。

#### 4. ランディングページのX流入最適化

X経由でアプリを訪れた初回ユーザーに向けた専用CTAを表示するよう、ランディングページを修正しました。X流入かどうかは `utm_source=twitter` または Referer で判定します。

### 詰まったポイント

**`&amp;` URL問題**: Edge FunctionでHTMLを組み立てる際、URLをHTMLエスケープすると `&` が `&amp;` になってしまい、リダイレクト先URLが壊れていた。`format=txt` の返却時にも同じ問題が潜んでいたため、プレーンテキスト生成パスと JSON パスを分けることで解決しました。

**Xポールのスレッドずれ**: 自動生成ポールの選択肢がスレッドの話題とずれることが多く、エンゲージメントが下がっていた。`poll subject-lock` の実装で、ポールはスレッドの主題に関するものだけを生成するよう制約しました。

**HEAD リクエスト対応**: メモページの存在確認に HEAD リクエストを使うクローラーがいたが、Edge Function が 405 を返していた。明示的に `if (req.method === 'HEAD') return new Response(null, { status: 200 })` を追加して対応。

### まとめ

今週の実装を振り返ると、**「AIが読める」「AIが書く」「AIが計測する」** という3つのレイヤーが揃ってきた週でした。

- メモをAIが読めるAPIにした (AI読み取り)
- Xへの投稿をAIが品質制約を守りながら書く (AI書き込み)
- 投稿パフォーマンスをAIが毎朝まとめる (AI計測)

個人開発でここまでの自動化を回せるのは、Claude Code + Supabase Edge Functions の組み合わせのおかげです。来週はXのフォロワー転換率 (profile-clicks → follow) をさらに掘り下げる予定です。
