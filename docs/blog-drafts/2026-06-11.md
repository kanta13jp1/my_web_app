### 実装方法

#### Part 268: 表示モード(ミニマム/標準/フル) + マネーカレンダー

最大の目玉は **表示モードの3段階切替** です。

```dart
enum AssetDisplayMode { minimal, standard, full }
```

- **ミニマム**: 合計残高と主要指標のみ表示。ウィジェットの高さを最小化
- **標準**: 収支カード + 月次サマリー
- **フル**: マネーカレンダー含む全情報

マネーカレンダーは週単位のRow表示で、各日付セルに収支アイコンを配置。Flutter の `Table` ウィジェットを使って実装しましたが、最初は `stretch` 起因で **無限高さクラッシュ** が発生しました（Part 268b でホットフィックス）。

```dart
// NG: Table の defaultColumnWidth に FlexColumnWidth を使うと
//     ListView 内で無限高さになる
Table(
  defaultColumnWidth: const FlexColumnWidth(), // ← ここが原因
  ...
)

// OK: FixedColumnWidth または FractionColumnWidth を使う
Table(
  defaultColumnWidth: FractionColumnWidth(1 / 7), // 7列均等
  ...
)
```

`ListView` や `Column` の中に `Table` を置く場合、**高さが確定しないウィジェットを使うと無限ループ**になるのはFlutter実装の定番ハマりポイントです。

#### Part 270b: 現金マイナス残高を「使途不明金」として自動記録

現金残高がマイナスになる状況（財布の中身が追いつかない）で、減少分を自動的に「使途不明金」として記録するロジックを追加しました。

```dart
if (cashBalance < 0) {
  final unknownAmount = cashBalance.abs();
  await _recordUnknownExpense(unknownAmount);
}
```

これにより、「現金が消えた」ケースを手動入力せずに自動補完できます。家計簿アプリの地味だけど重要なUX改善です。

---

#### Part 270c: 「同額」簡易更新を前回記録ベースに緩和

資産残高を毎月更新するとき「先月と同じ金額」を入力する機会が多い。以前は厳密な比較でエラーになっていたところを、**前回記録ベースの±誤差許容** に変更しました。

```dart
// 前回記録との差分が閾値以内なら「同額」更新を許容
const threshold = 0.01; // 1円未満の誤差を無視
if ((newAmount - previousAmount).abs() < threshold) {
  return QuickUpdateResult.sameAsLast;
}
```

小さな変更ですが「毎月同じ金額でエラーが出る」というフラストレーションを解消します。

---

#### Part 271: 支払日警告から入力欄へのジャンプリンク

支払日が未入力の場合に表示される警告トーストから、**直接 支払日入力フォームへジャンプ** できるリンクを追加しました。

```dart
ScaffoldMessenger.of(context).showSnackBar(
  SnackBar(
    content: const Text('支払日が未入力です'),
    action: SnackBarAction(
      label: '入力する',
      onPressed: () => _scrollToPaymentDateField(),
    ),
  ),
);
```

これにより「警告を見てスクロールして探す」という手間がなくなります。

#### SaaS Human Approval Gate

AIが生成したアクション（自動送信・自動更新など）を実行前に人間が承認する仕組みを追加しました。

```dart
class HumanApprovalGate {
  Future<bool> requestApproval({
    required String action,
    required String description,
  }) async {
    // ダイアログで承認/拒否を選択
    return await showDialog<bool>(
      context: context,
      builder: (_) => ApprovalDialog(
        action: action,
        description: description,
      ),
    ) ?? false;
  }
}
```

AI駆動の自動化が進む中で、**重要な操作には必ず人間の確認を挟む** という設計原則（`docs/AI_DEV_PRINCIPLES.md` の deny-by-default）を実装に落とし込みました。

### 詰まったポイント

1. **Tableの無限高さ**: `FlexColumnWidth` を `ListView` 内で使うと無限高さになる。`FractionColumnWidth(1/7)` に変更で解決。

2. **表示モード状態の永続化**: `SharedPreferences` で保存すると再起動時に復元できるが、Supabase の `user_settings` テーブルと二重管理になるリスクがある。今回はローカルキャッシュを優先し、次回同期設計を予定。

3. **承認ゲートのUX**: モーダルダイアログは操作の中断感が強い。次フェーズでは Toast + アンドゥ方式への移行を検討中。
