# 個人開発者のユーザーインタビュー — 5人で見えてくる本当の課題

「作ったけど使われない」を避ける最善の方法はユーザーインタビューだ。5人に話を聞けばパターンが見える。実践した方法を公開する。

## なぜインタビューか

```
アンケート (NG): 「便利ですか？ → はい/いいえ」は何も教えてくれない
インタビュー (OK): 「どう使っているか」の行動から本当の課題が見える
```

ユーザーは自分が「何を欲しいか」を正確には言えない。でも「どういうときに困るか」なら言える。インタビューは行動の観察。

## 5人の法則

Jakob Nielsen の研究から: **5人のユーザーインタビューで85%の問題が見つかる**。

```
1人: 独自の問題 (ノイズ)
3人: パターンが見え始める
5人: 主要な問題はほぼ網羅される
10人以上: 新しい発見が激減 → ROI 低下
```

大規模調査は不要。まず5人に話を聞く。

## 質問の設計: 過去の行動を聞く

```
❌ NG: 「この機能があったら使いますか？」
   → 回答: 「使うと思います」(願望・仮定)

✅ OK: 「最後に [課題] で困ったのはいつですか？そのときどうしましたか？」
   → 回答: 実際の行動パターン
```

**5つの基本質問**:

1. 「[課題] について教えてください」(オープニング)
2. 「最後にそれで困ったのはいつですか？」(具体化)
3. 「そのときどうしましたか？」(行動)
4. 「何が一番大変でしたか？」(痛点)
5. 「今はどうやって解決していますか？」(現在の回避策)

## インタビューの進め方

```
所要時間: 30-45分
方法: Zoom / 対面 (録音 or メモ必須)
人数: 1対1 (複数はNG → 発言が偏る)
```

**やってはいけないこと**:

```
❌ 自分のプロダクトを紹介する (インタビューではなく営業になる)
❌ 「そうですよね」と共感しすぎる (誘導になる)
❌ 「でも〜の機能があれば解決できませんか？」(自分の答えを押しつける)
```

**やること**:

```
✅ 「もう少し教えてもらえますか？」で深掘り
✅ 沈黙を恐れない (考える時間)
✅ 「それはなぜですか？」を3回繰り返す (根本原因)
```

## メモのとり方

```
良いメモ: 相手の言葉そのまま (「〜が面倒で」「〜になるとつい...」)
悪いメモ: 解釈を入れる (「UX が悪い」「機能が足りない」)
```

インタビュー後 24 時間以内に整理する。記憶が薄れる前に。

## パターンの見つけ方 (5人分の分析)

```
ステップ1: 各インタビューの「困っていること」を付箋に書く
ステップ2: 似たものをグループ化 (アフィニティ図)
ステップ3: 3人以上が言ったことを「課題」として扱う
ステップ4: 1-2人だけが言ったことは保留 (まだ証拠不足)
```

5人 × 3〜5個の課題 = 最大 25 枚の付箋。グループ化すると 3〜7 個のテーマになる。

## うちのプロダクトへの適用例

AI大学 (280社の AI ツールデータベース) をリリースした後、5人にインタビューして気づいたこと:

```
ユーザーの言葉:
  「どれを選べばいいか分からない」
  「比較表がほしい」
  「実際に使った感想が知りたい」

解釈:
  機能一覧 → 比較軸 → 実体験
  単なるデータベースから「選べるツール」への転換が必要
```

この気づきが `/competitors` の比較ページ拡張に繋がった。

## インタビュー相手をどう探すか

```
個人開発者向け:
  1. dev.to / Qiita の記事コメントから声をかける
  2. X (Twitter) で「[課題] で困ってる人いますか？」
  3. Reddit / Discord の関連コミュニティ
  4. 既存ユーザーにメールで依頼 (開封率高い)

お礼: Amazon ギフト $10-20 / または無料プランアップグレード
```

断られることを恐れない。10人に声をかけて5人話してくれれば十分。

## まとめ

ユーザーインタビューは「市場調査」ではなく「共感構築」。相手の生活の中に課題がある。自分のプロダクトの話をする前に、相手の話を聞く。5人話せば、作るべきものが見える。
