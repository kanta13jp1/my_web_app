### はじめに

「自分株式会社」という個人開発アプリを Flutter Web + Supabase で育てています。コンセプトは「自分自身を株式会社のように経営する」——ノート・タスク・投資・家計・競馬予想まで、人生のあらゆる情報を一元管理するオールインワンツールです。

今週（2026-07-15〜07-21）は大きく3つの機能を実装しました。

1. **資産異常検知システム**（anomaly detection）
2. **投資ポートフォリオ履歴チャート**
3. **LPパブリックトライアル変換パス** + magic link 引継ぎ

この記事では特に実装工数が大きかった「資産異常検知システム」を中心に、設計から実装・テストまでの全プロセスを共有します。

### 実装方法

#### 1. 資産異常検知システム（第2弾D）

**全体設計**

```
anomaly_detections テーブル（Supabase PostgreSQL）
  ↓
asset.anomaly.detect Edge Function（Deno）
  ↓
daily-anomaly-scan cron（GitHub Actions / 毎日 09:00 JST）
  ↓
Flutter UI（残高不足・異常の導線表示）
```

**Step 1: DB テーブル設計**

`anomaly_detections` テーブルは次のカラム構成にしました。

```sql
CREATE TABLE anomaly_detections (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id      UUID NOT NULL REFERENCES auth.users(id),
  category     TEXT NOT NULL,
  target_month DATE NOT NULL,          -- 月次集計の対象月
  amount       NUMERIC(15,2) NOT NULL, -- 当月支出
  avg_3month   NUMERIC(15,2) NOT NULL, -- 3ヶ月平均
  deviation    NUMERIC(6,4) NOT NULL,  -- 偏差率（例: 0.35 = +35%）
  severity     TEXT NOT NULL,          -- 'low' | 'medium' | 'high'
  ai_explanation TEXT,                 -- LLM 説明（フラグ ON 時のみ）
  created_at   TIMESTAMPTZ DEFAULT now(),
  UNIQUE(user_id, category, target_month)  -- 冪等 upsert 用
);
```

`UNIQUE(user_id, category, target_month)` の複合ユニーク制約がポイントです。Edge Function を何度 invoke しても同じ月のレコードは上書き（upsert）されるため、cron の二重実行や手動再実行でデータが重複しません。

**Step 2: Edge Function — 異常検知ロジック**

`supabase/functions/asset.anomaly.detect/index.ts` を実装しました。

```typescript
const THRESHOLD = 0.20; // ±20% を異常とみなす

async function detectAnomalies(userId: string, targetMonth: Date) {
  // 当月カテゴリ別支出を集計
  const current = await fetchMonthlyByCategory(userId, targetMonth);

  // 過去3ヶ月平均を算出
  const avg3m = await fetch3MonthAvg(userId, targetMonth);

  const detections = [];
  for (const [category, amount] of Object.entries(current)) {
    const avg = avg3m[category] ?? 0;
    if (avg === 0) continue; // 新カテゴリはスキップ

    const deviation = (amount - avg) / avg; // 偏差率
    if (Math.abs(deviation) < THRESHOLD) continue;

    detections.push({
      user_id: userId,
      category,
      target_month: targetMonth.toISOString().slice(0, 10),
      amount,
      avg_3month: avg,
      deviation,
      severity: Math.abs(deviation) >= 0.5 ? 'high' : Math.abs(deviation) >= 0.35 ? 'medium' : 'low',
      ai_explanation: await maybeGenerateExplanation(category, deviation),
    });
  }

  // 冪等 upsert
  await supabase.from('anomaly_detections').upsert(detections, {
    onConflict: 'user_id,category,target_month',
  });
}
```

`ANOMALY_AI_EXPLANATION_ENABLED` 環境変数が `true` の場合のみ Claude を呼び出して自然言語説明を生成します。デフォルト OFF なので、通常稼働時はトークンコストゼロです。

テストは Deno で13本書きました。「3ヶ月データなし」「平均ゼロのカテゴリ」「ちょうど20%境界値」「upsert の冪等性」など。

**Step 3: 日次スキャン cron**

GitHub Actions でシンプルに実装。

```yaml
# .github/workflows/daily-anomaly-scan.yml
on:
  schedule:
    - cron: '0 0 * * *'  # 毎日 09:00 JST
  workflow_dispatch:       # 手動実行も可
    inputs:
      scan_all:
        type: boolean
        default: false
```

`scan_all: true` を渡すと全ユーザーをバッチ処理する「一括スキャン」モードに切り替わります。通常は直近アクティブユーザーのみスキャンするため、API コストを最小化しています。

**Step 4: Flutter UI — 残高不足の根拠表示**

残高不足エラーが出たとき、「何が足りないか」を明示した上で設定画面への導線を表示するようにしました。

```dart
if (insufficientBalanceError != null)
  AssetInsufficientBanner(
    error: insufficientBalanceError!,
    onTapSettings: () => context.push('/settings/asset'),
  )
```

ユーザーが「なぜエラーが出るのか」を理解できるようにすることで、離脱率を下げるのが狙いです。

#### 3. LP パブリックトライアル + magic link 引継ぎ

LP（ランディングページ）から「まず試す」ボタンを押すと、ログイン不要でアプリの主要機能を体験できるトライアルモードに遷移します。

今週のバグ修正の核心は「magic link でサインアップした場合にトライアル状態が消える」問題の解消。`auth.onAuthStateChange` リスナーで magic link 認証完了イベントをキャッチし、localStorage に保存しておいたトライアルデータを新規ユーザーに移行するようにしました。

### 詰まったポイント

**1. upsert の ON CONFLICT 指定**

Supabase JS クライアントの `.upsert()` は `onConflict` に複合キーを文字列で渡す必要があります（`'user_id,category,target_month'`）。最初はカンマなしで渡してエラーになりました。

**2. migration のリプレイ安全性**

開発中に「NOT NULL 制約を後から追加する」際の migration で `UPDATE` を書いていたところ、「本番では当然データがない → リプレイ時に問題なし」ですが、将来データがある状態でリプレイすると意図しない上書きが発生するリスクがあります。時間依存の `UPDATE` は migration に書かず、アプリ側で対処するようにしました。

**3. GitHub Actions cron と JST**

GitHub Actions の `schedule` は UTC 基準です。JST 09:00 にしたいなら UTC 00:00 なので `cron: '0 0 * * *'`。
