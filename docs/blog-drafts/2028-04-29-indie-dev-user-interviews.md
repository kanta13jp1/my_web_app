# 個人開発のユーザーインタビュー技法 — PMF 探索のための5つの質問

コードを書く前に話を聞く。それだけで「誰も使わないもの」を作るリスクが激減する。

## なぜインタビューが必要か

```
アンケート → 「あったらいいね」の嘘をつかれる
インタビュー → 実際の行動と感情が分かる
```

人は将来の行動を正確に予測できない。「使いますか？」には「使います」と答えても
実際には使わない。**過去の行動だけが信頼できるデータ**。

## 5 つの核心質問

### Q1: 最後に [課題] に直面したのはいつですか？

```
「最後にタスク管理で困ったのはいつですか？」
→ 最近のことを語らせる。遠い過去は記憶が薄れて役に立たない。
```

### Q2: そのとき何をしましたか？

```
「そのとき、具体的にどう対処しましたか？」
→ 実際の行動 (ツール/ワークアラウンド) を明らかにする。
   競合は「アプリ」だけではなく「Slack に送っておく」かもしれない。
```

### Q3: なぜそうしましたか？

```
「なぜ Notion ではなくメモ帳に書いたんですか？」
→ 動機と優先事項を掘り下げる。表面的な行動の奥にあるニーズが見える。
```

### Q4: 何が一番大変でしたか？

```
「そのとき何が一番ストレスでしたか？」
→ 感情レベルの問題を引き出す。ここに大きなビジネス機会がある。
```

### Q5: 今は他にどんな方法を試していますか？

```
「今はどうやって解決していますか？」
→ 競合と支払い意志額を確認する。既存解決策にお金を払っているなら本物の課題。
```

## インタビューの実施方法

```
対象: 5〜10 人で十分 (パターンが繰り返される)
時間: 30 分 / 人
場所: Zoom / Gather でリモートでも可
録画: 必ず許可を取って録画 (振り返りに不可欠)
謝礼: Amazon ギフト券 500〜1000 円 (参加率が上がる)
```

**ターゲット探し**:

```
- Twitter/X で「#個人開発 困っている」で検索
- dev.to / Qiita の読者にコメントで依頼
- 友人の友人 (直接の友人は「いいね」しか言わない)
```

## インタビュー後の分析

```
1. 録画から「問題の言葉」を抜き出す (ユーザーの言葉をそのまま使う)
2. 5 人分を並べて繰り返しパターンを見つける
3. 最も感情が強かった問題に着目する (怒り・諦め・恥)
```

**PMF の兆候**:

```
✅ インタビュー中に「それ作ってほしい！」と言われる
✅ 「いくらなら払いますか？」に具体的な金額が出る
✅ 「友人に紹介してもいい？」と自発的に言われる
```

## まとめ

```
Q1: いつ → 最近の具体的エピソードを引き出す
Q2: 何をした → 実際の行動 (競合含む) を把握
Q3: なぜ → 動機・価値観の発見
Q4: 何が大変 → 感情レベルの課題 = ビジネス機会
Q5: 今どうしてる → 支払い意思 + 競合の確認
```

「作りながら学ぶ」より「聞きながら作る」が PMF への最短ルート。
