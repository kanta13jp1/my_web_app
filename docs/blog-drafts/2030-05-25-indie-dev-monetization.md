# インディー開発者の収益化戦略 — 価格設計・サブスクリプション・フリーミアムの使い分け

プロダクトを作り上げても、収益化の設計を間違えると成長が止まる。インディー開発者が陥りやすい罠と、実データに基づいた戦略をまとめる。

## 3つの基本モデル

### 1. 買い切り (One-time Purchase)

**向く場面**: ツール系・生産性アプリ・完成度が高い成熟製品

```
例: Sketch $99/year → $9 Mac App
例: Tot (Iconfactory) $19.99 一生
例: MusicBox (iOS) $4.99
```

**メリット**:
- 購入障壁が低い (一度払えば安心)
- ユーザー信頼が高い
- 収益予測が安定 (大量販売時)

**デメリット**:
- MRR が積み上がらない
- アップデートの対価を取りにくい
- LTV が上限固定

### 2. サブスクリプション

**向く場面**: SaaS・データ更新が価値の源泉・コミュニティ型

```
例: Notion $10/month
例: Linear $8/seat/month
例: Raycast Pro $8/month
```

**メリット**:
- MRR 積み上げでキャッシュフロー安定
- 機能追加の対価を継続的に得られる
- ユーザーの継続エンゲージメントを測りやすい

**デメリット**:
- 初期転換率が低い (「また月額か」疲れ)
- Churn (解約率) 管理が必須
- 価値提供の継続義務

### 3. フリーミアム

**向く場面**: ネットワーク効果・バイラル拡散・ボリューム重視

```
例: Slack (無料→有料)
例: Figma (個人無料→チーム有料)
例: Canva (無料→Pro $15/month)
```

**メリット**:
- ユーザー獲得コストゼロに近い
- 口コミ・シェアが自然発生
- 有料転換の前に価値を実感させられる

**デメリット**:
- 無料ユーザーのコストを有料ユーザーが負担
- 転換率 2-5% が現実的上限
- 「永遠に無料で使える」期待値管理が難しい

## 価格設定の心理学

### アンカリング

```
❌ 1プラン: ¥980/月
✅ 3プラン:
  - Basic: ¥480/月 (機能制限あり)
  - Pro: ¥980/月  ← 大多数がここを選ぶ
  - Team: ¥2,980/月 (アンカー: Proを安く見せる)
```

中間プランを際立たせるデコイ効果。右端プランはアンカーで存在感を持たせる。

### 年払い割引

```
月払い: ¥980/月 = ¥11,760/年
年払い: ¥8,820/年 (25%割引) → 先払いキャッシュ + Churn 低減
```

年払いへの誘導で Churn を年1回に抑制できる。SaaS の生命線。

### 価格の端数

```
❌ ¥1,000/月
✅ ¥980/月  (左端数字効果: 9 vs 1)
✅ $9.99/month (英語圏標準)
```

## Churn 削減戦略

```
月間 Churn 率 5% → 年間 Churn 46%
月間 Churn 率 2% → 年間 Churn 21%
```

Churn を2%下げると LTV が約2倍になる。

### オンボーディング最適化

```dart
// Day 0: Welcome + 最初の成功体験まで案内
// Day 3: 使い方ヒント (機能ディスカバリー)
// Day 7: 価値確認 (どれだけ使ったか可視化)
// Day 14: アップグレード提案 (使用量 70%超時)
// Day 28: 解約前インターセプト (使用低下検知)
```

オンボーディングで価値を実感させることが最大の Churn 対策。

### Pause instead of Cancel

```
解約フロー:
[解約する] → [1ヶ月停止する] ← これを先に提示
```

「停止」オプションで解約率を20-30%削減した事例多数。

## インディー開発者向け現実的ロードマップ

### Phase 0: 月0円 (0-3ヶ月)
無料で配り、10人の熱狂ユーザーを見つける。お金より学びが価値。

### Phase 1: 月1万円 (3-6ヶ月)
買い切り $9 か月額 ¥500 で、支払う意志のあるユーザーを確認。

### Phase 2: 月10万円 (6-18ヶ月)
価格を2-3倍にする実験。ユーザー数より単価を上げる方が早い。

### Phase 3: 月100万円 (18ヶ月-)
サブスクに移行 or B2B プランを追加。LTV を最大化する設計に集中。

## 計測すべき指標

```
MRR (Monthly Recurring Revenue)
ARR = MRR × 12
Churn Rate = 解約数 / 期初ユーザー数
LTV = ARPU / Churn Rate
CAC (Customer Acquisition Cost)
LTV / CAC > 3 が健全なライン
```

## まとめ

| モデル | おすすめ段階 | 最重要指標 |
|--------|------------|----------|
| 買い切り | 初期 (検証フェーズ) | 購入転換率 |
| フリーミアム | 成長期 (拡散重視) | 有料転換率 |
| サブスク | 成熟期 (MRR積み上げ) | Churn Rate |

最初から「完璧な収益化モデル」を選ぶ必要はない。**買い切りで始めてサブスクへ移行**するパターンが多くのインディーアプリの王道。ユーザーの声を聞きながら段階的に設計する。
