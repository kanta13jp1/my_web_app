# 個人開発者のコンテンツマーケティング — ブログで月 1,000 ユーザーを獲得する

広告費ゼロ。コンテンツだけで見込みユーザーを集める戦略。

## コンテンツ戦略の基本構造

```
検索ボリューム × 転換率 = 登録者数

例:
  月間 5,000 PV × 転換率 2% = 月 100 登録
  月間 50,000 PV × 転換率 2% = 月 1,000 登録

PV は SEO × 記事数 × SNS シェアの積
転換率はランディングページと CTA の最適化
```

## トピック選定: 検索意図で分類

```
情報収集型 → 「Flutter Riverpod とは」「Supabase 料金 比較」
  → ブランド認知向上 / 購買意欲は低い

解決型   → 「Flutter error: setState after dispose 解決」
  → 高い転換率 / SEO で狙いやすい

比較型   → 「Supabase vs Firebase どちらがいいか」
  → 意思決定フェーズ / 自社製品比較記事に最適
```

**個人開発に最適なトピック**:

```dart
// ターゲット像から逆算
// ユーザー = Flutter + Supabase を使う個人開発者

final topics = [
  '自分が詰まった問題の解決策',    // 解決型 / 検索ボリューム確実
  '使っている技術スタックの Tips', // 情報収集型 / 認知拡大
  '自分のプロダクトの機能紹介',    // 比較型 / 転換率高
  '失敗談と学び',                  // SNS シェア率高 / 共感型
];
```

## dev.to で検索流入を作る SEO Tips

```markdown
# タイトル設計 (検索ボリュームを意識)
❌ 「Flutter の便利な Tips」
✅ 「Flutter WebView: URL スキームでアプリ連携する方法」

# 冒頭 3 行で検索意図を満たす
読者は「この記事で問題が解決するか」を 10 秒で判断する。
結論を最初に書く。

# コードスニペット必須
エンジニア向け記事は実装例がないと離脱率 2 倍。

# タグ 4 個 (dev.to の上限)
具体的な技術 > 汎用カテゴリ の順に並べる
```

## 投稿頻度と累積効果

```
週 1 本ペース:
  3 ヶ月後: 12 本 → 月 500 PV
  6 ヶ月後: 24 本 → 月 2,000 PV
  1 年後:   52 本 → 月 8,000 PV (SEO は複利で効く)

コツ: 同じトピックを深掘りするシリーズ記事は
  単発記事より 3 倍の被リンクを獲得しやすい
```

## まとめ

```
トピック選定 → 解決型 (詰まった問題) + 比較型 (競合比較) 優先
SEO         → タイトルに検索キーワード / 冒頭で結論 / コードスニペット必須
頻度        → 週 1 本 × 1 年 = 月 8,000 PV 圏内 (SEO の複利効果)
転換率      → CTA を記事末に 1 つだけ / LP の読み込み速度も重要
```

コンテンツは「作って終わり」ではなく資産。1 年後も検索から流入し続ける。
