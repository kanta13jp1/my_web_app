### 実装方法

#### 1. AI使用量ゲートの設計思想

Supabase Edge Functions (Deno) の `ai-hub` 関数内に `usage_gate.ts` として純粋関数でロジックを切り出しました。

```typescript
// supabase/functions/ai-hub/usage_gate.ts

export type UsagePlan = "free" | "pro";

export interface UsageGateResult {
  allowed: boolean;
  reason?: string;
  remaining?: number;
}

export async function decideUsage(
  userId: string,
  plan: UsagePlan,
  currentMonthCount: number
): Promise<UsageGateResult> {
  // pro は無制限
  if (plan === "pro") {
    return { allowed: true };
  }

  // free は 30回/月 上限
  const FREE_LIMIT = 30;
  if (currentMonthCount >= FREE_LIMIT) {
    return {
      allowed: false,
      reason: "月間無料AI利用回数(30回)に達しました。Proプランへアップグレードしてください。",
      remaining: 0,
    };
  }

  return {
    allowed: true,
    remaining: FREE_LIMIT - currentMonthCount,
  };
}
```

**ポイント**: フェイルオープン設計 — DBエラー等でゲート判定が落ちた場合でも、ユーザー体験を最優先にして `allowed: true` で通します。課金ロジックは収益に直結するため、バグによる機会損失より「通しすぎ」の方が安全という判断です。

#### 5. Stripe env値の `.trim()` 防衛

```typescript
// Edge Function 内
const stripeKey = Deno.env.get("STRIPE_SECRET_KEY")?.trim() ?? "";
const priceId = Deno.env.get("STRIPE_PRICE_ID_PRO")?.trim() ?? "";
```

Supabase のダッシュボードから環境変数をコピペすると、末尾に空白が混入することがあります。`No such price` エラーの温床になるため、`.trim()` を必ず付けるようにしました。本番移行前に気づけたのはラッキーでした。

#### Stripe 返却URLのタイポ

#### 資産管理ページの毎秒再ビルド問題

`initState` で `Timer.periodic(Duration(seconds: 1), ...)` を使って時刻を更新していたのですが、このタイマーが `setState(_now = DateTime.now())` を呼ぶことでページ全体の再ビルドが毎秒発生していました。

実際には「日付(M/d)」しか表示していないので、**日付が変わった時だけ再描画**する実装に変更しました。

```dart
Timer.periodic(const Duration(seconds: 1), (timer) {
  final newNow = DateTime.now();
  // 月次処理などの評価は毎tick行う
  _maybeDetectSalaryDeposit(newNow);

  // UIの再描画は日付変更時のみ
  if (newNow.day != _now.day || newNow.month != _now.month) {
    setState(() => _now = newNow);
  } else {
    _now = newNow; // setState不要 — 表示変化なし
  }
});
```

idle時の毎秒フル再ビルド + `buildWorkbook` 再計算がほぼゼロになり、操作時のカクつきが改善されました。
