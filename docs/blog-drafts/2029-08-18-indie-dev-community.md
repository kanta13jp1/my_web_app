# インディー開発者のコミュニティ構築 — ユーザーを仲間にする戦略

インディー SaaS にとって「コミュニティ」は最強の差別化要因です。大手が真似できないのは、創業者が直接ユーザーと話せる規模感だけが持てる「熱量」だからです。

## なぜコミュニティが重要か

```
広告: CPA が毎年上がる
SEO: Google アップデートで一夜にして崩壊
コミュニティ: ユーザーが次のユーザーを連れてくる (CAC = 0)
```

コミュニティを持つ SaaS は解約率が平均 30% 低いというデータがあります。理由は「プロダクトを離れるとコミュニティも失う」から。

## フェーズ別コミュニティ設計

### フェーズ 1: 0→100人 (個別対話期)

```
目標: 熱烈な初期ユーザー 10 人を見つける
手段:
  - Twitter/X でビルドログを発信
  - ProductHunt の Coming Soon で事前登録収集
  - 競合のレビューサイト (G2 / Capterra) で不満ユーザーをDM
  - Reddit /r/<ニッチ> で問題を共感する投稿
戒め: Slack を作るのは早い。Discord はもっと早い。
     まず個別 DM → メール → 小グループ の順。
```

### フェーズ 2: 100→1,000人 (コンテンツ期)

```dart
// "Changelog + Ask" パターン
// 毎週: 今週追加した機能 + ユーザーに1つ質問

final changelog = Changelog(
  version: '0.42',
  features: ['タスクの並び替え', 'ダークモード対応'],
  ask: 'この2つのうち、どちらが先に欲しかったですか？',
);
```

ポイントは必ず「1つの質問」を入れること。返信率が 5 倍になります。

### フェーズ 3: 1,000人→ (自走期)

```
コミュニティリーダーを育てる:
  - Power User を特定 (利用頻度 + 投稿数)
  - 非公式 Beta テスター に任命
  - 「アンバサダー」プログラムで紹介インセンティブ
  - User-Generated Content (使い方 Tips) を公式でシェア
```

## プラットフォーム選定マトリクス

| プラットフォーム | 強み | 弱み | 推奨フェーズ |
|---------------|------|------|----------|
| X (Twitter) | 発見性 ◎ / リアルタイム | 流れやすい | 全フェーズ |
| Discord | リアルタイム雑談 | 検索性 × | 100人〜 |
| Slack Connect | B2B 感 / 通知開封率高 | 有料制限 | 企業向け |
| Reddit | 長期 SEO ◎ | 匿名 / 燃えやすい | 発見チャネル |
| Circle | コース+コミュニティ統合 | 有料 | コンテンツ系 |
| Notion | 非同期 / ナレッジ蓄積 | 双方向性 × | ヘルプ文書 |

**推奨**: 最初は **X + メールリスト** のみ。100人超えてから Discord or Slack を追加。

## コミュニティ活性化のトリガー設計

```sql
-- 活性化トリガー例 (自動メール)
SELECT user_id
FROM user_events
WHERE event_type = 'task_completed'
  AND created_at > now() - interval '24 hours'
  AND user_id NOT IN (
    SELECT user_id FROM community_posts WHERE created_at > now() - interval '7 days'
  )
LIMIT 100;
-- → 「タスク完了おめでとう！コミュニティに結果を共有しませんか？」
```

## NG パターン集

```
❌ 自分だけが投稿するコミュニティ
   → ユーザーは「広告チャネル」と判断してすぐ離れる

❌ 質問に 48h 以上返信しない
   → 公開の無視は信頼を瞬時に破壊する

❌ フィードバックを無視して機能追加だけ発表
   → 「自分たちの声は届かない」と感じさせる

❌ コミュニティを CRM 代わりに使う
   → セールス色が強まると離脱率上昇

✅ 毎週 1 回は創業者本人が投稿する
✅ ユーザーの成功事例を積極的にシェア
✅ ロードマップをコミュニティで投票
✅ バグ報告に「ありがとう」を必ず言う
```

## 測定指標

```
DAU / MAU 比率: 20%+ が目標 (健全なコミュニティ)
投稿者比率: 全メンバーの 1-9-90 法則
  - 1%: 活発な投稿者
  - 9%: コメンター
  - 90%: 読むだけ (ロムりょ)
NPS: コミュニティ参加者 vs 非参加者を比較
解約率: コミュニティ参加者の方が低いはずなので必ず計測
```

コミュニティを作ってから、口コミ経由の新規登録が月間 40% を占めるようになりました。
