## 本文下書き

### はじめに

Flutter Web + Supabase で「自分株式会社」という個人向け資産・時間管理 SaaS を開発しています。本番 URL は https://my-web-app-b67f4.web.app/ です。

このプロダクトは「AI をフル活用してインディー開発者が大企業と戦えるか」という実験でもあります。今週は**Karpathy 4サイクル**（Ingest → Compile → Query → Lint）の定常稼働と、AI大学コンテンツの完全自動更新が大きな節目を迎えました。

---

### 実装方法

#### 1. Karpathy 4サイクル — wiki compile の定常稼働

Andrej Karpathy が提唱する「第二の脳」構築サイクルをプロダクト開発に応用しています。

| サイクル | 実装 | 状態 |
|---|---|---|
| Ingest | `scripts/memory_ingest.py` | ✅ 定常稼働 |
| Compile | `scripts/wiki_compile.py` | ✅ 毎日自動実行 |
| Query | `notebooklm` CLI | ✅ ゼロトークンリサーチ |
| Lint | `scripts/knowledge_vault_lint.py` | ✅ 定常稼働 |

今週は **wiki compile（Karpathy Compile cycle）** が正常実行され、`docs/concepts/` と `docs/INDEX.md` が自動生成されました。開発中に蓄積した知識が自動的に整理・インデックス化される仕組みが完全に定着しています。

#### 2. AI大学コンテンツ自動更新

「自分株式会社」の主要機能のひとつである **AI大学** では、最新の AI ツール・サービス情報を GitHub Actions で毎日自動更新しています。

今週だけで **10回以上** の自動コミットが実行され、コンテンツが常に最新状態に保たれています。手動作業ゼロで情報鮮度を維持できるのは、個人開発者にとって大きなアドバンテージです。

実装のポイント：
- GitHub Actions のスケジュール実行（cron）でコンテンツ更新 API を定期呼び出し
- Supabase Edge Functions で AI サービス情報を取得・整形
- コンテンツに変化があった場合のみコミット（不要な差分を防止）

#### 3. CI/CDコスト監査の自動化

今週の重要な取り組みのひとつが **CI/CD コスト監査の自動化** です。

GitHub Actions の実行コストを定期的に可視化し、無駄なワークフロー実行を検知する仕組みを構築しました。個人開発者がエンタープライズ級の自動化を維持するには、コスト管理が欠かせません。

監査で確認している項目：
- ワークフロー別の実行時間・頻度
- 並列実行の最適化機会
- キャッシュ効果の測定
- 月次コスト予測

#### 4. インフラヘルスチェック × 日次レポート

本番環境 https://my-web-app-b67f4.web.app/ の稼働状況を **毎時チェック** し、問題があれば即座にアラートする仕組みが定着しています。

```
毎時: インフラヘルスチェック（応答時間・エラー率）
毎日: 日次レポート（KPI・ユーザー動向・コスト）
毎日: CS チェック（カスタマーサポート対応要件の自動判定）
```

これらはすべて GitHub Actions で実行されており、開発者（私）が何もしなくても監視が継続されています。

### 詰まったポイント

#### wiki compile と memory ingest の競合

最初の実装では、`memory_ingest.py` と `wiki_compile.py` が同時実行されると `docs/INDEX.md` の書き込みが競合する問題が発生しました。

解決策として：
- GitHub Actions のジョブ依存関係（`needs:`）で順序を保証
- ファイルロック機構を Python で実装
- 競合が検知された場合は次の実行サイクルにリトライ

#### AI大学コンテンツ更新の冪等性

毎日複数回実行される自動更新で、同じコンテンツに対して重複コミットが発生する問題がありました。

```python
# コンテンツのハッシュ値を比較してから更新判定
import hashlib
current_hash = hashlib.sha256(content.encode()).hexdigest()
if current_hash != stored_hash:
    # 更新処理
    update_content(content)
    store_hash(current_hash)
```

このハッシュ比較により、不要なコミットを防止しつつ本当に変化のあったコンテンツのみを更新できるようになりました。
