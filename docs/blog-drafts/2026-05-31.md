## 本文下書き

### はじめに

「自分株式会社」は Flutter Web + Supabase で構築した個人用統合管理アプリです。メモ・資産管理・AI大学・競合分析など30以上の機能を一つのアプリに集約し、Claude Code で毎日開発を続けています。

今週の主要な実装は **資産管理AI分析履歴の永続化 (feat: persist asset AI analysis history)** です。これまで資産管理ページで AI によるポートフォリオ分析を実行できましたが、分析結果はセッション内限りで消えてしまっていました。今回、Supabase PostgreSQL に分析履歴テーブルを作成し、Flutter から履歴を保存・参照できるようにしました。

加えて、GitHub Actions のCI最適化として **docs-onlyプッシュでは高コストなパイプラインをスキップする仕組み** も導入しました。毎日大量の自動コミットが走るリポジトリならではの悩みを解決した実装です。

### 実装方法

#### 1. Supabaseマイグレーション: AI分析履歴テーブル

```sql
-- supabase/migrations/create_asset_management_ai_analysis_history.sql
CREATE TABLE asset_management_ai_analysis_history (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  analysis_type TEXT NOT NULL,
  prompt TEXT,
  result_json JSONB,
  model_used TEXT,
  created_at TIMESTAMPTZ DEFAULT now()
);

ALTER TABLE asset_management_ai_analysis_history ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Users can manage own history"
  ON asset_management_ai_analysis_history
  FOR ALL USING (auth.uid() = user_id);
```

ポイントは **JSONB型** での結果保存です。Claude APIのレスポンスはテキストですが、JSONBにすることで将来的に PostgreSQL の JSON 演算子を使ったクエリが可能になります。

#### 2. Dartモデルクラス

```dart
class AssetManagementAiAnalysisHistoryEntry {
  final String id;
  final String userId;
  final String analysisType;
  final String? prompt;
  final Map<String, dynamic>? resultJson;
  final String? modelUsed;
  final DateTime createdAt;

  AssetManagementAiAnalysisHistoryEntry({
    required this.id,
    required this.userId,
    required this.analysisType,
    this.prompt,
    this.resultJson,
    this.modelUsed,
    required this.createdAt,
  });

  factory AssetManagementAiAnalysisHistoryEntry.fromJson(Map<String, dynamic> json) {
    return AssetManagementAiAnalysisHistoryEntry(
      id: json['id'],
      userId: json['user_id'],
      analysisType: json['analysis_type'],
      prompt: json['prompt'],
      resultJson: json['result_json'],
      modelUsed: json['model_used'],
      createdAt: DateTime.parse(json['created_at']),
    );
  }
}
```

#### 3. Serviceクラス: 保存と取得

```dart
class AssetManagementAiAnalysisHistoryService {
  final SupabaseClient _client;

  Future<void> saveAnalysis({
    required String analysisType,
    String? prompt,
    required Map<String, dynamic> resultJson,
    String? modelUsed,
  }) async {
    await _client.from('asset_management_ai_analysis_history').insert({
      'user_id': _client.auth.currentUser!.id,
      'analysis_type': analysisType,
      'prompt': prompt,
      'result_json': resultJson,
      'model_used': modelUsed ?? 'claude-sonnet-4-6',
    });
  }

  Future<List<AssetManagementAiAnalysisHistoryEntry>> fetchHistory({
    int limit = 20,
  }) async {
    final data = await _client
        .from('asset_management_ai_analysis_history')
        .select()
        .order('created_at', ascending: false)
        .limit(limit);
    return data.map(AssetManagementAiAnalysisHistoryEntry.fromJson).toList();
  }
}
```

#### 4. CI最適化: docs-onlyプッシュのスキップ

```yaml
# .github/workflows/ci.yml
on:
  push:
    paths-ignore:
      - 'docs/**'
      - '**.md'
      - 'memory/**'
```

自分株式会社では毎時間 GHA から自動コミットが走ります (ヘルスモニター/AI大学更新/競合レポート等)。これらのほとんどは `docs/` や `memory/` への書き込みのため、CI の Flutter ビルドやテストを走らせる必要がありません。`paths-ignore` を追加することで**月間数百回分のランナー時間を節約**できます。

### 詰まったポイント

**JSONB vs TEXT の選択**

当初 `result_text TEXT` でシンプルに保存しようとしましたが、後から「分析タイプ別の集計」「特定フィールドの全文検索」などのニーズが生まれることを見越してJSONBにしました。Supabase のダッシュボードから `result_json->>'summary'` のようなクエリが直接使えるのは大きな利点です。

**Flutter での非同期状態管理**

履歴パネルを `StatefulWidget` で実装したところ、`initState` での `async` 呼び出しがうまく機能しないケースがありました。`WidgetsBinding.instance.addPostFrameCallback` でフレーム後に実行するよう変更して解決しました。

**CI paths-ignore のグロブ注意点**

`docs/**` だけでなく `**.md` も必要なことに気づくのに少し時間がかかりました。`docs/` 外の Markdown ファイル (CLAUDE.md など) も対象にするためです。
