### Edge Function 量産のポイント

**1. Deno + Supabase の標準テンプレートを使い回す**

```typescript
// supabase/functions/_shared/cors.ts
export const corsHeaders = {
  'Access-Control-Allow-Origin': '*',
  'Access-Control-Allow-Headers': 'authorization, x-client-info, apikey, content-type',
};
```

全 Function がこの共通ヘッダーを import するだけで CORS 対応完了。`OPTIONS` ハンドリングも定型コードなので、ビジネスロジックに集中できます。

**2. サービスロールキーで RLS をバイパス**

Edge Function は Supabase の `service_role` キーで動作するため、Row Level Security の設定に依存せず管理者操作が可能。Claude Code (AI) から自動実行される CS チェックや日次レポートでは特に重要です。

**3. deno lint を CI に組み込む**

`.github/workflows/daily-report.yml` などで `deno lint --config deno.json` を常時実行。ローカルでも変更後に手動チェックを徹底することで、積み上げ式でも品質を担保できます。

### 通知センターUI — dart:html 廃止対応

Flutter 3.x 以降、`dart:html` は非推奨（Web 以外のプラットフォームとの互換性問題が理由）。今回の通知センター実装で `window.localStorage` アクセスに `dart:html` を使おうとしてコンパイルエラーが発生しました。

**解決策：`universal_html` → `package:web` への移行**

```dart
// Before (deprecated)
import 'dart:html' as html;
html.window.localStorage['key'] = value;

// After (Flutter 3.x 推奨)
import 'package:web/web.dart' as web;
web.window.localStorage.setItem('key', value);
```

`pubspec.yaml` に `web: ^1.0.0` を追加するだけで移行完了。`flutter analyze` のエラーもゼロに戻りました。

### 通知センターの実装概要

```dart
// lib/pages/notification_center_page.dart (抜粋)
class NotificationCenterPage extends StatefulWidget { ... }

class _NotificationCenterPageState extends State<NotificationCenterPage> {
  List<AppNotification> _notifications = [];

  @override
  void initState() {
    super.initState();
    _loadNotifications();
  }

  Future<void> _loadNotifications() async {
    final response = await supabase
        .from('notifications')
        .select()
        .order('created_at', ascending: false)
        .limit(50);
    setState(() => _notifications = response.map(AppNotification.fromJson).toList());
  }
}
```

Supabase の `notifications` テーブルから最新50件をフェッチし、既読管理は `notification-center` Edge Function 経由で行います。セキュリティ上、mark-as-read は RLS + Edge Function による所有者確認を実施（Issue #254 対応済み）。

### 詰まったポイント

**migration の重複バージョン問題**

Edge Function を大量追加するたびに migration ファイルも増えていくのですが、複数セッション並行作業でバージョン番号が衝突。`000094_xxx.sql` と別の `000094_yyy.sql` が共存してしまい、Supabase の migration 適用が失敗する事態に。

対処法：重複したファイルを `000130_yyy.sql` にリネームし、`ALTER TABLE` 文が存在する場合はそちらも更新。衝突検知は `ls supabase/migrations/ | sort | uniq -d` で即座に特定できます。

**CS チェック Schedule のトリガー schema 修正**

`schedule-task-monitor` Edge Function で `task_id` カラムが存在しないエラー。`schedule_executions` テーブルに `task_name TEXT` カラムを追加する migration を追記して解消しました。
