## 本文下書き

### はじめに

「自分株式会社」というコンセプトで、自分自身の収支・資産・負債をSaaSのように管理するFlutter Webアプリを個人開発しています。今週は **資産管理ページ（Asset Management）** のUX改善を中心に、Claude Opus 4.8との協働でいくつかの機能追加・バグ修正・CI/CD最適化を進めました。

本記事では実装の経緯・詰まったポイント・AI駆動開発の知見を共有します。

---

### 実装内容

#### 1. 収入¥0 時に手入力収入導線（CTA）を追加 (#3599)

**課題**: アプリの「収支サマリー」カードで、当月の収入が¥0のときにそのまま「収入¥0」と表示されると、ユーザーが常に赤字に見えてしまう問題がありました。④収支の記録カードには「収入」種別があるのですが、デフォルトが「支出」のため、手入力できることに気づきにくかったのです。

**解決策**: 当月サイクルの収入が¥0の場合のみ「収入を記録する」というCTAボタンを表示するようにしました。タップすると④収支カードへスクロールし、種別を「収入」にプリセットした状態で手入力を促します。

```dart
// 収入¥0のときのみCTAを表示
if (totalIncome == 0) {
  return AssetIncomeCtaWidget(
    onTap: () => _scrollToIncomeEntry(presetType: '収入'),
  );
}
```

Widgetスモークテストも2件追加（CTA表示確認 / 収入有で非表示確認）し、リグレッションを防ぎます。

---

#### 2. カード請求負債の確認手順をカード利用明細ベースへ変更 (#3617)

**課題**: `includedInCard`（カード請求にまとめて支払い）の負債は、実際の引き落としがカード締め日にまとまります。従来のガイドは「銀行口座の入出金明細で個別額を探す」という手順になっており、実態と乖離していて誤誘導していました。

**解決策**: `buildBaseGuide` / `buildAiPrompt` に任意の `billingCardName` を追加し、指定時は「カード利用明細を確認する」手順へ分岐するロジックを実装。直接引き落とし負債は従来手順のまま（振る舞い不変）。

```dart
String buildBaseGuide({String? billingCardName}) {
  if (billingCardName != null && billingCardName.isNotEmpty) {
    return _buildCardStatementGuide(billingCardName);
  }
  return _buildBankGuide();
}
```

純粋単体テスト（カード手順 / 金額欠落 / 空billingCardNameフォールバック）を追加してロジックを保護しました。

---

#### 3. アコムショッピング枠のAnthropic分を現金支出から除外 (#3620)

**課題**: 内蔵の「Anthropicサブスク（アコムショッピング返済）」¥40,000を現金支出として計上していましたが、実態はアコムショッピング枠経由の購入であり現金返済はしません。これにより現金の二重計上と期限超過誤アラートが発生していました。

**解決策**: 当該エントリを `includedInBillingAccount: true` に変更し、アコムショッピング請求に含む扱いへ。使用可能額・未払い合計からも除外し、アコム最低返済のみが現金支出として残る状態に整理しました。

---

#### 4. CI/CD最適化: cancel-in-progress: true (#3621)

`wbs-ai-review` と `feature-review` ワークフローに `cancel-in-progress: true` を追加。PRへの連続プッシュで古いCIランが無駄に動き続ける問題を解消し、コストと待ち時間を削減しました。

---

### 詰まったポイント

**1. テストでの Widget Key 付与**: 種別ドロップダウンに `Key` を付与しないとテストから要素を特定できず、`finder.text()` で誤マッチが起きました。Flutter Widgetテストでは積極的に `Key` を使うのが鉄則です。

**2. AI との「コンテキスト共有」の大切さ**: Claude Opus 4.8に「アコムショッピング枠のAnthropic分」の修正を依頼した際、最初はドメイン知識（アコムの仕組み、includedInBillingAccountの意味）を共有せずに依頼してしまい、엉뚱な修正提案が来ました。AIに実装させるには「なぜそうなっているか」のコンテキストを先に渡すことが重要です。

**3. CI cancel-in-progress の注意点**: `cancel-in-progress: true` を設定すると、マージ直前のCI確認が途中でキャンセルされるリスクがあります。`github.event_name == 'push' && github.ref != 'refs/heads/main'` 条件でmainへのプッシュは除外する配慮が必要です。

### まとめ

今週の自分株式会社開発は、「資産管理ページのUX正確性向上」がテーマでした。

- **UX改善**: 収入¥0時のCTA追加でユーザーが迷わず手入力できる導線を整備
- **データ正確性**: カード請求フローの誤誘導を修正し、二重計上バグを解消
- **CI/CD効率化**: cancel-in-progress導入でCI待ち時間とコストを削減

すべての実装にClaude Opus 4.8が Co-author として参加。設計議論からコード生成・テスト追加まで一気通貫でAIと協働するスタイルが定着してきました。

個人開発でもこれだけの品質・速度で開発できるのがAI駆動開発の醍醐味です。
