## 本文下書き (約2000字)

### はじめに

個人開発アプリ「自分株式会社」に、今週大きな機能を追加しました。

**給与明細（PDF）をアップロードするだけで、今月の可処分所得を自動計算し、AI が節約・支出改善のアクションを提案する** という仕組みです。

「毎月の給与は分かっているのに、いつの間にかお金が消えている」という感覚、ありませんか？  
その正体は固定費・変動費の把握不足と、可処分所得の計算が曖昧なことにあります。  
本機能はその課題を、Claude AI + Supabase Edge Functions + Flutter Web で解決します。

---

### 実装した機能の全体像

今回 PR #3008 でマージした機能は大きく3つのモジュールに分かれます。

#### 1. Payslip Ingestion (給与明細OCR解析)

`supabase/functions/ai-hub/payslip_ingestion.ts`

- ユーザーが Supabase Storage の `payslips` バケットに PDF をアップロード
- Edge Function が PDF を読み込み、Claude AI に OCR 解析を依頼
- 解析結果（総支給額 / 手取り / 社会保険料 / 各種控除）を `payslips` テーブルに保存
- 信頼度スコア (`confidence`) が低い場合は `needs_review` ステータスで保存し、手動確認フラグを立てる

```typescript
export type ParsedPayslip = {
  pay_date: string | null;
  company_name: string;
  gross_amount: number;     // 総支給額
  net_amount: number;       // 手取り額
  taxable_amount: number | null;
  social_insurance_total: number | null;
  deductions: UnknownRecord;  // 控除明細
  earnings: UnknownRecord;    // 支給明細
  attendance: UnknownRecord;  // 出勤情報
  confidence: number;         // AI解析信頼度 0-1
  parsed_by: string;          // 使用モデル名
};
```

#### 2. Expense AI (AI支出分類)

`supabase/functions/ai-hub/expense_ai.ts`

- 家計簿に登録された支出を AI が自動でカテゴリ分類
- 「固定費」「変動費（削減可能）」「投資・自己研鑽」等のラベルを付与
- 分類結果を元に月次の支出傾向レポートを生成

#### 3. Disposable Balance Calculator (可処分所得計算)

`supabase/functions/ai-hub/disposable_balance.ts`

- 給与明細データ + 支出データを統合して「今月残り使える金額」を計算
- 次の給料日まであと何日か、1日あたりいくら使えるかを可視化
- AI がアクションプランを優先度順に最大5件提案

```typescript
export type DisposableBalanceResult = {
  status: "deterministic" | "ai_actions_generated";
  as_of_date: string;
  next_payday: string;
  // ... アクションリスト付き
};
```

### 詰まったポイント

#### PDF の Blob 処理

Supabase Storage から PDF を取得する際、`download()` の返り値が `Blob | ArrayBuffer | Uint8Array` の Union 型であることへの対応が必要でした。  
Deno (Edge Functions の実行環境) では `Blob.text()` が使えないケースがあるため、`ArrayBuffer → Uint8Array → TextDecoder` という変換チェーンで安定化しました。

#### AI 解析の信頼度管理

給与明細のフォーマットは会社ごとに異なります。Claude に解析させても、項目名が微妙に違ったり金額の位置がずれたりすることがあります。  
そこで `confidence` スコアを返すようにプロンプトを設計し、0.8 未満の場合は `needs_review` フラグを立てて UI 側でユーザーに確認を促す UX にしました。

#### RLS (Row Level Security) の設計

`payslips` テーブルには機密性の高い給与情報が入るため、RLS ポリシーを厳密に設計しました。  
Storage の `payslips` バケットも同様に、`auth.uid()` と一致するフォルダのみアクセス可能にしています。

```sql
create policy "Users can upload their own payslips"
  on storage.objects for insert
  with check (
    bucket_id = 'payslips'
    and (storage.foldername(name))[1] = auth.uid()::text
  );
```

### Flutter UI 側の実装

`lib/pages/asset_management_page.dart` と `lib/services/disposable_balance_service.dart` で、以下の UI を実装しました。

- PDF アップロードボタン（ファイルピッカー統合）
- 解析状況のプログレスインジケーター
- 可処分所得のサマリーカード（今月の残額 / 1日あたり予算）
- AI アクションプランのリスト表示
- 支出カテゴリ別グラフ
