### はじめに

「自分株式会社」は、個人の資産・収支・学習・健康・仕事を一元管理する Flutter Web アプリです。
バックエンドは Supabase (PostgreSQL + Edge Functions / Deno)、ホスティングは Firebase Hosting、
CI/CD は GitHub Actions で自動化しています。

今週は **資産管理機能の大幅強化** と **IQ テストの仮説検証ループ** を同時並行で進めました。
AI 駆動開発 (Claude Code / Codex) を使った開発スタイルで、週に 9 件の feat/fix をリリースできた
実践ログを共有します。

### 実装方法

#### 1. 「今日やること」ToDoを資産管理に統合 (#4418)

資産管理画面に **ToDoブロック** を追加し、その入力欄には「細木数子 AI」キャラクターが
コーチングメッセージを生成する仕組みを組み込みました。

```dart
// Edge Function 経由で細木数子スタイルのアドバイスを取得
final advice = await supabase.functions.invoke(
  'hosoki-advisor',
  body: {'context': todoText, 'date': today},
);
```

細木数子 AI とは、故・細木数子氏の六星占術スタイルを模倣した
キャラクター AI プロンプトで、運勢的な視点からその日の行動を後押しします。
Flutter の `AnimatedContainer` でメッセージが滑らかにフェードインする UX にしました。

#### 2. 返済報告カードの画像を X に添付 (#4416)

毎月の返済記録を可視化したカードを **Supabase 公開バケット** にアップロードし、
`mediaUrl` として X (旧 Twitter) 投稿 API に渡す機能を追加しました。

```
Supabase Storage (public bucket)
  └─ repayment-cards/2026-07-30.png
        ↓ URL 取得
X API v2 (media upload → tweet)
```

画像付きツイートは文字のみと比べてエンゲージメントが約 2〜3 倍になるとされており、
資産透明化と広報を同時に行えます。

#### 3. 二重計上バグの根本解消 (#4415)

`固定額 ¥80,000` を コード内にハードコードしていた資金移動ロジックが原因で、
毎月「幻の赤字」が表示されていた問題を解消しました。

```sql
-- 修正前: 毎月自動で ¥80,000 の transfer レコードが生成されていた
-- 修正後: transfer は UI から明示的に入力したときのみ生成
DELETE FROM scheduled_transfers WHERE type = 'hardcoded_80k';
```

ハードコード値はバグの温床。Supabase の RLS (Row Level Security) と組み合わせ、
ユーザーが明示的に設定した値のみを信頼する設計に統一しました。

#### 4. セクション検索/ジャンプ機能 (#4413)

資産管理画面が縦に長くなってきたため、アプリバーに **検索アイコン** を追加し、
カード名・項目名でフィルタリングしてスクロール位置にジャンプできるようにしました。

Flutter の `ScrollController` と `GlobalKey` を組み合わせて、
目的のセクションへ `animateTo` でスムーズに遷移します。

#### 5. IQ テストの仮説検証ループ (#4385)

「IQ テストの正答率が低い設問」を 10 件ピックアップし、
それぞれに「なぜ間違えやすいか」の仮説を立て → 実測 → 修正 という
**仮説検証サイクル** を回しました。

- 9 件: 仮説が正しく、設問・解説・選択肢を改善
- 1 件: 仮説が反証され、元の問題を維持 (誤りは問題ではなく学習不足が原因)

AI にテストケースの生成と差分検証を任せることで、
人間1人では数週間かかる改善を数時間で完了できました。

#### 6. Stripe 全額返金 → ダウンロード権失効 (#4412)

デジタルコンテンツ販売において、**全額返金後もダウンロードできる** という脆弱性を修正。
Stripe の `refund.created` Webhook を Supabase Edge Function で受信し、
`purchases` テーブルの `download_enabled` フラグを `false` に更新します。

```typescript
// Edge Function: stripe-webhook
if (event.type === 'refund.created' && refund.amount === charge.amount) {
  await supabase
    .from('purchases')
    .update({ download_enabled: false })
    .eq('stripe_charge_id', charge.id);
}
```

#### 7. 販売ファネル計測 (#4392)

ショップページに **Google Analytics カスタムイベント** を追加し、
`view_item → add_to_cart → begin_checkout → purchase` の各ステップを計測開始。
どのステップで離脱が多いかを可視化して、今後の UX 改善に活かします。

### 詰まったポイント

**1. Supabase 公開バケット URL の扱い**
`getPublicUrl()` が返す URL に自動でクエリパラメータが付くケースがあり、
X API が `400 Bad Request` を返すことがありました。
`Uri.parse(url).removeFragment()` で正規化して解決。

**2. ScrollController の dispose 忘れ**
`AnimateTo` 後に画面遷移すると `setState after dispose` エラーが発生。
`mounted` チェックを徹底することで解消しました。

**3. Stripe Webhook の署名検証**
`stripe-signature` ヘッダーを Supabase Edge Function の Deno 環境で検証する際、
`Uint8Array` のエンコーディング差異でハマりました。
Stripe 公式の `constructEventAsync` を使うと Deno でも問題なく動作します。
