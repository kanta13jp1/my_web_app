### はじめに

「自分株式会社」は Notion・Evernote・MoneyForward・Slack・X など21の競合SaaSを1つに統合するAIライフマネジメントアプリです。Flutter Web + Supabase Edge Function で構築し、https://my-web-app-b67f4.web.app/ で公開中です。

今回は **ギタースタジオで録音したデータを公開した瞬間にXへ自動投稿するバイラルパイプライン** を実装しました。ユーザーがコンテンツを生み出すたびに自動でSNS拡散が走る仕組みです。

---

### 背景と課題

自分株式会社には `guitar-recording-studio` Edge Function（ギター録音・公開ギャラリー）と `post-x-update` Edge Function（X自動投稿）が既に存在していました。

しかし「録音を公開する」という行為と「Xに投稿する」という行為は完全に分断されており、ユーザーが手動でX投稿ボタンを押す必要がありました。これでは投稿率が低く、バイラル係数が上がりません。

**目標**: 録音を `is_public: true` で保存した瞬間、バックエンドが自動的にXへ投稿する。

---

### 設計方針: fire-and-forget

X投稿の失敗で録音保存が失敗するのは論外です。そのため `fire-and-forget` パターンを採用しました:

```typescript
// guitar-recording-studio/index.ts に追加
async function postPublicRecordingToX(recording: GuitarRecordingRow): Promise<void> {
  if (!SERVICE_ROLE_KEY || !SUPABASE_URL) return;

  // ツイートテキスト生成 (≤280字)
  const durationStr = recording.duration_display ?? formatDuration(recording.duration_seconds);
  const preset = (recording.preset ?? "").replace(/_/g, " ");
  const shareUrl = buildShareUrl(recording.id);

  const lines = [
    `🎸 新しい録音を公開しました！`,
    `「${recording.title}」`,
    `${durationStr} / ${preset}`.trim(),
    ``,
    shareUrl,
    APP_URL,
    `#buildinpublic #FlutterWeb #guitar`,
  ];
  let text = lines.join("\n");
  if (text.length > 280) {
    // タイトルが長い場合は短縮
    const shortTitle = recording.title.length > 20
      ? recording.title.slice(0, 20) + "…"
      : recording.title;
    text = [`🎸 「${shortTitle}」を公開しました！`, shareUrl, `#buildinpublic #guitar`].join("\n");
  }

  try {
    const xPostUrl = `${SUPABASE_URL}/functions/v1/post-x-update`;
    const resp = await fetch(xPostUrl, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        "Authorization": `Bearer ${SERVICE_ROLE_KEY}`,
      },
      body: JSON.stringify({ text }),
    });
    if (!resp.ok) {
      console.warn(`[guitar-recording-studio] X post failed: ${resp.status}`);
    }
  } catch (e) {
    console.warn(`[guitar-recording-studio] X post error: ${e}`);
  }
}
```

キーポイントは3つです:

1. **try-catch で囲む** — X投稿の失敗を握り潰す
2. **await しない** — 呼び出し側は `postPublicRecordingToX(savedRow)` と書くだけで、Promiseを返すが `await` しない
3. **280字チェック** — ツイートテキストが長い場合は自動短縮

### saveRecording への組み込み

```typescript
// 録音を保存した後
const savedRow = data as GuitarRecordingRow;

// 公開録音ならX自動投稿 (fire-and-forget)
if (savedRow.is_public) {

return {
  success: true,
  recordingId,

```

`xPosted: true` をレスポンスに含めることで、Flutter側でスナックバー等に「Xに自動投稿しました」と表示できます。

### 手動シェアアクションも追加

ユーザーが「もう一度Xに投稿したい」ケースのため、`share_to_x` アクションも追加しました:

```typescript
case "share_to_x":
  return jsonResponse(await shareRecordingToX(auth, body));
```

```typescript
async function shareRecordingToX(auth: AuthContext, body: Json) {
  const user = requireUser(auth);
  const recordingId = normalizeString(body.recordingId);
  if (!recordingId) throw new Error("recordingId is required");

  const { data: row, error } = await auth.adminClient
    .from("guitar_recordings")
    .select("*")
    .eq("id", recordingId)
    .eq("user_id", user.id)
    .single();

  if (error || !row) throw new Error("Recording not found");
  const recording = row as GuitarRecordingRow;
  if (!recording.is_public) throw new Error("Recording must be public to share");

  await postPublicRecordingToX(recording);
  return { success: true, shareUrl: buildShareUrl(recording.id) };
}
```

### Edge Function間の呼び出しパターン

`guitar-recording-studio` から `post-x-update` を呼び出す際は、同一Supabaseプロジェクト内の Edge Function URLを使います:

```typescript
const xPostUrl = `${SUPABASE_URL}/functions/v1/post-x-update`;
const resp = await fetch(xPostUrl, {
  headers: { "Authorization": `Bearer ${SERVICE_ROLE_KEY}` },
  // ...
});
```

`SERVICE_ROLE_KEY` は Supabase Secrets に設定済みなので、Edge Function間でサービスロール認証が通ります。`post-x-update` は `authorizeAutomationActor` でこのキーを検証しています。

---

### 詰まったポイント

**post-x-update の認証方式**: `post-x-update` は `authorizeAutomationActor` という独自ヘルパーでサービスロールキーを検証しています。最初は JWT トークンで呼ぼうとしてエラーになりました。正解は `Bearer ${SERVICE_ROLE_KEY}` で直接呼ぶことでした。

**280字制限**: URLが長いため、タイトルが長いと超える場合があります。`text.length > 280` でフォールバック文字列に切り替えるロジックを入れました。

---

### まとめ

「ユーザーがコンテンツを公開する → 自動でSNS拡散」というバイラルループは、グロースエンジンの基本です。今回実装したパターンは:

- **fire-and-forget**: 主処理を止めない
- **Edge Function間呼び出し**: SERVICE_ROLE_KEY + Bearer認証
- **280字チェック**: 自動フォールバック

この実装により、毎日の録音 → X自動投稿 → 新規ユーザー流入 という循環が回り始めます。
