### 実装方法

#### 1. Flutter Web × MediaRecorder API

Flutter Webでマイク録音を行う際の最大の障壁は **ブラウザごとに異なるマイク権限エラー** です。

```dart
// マイク権限エラーの分類
try {
  final stream = await _requestMicrophone();
} catch (e) {
  final msg = e.toString().toLowerCase();
  if (msg.contains('notallowederror') || msg.contains('permission denied')) {
    _showPermissionGuide(PermissionErrorType.notAllowed);
  } else if (msg.contains('notfounderror') || msg.contains('devicenotfound')) {
    _showPermissionGuide(PermissionErrorType.notFound);
  } else if (msg.contains('notsupportederror')) {
    _showPermissionGuide(PermissionErrorType.notSupported);
  }
}
```

エラータイプを `NotAllowed / NotFound / NotSupported` の3種に分類し、それぞれについて **iOS Safari / Android Chrome / デスクトップChrome / Firefox** 向けの具体的な解決手順をダイアログで表示します。これにより「マイクが使えない」という一言エラーから、ユーザーが自己解決できるUIになりました。

#### 2. 録音完了後の共有フロー

保存後に公開設定を選んだ場合、自動的に「共有リンクをコピー」ボタンを表示します。

```dart
// Clipboard API を活用した共有リンクコピー
if (_isPublic && _savedRecordingId != null) {
  final shareUrl = 'https://my-web-app-b67f4.web.app/guitar-studio/$_savedRecordingId';
  await Clipboard.setData(ClipboardData(text: shareUrl));
  _showSnackBar('共有リンクをコピーしました！');

```

`flutter/services.dart` の `Clipboard` クラスはFlutter Webでも動作し、ネイティブアプリと同じAPIで実装できます。

#### 3. Supabase guitar_recordings テーブル + RLS設計

```sql
CREATE TABLE guitar_recordings (
  id          uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id     uuid REFERENCES auth.users(id) ON DELETE CASCADE NOT NULL,
  title       text NOT NULL,
  audio_url   text,
  duration_ms integer,
  bpm         integer,
  key_name    text,
  tags        text[],
  is_public   boolean DEFAULT false,
  created_at  timestamptz DEFAULT now(),
  updated_at  timestamptz DEFAULT now()
);

-- RLSポリシー
ALTER TABLE guitar_recordings ENABLE ROW LEVEL SECURITY;

-- 自分のデータは全操作可能
CREATE POLICY "owner_all" ON guitar_recordings
  FOR ALL USING (auth.uid() = user_id);

-- 公開データは全ユーザーが参照可能
CREATE POLICY "public_select" ON guitar_recordings
  FOR SELECT USING (is_public = true);
```

RLSを有効化することで、Supabase APIに直接アクセスしても他ユーザーのデータは見えません。`is_public = true` のレコードだけを全ユーザーが参照できる2層構造にしています。

#### 4. 2FA管理ページ — TOTP + 信頼済みデバイス

`/two-factor-auth` ページでは以下を実装しました。

- TOTP QRコード表示（Supabase Auth の `enrollMFA` API）
- 信頼済みデバイス一覧（`auth.mfa_factors` テーブル参照）
- バックアップコード生成・再発行
- 全セッション強制ログアウト

Flutter側は `supabase_flutter` パッケージの MFA API をそのまま使えるため、UIの実装に集中できました。

#### 5. IoTデバイス管理 — 部屋別グリッド

```dart
// 部屋ごとにデバイスをグルーピングして表示
```

### 詰まったポイント

#### 1. MediaRecorder の `isTypeSupported` の型エラー

```
The argument type 'String?' can't be assigned to parameter type 'String'.
```

Dart の null safety 制約で、`isTypeSupported` に渡す MIME タイプが `String?` になっていました。`??` 演算子でデフォルト値を指定することで解消：

```dart
final mimeType = _getSupportedMimeType() ?? 'audio/webm';
```

#### 2. RLSポリシーの順序

`ENABLE ROW LEVEL SECURITY` の前にポリシーを作成すると、ポリシーが無効になるケースがありました。必ず `ENABLE` → `CREATE POLICY` の順番で記述することが重要です。

#### 3. `updated_at` トリガーの重複

マイグレーションを複数回実行した際に `CREATE TRIGGER` が重複エラーになりました。`CREATE OR REPLACE TRIGGER`（PostgreSQL 14+）または `DROP TRIGGER IF EXISTS` を先に実行する方法で解決しました。
