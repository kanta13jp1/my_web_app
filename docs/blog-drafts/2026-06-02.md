## 本文下書き

### はじめに

Flutter Web + Supabase で「自分株式会社」という個人向け資産・時間管理 SaaS を開発しています。本番 URL は https://my-web-app-b67f4.web.app/ です。

このプロダクトは単なる個人プロジェクトではなく、「AI をフル活用してインディー開発者が大企業と戦えるか」という実験でもあります。今週、いくつかの重要な変化がありましたので、build in public として共有します。

---

### 実装方法

#### 1. 2インスタンス AI フリートへの最適化

以前は Claude Code を 10 インスタンス + Codex CLI を 2 インスタンスという大規模フリートで運用していましたが、2026年5月末に **2インスタンス体制** に整理しました。

- **Claude Code #1**: 問題定義・アーキテクチャ・コードレビュー・Hook 設計・クロスインスタンス調整
- **Codex #1**: 実装・SQL/マイグレーション・Edge Functions・GitHub Actions・UI ブラウザ QA

この役割分担により、コンテキストの混濁を防ぎつつ並列作業の効率を最大化しています。

#### 2. AI ツール監視スクリプト (`scripts/ai_tool_watch.py`)

Claude Code、Codex、Cursor、Gemini Code Assist、Devin など主要 AI 開発ツールの公式ページを毎日クロールし、変化を検知して GitHub にコミットする仕組みを構築しました。

今週の主な検知内容:
- **Claude Code 2.1.160** (2026-06-02) — 最新 Hook 機能強化
- **Codex Sites 機能** (2026-06-02) — Codex アプリ内でウェブサイトのビルド・デプロイが preview 提供開始
- **Cursor v3.6** (2026-05-29) — Shell/MCP/Fetch ツール呼び出しへの Auto-review 機能
- **Devin 2.2** (2026-05-29) — コンピューターユース E2E テスト強化

これらのシグナルを `codex-runtime` `hooks` `integration` `quality-cost` `schedule` の 5 ルーティンググループに分類し、対応アクション（GitHub Issues / WBS 更新 / Hook 設計）にマッピングします。

```python
# scripts/ai_tool_watch.py の概要
ROUTING_GROUPS = {
    "hooks": ["SessionStart", "UserPromptSubmit", "PostToolUse", "Stop"],
    "codex-runtime": ["worktrees", "in-app-browser", "broad-refactor"],
    "integration": ["MCP", "Slack", "GitHub", "NotebookLM"],
    "quality-cost": ["deny-by-default", "budget-routing", "telemetry"],
    "schedule": ["GitHub Actions", "Codex Automations", "daily-cron"],
}
```

#### 3. 競合21社自動監視 + xAI Grok Build の追加

`docs/competitor-reports/_competitors.json` で競合リストを管理しており、今週 **xAI Grok Build** を 21 社目として追加しました。

これは "AI コーディング支援" カテゴリの競合として脅威度: 🔴 High で登録。Bolt.new (5/24 発見) から 9 日の cooldown を経て discovery フローを走らせた結果です。

```json
{
  "name": "xAI Grok Build",
  "category": "AI Coding Assistant",
  "threat_level": "high",
  "discovered_at": "2026-06-02",
  "notes": "xAI が提供するコード生成・デプロイ統合 AI ツール"
}
```

現在追跡している競合カテゴリ:
- AI コーディング支援 (Claude Code, Codex, Cursor, Devin, Grok Build など)
- 個人資産管理 (MoneyForward, freee など)
- 知識管理 (Notion, Evernote など)
- コミュニケーション (Slack, Chatwork, Discord など)

毎朝 GHA の cron ジョブが各競合サイトの HTTP ステータスと変化を記録し、AI による分析レポートを自動生成します。

#### 4. Claude Code Hooks によるセッション自動化

`SessionStart` hook で毎セッション以下を自動実行:

```bash
# ~/.claude/hooks/inject-rules.txt
[INSTANCE] WEB版
[WORKDIR-ISOLATION] /home/user/my_web_app
[INSTANCE-ROLES] Architecture / Review-gate / Cross-instance coordination
[PHILOSOPHY-22] CEO感 / ミッション / mentor ...
[AI-DEV-23] Auth / deny-by-default / trace_id ...
```

これにより「ルールをその都度説明する」コストがゼロになります。30+ のワークフローと 5 つの daily cron はほぼ Claude 非依存で設計されており、quota 超過時も継続動作します。

### 詰まったポイント

#### 競合監視の API キー問題

GitHub Actions ワークフローで `SUPABASE_SERVICE_KEY` や `ANTHROPIC_API_KEY` が設定されていない場合、AI による分析生成をスキップして「可用性チェック結果のみ記録」する static-template モードにフォールバックするロジックを入れました。

CI/CD の安定性を優先し、外部依存が失敗してもコミット自体は成功する設計です。

#### 2インスタンス移行時の役割境界

Claude Code #1 と Codex #1 の役割が曖昧になるケース（特に「実装も必要なアーキテクチャ検討」）では、明示的に「どちらが Owner か」をコミットメッセージや Issue に記録するルールを設けました。

```
Co-Authored-By: Claude Opus 4.8 (1M context) <noreply@anthropic.com>
```
