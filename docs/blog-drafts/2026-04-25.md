## 本文下書き（約2200字）

### はじめに

Flutter Web と Supabase を組み合わせてアプリを作っていると、ある時点で必ずぶつかる問題がある。

**「ログインしていないユーザーがページを開いたとき、コンソールに大量の 401 Unauthorized が流れる」**

これは UX 上は一見問題なく見えても、以下の悪影響がある：

- ネットワークタブが汚染され、本物のエラーが埋もれる
- Supabase のログに不要なリクエストが蓄積される
- 場合によってはレート制限に引っかかるリスク
- ローカル開発時のデバッグが著しく困難になる

「自分株式会社」（Flutter Web + Supabase で作った AI統合ライフマネジメントアプリ）では、機能追加を繰り返すうちにこの問題が 16 ページ以上に広がっていた。今回、システム的に一括修正した方法を紹介する。

### 問題の根本原因

Flutter Web の StatefulWidget では、`initState()` でデータフェッチを行うのが一般的なパターンだ：

```dart
@override
void initState() {
  super.initState();
  _loadData(); // ここで Supabase API を呼ぶ
}
```

しかし、匿名ユーザー（未ログイン状態）でこのページに訪れると、RLS（Row Level Security）がブロックするため 401 が返る。ページ自体は動いているように見えるが、裏側でエラーが発生し続けている。

### 解決パターン：Anonymous Auth Guard

解決策はシンプルだ。`initState()` 内でデータフェッチを呼ぶ前に、認証状態を確認する：

```dart
Future<void> _loadData() async {
  // 匿名ユーザーはスキップ
  final user = Supabase.instance.client.auth.currentUser;
  if (user == null) return;

  // 以下、認証済みユーザー向けの処理
  final response = await Supabase.instance.client
      .from('my_table')
      .select()
      .execute();
  // ...
}
```

または、SnackBar でフレンドリーなメッセージを表示するパターン：

```dart
Future<void> _submitFeatureRequest() async {
  final user = Supabase.instance.client.auth.currentUser;
  if (user == null) {
    if (mounted) {
      ScaffoldMessenger.of(context).showSnackBar(
        const SnackBar(content: Text('この機能にはログインが必要です')),
      );
    }
    return;
  }
  // 以下、実際の処理
}
```

### 実装方法：16ページを一括修正した手順

今回の修正では、以下のページ群を対象にした：

| ページカテゴリ | 対象ページ数 | 修正内容 |
|---|---|---|
| AI大学 | 3ページ | badges / content / streaks の `initState` にガード追加 |
| ホーム系 | 2ページ | notification / feature_request にガード追加 |
| ツール系 | 4ページ | time_tracker / reading_list / calendar_events / support_tickets |
| 知識管理 | 3ページ | knowledge_base / goal_tracker / habit_tracker |
| その他 | 4ページ | notifications / daily_judgment / growth_weekly_digest / ai_assistant_chat |

修正方針は統一した：

1. **データフェッチのみ実行するケース** → `if (user == null) return;` で即リターン
2. **ユーザーアクション（ボタン押下など）** → SnackBar で「ログインが必要です」を表示
3. **ページ全体が認証必須の場合** → `initState` の先頭でガードし、代わりにログイン誘導UIを表示

### 詰まったポイント

#### `mounted` チェックを忘れない

非同期処理中にウィジェットが破棄されるケースがある。`ScaffoldMessenger.of(context)` を呼ぶ前には必ず `mounted` を確認する：

```dart
if (mounted) {
  ScaffoldMessenger.of(context).showSnackBar(...);
}
```

#### RLS ポリシーと整合させる

Supabase 側の RLS でも「anon ロールはアクセス不可」と設定しているはずなので、フロント側のガードはあくまでネットワークリクエスト削減が目的。RLS は二重のセキュリティとして必ず維持すること。

#### `Supabase.instance.client.auth.currentUser` が null のタイミング

Flutter の初期化タイミングによっては、`currentUser` が一時的に null になることがある。セッション永続化を有効にしていれば起動直後に復元されるが、`initState` での初回フェッチ時は null の可能性を常に考慮すること。

### 副産物：プロアクティブ診断ダッシュボード

一括修正の過程で、現在のアプリ状態を診断するダッシュボード機能も追加した。認証状態・API 接続状態・各機能の稼働状況をリアルタイムで確認できる。

これにより、今後のデバッグが大幅に楽になった。

### まとめ

- Flutter Web + Supabase の組み合わせでは、匿名ユーザーによる不要な 401 エラーが蓄積しやすい
- `initState()` の先頭に `if (user == null) return;` を追加するだけで根本解決できる
- ユーザーアクションには SnackBar でフレンドリーなフィードバックを
- RLS は二重安全網として維持すること

16 ページを一括修正したことで、開発時のノイズが大幅に減り、本物のエラーに集中できる環境が整った。同じ問題を抱えている方の参考になれば幸いだ。
