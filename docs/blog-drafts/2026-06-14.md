### はじめに

「自分株式会社」という家計管理 SaaS を Flutter Web + Supabase で個人開発しています。

今週（2026年6月上旬〜中旬）は一気に8本の機能をリリースしました。キャッシュフロー予測の強化、予算実績管理のカテゴリ対応、クロスデバイス同期、さらには**禁酒で借金完済チャレンジ**というユニークな機能まで。本記事ではその実装ポイントと躓いたところを共有します。

---

### 実装方法

#### 1. マルチ月キャッシュフロー予測カード (#3403 / #3419)

まず、複数月にわたるキャッシュフロー残高予測機能を追加しました。

```dart
enum ForecastHorizon { threeMonths, sixMonths, oneYear }

final cashflows = await supabase
  .from('monthly_cashflow')
  .select('month, amount, category')
  .gte('month', DateTime.now())
  .lte('month', horizon.endDate);
```

v2 では「安全ライン」（最低残高ライン）の可視化と、レビューリンク（問題のあるカテゴリへのジャンプ）を追加しました。Flutter の `fl_chart` パッケージで折れ線グラフを描画し、Supabase Edge Functions でサーバーサイド集計しています。

#### 2. 予算 vs 実績（カテゴリ別）(#3421)

月初に設定した予算に対して実績がどれだけ乖離しているかをカテゴリ別に表示する機能です。

```sql
SELECT
  b.category,
  b.budget_amount,
  COALESCE(SUM(t.amount), 0) AS actual_amount,
  b.budget_amount - COALESCE(SUM(t.amount), 0) AS remaining
FROM budgets b
LEFT JOIN transactions t
  ON t.category = b.category
  AND DATE_TRUNC('month', t.date) = DATE_TRUNC('month', NOW())
GROUP BY b.category, b.budget_amount;
```

Flutter 側は `Riverpod` で状態管理し、予算超過カテゴリを赤色で強調表示します。

#### 3. クロスデバイス同期 — 削除伝播の実装 (#3400 / #3402)

ウォッチリストやリボ払い設定をスマホで削除したとき、他端末にも即座に反映させる「削除伝播」の実装です。

従来の union マージ方式では「削除」がローカルからしか見えず、他端末に再現されない問題がありました。解決策は **Tombstone パターン**の採用です。

```sql
CREATE TABLE asset_pref_tombstones (
  user_id UUID,
  item_key TEXT,
  deleted_at TIMESTAMPTZ DEFAULT NOW(),
  PRIMARY KEY (user_id, item_key)
);
```

削除時にトゥームストーンを挿入し、マージ時に `deleted_at` が `updated_at` より新しければ削除として扱います。GC（ガベージコレクション）は挿入位置順でなく削除時刻順に並べることで audit 要件も満たしました（#3411）。

#### 4. Xシェア + AI自動対応パイプライン (#3390)

「結果をXでシェア」ボタンを押した後、ユーザーからフィードバックが届いたら AI が自動応答する仕組みを作りました。

フロー：
1. Flutter → X 共有 URL 生成（ハッシュタグ付き）
2. ユーザーが X でコメント → Webhook → Supabase Edge Function
3. Edge Function が Claude API を呼び出し → 自動返信文を生成
4. フィードバックを `feedback_queue` テーブルへ DLQ 保存

PII 保護のため、送信者メールは `user_id` に置換（#3413）しています。

#### 5. 禁酒で借金完済チャレンジ (#3388)

これが今週いちばんユニークな機能です。飲み会の機会をカレンダーで記録し「もし参加しなかったら節約できた金額」を累積表示、借金完済日を逆算します。

```dart
final savedAmount = opportunities
  .where((e) => e.skipped)
  .fold(0.0, (sum, e) => sum + e.estimatedCost);

final debtFreeDate = _calcDebtFreeDate(
  currentDebt: debtBalance,
  monthlyPayment: basePayment + (savedAmount / monthsElapsed),
);
```

### 詰まったポイント

**1. 表示設定 restore で削除済みセクションが復活する問題 (#3422)**

`asset_pref_mirror` から設定を復元するとき、削除済みセクションを上書きしてしまう不具合がありました。`tombstones` テーブルを参照してフィルタリングすることで修正しましたが、tombstone の参照タイミング（リアルタイム vs バッチ）で悩みました。

**2. ガス代の固定費計上 (#3396)**

ガス代を「毎月の固定費」に自動登録する機能では、既存の固定費テーブルに重複登録されるバグが発生。`ON CONFLICT DO NOTHING` での冪等性確保と、同名資産口座による誤抑止（#3409）の修正が必要でした。

**3. 多端末同期のレース条件**

restore と pull が競合するレース条件（#3418）は LWW (Last-Write-Wins) タイムスタンプの再調整で解決。フロント側で `updated_at` を必ず付与し、Edge Function 側でマージ判定するパターンが安定しました。
