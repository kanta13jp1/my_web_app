# 個人開発の90日プラン — KPI設計からマイルストーン管理まで

「なんとなく開発してしまう」を防ぐ。3ヶ月を設計して、測定して、改善する。実際に使っているフレームワークを公開する。

## なぜ90日か

```
1週間: 緊急タスクだけで終わる
1ヶ月: 少し戦略的に動けるが短い
90日:  トレンドが見える / 施策の効果が測定できる
1年:   長すぎてモチベーションが続かない
```

90日は「戦略的に動けて、モチベーションも持続できる」最適な単位。

## Phase 0: 目標設定 (Day 1-3)

```
OKR 形式で設定:
  Objective (目標):
    「[ユーザー像] に [価値] を提供する」
    例: 個人開発者が AI を使った開発を毎日できる環境を作る

  Key Results (主要成果指標):
    KR1: MAU 500人 (現在 0)
    KR2: NPS +30 (現在 不明)
    KR3: MRR ¥50,000 (現在 ¥0)
```

KR は「できたかどうか測定できる」ものだけ。

## Phase 1: 仮説検証 (Day 1-30)

```
Month 1 の目標:
  - ユーザーインタビュー 5人 完了
  - MVP リリース (コアユースケース1つのみ)
  - 有料プランの仮価格を設定して反応を見る

成功基準:
  - 5人中 3人が「これを毎週使いたい」と言う
  - DAU / MAU 率 > 20% (リテンション確認)
```

Month 1 では「作る」より「検証する」が優先。

```
週次チェック (毎週金曜):
  ✅ 今週学んだことは何か?
  ✅ 仮説は正しかったか?
  ✅ 次週の最優先タスクは何か?
```

## Phase 2: グロース (Day 31-60)

```
Month 2 の目標:
  - SEO コンテンツ 4本 公開
  - /vs-{competitor} ページ 20社 追加
  - X での weekly 投稿を自動化
  - 初の有料ユーザー 獲得

成功基準:
  - オーガニック流入 300/月 超
  - チャーンレート < 10%/月
  - MRR ¥10,000 超
```

Month 2 では「作る」と「広める」のバランスを取る。

## Phase 3: 安定化 (Day 61-90)

```
Month 3 の目標:
  - 主要バグ 0件
  - 自動化 (GHA Schedule) で運用工数 50% 削減
  - 次の 90日プランを設計

成功基準:
  - MAU の前月比 +20%
  - サポート対応 < 週2時間
  - 週の開発時間 20時間以内で目標達成
```

Month 3 では「持続可能にする」が最優先。

## KPI ダッシュボードの設計

```sql
-- Supabase でカスタム KPI テーブル
CREATE TABLE weekly_kpis (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  week_start DATE NOT NULL,
  mau INT,
  new_users INT,
  mrr_jpy INT,
  nps INT,
  churn_rate DECIMAL(4,2),
  recorded_at TIMESTAMPTZ DEFAULT NOW()
);
```

```yaml
# GHA で毎週自動集計
on:
  schedule:
    - cron: '0 8 * * SUN'  # 毎週日曜8時
```

## 振り返りフレームワーク (月末)

```
月次振り返り テンプレート:

## [Month X] 振り返り

### できたこと
- [KR1] MAU: 目標 500 → 実績 320 (64%)
- [KR2] NPS: 目標 +30 → 実績 +22 (73%)

### できなかったこと
- [KR3] MRR: 目標 ¥50,000 → 実績 ¥18,000 (36%)

### 学んだこと
- 有料転換は無料期間が短いほど高い

### 来月の調整
- 無料期間を 30日 → 14日 に短縮
```

## まとめ

```
90日プランの鉄則:
  1. OKR で測定可能な目標を設定
  2. Month 1: 検証 / Month 2: グロース / Month 3: 安定化
  3. 週次チェックで軌道修正を続ける
  4. KPI は自動集計 (GHA + Supabase)
  5. 月末振り返りで学びを次の90日に活かす
```

「なんとなく」から「設計して測定する」への転換が、個人開発を持続可能にする最大のレバーだった。
