# Parsing XLSX/DOCX in the Browser with Pure Dart — No Server Round-Trip Needed

## Introduction

I'm building [jibun inc.](https://my-web-app-b67f4.web.app/), a Flutter Web + Supabase personal SaaS competing with Notion. When Notion 3.6 shipped Excel/Word import, I needed to match that feature fast.

Two constraints made it non-trivial:

1. **No `dart:io` on Flutter Web** — all file content must come through as `Uint8List`.
2. **Avoiding unnecessary server calls** — routing 5 MB Excel files through an Edge Function on every import is bad UX and wastes cold-start latency.

The solution: a **pure Dart parser that runs entirely in the browser**.

## How OOXML Works

Both `.xlsx` and `.docx` are ZIP archives containing XML files — the Office Open XML (OOXML) standard. Rename any `.xlsx` to `.zip` and unzip it to see:

```
book.xlsx
├── xl/sharedStrings.xml   ← string dictionary
├── xl/worksheets/sheet1.xml ← cell data (index references)
└── [Content_Types].xml
```

Dart's `archive` package handles the ZIP layer, and `xml` handles the XML parsing. The whole parser is a zero-Flutter-dependency class: `OfficeDocumentParser`.

## Implementation

### XLSX Parsing

The tricky parts of parsing XLSX:

**1. Shared strings** — string cells don't store text directly; they store an integer index into `sharedStrings.xml`. Cells with `<c t="s">` hold indices; cells without `t` hold raw numbers.

**2. Column address → index conversion** — cells are addressed as `A1`, `BC42`, etc. Empty cells are simply absent from the XML, so you must reconstruct the full 2D grid:

```dart
int _colIndex(String ref) {
  // "A"→0, "B"→1, "Z"→25, "AA"→26
  final letters = ref.replaceAll(RegExp(r'[0-9]'), '');
  return letters.codeUnits.fold(0, (acc, c) => acc * 26 + (c - 64)) - 1;
}
```

**3. Namespace-agnostic element matching** — use `localName` instead of `name`:

```dart
// Works regardless of whether elements are prefixed w:p or unprefixed p
doc.findAllElements('p', namespace: '*')
```

### DOCX Parsing

Word documents are simpler: extract paragraphs from `word/document.xml`:

```dart
String parseDocxToText(Uint8List bytes) {
  final archive = ZipDecoder().decodeBytes(bytes);
  final content = utf8.decode(
    archive.findFile('word/document.xml')!.content as List<int>
  );
  return XmlDocument.parse(content)
      .findAllElements('p', namespace: '*')
      .map((p) => p.findAllElements('t', namespace: '*')
          .map((t) => t.innerText)
          .join())
      .where((s) => s.isNotEmpty)
      .join('\n');
}
```

### Structured Task Fields (GitHub Issue Fields equivalent)

Alongside the import feature, I added `priority` / `effort` / `target_date` columns to the task tables. Supabase migration:

```sql
ALTER TABLE feature_requests
  ADD COLUMN priority TEXT CHECK (priority IN ('p0','p1','p2','p3')),
  ADD COLUMN effort   TEXT CHECK (effort   IN ('xs','s','m','l','xl')),
  ADD COLUMN target_date DATE;
```

On the Flutter side, a shared `StructuredFieldChips` widget renders these fields consistently across the public feature-requests page and the admin dashboard.

## Challenges

**API drift between major versions** — `archive` 4.x changed the `decodeBytes` return type, and `xml` 6.x made `namespace` a required parameter in some contexts. Lesson: verify the actual API against the GitHub source before writing code, and pin versions explicitly in `pubspec.yaml`.

**`file_picker` on Web returns bytes, not paths** — `PlatformFile.bytes` gives you the `Uint8List` directly. No temp files, no paths — pass it straight to the parser.

**Shared string index vs. raw value** — forgetting to check the `t="s"` attribute means every string cell shows as a number. The `t` attribute is the discriminator between string-index cells and numeric cells.

## Results

- XLSX and DOCX import now run fully in the browser — zero server calls
- The parser is a plain Dart class with no Flutter dependency, so it's easily testable with `dart test` (VM tests, no widget overhead)
- `CHECK` constraints in Supabase enforce valid priority/effort values at the DB layer
