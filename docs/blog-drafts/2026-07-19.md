### はじめに

ここ1週間、「自分株式会社」こと私の個人プロジェクト [my-web-app](https://my-web-app-b67f4.web.app/) で、個人資産管理モジュールの開発を集中的に進めた。

「自分株式会社」とは、自分の人生を一つの会社として捉えるコンセプトのもと、時間・資産・タスク・目標を一元管理するFlutter WebアプリだーSupabase（PostgreSQL + Edge Functions）をバックエンドに、Firebase Hostingで配信している。

今回の開発では以下の機能を実装した：

- **純資産パネル** ── 前月比±¥/±% と 直近6ヶ月スパークライン
- **月次キャッシュフローパネル** ── 月収・月支出・累積キャッシュフロー
- **統合アラートパネル** ── 異常検知 + リマインダーを1箇所に集約
- **負債マスタ ドル建て入力** ── 為替自動換算（JPY/USD対応）
- **資金繰り盲点修正** ── 引落元が現金・預金口座でない支払いの除外バグ
- **Google Fonts廃止** ── LCP改善のためのランタイム読み込み排除

一つひとつは小さな機能だが、まとめて動かすと「財務ダッシュボード」としての体験が大きく変わった。

---

### 実装方法

#### 1. 純資産パネル（Net Worth Panel）

純資産 = 総資産 − 総負債 をリアルタイムで可視化するパネル。前月比の絶対値と相対値（±¥xxx / ±x.x%）を表示し、直近6ヶ月のスパークラインで推移を確認できる。

Supabaseの`asset_items`テーブルと`liability_items`テーブルを月次集計ビューで結合し、Flutter側では`fl_chart`ライブラリでスパークラインを描画した。

```dart
// 純資産スパークライン用データ取得
final netWorthHistory = await supabase
  .from('monthly_net_worth_summary')
  .select('month, net_worth')
  .order('month', ascending: true)
  .limit(6);
```

前月比の計算はSupabase側のPostgreSQL Viewで行い、Flutterはシンプルに値を受け取るだけにした。ロジックをDB側に寄せることで、将来的なプラットフォーム展開（モバイル等）にも対応しやすい設計だ。

#### 2. 月次キャッシュフローパネル

「今月いくら入って、いくら出て、累積でどうなっているか」を一目で確認できるパネル。収入予定が未登録の場合は、数字が過大に厳しく表示されてしまう問題も今回修正した。

```dart
// 収入予定未登録の警告表示
if (expectedIncome == null || expectedIncome == 0) {
  return CashflowWarningCard(
    message: '収入予定が未登録のため、資金繰りの数字が実態より厳しく表示されています',
  );
}
```

ユーザーへの正直な告知は、数字の信頼性を保つ上で重要だと感じた。

#### 3. 負債マスタ ドル建て入力 + 為替自動換算

サブスク費用などドル建て負債を入力したとき、現在の為替レートで自動的にJPY換算する機能を追加した。Edge Functionsで定期的にレートを取得・キャッシュし、クライアントはキャッシュ値を参照する設計にした。

```typescript
// Edge Function: 為替レート取得 + キャッシュ
const rate = await fetchUsdJpyRate();
await supabase.from('exchange_rate_cache').upsert({
  pair: 'USD_JPY',
  rate,
  updated_at: new Date().toISOString(),
});
```

#### 4. 資金繰りの盲点修正

引落元が「現金」や「預金口座」以外（クレジットカード等）の支払いが、資金繰り計算から消えていたバグを修正した。フィルタ条件に口座種別チェックを追加する小さな修正だが、数字の正確性に直結する重要な修正だった。

```sql
-- 修正前: 全支払いを対象
SELECT * FROM payments WHERE date BETWEEN $1 AND $2;

-- 修正後: 口座引落のみ資金繰りに反映
SELECT * FROM payments
WHERE date BETWEEN $1 AND $2
  AND source_account_type IN ('cash', 'bank_account');
```

#### 5. Google Fonts ランタイム読み込み廃止

`index.html`に直書きされていたGoogle Fontsの`<link>`タグを削除し、フォントをビルド成果物に含める形に変更した。LCP（Largest Contentful Paint）が大幅に改善し、特にモバイル回線でのファーストビュー表示速度が向上した。

### 詰まったポイント

**1. PostgREST 1000行上限**

WBSタスクを全件取得しようとしたとき、PostgRESTのデフォルト上限1000行で集計が破綻していた。`Range`ヘッダーでのページネーションか、Supabase側でのaggregate Viewを使う必要がある。最終的にはViewで集計して返す方式を採用した。

**2. AIエージェントの Statement Timeout**

`agent_memories`テーブルへのクエリが本番環境で statement timeout（500ms）に引っかかっていた。既存インデックスを活用するようにクエリを書き直し、実行計画を確認してから本番適用した。

**3. AI要約の生成中表示**

AI要約のリクエスト中に「空白」が表示されていた問題。生成中インジケーターを追加し、`maxTokens`の設定も見直してレスポンスが途中で切れないようにした。

### まとめ

一週間で6つの機能を実装・修正できたのは、Flutter + Supabase の組み合わせによる開発速度の高さと、Claude Codeを使ったAI駆動開発のおかげだ。

特に今回感じたのは、**ユーザーへの正直な告知の重要性**。資金繰りや純資産といった財務数字は、間違った数字を「正しそうに」見せてしまうとユーザーの判断を誤らせる。収入未登録の警告表示や、資金繰り盲点の修正はどれも「数字の正直さ」という軸で実装した。

今後は、資産推移のAI分析（異常検知・アドバイス生成）や、複数通貨対応の強化を進めていく予定だ。
