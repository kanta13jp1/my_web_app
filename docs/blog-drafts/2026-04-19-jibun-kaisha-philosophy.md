# 200ページのSaaSを1人で作る判断基準 — 自分株式会社の9原則

## なぜ「判断基準」が必要になったか

[自分株式会社](https://my-web-app-b67f4.web.app/)は、Notion・Evernote・MoneyForward・Slack・X・Amazonなど21競合の機能を1つに統合するFlutter WebアプリをAIと協力して開発しています。

200ページになった今、毎日こういう質問に直面します:

- 「競馬予測機能を追加すべきか?」
- 「この自動化はユーザーの代わりにやりすぎていないか?」
- 「このKPIを追うと本来のゴールから離れないか?」

個人開発でも、1人CEO+1人エンジニアとして意思決定を毎日迫られる。
そのための判断基準として、**9原則**を策定しました。

## 9原則

### 原則1: CEO感 (最終決定権)

> ユーザーが最終決定権を握る。AI/自動化のみは NG。

```dart
// ❌ 勝手に決める
await autoPublishBlogPost(content);

// ✅ ユーザーに確認を挟む
final approved = await showConfirmDialog(content);
if (approved) await publishBlogPost(content);
```

自動化は補助。「AIが全部やる」設計は原則1違反。

### 原則2: ミッション・コアバリュー駆動

> 機能はユーザーのミッション・コアバリューに紐付く。

「競合にあるから作る」ではなく「このユーザーの価値観にどう貢献するか」で判断。
新機能を設計するとき必ず問う: **「誰のどの価値観を支援するか?」**

### 原則3: 優しい mentor (取締役会)

> 監視・命令ではなく支援。

通知・リマインダー・AI分析は「監視官」ではなく「コーチ」として設計する。

```
❌ 「昨日3時間以上SNSを使いました。削減してください」
✅ 「昨日のSNS時間: 3h12m。今日の目標は?」
```

### 原則4: 6部署バランス (人事最優先)

> R&D / 財務 / マーケ / 人事 / 本社。人事部がNGなら全部停止。

「人事 = ウェルビーイング」。心身の健康を損なう機能は他の部署がOKでも却下。

### 原則5: 商品 = ユーザーの価値増大

> 価値消費ではなく価値増大。

SNS中毒・課金誘導・通知爆弾は原則5違反。
作った機能がユーザーの時間・能力・幸福感を「増やすか減らすか」で評価する。

### 原則6: 資本 = 時間

> 操作時間最小化・配分可視化。

UIの設計基準: **「このタップは何秒節約するか?」**
機能を増やすより、既存の操作を速くする方が原則6に適合する。

### 原則7: 資産 vs 負債バランスシート

> 資産(スキル・人脈・健康・知識)増加、負債(依存・浪費・不健康)減少。

機能リリース前に問う: **「これは資産を増やすか、負債を増やすか?」**

### 原則8: KPI = 昨日の自分

> 他人比較より自己進捗。

ランキング機能を作るとき、「他人との比較」ではなく「昨日の自分」との比較軸を必ず追加する。

```dart
// ✅ 自分史上最高記録との比較
final personalBest = await fetchPersonalBest(userId);
final improvement = currentScore - personalBest;
```

### 原則9: ゴール = IPO/ウェルビーイング

> 短期KPI競争より長期幸福感。

月次DAU・課金率より「このサービスが5年後もユーザーの人生にプラスか」で判断する。

## チェックリストの使い方

新機能を設計するとき9項目にチェック:

| 原則 | チェック |
|------|---------|
| CEO感 | ✅/❌ |
| ミッション駆動 | ✅/❌ |
| 優しい mentor | ✅/❌ |
| 6部署バランス | ✅/❌ |
| 価値増大 | ✅/❌ |
| 時間最小化 | ✅/❌ |
| 資産+負債- | ✅/❌ |
| 昨日の自分 | ✅/❌ |
| 長期ウェルビーイング | ✅/❌ |

- **7+** ✅ → 実装可
- **4-6** ✅ → 設計再考
- **3以下** → 見送り

## 実際に判断した例

| 機能 | スコア | 結果 |
|------|--------|------|
| 競馬予測 | 5/9 | 「R&D学習枠」として再定義 |
| AI自動投稿 | 4/9 | 「確認ダイアログ必須」条件付きOK |
| SNSランキング | 6/9 | 「昨日の自分比較軸」追加で再設計 |
| AI大学 (学習機能) | 9/9 | 即実装 |

## まとめ

21社の競合と戦う個人開発者が差別化できるのは、機能数でも価格でもなく**哲学**だと気づきました。

9原則は「何を作るか」の判断基準。
[前回紹介したAI開発7原則](https://dev.to/kanta13jp1/7-principles-for-using-ai-agents-safely-in-production-a-solo-devs-checklist-568n)は「どう作るか」の実装規律。

**両方をクリアした機能だけを作る**という制約が、逆に開発の方向性をブラしません。
