## 本文下書き (約2000字)

### はじめに

自社サービス「自分株式会社」(https://my-web-app-b67f4.web.app/) のバイラル動画広告生成機能で、音声生成の信頼性を大幅に改善しました。

この機能は、ユーザーが作成したコンテンツを自動的に動画広告へ変換するもの。ElevenLabs の高品質 AI 音声を使って動画の音声トラックを生成し、Hedra という AI プレゼンター動画生成サービスと組み合わせることで、リアルな「話す人物動画」を自動生成します。

しかし、ElevenLabs API が不安定な状況や、音声生成に失敗するケースが発生したとき、従来の実装には大きな問題がありました。

### 問題: フォールバックが中途半端だった

従来の実装を読み解くと、フォールバックの条件が複雑でした：

```
ElevenLabs 失敗
  └─ requiresUploadedAudio かつ 音声系エラーの場合のみ
        └─ フォールバック音声を試す
              └─ さらに条件を満たせば OpenAI TTS
  └─ それ以外 → 壊れた Hedra TTS へ直行
```

つまり、ElevenLabs が失敗しても `requiresUploadedAudio` フラグが立っていないケース、あるいは音声系以外のエラー（ネットワークタイムアウトなど）では、OpenAI TTS へのフォールバックが実行されず、品質の低い Hedra 内蔵 TTS に直行していました。結果として生成される動画の音声品質が低下するという問題が起きていました。

さらに問題だったのは、**どのプロバイダーで何が起きて最終的に Hedra TTS になったのかが、ログを見ないとわからない**という診断性の悪さでした。エラーレスポンスを受け取ったユーザーやサポートチームが、原因を追跡するのに時間がかかっていました。

### 実装: 2つの改善

#### 改善1: OpenAI TTS を無条件フォールバックに昇格

修正後の設計はシンプルです：

```typescript
// ElevenLabs 失敗時の処理
} catch (error) {
  speechChain.push(`elevenlabs=${providerErrorMessage(error)}`);
  
  // フォールバック音声を試す (requiresUploadedAudio の場合)
  if (params.requiresUploadedAudio && shouldRetryElevenLabsWithFallbackVoice(error)) {
    // ... フォールバック音声試行 ...
    speechChain.push(`fallback_voices=${fallbackResult.reason}`);
  }
  
  // OpenAI TTS は ElevenLabs 失敗時の無条件フォールバック
  if (OPENAI_API_KEY) {
    try {
      const openAiAudio = await createOpenAiSpeechAsset(/* ... */);
      audioProvider = "openai_tts_fallback";
      return await createHedraVideoFromUploadedAudio(/* ... */);
    } catch (openAiError) {
      speechChain.push(`openai_tts=${providerErrorMessage(openAiError)}`);
    }
  }
}
```

ElevenLabs が失敗した場合（理由を問わず）、OpenAI TTS が設定されていれば必ず試みるようになりました。これにより、動画の音声品質をできる限り高いレベルに保てます。

フォールバックの優先順位:
1. ElevenLabs（メイン）
2. ElevenLabs フォールバック音声（条件付き）
3. **OpenAI TTS（無条件フォールバック）** ← 今回追加
4. Hedra TTS（最終手段）

#### 改善2: speech_chain 診断ログ

もう一つの改善が、`speechChain` 配列によるエラー追跡です：

```typescript
const speechChain: string[] = [];

// 各失敗をチェーンに追記
speechChain.push(`elevenlabs=quota_exceeded`);
speechChain.push(`fallback_voices=all_failed`);
speechChain.push(`openai_tts=network_timeout`);

// 最終ログに全チェーンを含める
console.warn(
  "Premium speech generation failed; falling back to Hedra TTS",
  speechChain.join(" | ")
);
```

ログ出力例:
```
Premium speech generation failed; falling back to Hedra TTS
elevenlabs=quota_exceeded | fallback_voices=voice_not_found | openai_tts=OPENAI_API_KEY not configured
```

このログ一行で「ElevenLabs がクォータ超過し、フォールバック音声も見つからず、OpenAI TTS も未設定のため Hedra TTS を使用した」という全経緯がわかります。ダッシュボードを開かずにレスポンスを見るだけで診断できます。

### 詰まったポイント

**条件分岐の微妙な差異**: 元のコードは `requiresUploadedAudio && shouldRetryElevenLabsWithFallbackVoice(error)` という AND 条件の中に OpenAI TTS フォールバックが入っていました。これを外に出すリファクタリングは、一見シンプルに見えて、「フォールバック音声を試した後に OpenAI TTS を試す順序」を壊さないよう慎重に実装する必要がありました。

**Supabase Edge Function での async エラー処理**: Deno 上で動く Edge Function では、async/await のネストが深くなりがちです。`speechChain` を外側のスコープに持つことで、どのネスト層でも追記できる設計にしました。

**`OPENAI_API_KEY` 未設定時のハンドリング**: 環境変数が未設定の場合もチェーンに記録し、「設定ミスで OpenAI TTS が使えなかった」ことをログで明示しました。

### まとめ

今回の修正で達成したこと：

- **可用性向上**: ElevenLabs 障害時に OpenAI TTS へ自動フェイルオーバーし、高品質音声での動画生成を維持
- **診断性向上**: `speech_chain` ログで音声生成の経緯を1行で把握可能
- **コードの明確化**: フォールバック条件のネストを整理し、意図が読み取りやすい構造に

AI API を複数組み合わせる際の「フォールバック設計」は、可用性と診断性の両立が鍵です。各プロバイダーの失敗を記録しながら次の手段へ進む `speech_chain` パターンは、マルチプロバイダー構成のあらゆる場面で応用できます。
