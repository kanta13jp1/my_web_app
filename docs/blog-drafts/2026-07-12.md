# Notion 移行ゼロステップへ: Flutter+Dart で XLSX/DOCX をブラウザ完結インポートした

## はじめに

自作 Web アプリ「自分株式会社」は Notion の競合として開発している Flutter Web + Supabase の個人 SaaS だ。Notion 3.6 が「Excel/Word をそのままインポートできる」機能を発表したとき、即座に同等機能を実装する必要が生じた。

課題は大きく2つあった。

1. **サーバーレス環境でのファイル解析**: Supabase Edge Function (Deno) でもできるが、毎回サーバーラウンドトリップが発生する。5MB の Excel をアップするたびに Edge Function を呼び出すのは UX 的にも通信コスト的にもよくない。
2. **Flutter Web の制約**: native ファイル IO は使えない。`dart:io` は Web では動作しないため、すべてを `Uint8List` (バイト列) として扱う必要がある。

解決策は「**ブラウザ内で完結する Dart 純関数パーサー**」だった。

## 実装方法

### OOXML とは何か

Excel (.xlsx) も Word (.docx) も、実体は **ZIP アーカイブの中に XML ファイルを格納した OOXML (Office Open XML)** 形式だ。拡張子を `.zip` に変えて展開するとその構造が見える:

```
book.xlsx
├── xl/
│   ├── sharedStrings.xml   ← セル文字列の辞書
│   ├── worksheets/sheet1.xml ← セルデータ (インデックス参照)
│   └── ...
└── [Content_Types].xml
```

これを利用して、Dart の `archive` パッケージで ZIP を展開し `xml` パッケージで XML を解析する純粋関数として実装した。

### OfficeDocumentParser の実装

```dart
import 'dart:typed_data';
import 'package:archive/archive.dart';
import 'package:xml/xml.dart';

class OfficeDocumentParser {
  static const int maxRows = 5000;
  static const int maxCols = 256;

  List<List<String>> parseXlsxToRows(Uint8List bytes) {
    final archive = ZipDecoder().decodeBytes(bytes);
    // sharedStrings を先に解決
    final sharedStrings = _parseSharedStrings(archive);
    final sheet = _findFile(archive, 'sheet1.xml');
    if (sheet == null) return const [];
    return _parseSheet(sheet, sharedStrings);
  }

  String parseDocxToText(Uint8List bytes) {
    final archive = ZipDecoder().decodeBytes(bytes);
    final doc = _findFile(archive, 'word/document.xml');
    if (doc == null) return '';
    // localName で照合 → 名前空間プレフィックス (w:) に依存しない
    return XmlDocument.parse(doc)
        .findAllElements('p', namespace: '*')
        .map((p) => p.findAllElements('t', namespace: '*')
            .map((t) => t.innerText)
            .join())
        .where((s) => s.isNotEmpty)
        .join('\n');
  }
}
```

**ポイント**: XML 要素の照合は `element.localName` で行う。名前空間プレフィックス (`w:p`, `w:t`) の有無に関わらず動作するためだ。これを `element.name` で照合していると、名前空間宣言の違いで全く一致しないという罠にはまる。

### XLSX の列位置復元

XLSX のセルは `A1`, `BC42` のようなアドレスで記録されている。欠落セル (空白セル) はレコード自体が存在しないので、「列アドレス → 0-based インデックス」の変換が必要だ。

```dart
int _colIndex(String ref) {
  // "A" → 0, "B" → 1, "AA" → 26
  final letters = ref.replaceAll(RegExp(r'[0-9]'), '');
  return letters.codeUnits.fold(0, (acc, c) => acc * 26 + (c - 64)) - 1;
}
```

このインデックスを使って、欠落セルを空文字で埋めた 2 次元配列を構築する。

### 構造化タスク管理 (GitHub Issue Fields 相当)

XLSX インポートと同時に、タスクへの priority/effort/target_date フィールドも追加した。Supabase のマイグレーションで既存テーブルに列を追加:

```sql
ALTER TABLE feature_requests
  ADD COLUMN priority TEXT CHECK (priority IN ('p0','p1','p2','p3')),
  ADD COLUMN effort TEXT CHECK (effort IN ('xs','s','m','l','xl')),
  ADD COLUMN target_date DATE;
```

Flutter 側では `StructuredFieldChips` という共有 Widget を作り、feature_requests_page と admin ダッシュボードの両方から再利用している。

## 詰まったポイント

### `archive` 4.x と `xml` 6.x の API 差異

`archive` パッケージの 4.x 系は `ZipDecoder().decodeBytes()` の返り値が `Archive` 型になったが、3.x 系では `ArchiveFile` のリストだった。また `xml` 6.x では `findAllElements` に `namespace` パラメータが必須になっている箇所がある。

→ 実装前に GitHub のソースで実際の API を確認し、バージョンを pubspec に明示固定した。

### Flutter Web での `file_picker` + バイト列

Flutter Web は `dart:io` の `File` が使えないため、`file_picker` で選択したファイルは `PlatformFile.bytes` (= `Uint8List`) として受け取る。これを直接パーサーに渡すことで、EF (Edge Function) を経由しないブラウザ完結処理が実現できた。

### 共有文字列 (sharedStrings) の落とし穴

Excel の文字列セルは実際の文字列を直接持たず、`sharedStrings.xml` のインデックスを参照する仕様になっている。これを見落とすと全セルが数字のインデックスになって当惑する。数値セルと文字列インデックスセルは `<c t="s">` の `t` 属性で区別できる。

## まとめ

- XLSX/DOCX は **ZIP + XML** なので、Dart の `archive` + `xml` だけでブラウザ完結パースができる
- 名前空間プレフィックスに依存しない `localName` 照合が安定動作の鍵
- 欠落セルを空文字で補完する列インデックス変換が必要
- Supabase の `CHECK` 制約で priority/effort の型安全を確保できる

Notion 追随を目指した今回の実装で、「Excel をそのままインポートして構造化タスクに変換する」フローがブラウザ内だけで完結するようになった。EF のコールドスタートを待たず、大きなファイルでも快適に動作する。

次のステップは **AI による自動タグ付け** — インポートしたスプレッドシートのヘッダーを見て priority/effort を自動推定する機能を Supabase Edge Function + Claude API で実装予定だ。
