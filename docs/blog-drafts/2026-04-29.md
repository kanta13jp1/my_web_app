### はじめに

「自分株式会社」——個人開発者が、Notion・Evernote・MoneyForward・Slack・Amazonなど**21競合の機能を1つのアプリに統合する**プロジェクトを続けて1年以上。今週、競合比較データベースが**1816社**を突破しました。

先週末の1555社から今週末の1816社まで、**わずか7日間で261社を追加**しました。これを可能にしたのは、12インスタンス並行開発体制と、PS#4専任インスタンスによる「9社ずつバッチ追加」戦略です。

今週のもう一つの大きな成果は、**memory-search-hub Edge Function** のフル実装です。AIタスクルーティングエンジン（effort_router / task_budget）をSupabase Deno Edge Functionとして実装し、本番デプロイしました。

### 実装方法 — PS#4バッチ追加戦略

#### 9社ずつの意味

競合データ追加はPS#4インスタンスが専任で担当しています。1回のコミットで9社を追加するのには理由があります。

- **git commit size**: 9社 = 1PRの適切なサイズ
- **CI時間**: 9社追加 → sitemap更新 → flutter analyze → deploy で約4分
- **レビュー可能性**: 9社ならレビューが現実的

```bash
# PS#4の標準コミットパターン
feat(competitors): PS#4 S600-S602 競合9社追加 1618→1627社
feat(competitors): PS#4 S603-S605 競合9社追加 1627→1636社
feat(competitors): PS#4 S606-S608 競合9社追加 1636→1645社
```

### memory-search-hub: AIルーティングエンジンの実装

#### 設計思想

memory-search-hub は「タスクの複雑度を自動推定して最適なAIモデルに振り分ける」Edge Functionです。Codex#2が実装し、PS#5がシードSQLを追加しました。

```
effort_router: タスクの effort level を推定 (S/M/L/XL)
task_budget:   利用可能なコンテキスト予算を計算
```

#### Deno実装の核心

```typescript
// supabase/functions/memory-search-hub/index.ts
interface TaskEffortEstimate {
  level: 'S' | 'M' | 'L' | 'XL';
  estimated_tokens: number;
  recommended_model: string;
}

async function effortRouter(task: string): Promise<TaskEffortEstimate> {
  const complexity = await analyzeComplexity(task);
  
  if (complexity.score < 0.3) {
    return { level: 'S', estimated_tokens: 2000, recommended_model: 'claude-haiku-4-5' };
  } else if (complexity.score < 0.6) {
    return { level: 'M', estimated_tokens: 8000, recommended_model: 'claude-sonnet-4-6' };
  } else if (complexity.score < 0.85) {
    return { level: 'L', estimated_tokens: 32000, recommended_model: 'claude-sonnet-4-6' };
  } else {
    return { level: 'XL', estimated_tokens: 100000, recommended_model: 'claude-opus-4-7' };
  }
}
```

#### タスクバジェット管理

```typescript
async function taskBudget(sessionId: string): Promise<BudgetStatus> {
  const usage = await getSessionUsage(sessionId);
  const limit = getModelLimit(usage.current_model);
  
  return {
    used: usage.tokens,
    remaining: limit - usage.tokens,
    utilization_pct: (usage.tokens / limit) * 100,
    should_compact: usage.tokens > limit * 0.8,
  };
}
```

これにより「気づかないうちにコンテキスト上限に近づいている」問題を早期検出できます。

### 詰まったポイント

#### 1. CI の `@TestOn('browser')` 問題

今週、CI が突然テストを落とし始めました。調査すると `@TestOn('browser')` アノテーションが9ファイルから消えていました。

```dart
// 修正前 (VM上では実行できないブラウザテスト)
@TestOn('vm')  // 誤ってVMに変更されていた
void main() {
  testWidgets('...', (tester) async { ... });
}

// 修正後
@TestOn('browser')
void main() { ... }
```

`fix(ci): restore VM test enforcement — @TestOn('browser') on 9 files` として1コミットで修正しました。

#### 2. 1800社規模でのFlutter Web パフォーマンス

1800社のデータを一度にレンダリングするとフリーズします。対策:

- **遅延ロード**: スクロール位置に応じてバッチロード
- **検索フィルタリング**: クライアントサイドで高速絞り込み
- **仮想リスト**: `flutter_staggered_grid_view` で画面外をDOMから除去

#### 3. サイトマップの1912 URL管理

sitemap.xml を手動管理するのは限界でした。GHAスクリプトで `comparison_page.dart` からURLを自動抽出→sitemap.xml を自動生成する仕組みに移行しました。
