### はじめに

個人で会社を運営しながらソフトウェア開発をするというのは、エンジニアリングと経営の両方を一人でこなすことを意味します。「自分株式会社」は Flutter Web + Supabase で構築した SaaS アプリで、現在ユーザー数 37 名、機能リクエスト 53 件が積み上がっています。

この規模感では、開発速度が事業の命運を分けます。そこで私が導入したのが「AI エージェント 2 台体制」です。Claude Code と Codex CLI を並列で動かし、それぞれに担当領域を割り当てることで、一人のエンジニアが複数人分の実装速度を出せる仕組みを作りました。

本記事では、直近の開発サイクル（2026-05-28 週）で実際に何が起きたか——CI ゲートのトラブル、AI大学コンテンツ自動更新、WBS の自動リバランス——を赤裸々に記録します。

---

### 実装方法

#### 1. AI エージェント 2 台体制の構成

私のフリートは以下の 2 台です。

| インスタンス | 役割 | 主なタスク |
|---|---|---|
| Claude Code #1 | アーキテクト兼スクラムマスター | 設計判断・PR レビュー・ブログ下書き |
| Codex #1 | 実装担当 | 機能実装・WBS 更新・アセット管理 |

この 2 台が Git ブランチを介して協調します。Claude Code がアーキテクチャを設計し、Codex が実装するという分業です。これに加えて GitHub Actions で 30 以上のワークフローを自動化しており、毎時のインフラヘルスチェック、AI 大学コンテンツの自動更新、CS チェック（カスタマーサポートログの自動記録）などが無人で動いています。

#### 2. Karpathy 4 サイクルによる知識管理

Andrej Karpathy が提唱する「Ingest → Compile → Query → Lint」の 4 サイクルを自社開発に適用しています。

- **Ingest**: `scripts/memory_ingest.py` — 会話ログや実装メモを構造化して取り込む
- **Compile**: `scripts/wiki_compile.py` — `docs/concepts/` と `docs/INDEX.md` を自動生成
- **Query**: `notebooklm` CLI — トークンゼロで過去の設計判断を検索
- **Lint**: `scripts/knowledge_vault_lint.py` — 知識ベースの整合性チェック

これにより「3ヶ月前になぜこの設計にしたのか」を瞬時に呼び出せるようになりました。

#### 3. CI ゲートの詰まりと対処法

今週の最大のトラブルは CI ゲートの停止でした。GitHub Actions の PR Gate ワークフローが特定の条件下で `declaration body patch` エラーを吐き、PR が Close/Reopen を繰り返すパターンです。

原因は `GITHUB_OUTPUT` への書き込みタイミングとステップ間の依存関係の競合でした。対処は以下の 3 ステップ：

```yaml
# Before (problematic)
- name: Check status
  run: echo "status=pending" >> $GITHUB_OUTPUT

# After (fixed)  
- name: Check status
  id: check
  run: |
    echo "status=pending" >> "$GITHUB_OUTPUT"
    echo "::notice::Status set to pending"
```

さらに、v21 5 層構造予防仕様（Z-DD アーキテクチャ）を策定しました。これは「同日中の自然回復を確認するまでマージしない」というルールで、CI の不安定性を許容しながら前進する方法論です。

#### 4. アセット管理 WBS の AI ベンチマーク対応リバランス

Codex #1 が担当した今週の大仕事は、アセット管理機能のロードマップ WBS を AI モデルのベンチマーク計画と整合させることでした。

具体的には、各タスクの工数見積もりを「Claude で書く場合」「Codex で書く場合」「人間が書く場合」の 3 パターンで比較し、最適な AI 割り当てマトリクスを生成しています。

### 詰まったポイント

**1. AI エージェント間の文脈共有**

Claude Code と Codex は異なるセッションで動くため、MEMORY.md を Git で共有する仕組みを作りました。毎ターン inject される `~/.claude/hooks/inject-rules.txt` が双方の AI に同じルールセットを適用します。

**2. GitHub Actions のクォータ管理**

30 以上のワークフローを毎時動かすと、GitHub Actions のクォータ（2,000 分/月・無料プラン）に当たります。解決策は 2 つ：

- ほとんどのワークフローを Claude 非依存設計にする（AI 呼び出しは必要な場合のみ）
- クォータ超過時は Gemini Code Assist Agent Mode にフォールバック

**3. Flutter Web の Service Worker キャッシュ問題**

ユーザーからのバグ報告「Loading from existing service worker.」が継続中。Flutter Web の `flutter_service_worker.js` が古いキャッシュを参照し続ける問題で、`flutter build web --pwa-strategy=none` で回避中ですが根本解決には至っていません。
