# Notionをやめて Flutter + Supabase で自作した話 — 個人開発者が全部入りアプリを作るまで

## なぜ Notion を使い続けられなかったのか

2024年末、私は Notion の無料枠上限に達した。

5年分の日記、KPIデータベース、副業収入の記録、読書メモ、プロジェクト管理。これらをすべて Notion に入れていた私は、ある日「これ、月 $8 払い続けても根本的な問題は解決しないな」と気づいた。

**Notion の問題は価格ではなかった。設計思想だった。**

Notion はチームのナレッジ管理ツールだ。私が求めていたのは「個人の CEO ダッシュボード」だった。この2つは根本的に別物なのだ。

---

## 「自分のデータは自分で持つ」という決断

Notion を離れる前に、いくつかの代替ツールを試した。

- **Obsidian**: ローカルファイル管理は優秀。しかし API 連携やリアルタイムデータ取得ができない
- **Coda**: Notion より高機能だが、同じく「チーム向け設計」の問題が残る
- **Airtable**: データベース操作は優秀。しかし KPI 可視化は別途 Chart ツールが必要
- **自作 spreadsheet**: 結局 Google スプレッドシートに逃げてみたが、モバイルで使いにくい

全部試した結論: **自分が本当に欲しいものは、誰も作っていなかった。**

ならば自作するしかない。

---

## Flutter + Supabase を選んだ理由

技術選定で最重要だったのは「**自分1人でフルスタック開発できるか**」だ。

### Flutter を選んだ3つの理由

**1. Web + iOS + Android をコード1つで**  
Flutter Web でブラウザ対応 → PWA でスマホも対応。React Native と比べて Web の品質が高い。

**2. Dart の型安全性**  
`null safety` が強制される Dart は、個人開発の「後から見たらわからない」問題を防いでくれる。

**3. Widget ツリーの直感性**  
「こういう UI にしたい」が `Column(children: [Text(), ElevatedButton()])` のような構造で書けるのは、バックエンド出身の私には馴染みやすかった。

### Supabase を選んだ3つの理由

**1. PostgreSQL がそのまま使える**  
Firebase は NoSQL で複雑なリレーションが辛い。Supabase は PostgreSQL なので、テーブル設計が自由だ。

**2. Edge Functions (Deno) で AI 連携が簡単**  
LLM API 呼び出し・外部サービス連携を Edge Function で完結できる。Vercel Functions より Supabase の方が DB との結合が自然だった。

**3. 無料枠が本番運用に耐える**  
月間 50,000 MAU まで無料。個人プロダクトの初期フェーズには十分すぎる。

## 実際に作ったもの: 自分株式会社

アプリ名は「**自分株式会社**」。

コンセプトは「あなた自身を会社として経営する」。

```
人事部署  → 健康・睡眠・ウェルビーイング管理
財務部署  → 資産・負債・収支トラッキング
営業部署  → 副業収入・フリーランス案件管理
商品部署  → スキル・学習・AI大学(206社対応)
マーケ    → X/Qiita/dev.toブログ自動投稿
法務部署  → 契約・保険・法人設立計画
```

Notion で「なんとなく管理していた」6つの領域を、明確な役割分担で一元管理する設計にした。

## 開発で詰まった3つのポイントと解決策

### 詰まり #1: Edge Function の 50本制限

Supabase は 50本のEdge Functionまでしかデプロイできない。当初、機能ごとに1 EF を作っていたら 30本を超えた。

**解決策**: Hub パターン。`core-hub`, `tools-hub`, `ai-hub` など用途別の「ハブ」EF を作り、action パラメータでルーティングする。現在 16本のハブEFで 200+ アクションをカバー。

### 詰まり #2: Flutter Web の Service Worker

PWA 対応でハマった。`flutter build web` の Service Worker は `flutter_bootstrap.js` で自動管理されるが、キャッシュ戦略のカスタマイズが難しい。

**解決策**: `web/flutter_service_worker.js` を直接カスタマイズ。オフラインフォールバックと OGP 画像のキャッシュを手動管理。

### 詰まり #3: GitHub Actions の並行インスタンス問題

10インスタンス (VSCode版/Win版/PS版×6/WEB版/スマホ版) が同時に同じリポジトリへ push するため、`rebase conflict` が頻発した。

**解決策**: Worktree 分離。各インスタンスが独立した worktree で作業し、`git push origin <branch>:main` でマージする。`GROWTH_STRATEGY_ROADMAP.md` のような共通ファイルは「skip → 再append」パターンで対処。

## 「自作するか、使い続けるか」の判断基準

Notion を離れて Flutter + Supabase で自作したのは正解だったか?

**正解だった理由**:
- 自分が本当に欲しい機能を自分で作れる
- データを自分でコントロールできる
- 技術スタックの学習が副産物として得られる
- OSS + 無料枠で月額 $0 で運用できる

**コストになった部分**:
- 初期開発に 3ヶ月かかった
- バグ修正・インフラ管理は全部自分で行う
- UIの完成度は Notion に及ばない

**結論**: 個人開発者で「自分のための最強ツールを作りたい」なら自作の価値はある。チームで使うなら Notion の方が合理的。
