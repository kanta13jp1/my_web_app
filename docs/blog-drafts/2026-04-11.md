### はじめに

個人開発の SaaS「自分株式会社」を Flutter Web + Supabase で運営しています。
Notion・Evernote・MoneyForward・Slack・X・Amazon など **21 競合の機能を 1 つに統合**するという野心的なコンセプトで、毎週新機能を追加し続けています。

ところが、開発を続けるうちにある深刻な問題に直面しました。

**「Supabase Edge Function が 94 本になってしまった」**

Supabase の Edge Function は Deno ベースのサーバーレス関数で、1 つのプロジェクトに何本でも追加できます（無料プランでも）。しかし実際に 94 本を管理すると、以下の課題が噴出しました：

- **デプロイ時間の肥大化**: 全関数デプロイに 30 分以上かかる
- **CI/CD の複雑化**: GitHub Actions ワークフローが見通せなくなる
- **認知負荷の増大**: どの関数が何をするか把握しきれない
- **コスト管理の困難**: 呼び出し回数・実行時間の把握が散漫になる

そこで今週、**「EF ハードキャップ 50 本以下」** という制約を設け、94 本を **15 本** まで削減するリファクタリングを実施しました。

### 実装方法

#### Action 分岐パターンの採用

削減の核心アイデアは「**1 つの Edge Function が `action` パラメータで複数の処理を担う**」というパターンです。

```typescript
// 旧: 関数を機能ごとに分割
// POST /ai-university-streaks-get
// POST /ai-university-streaks-update
// POST /ai-university-streaks-reset
// POST /ai-university-badges-issue
// POST /ai-university-badges-list

// 新: ai-hub が action で分岐
// POST /ai-hub
// { "action": "university_streaks_get", ... }
// { "action": "university_streaks_update", ... }
// { "action": "university_badges_issue", ... }
```

具体的な実装例：

```typescript
// supabase/functions/ai-hub/index.ts
import { serve } from "https://deno.land/std@0.177.0/http/server.ts";
import { createClient } from "https://esm.sh/@supabase/supabase-js@2";

serve(async (req) => {
  const { action, ...params } = await req.json();
  const supabase = createClient(
    Deno.env.get("SUPABASE_URL")!,
    Deno.env.get("SUPABASE_SERVICE_ROLE_KEY")!
  );

  switch (action) {
    case "university_streaks_get":
      return handleStreaksGet(supabase, params);
    case "university_streaks_update":
      return handleStreaksUpdate(supabase, params);
    case "university_badges_issue":
      return handleBadgesIssue(supabase, params);
    // ... 30+ actions
    default:
      return new Response(
        JSON.stringify({ error: `Unknown action: ${action}` }),
        { status: 400 }
      );
  }
});
```

#### Flutter 側のクライアント改修

Hub パターンに移行したことで、Flutter 側の HTTP クライアントも統一できました：

```dart
// lib/services/edge_function_service.dart

class EdgeFunctionService {
  static const _baseUrl =
      'https://smmkxxavexumewbfaqpy.supabase.co/functions/v1';

  Future<Map<String, dynamic>> callHub(
    String hub,
    String action,
    Map<String, dynamic> params,
  ) async {
    final response = await _client.post(
      Uri.parse('$_baseUrl/$hub'),
      headers: _headers,
      body: jsonEncode({'action': action, ...params}),
    );
    return jsonDecode(response.body);
  }
}

// 使用例
final result = await EdgeFunctionService().callHub(
  'ai-hub',
  'university_streaks_update',
  {'userId': userId, 'studiedAt': DateTime.now().toIso8601String()},
);
```

### 詰まったポイント

#### 1. Deno のトップレベル await と import の整理

94 本の関数を 15 本に統合する際、各関数のヘルパーを shared モジュールに切り出す必要がありました。しかし Deno の ES Module 解決は Node.js と異なり、相対パスの `../shared/` がデプロイ時に解決されないケースがありました。

**解決策**: `supabase/functions/_shared/` に共通モジュールを置き、各 Hub からは必ず `../_shared/` 経由でインポートする規則を徹底。

#### 2. CI/CD でのデプロイ順序依存

Hub 統合後、GitHub Actions の `deploy-prod.yml` で Hub 間の依存関係（例：`core-hub` が完了してから `ai-hub` をデプロイ）を考慮する必要がありました。

```yaml
# .github/workflows/deploy-prod.yml
deploy-core:
  runs-on: ubuntu-latest
  steps:
    - run: supabase functions deploy core-hub

deploy-ai:
  needs: deploy-core  # core-hub 完了後に実行
  runs-on: ubuntu-latest
  steps:
    - run: supabase functions deploy ai-hub
```

#### 3. テスト戦略の見直し

統合前は各 EF に `index.test.ts` がありましたが、Hub 化後は **pure-logic テスト** に切り替えました。HTTP レイヤーのテストは E2E に任せ、ビジネスロジックの単体テストに集中する設計です。

```typescript
// supabase/functions/ai-hub/logic.test.ts
import { assertEquals } from "https://deno.land/std@0.177.0/testing/asserts.ts";
import { calculateStreak } from "./logic.ts";

Deno.test("ストリーク: 連続2日は2日カウント", () => {
  const result = calculateStreak([
    new Date("2026-04-10"),
    new Date("2026-04-11"),
  ]);
  assertEquals(result, 2);
});
```

今週この方針で **AI 大学関連 EF に 41 本のテスト**を追加しました。

各プロバイダーのデータは Supabase `ai_university_content` テーブルで管理し、GitHub Actions が 2 時間毎に RSS を収集して自動更新します。

```sql
-- ai_university_content テーブル
CREATE TABLE ai_university_content (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  provider text NOT NULL,        -- 'google', 'openai', 'huggingface' など
  category text NOT NULL,        -- 'overview', 'models', 'api', 'news'
  title text NOT NULL,
  content text NOT NULL,         -- Markdown 形式
  published_at date,
  created_at timestamptz DEFAULT now(),
  UNIQUE(provider, category)
);
```

Flutter 側のタブ UI は DB 駆動で動的に生成されるため、**新プロバイダーを DB に追加するだけでタブが自動生成**されます。
