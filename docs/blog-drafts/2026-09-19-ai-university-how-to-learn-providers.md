# AI大学 236社の学び方 — 「全部触る」より「深さ優先」が正しい理由

## AI ツールの学習が続かない本当の理由

「新しい AI ツールが毎週出て、追いかけるだけで疲れる」

この感覚を持っている人は多い。しかし問題の本質は「AI ツールが多すぎる」ことではなく、**学習の設計が間違っている**ことだ。

自分株式会社の AI 大学では 236社の AI プロバイダーを登録・学習管理している。そこから見えてきた「続く学習設計」を整理する。

---

## なぜ「全部触る」はうまくいかないか

### 更新頻度が速すぎる

主要 AI ツールの機能更新サイクル:

| ツール | 主要アップデート頻度 |
|--------|-------------------|
| Claude | 月1〜2回 |
| Cursor | 週1〜2回 |
| GitHub Copilot | 月1〜3回 |
| LangChain/LangGraph | 週1〜3回 |

「学んだ」と思ったら次のバージョンで UI が変わる。網羅的に追うのは構造的に不可能。

### 使わない知識はすぐ消える

人間の記憶は「使わない情報を 72時間以内に忘れる」。ツールを触っただけで業務に組み込まなければ、1週間後には記憶にない。

---

## AI大学の学習設計: 3ゾーン分類

自分株式会社 AI 大学では 236社を3ゾーンに分類する:

### Zone 1: 毎日使う (Core 5〜10社)

```
毎日使うから自然に深くなるゾーン
→ Claude Code, GitHub Copilot, Supabase, Flutter, Gemini API
→ 「学習」ではなく「使う」が正解
```

### Zone 2: 月1〜2回参照 (Reference 20〜30社)

```
必要なときに参照するゾーン
→ LangGraph, LiteLLM, Weaviate, Firecrawl, Tavily
→ 「使い方を覚える」より「どこに何があるか」だけ把握
```

### Zone 3: 知っておけば十分 (Horizon 200社+)

```
存在を知っている = 必要になったとき検索できる
→ 残り 200社以上
→ AI大学の分類・スコアで「どんなカテゴリか」だけ把握
```

**重要**: Zone 1 に 10社以上入れない。増やすたびに全ての深さが下がる。

---

## AI大学スコアの読み方

各プロバイダーには2つのスコアがある:

| スコア | 意味 | 範囲 |
|--------|------|------|
| **学習価値** | 個人開発者・スタートアップへの有用性 | 1〜10 |
| **市場影響力** | 業界への影響・資金調達・ユーザー数 | 1〜10 |

スコアの使い方:

```
学習価値 9/10 + 市場影響力 9/10 → Zone 1 候補 (最優先)
学習価値 7/10 + 市場影響力 9/10 → Zone 2 (参照用)
学習価値 5/10 + 市場影響力 7/10 → Zone 3 (知識として)
学習価値 3/10 以下 → ほぼ不要 (特殊用途)
```

実例:

| Provider | 学習価値 | 市場影響力 | ゾーン |
|----------|---------|-----------|-------|
| Claude Code | 9 | 9 | Zone 1 |
| LangGraph | 9 | 8 | Zone 1〜2 |
| Weaviate | 8 | 8 | Zone 2 |
| Moveworks | 8 | 9 | Zone 2〜3 |
| Harvey AI | 6 | 8 | Zone 3 |

## 正しい学習サイクル

### Zone 1 学習: 「問題ベース」で深める

```
悪い例: "Claude Code の全機能を体系的に学ぶ"
良い例: "この PR を Claude Code で自動レビューできるか試す"
→ 実際の問題を解くときに深さが生まれる
```

### Zone 2 学習: 30分の「実験」を月1回

```
目標: "LangGraph で Hello World ができる"
     → 達成したら終了 (完璧に理解しなくていい)
実験ログを docs/ai-experiments/ に記録
→ 「また調べればいい」状態が最適
```

### Zone 3 学習: AI大学の更新を週1回眺める

```
RSS フィードで新プロバイダーのニュースを流し読み
新規登録されたプロバイダーの summary だけ読む
→ 存在を知ることが目的
```

---

## AI大学の RSS 更新システム

自分株式会社 AI 大学は各プロバイダーの情報を 2時間ごとに自動更新している:

```
ai-university-update (GHA cron) → 
  各プロバイダーの RSS フィード取得 → 
  Gemini 1.5 Flash で要約 → 
  Supabase ai_university_content テーブルに保存
```

これにより:
- 236社の最新情報が常に最新
- ユーザーは「何が変わったか」だけチェックすればいい
- 全プロバイダーを自分で追う必要がない

---

## 継続できる学習の設計まとめ

1. **Zone 1 (5〜10社) を死守する** — これ以上増やさない
2. **毎日使うことが最良の学習** — 意図的な「学習時間」を作らなくていい
3. **Zone 2 は月1回の実験で十分** — 完璧に理解しなくていい
4. **Zone 3 は AI 大学に任せる** — 自分で追わなくていい
5. **学習ログを残す** — 「使えた」体験が次の動機になる

AI ツールは学ぶものではなく、**使いながら深くなるもの**。設計が正しければ、意識しなくても学習は進む。
