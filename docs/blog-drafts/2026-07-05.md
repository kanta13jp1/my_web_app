### はじめに

X（旧Twitter）に動画を投稿したことがある方なら、あの「自動ミュート再生」の壁を知っているはずだ。タイムラインに流れてくる動画は無音でスタートする。ユーザーが自分でミュートを解除しない限り、声は届かない。

自分株式会社では、Flutter Web + Supabase を使って「自社プロダクトのアップデートを動画で自動投稿するシステム」を運用しているが、この1週間でその動画投稿パイプラインを大きく強化した。

具体的には次の3点だ：

- **Cloud Run 上にキャプション焼き込みマイクロサービスを構築**（#3813）
- **動画の最初3秒をフックで始まるよう生成プロンプトを改善**（#3819）
- **Growth Hub に投稿パフォーマンスデータをLLMへ渡す仕組みを追加**（#3821）

本稿ではこれらの実装を振り返る。

---

### 実装方法

#### 1. キャプション焼き込み Cloud Run サービス (#3813)

Deno の Edge Function ではffmpegをin-processで実行できない。そこで、**超軽量なNode.jsマイクロサービスをCloud Runにデプロイ**した。

このサービスのインターフェースはシンプルだ：

```
POST /burn
{
  "videoUrl": "...",
  "srt": "1\n00:00:00,000 --> 00:00:02,500\n自分株式会社のアップデート",
  "forceStyle": "FontSize=24,PrimaryColour=&H00FFFFFF",
  "resolution": "1080x1920",
  "style": "subtitle"
}
→ { "url": "焼き込み済みmp4のURL" }
```

ffmpegの `subtitles` + `force_style` フィルタを使ってSRTをMP4に焼き込み、Supabase Storageに再アップロードする。生成したファイルの寿命は数秒で十分なので、GCSは使わない設計にした。

日本語キャプションの文字化けを防ぐため、`fonts-noto-cjk` をDockerイメージに含めた点がポイントだ。

**失敗しても投稿をブロックしない設計**も重要だった。トランスコーダーがエラーを返した場合は、キャプションなしの元のmp4をそのまま投稿する。キャプションのために投稿が失敗するのは本末転倒だからだ。

#### 2. 動画最初3秒のフック最適化 (#3819)

muted autoplayの環境では、最初の3秒でユーザーが「見続けるかどうか」を決める。

従来は「おはようございます。今日の話題は…」というジェネリックな前置きから始まっていた。これを改め、**トピックが存在する場合はローテーション式フックで始まる**ようにした：

```dart
// トピックフック例（ローテーション）
'<topic>、30秒で要点だけ。'
'<topic>について、今すぐ知るべきこと。'
'もし<topic>を見逃したら、損するかもしれない。'
```

同時に、`lib/services/universal_x_share_service.dart` の動画プロンプトに「強い最初のビート（即座のスピーチ＋プッシュイン）」を指示するプロンプト文を追加。観察していた「た。今日の話題は…」という文中断キャプションフラグメントも修正された。

#### 3. Growth Hub への LLM 文脈強化 (#3821)

投稿を続けると、どのバリアント（フォーマット）が効いているかのデータが蓄積される。`supabase/functions/growth-hub/index.ts` の `buildXPerformanceContextFromLogs` 関数を拡張し、以下の集計情報をLLMプロンプトに渡すようにした：

- **バリアントランキング** (上位5件、サンプルサイズ保証付き)
- **メディアあり vs なし の平均スコア差**
- **リンク配置による平均スコア差**
- **最適スレッド長バケット**
- **「真似すべきフックの構造」** (具体的な言葉ではなく構造)

サンプル数が少ないバケットは出力しない (`rows >= 2` or `>= 3` のガード)ことで、統計的に薄いデータがLLMを誤誘導しないようにした。

### 詰まったポイント

**キャプションの改行問題**（#3818）が地味に厄介だった。ffmpegのsubtitlesフィルタはデフォルトでは横幅を超えるテキストを改行しない。`wrap_unicode=1` オプションを追加し、縦型動画(1080x1920)のフレーム内に収まるよう強制した。

**ポールJSONの漏れ**（#3816）も手こずった。X APIのレスポンスにネストされたポールデータが含まれる場合、正規表現でJSONブロックを抽出するロジックが生JSONをリプライに貼り付けてしまうバグがあった。パースロジックのフォールバックを整備して修正。

**ツイートメトリクスの100ID上限**（#3822）は、X API の `GET /2/tweets` が一度に取得できるのが最大100件という制約から来る問題だ。バッチ処理を実装して対応した。
