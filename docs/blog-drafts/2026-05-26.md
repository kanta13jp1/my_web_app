## 本文下書き

### はじめに

個人の財務管理において「今月、自由に使えるお金はいくらか」を正確に把握することは意外と難しい。給与が入っても、家賃・光熱費・ローン返済・クレジットカード引き落としが重なると、実際の可処分残高は銀行残高とは大きくかけ離れる。

「自分株式会社」(https://my-web-app-b67f4.web.app/) では Flutter Web + Supabase を使って個人財務管理アプリを開発しており、今週は **可処分残高の精度を大きく向上させる機能群** を実装した。具体的には以下の3点だ：

- 固定費（家賃・光熱費など）とローン返済を自動分類し、可処分残高カードにインライン表示
- auPay カードの資金移動トランザクションをキャッシュフローとして自動追跡
- Anthropic Acom（クレジット枠の返済）をキャッシュフロー行として記録

### 実装方法

#### 1. キャッシュフロー固定支払いを可処分残高へマッピング

最初の課題は「キャッシュフローの行が固定費なのか返済なのかを判別する」ことだった。

```dart
// cashflow_to_disposable_adapter.dart の核心ロジック
enum DisposableBucket { fixedExpense, repayment, other }

DisposableBucket classify(CashflowRow row) {
  if (row.category == Category.loanRepayment ||
      row.category == Category.creditCardPayment) {
    return DisposableBucket.repayment;
  }
  if (row.paymentDay != null && row.isRecurring) {
    return DisposableBucket.fixedExpense;
  }
  return DisposableBucket.other;
}
```

家賃（25日引き落とし）・光熱費などは `fixedExpense`、auPay カード・Acom 返済などは `repayment` に分類される。このアダプター層を導入することで、UI 側は分類ロジックを持たずに済む。

#### 2. 可処分残高カードのインライン内訳表示

`DisposableBalanceCard` ウィジェットに内訳を展開表示する仕組みを追加した。

```dart
// 展開前：残高合計のみ表示
// 展開後：固定費 ¥XXX / 返済 ¥XXX の内訳を inline 表示
Widget _buildBreakdown(DisposableBalanceSummary summary) {
  return Column(
    children: [
      _BreakdownRow(label: '固定費', amount: summary.fixedExpenseTotal),
      _BreakdownRow(label: '返済', amount: summary.repaymentTotal),
    ],
  );
}
```

当初はツールチップ方式で実装したが、モバイルでの操作性が悪かったため、インライン展開方式に切り替えた。コミット履歴にも `Revert "feat: show disposable balance breakdown tooltips"` が残っている通り、一度リバートしてから再設計している。

#### 3. auPay カード資金移動の自動追跡 (#3028)

auPay カードは「クレジット枠での支払い → 月末に銀行口座から引き落とし」というキャッシュフローパターンを持つ。このトランザクションを Supabase の `cashflow_entries` テーブルに自動で記録する Edge Function を実装した。

```typescript
// supabase/functions/sync-aupay/index.ts
const transfer: CashflowEntry = {
  title: 'auPay カード引き落とし',
  amount: -totalCharged,
  category: 'credit_card_payment',
  payment_day: settlementDay,
  is_recurring: true,
};
await supabase.from('cashflow_entries').upsert(transfer);
```

#### 4. Anthropic Acom 返済キャッシュフロー (#3027)

Claude API の利用料金は Anthropic Acom（後払い）を経由する場合がある。この返済行をキャッシュフローとして管理することで、AI ツール利用コストを他の固定費と同列に追跡できるようになった。

### 詰まったポイント

**GitHub Actions の環境問題**

`feat: show disposable balance breakdown inline` のコミットメッセージにも記載されているが、今回 GitHub Actions が `checkout/action-download` のインフラエラーで詰まった。ローカルでは `flutter analyze` / `flutter test` / `flutter build` が全て通っているため、CI の問題であって実装の問題ではないと判断し、先にプッシュして対処した。

CI のインフラ依存でリリースが止まることを避けるため、`ci: avoid suspended checkout path for deploy` というコミットで GHA のパス設定を修正している。

**ツールチップ → インライン への方針転換**

UI/UX の試行錯誤として、最初に実装したツールチップ方式をリバートしてインライン方式に切り替えた。ツールチップはデスクトップ（ホバー）では自然だが、タッチデバイスでは長押しが必要になり UX が悪化する。Flutter Web はデスクトップとモバイル両方をサポートする必要があるため、インライン表示を選んだ。

**アダプター層のテスト設計**

25 日引き落としの家賃ケースを確定的にカバーするためのアダプターテストを追加した。実際の支払い日に基づくテストケースを書くことで、分類ロジックのリグレッションを防いでいる。

### まとめ

今週の実装を通じて、個人財務アプリにおける「可処分残高の精度」が大きく向上した。単に銀行残高を表示するだけでなく、固定費・返済を自動分類してインライン表示することで、ユーザーは今月の「本当の自由残高」を直感的に把握できる。

キャッシュフロー設計の核心は **「分類アダプター層」を UI から分離すること** だ。UI 側は分類済みのデータを受け取るだけにすることで、分類ロジックの変更が UI に影響しないクリーンな設計を実現している。

次のステップとして、auPay や Acom 以外のカード・ローンへの対応拡張、および月別推移グラフへの組み込みを予定している。
