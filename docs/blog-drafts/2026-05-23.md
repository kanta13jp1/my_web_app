### はじめに

インディー開発者にとって「競合調査」は永遠の課題だ。毎日チェックしていると時間が溶けるし、サボると見落としが出る。そこで私は「自分株式会社」の開発リポジトリに、Claude Code + GitHub Actions + Supabaseを使った**競合自動監視システム**を組み込んだ。

今週、監視対象がついに21社に達した。最新の追加はBolt.new。これでCursor / Replit / Lovable / Bolt.newという**vibe coding 4強**が全て揃った。

この記事では、その仕組みと「Karpathy式第二の脳」をSaaSに組み込んだ運用フローを紹介する。

---

### 実装方法

#### 1. 競合監視パイプライン (GHA + Claude Opus 4.7)

毎日1回、GitHub Actionsが競合21社の最新シグナルを収集し、`docs/competitor-reports/` に日次レポートを自動生成する。

```
GHA cron → Claude Opus 4.7 (1M context)
         → docs/competitor-reports/YYYY-MM-DD.md
         → docs/competitor-reports/_competitors.json (21社マスター)
         → git commit & push
```

レポートには以下が含まれる：
- 各社の直近シグナル (リリース / 戦略変更 / 価格改定)
- 自社への影響度評価 (🔴🟡🟢)
- 戦略レビュー候補議題

今週のシグナルで特に重要だったのは：
- **Anthropic Memory for Managed Agents** — 自社のKarpathy 4サイクルと直接競合する可能性
- **OpenAI Codex Goals default化** — AIコーディング体験の標準化が加速
- **Cursor Bugbot + 3.3並列エージェント** — IDE統合型AIの進化

#### 2. Karpathy 4サイクルによる知識管理

Andrej Karpathyが提唱する「第二の脳」の4サイクル (Ingest → Compile → Query → Lint) を、自社開発フローに完全統合している。

```
Ingest:  scripts/memory_ingest.py
         → raw/ 以下の記事・URL をAtomic Noteに変換
         → memory/vault/ に保存

Compile: scripts/wiki_compile.py  
         → docs/concepts/ の概念ページを自動生成
         → docs/INDEX.md マスターインデックスを再生成

Query:   notebooklm CLI
         → ゼロトークンで過去の判断を参照
         → NotebookLM の Deep Research モード活用

Lint:    scripts/knowledge_vault_lint.py
         → orphan / broken link / duplicate title を検出
         → Health Score を算出
```

毎週1回のwiki compileサイクルと、毎日のlintが自動実行される。これにより「過去の判断に一貫性があるか」を常時チェックできる。

#### 3. Flutter Web + Supabase の技術スタック

フロントエンドはFlutter Web、バックエンドはSupabase (PostgreSQL + Edge Functions / Deno)。本番環境はFirebase Hostingにデプロイしている。

Supabase Edge FunctionsはDeno製で、TypeScriptで書ける。AI機能 (Claude API呼び出しなど) もEdge Functionとして実装し、サービスキーで認証している。

```typescript
// Edge Function例 (Deno)
import { serve } from "https://deno.land/std@0.168.0/http/server.ts"

serve(async (req) => {
  const { title, content } = await req.json()
  // Claude APIで要約生成
  const summary = await generateSummary(content)
  return new Response(JSON.stringify({ summary }), {
    headers: { "Content-Type": "application/json" },
  })
})
```

### 詰まったポイント

#### GHAのClaude API quota管理

GHAのcronジョブが並列で走ると、Claude APIのquotaを一気に消費する。対策として：

1. **quota fallback設計**: Claude quota超過時はGemini 1.5 Flash / Codex CLIに自動フォールバック
2. **Claude非依存cron**: ヘルスチェック・インフラ監視はClaude APIを使わない設計
3. **Prompt Caching活用**: Opus 4.7 + Prompt Cachingで約88%のコスト削減 (Issue #1756)

#### 競合の「発見」をどう自動化するか

既知の競合をモニタリングするのは簡単だが、「新しい競合を発見する」のは難しい。現在は以下のアプローチで対応：

- Claude OpusによるWebリサーチで関連カテゴリを定期スキャン
- 競合採択基準を明文化 (`_competitors.json` に記録)
- 7サイクル連続でPlan A第1候補に上がった場合に採択 (Bolt.newはこのパターンで採択)
