# Firebase 障害対応・相談・AI支援ガイド

対象: Issue #1397。公式情報の確認日: 2026-09-06。
本書は手順書であり、実プロジェクトの設定変更・問い合わせ送信・AI利用を
実施した証拠ではない。画面や利用条件が変わった場合はリンク先を再確認する。

## 最初に障害を切り分ける

1. 発生時刻（タイムゾーン付き）、対象環境、サービス、影響範囲、エラーコード、
   最後に成功したデプロイと現在のリビジョンを記録する。
2. [Firebase Status Dashboard](https://status.firebase.google.com/)で該当サービスと
   発生時間帯を確認する。該当インシデントのリンク・更新時刻・回避策をIssueに残す。
3. 掲載がなくても正常とは断定しない。直近の設定変更とGitHub Actionsのログを
   照合し、再現手順を絞る。障害解消のためだけに課金・IAM・セキュリティルールを変更しない。
4. 原因と対応責任者を決め、復旧後に元の操作の成功と影響範囲を確認して記録する。

このリポジトリでは `.firebaserc` の既定プロジェクトは `my-web-app-b67f4`。
この記載だけでは開発/本番の分離や実際の料金プランは証明できない。
Firebase Hostingの配信失敗とアプリのバックエンド障害は分けて調査する。
ローカルで重い再ビルドを始めず、AGENTS.mdのクラウド優先方針に従う。

## 相談先を選ぶ

| 問題 | 次の行動 |
| --- | --- |
| サービス停止の疑い | Status Dashboard → 該当がなければ公式サポート |
| 再現可能な製品バグ・機能要望 | [Bugs / feedback / feature requests](https://firebase.google.com/support/troubleshooter/report) |
| APIの使い方・実装上の疑問 | [Firebase Support](https://firebase.google.com/support)からStack Overflowへ。最小再現例を添える |
| 運用経験・設計の相談 | 同ページからRedditへ。コミュニティ回答を公式仕様の代わりにしない |
| プロジェクト固有の障害・請求問題 | 公式Supportの「submit a support case」から、該当製品・請求カテゴリを選ぶ |

問い合わせ前にAuthentication、Databases、Hosting、Billingなど実際に問題がある
領域を整理する。フォームの分類名は変更され得るため、現在の選択肢に合わせる。
公開の場で請求情報やアカウント情報を相談しない。チームで送信内容と送信者を確認し、
ケース番号・回答・次の確認日を元のIssueへ戻す。

問い合わせ用メモ:

```text
対象サービス・環境:
発生時刻と影響範囲:
期待する動作 / 実際の動作:
最小再現手順とSDKバージョン:
エラーコード、秘匿情報を除いたログ:
Status Dashboardの確認結果:
関連Issue / CI run / リビジョン:
試した対処と結果:
```

APIキー、トークン、Cookie、サービスアカウント鍵、実ユーザーの健康・金融記録、
メールアドレス等を貼らない。公式窓口でも必要最小限とし、公開投稿は匿名化した
架空データで再現する。障害時の証拠は保持し、ログ全体を無条件に転載しない。

## Gemini in Firebaseを任意で利用する

[公式セットアップ](https://firebase.google.com/docs/ai-assistance/gemini-in-firebase/set-up-gemini)
の確認時点では、ユーザー・プロジェクト単位で有効化し、全ユーザーに無償提供と
説明されている。Google Workspaceを使わないメンバーもこの手順が対象になる。
AI支援の無償提供はFirebaseのインフラや他のAI APIまで無料にするものではない。

1. チームのAI利用・データ送信方針を確認する。有効化はOwnerまたはEditorが行う。
   Viewerは自分で有効化できないため、必要なら管理者に依頼する。権限を自動で昇格しない。
2. Firebase consoleで対象プロジェクトを確認し、右上の「Gemini in Firebase」を開く。
   表示された条件を読み、承認済みの場合だけ「Get started」を選択する。
3. チャットに個人情報を含まない質問を入力する。例えば
   「Hostingで404が出る場合の切り分け項目を、公式ドキュメントへのリンク付きで説明して」。
4. 回答中のURLを開き、対象サービス・SDK・現在の設定に合うか検証する。
   提案コードは差分レビューと適切なCIを通す。AI回答だけで本番変更や完了判定をしない。
5. ボタンがない場合は管理者がGemini for Google Cloud APIの有効状態を確認する。
   この確認を口実にAPIの有効化や追加契約を自動実行しない。

公式案内では、このチャットは特定のコードベースにアクセスしないため
Security Rulesの生成には対応していない。認証・権限・ルール変更は別途人のレビューが必要。
無効化のためのGemini for Google Cloud API停止は他のGemini for Google Cloud機能にも
影響するため、管理者が依存機能を確認して判断する。

## レビュー時の確認

- 障害切り分けの開始点と、製品バグ・質問・請求の相談先を説明できるか。
- 公開できない情報がテンプレートやAI質問例に混入していないか。
- AIの有効化・権限付与・課金変更が、手順書の作成だけで実行されていないか。
- 実際に操作する担当者が、当日の画面・利用条件・対象プロジェクトを確認したか。

手順書の受入条件と実アカウントでの動作確認は区別する。
本書作成時はログイン後の画面操作・ケース送信・AI呼び出しは実施していない。
